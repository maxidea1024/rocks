### 9.1 선행 구현 재작업(UW 단계, 2026-11-25)

UI 코드 일부가 9절 순서(UT0·CB2 선행)보다 먼저, 글꼴 시스템이 없던 때 만들어졌다. UT1·UT3 상당 부분, UT2 일부(UiRender), UT5·UT6 일부가 섞여 있다. 2026-11-25 리뷰(영역별 리뷰어 4명 + policy·format 검사)의 결론은 "동작은 하지만 병합 불가, 기반 품질은 좋아 다시 쓰지 않고 경계를 옮긴다"이다. 이 절은 그 편차와 해소 단계다. UW가 끝나면 UT1 완료 판정(UV1–UV4, UV6 CPU)으로 넘어간다.

**편차(리뷰 결과 요약).**
- 렌더 경계(2·3.4·3.7절 위반): `graphics::Device&`가 UiCore 공개 헤더(`WidgetSurfaceScene::Draw`)와 UiWidget(`ViewportWorld`)에 나와 있다. UiRender(`WidgetSurfaceHost`)가 Element 트리를 순회하고 World를 tick한다. `DrawBatchBuffers`가 Game lane `DrawBatch` 참조를 보관한다. 표면마다 따로 제출하고 `RenderLane`·RenderGraph·`UiRenderer` 계약이 없다. UiRender 객체가 장치를 멤버로 보관한다.
- 셰이더: UI 셰이더를 HLSL·GLSL 원문으로 코드에 넣었다. engine-runtime은 런타임 셰이더 컴파일러를 제거했으므로(셰이더 시스템 SH2e2) 이 경로는 더는 동작하지 않는다.
- 텍스트(3.12절): worktree 판 `TextLayout`(GlyphAtlas·GlyphAtlasCache)이 글꼴 시스템의 같은 이름 모듈과 겹친다. 데모가 GDI로 래스터한다. `TextLabel`은 shaping 결과와 renderer handle을 받고 배율을 무시한다.
- 창·입력(3.8·3.11·7.2절): OS 메시지 스레드 = 게임 스레드 가정(`WM_NCHITTEST`에서 UI 트리 판정), IMM push형 IME, DPI 없음, `InputEvent`의 공유 문자열, 창 단위 `WaitForEvents`, backend 안의 전체 화면 전환.
- Element 동작: 실제 시계 직접 사용(3.10절 주입 시계 아님), 비활성 Element hit가 UE와 다름, Element slot 대신 wrapper, hit grid를 그리기와 따로 만듦, Hidden 속성 갱신 생략, navigation 변환 위치, 스타일 체계(4절) 없음.
- Widget 층: 속성 접근이 손으로 쓴 이름 표(UT0 CU 지정자 없음), 텍스트 편집 Element가 UiWidget Private, UiScreens 입력 설정 미적용, Element 소멸자의 사용자 코드, UD12와 다른 이름(`Retainer`·`CanvasPanel`·`ScaleBox`·`WrapBox`·`InvalidationBox`).
- 규칙: 빌드 파일 한국어 주석, 데모 표시 문자열 한국어, format 위반, 이름 없는 수치, 시험 부족(UV 기준값 없음).

**우선순위(사용자 결정 2026-11-25).** UI는 에디터부터 쓴다. 게임 UI는 그 뒤다. 목표는 UE 5.8 에디터의 룩과 기능 수준이고, 에디터에서 어떻게 보이는지가 가장 중요하다. 그래서 에디터 룩(UW3)과 모든 위젯을 탭별로 시험하는 갤러리(UW4)를 렌더 경계·입력 계약 정리보다 앞에 둔다. 데모 화면(궤도 시각화)은 위젯 시험에 쓸모가 없어 갤러리로 바꾼다.

**병합 때 정한 것(UW0).**
- 터치는 Input의 `TouchBegan`·`TouchMoved`·`TouchEnded`(손가락 번호, `cancelled`)를 쓴다([터치 입력](../TouchInput.ko.md) 3.1절). UI 쪽 `TouchBegin`·`TouchMove`·`TouchEnd`·`TouchCancel`과 `pointerId` 필드는 지웠다. `InputAdapter`가 손가락 번호를 pointer 번호로 쓰고 `cancelled`를 Cancel로 바꾼다. UI capture는 (source, user, pointer)로 찾으므로 마우스 0번과 손가락 0번은 겹치지 않는다.
- 마우스 capture 상실은 취소(`PointerCaptureLost`)다(UE `OnMouseCaptureLost`). engine-runtime의 "눌린 버튼마다 가짜 MouseUp" 방식은 버린다. 가짜 뗌은 Button을 클릭으로 처리한다. `InputState`는 취소를 받으면 눌린 버튼을 뗀 것으로 기록한다(클릭 없음).
- `PlatformWindow`의 창 기본 구현(`Window.cpp`)은 `Private/Common`으로 옮겼다. Android는 clipboard·조합 창·drag 이미지를 아직 구현하지 않아 Unsupported를 낸다(`AndroidUiServices.cpp`).
- 병합 때 `MaterialBase`를 클래스 단위로 export했으나(빌드 타깃 BS8d3 — 다른 모듈의 파생) UW1a에서 파생 클래스(`RetainerEffectMaterial`)를 지우며 되돌렸다.

**UW3a 둥근 상자(UE `FSlateRoundedBoxBrush`, 14장 5절).**
- `Brush`에 `BrushMode::RoundedBox`와 외곽선 설정(모서리 반경 4개 — 왼쪽 위·오른쪽 위·오른쪽 아래·왼쪽 아래 순, 색, 두께, 반경 방식 Fixed·HalfHeight)을 더한다. 반경을 주지 않으면 HalfHeight(높이의 절반 — 알약·원)다(UE와 같다).

**UW7a 크기 조절 중 실시간 다시 그리기(설계, 사용자 요청으로 UW7에서 앞당김 — 2026-11-25).** Windows는 창 테두리를 끄는 동안 `DefWindowProc` 안의 크기·이동 modal 루프에서 메시지를 처리하므로, 그동안 호스트 프레임 루프가 돌지 않고 DWM이 마지막 그림을 늘린다. UE 5.8은 그 루프 안의 `WM_SIZE`에서 `FSlateApplication::OnSizeChanged`가 스왑 체인 크기를 바꾸고(`RequestResize`) 바로 그린다(`PrivateDrawWindows` — WindowsApplication.cpp 3943–3969행, SlateApplication.cpp 6960–6980행). UE가 그 자리에서 그리는 것은 OS 테두리가 없는 창(에디터 창)뿐이다(6977행). Rocks는 OS 테두리 창도 그린다 — 지금 창이 모두 OS 테두리 창이고, 에디터 룩의 실시간 재배치를 보이려는 것이다.
- `platform::Window::SetLiveResizeHandler(Delegate<void()>)`: 크기·이동 modal 루프 안에서 크기가 바뀌면(`WM_ENTERSIZEMOVE`와 `WM_EXITSIZEMOVE` 사이의 `WM_SIZE`, 최소화 제외) 창이 `PumpEvents` 안에서 이 콜백을 동기로 부른다. 호스트는 `ConsumeResize`로 새 크기를 받아 스왑 체인을 바꾸고 배치·그리기·present를 한 번 한다. 콜백 안에서 `PumpEvents`를 다시 부르면 안 되고, 창은 콜백 중 다시 들어온 `WM_SIZE`로 콜백을 겹쳐 부르지 않는다. 호스트를 파괴하기 전에 빈 콜백으로 해제한다(`SetRegionHitTest`와 같은 수명 규칙).
- 다른 플랫폼: 크기 조절 중에도 프레임 루프가 도는 플랫폼(Android, macOS의 live resize는 별도 확인)은 아무것도 하지 않는 기본 구현이다.
- modal 루프 밖의 크기 변경(최대화 단추·코드로 바꾼 크기)은 지금처럼 다음 프레임에 처리한다. 버린 대안은 modal 루프를 쓰지 않는 직접 크기 조절(`WM_NCLBUTTONDOWN`을 가로채 직접 끄기)이다 — OS 창 동작(스냅·에어로 셰이크)을 다시 만들어야 한다. 타이머(`SetTimer`)로 루프 안에서 프레임을 돌리는 대안도 버린다 — 크기가 바뀔 때만 그리면 되고, 시간에 기대는 갱신이 된다.
- 확인: UiDemo가 콜백에서 그 창의 프레임만 그리고(실패는 기록했다가 다음 루프 차례에 돌려준다), 사람이 끌면서 내용이 다시 배치되는지 본다. 실제 창을 띄우는 시험은 데스크톱 세션이 필요해 EngineTests에 두지 않는다(PlatformWindow 시험의 기존 원칙).

**UW4f 초점 표시와 텍스트 입력(2026-11-26 — 사용자 지적: "포커스 처리랑 텍스트 입력(IME 지원)이 없네").** 둘 다 코드 일부는 있었으나 갤러리에서 보이지 않고 에디터가 쓸 수 없는 상태였다. 세 단계로 나눈다.

- **UW4f1 초점 외곽선.** Application의 사용자별 초점 항목에 원인 `FocusCause`(Pointer·Navigation·Direct — UE `EFocusCause`의 Mouse·Navigation·SetDirectly, Cleared는 `SetFocus(user, {})`가 맡아 두지 않는다, UiCore)를 둔다. `SetFocus(user, target, cause = Direct)`, 포인터 누름이 고른 초점은 Pointer다. `MoveFocus`·`MoveFocusWithin`·`Navigate`는 `cause` 인자(기본 Direct)를 받고, 사용자 이동 경로(InputAdapter의 Tab·방향키, ScreenInputRouter의 게임패드 방향)만 Navigation을 넘긴다 — 메뉴·화면의 첫 초점처럼 코드가 옮기는 초점에는 외곽선이 없다(UE SetDirectly). 메뉴는 연 원인을 첫 항목과 닫은 뒤 복원에 잇고(키보드로 연 메뉴는 외곽선 유지 — UE보다 낫게), 목록 스크롤 뒤 초점 보정은 이전 원인을 잇는다. 빈 곳을 누르면 초점은 두고 외곽선만 끈다. 요소는 `OnQueryShowFocus(cause)`로 외곽선을 강제하거나 끌 수 있다(UE `SWidget::OnQueryShowFocus`, 초점 잎부터 루트 방향 첫 답). Primary 바탕 버튼은 흰 외곽선(`FocusOutlineOnAccentStyle` — UE는 Primary 외곽선이 바탕에 묻힌다). 외곽선은 요소 경계 안쪽에 그려져 자기 clip에 잘리지 않으므로 UE처럼 PopClip 뒤로 옮기지 않는다. Application이 보이기 상태를 바꿀 때 해당 요소의 `SetFocusOutlineVisible`(사용자 수 계수)을 부르고 그 요소의 그리기를 무효화한다 — 기록이 요소 단위라 cache root·지역 캐시가 그대로 맞는다. `Element::Paint`는 자기 내용과 자식을 그린 뒤 그 위 층에 `FocusOutlineBrush()`를 요소 크기로 그린다(UE `SWidget::Paint`의 `GetFocusBrush` — 기본 UiCore `FocusOutlineStyle()` = RB(Transparent, 4, Primary, 1), 14장 "FocusRectangle"). 테두리로 초점을 보이는 부품(편집 텍스트)은 빈 brush를 돌려 외곽선을 그리지 않는다(UE `SEditableText::GetFocusBrush` = null). 초점 해제·창 입력 끊김·요소 분리(`ReleaseInactiveTargets`)도 보이기 상태를 지운다. 갤러리: Behavior 탭 "Focus Outline" 행(버튼·체크 상자·슬라이더를 Tab으로 돌며 외곽선, 눌러서 옮긴 초점은 외곽선 없음), self-test는 Tab 뒤 외곽선 화소와 누름 뒤 없음을 단언한다.

**UW7d 팝업 허용 영역 — 시스템 기본 규칙(사용자 지적 2026-11-26 — "툴팁이나 메뉴 하위 팝업은 물리적인 화면을 벗어나면 안 된다", "케이스별이 아니라 시스템의 기본 룰로").** 지금까지 메뉴 층·툴팁 층은 각자 창 경계 안으로만 밀어 넣어, 창이 모니터 밖에 걸치면 팝업도 모니터 밖에 놓였다. UE는 팝업 창 위치를 앵커가 있는 모니터의 작업 영역으로 정한다(`FSlateApplication::CalculatePopupWindowPosition` — `GetWorkArea(AnchorRect)`). Rocks는 팝업을 창 안 층으로 그리므로 같은 규칙을 호스트에서 강제한다. (1) 플랫폼 — `platform::Window::WorkAreaAt(IntVec2 client)`: 그 client 지점이 놓인 모니터(가장 가까운 모니터)의 작업 영역(작업 표시줄 제외 — Win64 `MonitorFromPoint`·`GetMonitorInfoW` rcWork, 전체 화면 창이면 rcMonitor)을 client 좌표 사각형으로 돌려준다. 지원하지 않는 backend는 Unsupported. (2) 앱 — `Application::SetPopupWorkArea(Delegate<bool(Vec2 window, Box2<float>& area)>)`: 창 호스트가 한 번 등록한다(UiDemo `DockWindows`는 창마다 `WorkAreaAt`을 잇는다). Application은 이를 루트 Element에 단다(루트를 바꾸거나 툴팁 임시 호스트로 감쌀 때도 옮긴다). Element는 `QueryPopupWorkArea(window point, area)`로 조상에서 가장 가까운 공급자를 찾는다(공급자는 의미 정보에 두어 다른 요소에는 비용이 없다). (3) 호스트 강제 — `Overlay`는 자기가 품은 팝업 층마다 기준 지점의 허용 영역을 묻고(여러 모니터 — 사용자 지적 2026-11-26 "멀티 스크린도 고려": 기준 지점은 UE와 같게 앵커의 왼쪽 위다 — `CalculatePopupWindowPosition`의 WorkAreaFinderRect가 앵커 왼쪽 위 1 px이고 Windows `GetWorkAreaFromOS`가 `MonitorFromRect(MONITOR_DEFAULTTONEAREST)`로 가장 가까운 모니터를 고른다(SlateApplication.cpp 4185행·WindowsApplication.cpp 1743행). 커서에 붙는 툴팁 층은 `Element::PopupWorkAreaPoint`로 커서 지점을 준다(UE `CalculateTooltipWindowPosition`). 그래서 두 모니터에 걸친 창에서도 팝업은 한 모니터 안에만 놓인다. 모니터별 DPI 배율은 UW5에서 함께 본다), 층을 `Overlay 경계 ∩ 허용 영역`으로 배치한다(없으면 지금처럼 Overlay 전체). 층의 계약: 내용은 자기 경계 안에 놓고(뒤집기·밀어 넣기) 경계로 자른다 — 메뉴 층(`MenuPopupLayer`, 맞춤 켬)·툴팁 층이 이미 그렇다. 그래서 메뉴·하위 메뉴·콤보 목록·툴팁·앞으로의 팝업이 개별 처리 없이 화면 안에 놓인다. (4) 하위 메뉴는 오른쪽이 모자라면 왼쪽으로, 아래가 모자라면 위로 민다(기존 뒤집기가 이제 허용 영역 기준). (5) 버린 안: 층마다 화면 질의(케이스별 — 새 팝업이 빠뜨린다), 팝업을 별도 OS 창으로(UE 방식 — 창 밖으로도 펼칠 수 있지만 창·입력·초점·스왑 체인이 팝업마다 필요하다; 창 밖 펼침이 필요해지면 후속 단계로). (6) 시험 — Overlay가 허용 영역으로 층을 놓는지, 두 모니터에 걸친 앵커는 왼쪽 위 모니터를 고르는지·커서 툴팁은 커서 모니터를 쓰는지, 메뉴·하위 메뉴·툴팁이 영역 오른쪽·아래 끝에서 뒤집히고 밀리는지, 공급자 없을 때 지금 동작, 툴팁 임시 호스트로 감쌀 때 공급자 이동, Win64 `WorkAreaAt`이 창 client 안 지점에서 성공하는지.

**UW3c 비활성 효과(설계, 리뷰 반영 2026-11-25).** UE 5.8은 비활성 위젯을 `ESlateDrawEffect::DisabledEffect`로 그리고, 픽셀 셰이더가 알파에 0.45를 곱한다(SlateElementPixelShader.usf 645행 — 탈색하는 레거시 효과는 32행에서 끔). 판정은 `ShouldBeEnabled(bParentEnabled)`라 조상이 비활성이면 자손도 효과를 받는다.
- `PaintList`가 그리는 동안 "이 요소나 조상이 비활성"을 들고(`IsDisabled`), `Element::PaintSubtree`가 들어갈 때 `부모 || !enabled_`로 세우고 나올 때 되돌린다. `TryAddBox`가 이 상태면 알파(채움·외곽선)에 `DisabledEffectOpacity`(0.45)를 곱한다. 효과는 비활성 경계에서 한 번만 걸린다(조상·자손이 함께 비활성이어도 0.45²가 아니다).
- 비활성 전용 brush가 있는 버튼은 자기 brush에서만 효과를 뺀다(UE SButton `bShowDisabledEffect`, 171–192행). `PaintList::DisabledEffectExemption` 범위로 표시하고, 자식(레이블)은 효과를 받는다. 버튼 brush·전경색은 상속 비활성도 본다(`Element::PaintForegroundColor(disabled)` — UE SBorder의 DisabledForegroundColor).
- 캐시: `SetEnabled`는 그리기 계획을 바꾸므로 `CacheRoot`가 전체를 다시 만든다. 항목은 기록 때 비활성 상태를 보관하고 다시 기록할 때 되돌린다. 지역 캐시(`CachePanel`)는 물려받은 비활성 상태가 기록 때와 다르면 전체를 다시 만든다.
- 버린 대안: 비활성 하위 트리를 render opacity로 낮추기(조상·자손 중복 곱, 비활성 전용 brush 예외를 표현하지 못함), 셰이더 플래그(UE 방식이지만 명령마다 상수가 늘고 배치가 갈라진다 — CPU 알파 곱과 결과가 같다).
- 외곽선 알파: 둥근 상자의 외곽선 색은 명령 상수라 불투명도·비활성 효과를 곱하면 정점만 갱신하는 경로를 쓸 수 없다(외곽선 있는 상자를 페이드하면 프레임마다 배치를 다시 만든다). UE도 외곽선을 요소 셰이더 인자로 매 프레임 다시 만든다. 지금은 이 비용을 받아들이고, 페이드가 많은 화면이 생기면 외곽선 불투명도를 정점 속성으로 옮긴다.

- 버린 대안: 위젯마다 색 setter로 갤러리에서만 맞추기(에디터가 같은 룩을 얻지 못한다).

**UW3c 위젯 스타일 적용(설계).** 위젯에 박힌 색·크기를 스타일 조회로 바꾼다. 위젯마다 커밋을 나누되, 공통 기반을 먼저 둔다.
- 전경색 상속(UE `FWidgetStyle`의 foreground, `SWidget::GetForegroundColor`): `Element::GetForegroundColor()`는 자식에게 물려줄 색을 `ColorRef`로 돌려준다. 기본은 상속(`ColorSource::Foreground`)이고, `SetForegroundColor`로 정하거나 파생 클래스가 상태별로 바꾼다(버튼). `PaintList`가 그리는 동안 현재 전경색을 들고(루트는 UE `FWidgetStyle` 기본값인 흰색), `Element::PaintSubtree`가 불투명도처럼 들어갈 때 풀고 나올 때 되돌린다. 텍스트는 `ColorRef` 색을 이 전경색 문맥으로 푼다.
- 캐시: `CacheRoot` 항목이 기록 때의 전경색을 불투명도와 같이 보관하고, `Refresh`가 부모 본문의 새 전경색으로 다시 계산해 달라진 자식만 다시 기록한다(버튼이 올림 상태가 되면 레이블만 다시 그린다). 지역 캐시(`CachePanel`)는 바깥에서 물려받은 전경색·테마가 기록 때와 다르면 전체를 다시 만든다. 버린 대안은 전경색 변경 때 자식 전체를 무효화하는 것이다(불투명도 경로와 갈라진다).
- 정점만 갱신 판정에 둥근 상자의 명령 단위 값(크기·두께·외곽선 색)을 넣는다(UW3a 누락 — 같은 정점 수로 크기만 바뀐 둥근 상자가 이전 상수로 그려졌다).
- 버튼(UE `SButton`): `Button::Args`가 `style`(기본 `DefaultButtonStyle()`, 값 복사), `color`(UE `ButtonColorAndOpacity` — brush 색에 곱함, 기본 흰색), `foregroundColor`(없으면 스타일의 상태별 전경색 — UE `UseStyle`), `contentPadding`(스타일의 보통·눌림 여백에 더함 — UE `GetCombinedPadding`)을 받는다. 비활성이면 disabled brush·전경색이다. 상태별 색·brush를 따로 받던 `pressedColor`·`hoveredColor`·`SetStateBrushes`는 없앤다(스타일로 대신함 — 하위호환 없음).
- `ButtonWidget`(UE `UButton`): `style`(native), `backgroundColor`(UE `BackgroundColor` → `color`), `padding`(내용 여백)을 둔다. 상태별 tint와 brush 필드(`normalTint`·`hoveredTint`·`pressedTint`·brush 셋)는 없애고 ID를 은퇴시킨다. 스타일을 리플렉션 필드로 직렬화하는 것은 UW9(Widget 층 UE 정렬)에서 한다.
- 나머지 위젯(체크 상자·콤보·편집 텍스트·숫자 입력·슬라이더·스크롤 막대·진행 막대·표·도킹 탭·메뉴·툴팁)은 14장 값으로 형식별 스타일 구조체를 하나씩 더하며 바꾼다.
