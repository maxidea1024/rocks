# 머티리얼 시스템(MaterialSystem) 설계

## 6. IR — MS2f 구현 세부

### 6.13 MS2f 구현 세부(고급·보조 노드)

근거는 UE 5.8 고전 번역기다: `MaterialExpressions.cpp`(ME), `MaterialExpressionNoise.cpp`, `HLSLMaterialTranslator.cpp`(HT), 셰이더 `MaterialTemplate.ush`·`Common.ush`·`Random.ush`·`SobolRandom.ush`·`ColorSpace.ush`·`HairShadingCommon.ush`(SH). 결과 값은 고전 번역기를 따른다(6.8절).

| 묶음 | 노드 | 선행 |
|---|---|---|
| MS2f1 | RotateAboutAxis·SphereMask·DeriveNormalZ·Fresnel·BumpOffset·Desaturation·HsvToRgb·RgbToHsv·BlackBody·SrgbToWorkingColorSpace·HairColor(ALU — IR 기본 연산으로 펼친다) | 없음 |
| MS2f2 | Sobol·TemporalSobol(UE LUT `View.SobolSamplingTexture`는 XOR 상수표라 ALU로 같은 값을 낸다 — 표·함수는 MS2f2 설계에서 확정) | 없음 |
| MS2f3 | Noise·VectorNoise(ALU 함수 — GradientALU·ValueALU·Voronoi·Cellnoise·Perlin 3D·Gradient·Curl. LUT 함수 — SimplexTex·GradientTex·GradientTex3D는 엔진 LUT 텍스처가 필요하다, 선행은 MS2f3 설계에서 확정) | 일부 |
| MS2f4 | ColorRamp(상수 입력은 CurveAssets 평가식과 비트까지 같게, 연결 입력은 UE 키 구간 합) | CurveAssets CA1 |
| MS2f5 | CustomHlsl(7.5절 규칙 — V13 검사, 생성 함수 모양은 MS2f5 설계에서 UE 차이표와 함께 확정) | 없음 |

묶음마다 시험을 붙이고, 리뷰는 MS2f 끝에 리뷰어 한 명이다.

**공통 결정.**
- **IR로 펼친다.** MS2f1 노드는 HLSL 보조 함수 호출이 아니라 IR 기본 연산(Dot·Cross·Sin·Cos·Logarithm·Exponential·Sqrt·Select 등)으로 펼친다(결정 MD2 — IR이 정본이고 CPU bake·ray profile도 소비한다). 상수 피연산자는 IR 접기 규칙대로다. UE가 C++에서 미리 계산하는 상수(예: `2π / Period`, SphereMask의 `1 / max(1 − p·0.01, 1e−5)`)는 같은 float 식으로 번역 때 계산한다.
- **정밀도.** Rocks 생성 원문은 모든 단계에서 float다. UE는 픽셀 셰이더의 `MaterialFloat`가 half다(SH Common.ush:13–32 — `FORCE_MATERIAL_FLOAT_FULL_PRECISION`이 아니면). UE와 마지막 bit가 다를 수 있다(편차 — half 경로는 품질·형식 정책이 생기면 다시 본다).
- **연결 여부로 식이 바뀌는 노드.** Rocks는 UE의 "입력 + 덮기 상수 속성"을 핀 기본값 하나로 합쳤다(19.13절). UE가 연결 여부로 식을 바꾸는 노드(SphereMask Hardness, Desaturation Fraction, ColorRamp)는 lowering이 연결을 먼저 본다(`IsConnected`). 연결되지 않으면 핀 사용자 값·정의 기본값이 UE 덮기 상수 자리다.

**MS2f1 노드.**
- **RotateAboutAxis**(ME:18479–18508, HT:11721–11742, SH MaterialTemplate.ush:2031–2075): 네 입력은 필수다(UE 문구 "Missing RotateAboutAxis input NormalizedRotationAxis"·"… RotationAngle"·"… PivotPoint"·"… Position", MissingInput). 각도 = RotationAngle × (2π / `period`)(상수 2π/period는 번역 때 float로 계산 — UE `2.0f * (float)UE_PI / Period`), 축은 Float3로 맞춘다(UE ForceCast — 넓으면 앞 성분). 스칼라 축은 UE 오류 "Cannot cast from smaller type float2 to larger type float4."(TypeMismatch)다: Rocks 스칼라는 UE MCT_Float(상수·파라미터 — `SourceType & DestType`이 참이라 ForceCast가 그대로 돌려주고, AppendVector 뒤 CoerceParameter Float4가 실패한다, HT:4791·4915)로 본다(DeriveNormalZ와 같은 기준 — Rocks 형에는 MCT_Float·MCT_Float1 구분이 없다), 각도는 Float1(첫 성분). 결과는 회전 후 위치가 아니라 **오프셋**(float3)이다: `C = Pivot + axis·dot(axis, Position − Pivot)`, `U = Position − C`, `V = cross(axis, U)`, `R = U·cos(a) + V·sin(a)`, 결과 `(C + R) − Position`. Pivot이나 Position이 Double(LWC)이면 둘 다 Double로 맞추고 `C`는 Double, `U = float(Position − C)`, 결과 `R − U`(UE LWC 오버로드 — 같은 식을 줄인 형태)다.
- **SphereMask**(ME:18521–18594): A·B 필수("Missing input A"·"Missing input B"). 거리는 A·B가 둘 다 스칼라면 `abs(A − B)`, 아니면 `length(A − B)`(UE `CompileHelperLength`). 역반지름 = `1 / max(1e−5, Radius)`(Radius 핀 값 — 연결·기본 같은 식). 역경도: Hardness가 연결되면 비율로 `1 / max(1 − Hardness, 1e−5)`, 아니면 핀 값은 퍼센트라 번역 때 `1 / max(1 − p·0.01, 1e−5)`를 계산한 상수다(UE `HardnessPercent`). 결과 `saturate((1 − 거리·역반지름)·역경도)`.
- **DeriveNormalZ**(ME:12690–12706): InXY 필수("Missing input normal xy vector whose z should be derived."). 입력을 Float2로 맞추되 UE ForceCast 규칙대로 스칼라는 그대로 둔다. z = `sqrt(saturate(1 − dot(xy, xy)))`. 결과는 벡터면 `float3(xy, z)`, 스칼라면 `float3(x, z, 0)`이다(UE `AppendVector(scalar, z)` 뒤 ForceCast Float3가 0을 붙인다).
- **Fresnel**(ME:11936–11953): 필수 입력 없음. N = Normal 연결 값, 없으면 문맥 값 `PixelNormal`(픽셀 전용 — 정점 문맥이면 6.9절 V4). `x = 1 − max(0, dot(N, CameraVector))`(Dot 맞춤은 5.3절 — UE Dot은 큰 쪽을 작은 쪽 폭으로 자른다), 밑 `max(abs(x), 1e−4)`(UE `UE_KINDA_SMALL_NUMBER`), `Power(밑, ExponentIn)`은 Power 노드와 같은 규칙(UE `PositiveClampedPow` — LowerMath의 같은 경로), 결과 `pow·(1 − BaseReflectFractionIn) + BaseReflectFractionIn`.
- **BumpOffset**(ME:5987–6007): Height 필수("Missing Height input"). `t = TransformWorldVectorToTangent(CameraVector).xy`(문맥 값 — UE `mul((float3x3)TangentToWorld, CameraVector)`), `hr = HeightRatioInput` 첫 성분, `h = Height` 첫 성분, 결과 `Coordinate + t·(hr·h + (−referencePlane·hr))`. Coordinate가 연결되지 않으면 `TexCoord(constCoordinate)`(6.9절 TexCoord 규칙).
- **Desaturation**(ME:7939–7951): Input 필수("Missing Desaturation input"). `Color`는 Float3로 맞춘다(UE `ForceCast(…, Float3, ExactMatch|ReplicateValue)` — float4는 rgb, float2는 (x, y, 0), 스칼라는 복제). `Grey = dot(Color, luminanceFactors.rgb)`. Fraction이 연결되면 `lerp(Color, Grey, Fraction)`(float3), 아니면 `Grey`(스칼라 — UE도 출력 형이 연결 여부로 바뀐다).
- **HsvToRgb·RgbToHsv**(ME:10909–10957, HT:10964–11036): Input 필수("Missing HSVToRGB input"·"Missing RGBToHSV input"). 입력이 정확히 Float3·Float4가 아니면 오류 없이 입력을 그대로 낸다(UE). HsvToRgb: `H = in.x`, `rgb = saturate(float3(abs(H·6 − 3) − 1, 2 − abs(H·6 − 2), 2 − abs(H·6 − 4)))`, 결과 `((rgb − 1)·in.y + 1)·in.z`(Float4면 알파 `in.w`를 붙인다 — 색상은 frac하지 않는다). RgbToHsv: `P = (g < b) ? float4(b, g, −1, 2/3) : float4(g, b, 0, −1/3)`, `Q = (r < P.x) ? float4(P.x, P.y, P.w, r) : float4(r, P.y, P.z, P.x)`, `chroma = Q.x − min(Q.w, Q.y)`, `hue = abs((Q.w − Q.y) / (6·chroma + 1e−10) + Q.z)`, `s = chroma / (Q.x + 1e−10)`, 결과 `(hue, s, Q.x[, a])`. 조건 선택은 IR Select(Bool 스칼라 조건)다.
- **BlackBody**(ME:18990–19006, SH MaterialTemplate.ush:2112–2131): Temp는 첫 성분(Float1)이다. 식은 UE 함수 그대로(u·v 플랑크 궤적 근사 → x·y·z → X = x/y·Y, Z = z/y·Y, Y = 1 → `max(0, XYZ_2_LinearRGB(X, Y, Z))·pow(0.0004·Temp, 4)` — pow는 HLSL pow, Power 노드 규칙이 아니다). `XYZ_2_LinearRGB`는 작업 색공간 sRGB 행렬(SH ColorSpace.ush:40–45 — Rocks 작업 색공간은 sRGB/Rec.709 고정, 색공간 설정은 후속). UE는 Temp가 연결되지 않으면 오류 없이 값이 없어 출력 속성 기본값이 된다 — Rocks는 MissingInput "Missing BlackBody Temp input"으로 진단한다(값 없음을 조용히 기본값으로 바꾸는 경로가 없다, 편차).
- **SrgbToWorkingColorSpace**(ME:10492–10520): Input 필수("Missing sRGBColorToWorkingColorSpace input"). 작업 색공간이 sRGB 고정이므로 입력을 그대로 낸다(UE sRGB 분기와 같다 — 색공간 설정이 생기면 행렬 열 dot·알파 보존 경로를 더한다).
- **HairColor**(ME:21213–21234, SH HairShadingCommon.ush:58–97): 입력은 선택이고 연결이 없으면 UE Compile 상수 Melanin 0.5·Redness 0·DyeColor (1, 1, 1)이다(Rocks 핀에는 기본값이 없어 lowering이 넣는다). Melanin·Redness는 첫 성분, DyeColor는 Float3(스칼라 복제). 식: `m = saturate(Melanin)`, `r = saturate(Redness)`, `melanin = −log(max(1 − m, 1e−4))`, `A = melanin·(1 − r)·(0.506, 0.841, 1.653) + melanin·r·(0.343, 0.733, 1.924) + (log(saturate(Dye)) / D)²`, 결과 `exp(−sqrt(A)·D)`이고 `D = 5.969 − 0.215·B + 2.532·B² − 10.73·B³ + 5.574·B⁴ + 0.245·B⁵`(B = 0.3 — UE와 같은 float 식으로 번역 때 계산한다).
- **시험(MS-T3 범위).** 노드마다 상수 입력의 결과 값(UE 식을 C++ float로 같은 순서로 계산한 기대값), 필수 입력 오류 문구, 연결 여부 분기(SphereMask Hardness·Desaturation Fraction·Fresnel Normal·BumpOffset Coordinate·HairColor 기본값), 형 규칙(DeriveNormalZ 스칼라, Hsv 통과, RotateAboutAxis Double)을 본다.

**MS2f2 Sobol.**
- **LUT 없이 ALU로**(UE `View.SobolSamplingTexture`는 32×16 R16_UINT 표이고 내용은 `FSobol::ComputeGPUSpatialSeed`의 bit별 XOR 상수다 — Core Sobol.cpp:241–275, SystemTextures.cpp:421–456). `SobolPixel(p)`(SH SobolRandom.ush:21–31)의 `Load(lo) ^ Load(hi)`를 `Seed0(p & 0xF) ^ Seed1((p >> 4) & 0xF)`로 낸다: Seed0은 x bit 0–3마다 0xf68e·0x8e56·0x1135·0x220a, y bit 0–3마다 0x94c4·0x4ac2·0xfb57·0x0454를 XOR하고, Seed1은 x bit마다 0x4414·0x8828·0xe69e·0xae76, y bit마다 0xa28a·0x265e·0xe69e·0xae76이다. 결과 `uint2(packed, packed << 8) & 0xff00`. 그래서 Sobol은 View 기능이 필요 없다(UE는 텍스처 샘플 2를 센다 — Rocks는 세지 않는다).
- **SobolIndex**(SobolRandom.ush:33–51): bit b(0–9)마다 `(index & (1 << b)) ? N[b] : 0`을 XOR한다(N은 UE 표 열 개 그대로). index는 하위 10 bit만 쓰인다(UE 기본 Bits = 10).
- **Sobol**(ME:18601–18607, HT:11946–11956): Cell이 연결되지 않으면 (0, 0)(Rocks 핀에는 기본값이 없어 lowering이 넣는다), Index·Seed는 핀 값(기본 0·(0, 0) — UE ConstIndex·ConstSeed). `uint2(Cell)`은 Float2로 맞춘 뒤(스칼라 복제) UInt 변환, `uint(Index)`는 첫 성분 UInt 변환이다. 결과 `floor(Cell) + float2(SobolIndex(SobolPixel(uint2(Cell)), uint(Index)) ^ (uint2(Seed · 0x10000) & 0xffff)) / 0x10000`(HLSL `&`가 `^`보다 먼저다).
- **TemporalSobol**(ME:18618–18623, HT:11958–11966): 픽셀 위치는 새 문맥 값 `SvPosition`(UE 템플릿 필드 `Parameters.SvPosition`, Float4, 픽셀 단계 전용 — 정점 문맥이면 6.9절 V4. UE 번역기는 검사하지 않아 HLSL 컴파일 실패가 된다)의 xy, index는 `uint(StateFrameIndexMod8 + 8 · Index)`(새 문맥 값 `StateFrameIndexMod8` — UE View 필드, UInt1, View 기능, previous 변형 없음, 기본값 0). 결과는 `floor`를 더하지 않은 `float2(…) / 0x10000`이다.
- **시험.** 상수 Cell·Index·Seed의 Sobol 결과를 UE 표 계산(ComputeGPUSpatialSeed·SobolIndex를 C++로 옮긴 기대값)과 대조하고, TemporalSobol은 정점 문맥 V4와 IR 모양을 본다.

**MS2f3 Noise.**
- **라이브러리 호출 연산.** 옥타브(최대 10)·Voronoi 탐색(최대 32칸)을 IR로 펼치면 노드 하나가 수천 값이 되므로, UE처럼 셰이더 라이브러리 함수 하나를 부른다. IR 연산 `Library`(번호 93, `IrOpCount` 94 — 6.2절 연산 집합에 더한다): 즉시값 [0]은 라이브러리 함수 번호(`IrLibraryFunction` — MaterialCompiler 공개 `MaterialIrLibrary.h`, Noise 0·VectorNoise 1), [1]–[3]은 그 함수의 정적 정수 인자, 피연산자(최대 4)는 실행 값이다. 결과 타입은 함수가 정한다. 상수 접기를 하지 않는다(UE도 셰이더에서 계산한다). 빈도는 피연산자 빈도의 최대다. 생성 원문은 UE 함수 이름·인자 순서 그대로의 호출이고(정적 인자는 리터럴), 함수 원문은 `Engine/Shaders/Private/Material/MaterialNoise.rsh`(MaterialCommon.rsh가 include — UE Common.ush:1648–1847·Random.ush의 noise 알고리즘을 옮긴다)다. CPU 소비자(굽기 — 계획 14.10절)는 같은 함수 표를 구현해야 한다(그 단계에서 — 지금은 HLSL만).
- **Noise**(MaterialExpressionNoise.cpp:109–134, HT:11968–12016): Position이 연결되지 않으면 `worldPositionOriginType`의 월드 위치(Absolute → 문맥 값 `WorldPosition`, CameraRelative → `TranslatedWorldPosition`), FilterWidth는 연결 값 아니면 0. CameraRelative 위치는 TranslatedWorld → World로 바꿔 늘 절대 월드에서 계산한다(UE). levels는 1–10으로 클램프한다. quality는 [1, 4]로 클램프해 담는다(UE는 int32 그대로 넘기지만 셰이더는 Voronoi의 `≤ 2`·`== 2`·`== 3`·`≥ 4` 비교에만 쓰므로 값이 같다 — 즉시값 8 bit 칸에 넣는다, VectorNoise도 같다). CameraRelative 위치는 3성분 이상이어야 한다(UE TransformBase 문구 "input must be a 3-component vector (current: <형>) or a scalar (if source is Tangent)", TypeMismatch — Float4는 앞 셋). 호출은 `MaterialExpressionNoise(Position, Scale, Quality, Function, Turbulence, Levels, OutputMin, OutputMax, LevelScale, FilterWidth, Tiling, RepeatSize)`(결과 float)이다 — 즉시값 [1] = Function | Quality << 8 | Turbulence << 16 | Tiling << 17 | Levels << 24 | RepeatSize << 32, [2] = Scale bit | LevelScale bit << 32, [3] = OutputMin bit | OutputMax bit << 32(float는 32 bit 그대로), 피연산자 Position·FilterWidth. Position이 Double(LWC)이면 UE LWC 오버로드(타일 크기 2097152 — WSVECTOR_IS_TILEOFFSET)와 같은 식이다.
- **VectorNoise**(MaterialExpressionNoise.cpp:222–260): Position 규칙은 Noise와 같고 Double이면 float3로 낮춘다(UE는 VectorNoise를 LWC로 부르지 않는다 — Noise와 다르다). 호출은 `MaterialExpressionVectorNoise(Position, Quality, Function, Tiling, TileSize)`(호출 결과 float4)다. 노드 결과는 GradientALU·VoronoiALU면 float4, 나머지(Cellnoise·Perlin·Curl)는 `.xyz` float3다(UE HT:12039–12056 — 출력 핀은 Result 하나이고 UE의 RGB·A 마스크 핀은 ComponentMask가 대신한다) — 즉시값 [1] = Function | Quality << 8 | Tiling << 16 | TileSize << 32, 피연산자 Position.
- **LUT 함수.** Noise의 SimplexTex(0)·GradientTex(1)·GradientTex3D(2)는 UE View 시스템 텍스처(PerlinNoiseGradientTexture 128² 2D·PerlinNoise3DTexture 16³ 3D — FRandomStream 시드로 만든다)를 읽는다. 렌더러가 같은 시스템 텍스처를 낼 때까지 새 선행 `MPQ-NoiseTexture`(19.4.1절)로 둔다 — 그 함수 값이면 Pending 자리 값이고 결과에 닿으면 PrerequisiteMissing이다(속성 값별 선행 — 카탈로그 `propertyPrerequisites`). ALU 함수(GradientALU 3·ValueALU 4·Voronoi 5)와 VectorNoise 다섯은 바로 번역한다.
- **시험.** 생성 원문의 호출 모양(인자 순서·리터럴), levels 클램프(위·아래), quality 클램프, CameraRelative 변환과 3성분 미만 오류, LUT 함수의 늦은 진단, Double 위치, VectorNoise 출력 마스크를 본다. 셰이더 함수 값 대조는 MS2 완료의 DXC/FXC 확인 때 한다.

**MS2f4 ColorRamp**(UE ME:4899–5014, MaterialExpressionColorRamp.h).
- **커브 공급.** 번역은 에셋 객체가 아니라 snapshot을 본다(19.4.2절): `MaterialSourceProvider::FindColorCurve(AssetId)` → `MaterialColorCurveSnapshot`(R·G·B·A `TangentCurve`와 `ColorCurveAdjustments` — CurveAssets `ColorCurveAsset`의 칸 그대로, 기본 구현 nullptr). 찾은 커브는 번역 의존 `MaterialDependencyRole::ColorCurve`로 남고(쿠킹 키 — 12.2절), 에셋 Build 의존 hook이 `colorCurve` 참조를 더한다(4.6.1절 — 함수 호출·MaterialSample과 같은 자리). MaterialCompiler는 CurveAssets 모듈에 의존한다(평가 함수를 같이 쓰려고). UE와 다른 점: UE `ColorCurve`는 노드가 소유하는 `Instanced` 하위 객체(MaterialExpressionColorRamp.h:25–26 — 생성자가 R·G·B에 (0, 1)·(1, 0) 키의 흰색→검정 커브를 만든다, ME:4860–4876, 쿠킹 저장 때 지운다, ME:4879–4888)이고 Rocks는 외부 `ColorCurveAsset` 참조다(커브를 여러 노드·에셋이 함께 쓰고, 쿠킹 데이터에는 번역 결과만 남는 지금 구조와 같다). 그래서 Rocks 새 노드는 커브를 고르기 전까지 "Missing ColorCurve"다(기본 커브를 만드는 에디터 동작은 에디터 단계 — 14장). UE 교환 임포트는 노드의 인라인 커브를 별도 `ColorCurveAsset`으로 뽑아 참조한다(UnrealExchange 8절에 넘길 요구).
- **커브 없음.** 참조가 비었거나 공급이 없으면 UE 문구 "Missing ColorCurve"(MissingInput — UE는 커브가 없는 경우뿐이다), 참조는 있는데 공급에 없으면 "Color curve asset is not available"(MissingInput — FunctionCall의 "…asset is not available"과 같은 나눔, UE에는 그 상태가 없다)다. snapshot 채널이 비어 있으면(공급 구현 잘못) 앞 문구다.
- **상수 입력**(Input 미연결 — UE `ConstInput` 0.5가 Rocks 핀 기본값·사용자 값이다, 19.13절): `EvaluateAdjustedColorCurve(r, g, b, a, adjustments, input, false)`(UE `GetLinearColorValue` — 조정 포함, 원본 RGB가 LDR일 때만 명도 자르기, 알파 키가 없으면 A = 1)를 번역 때 부른 float4 상수다. CurveAssets와 같은 함수라 비트까지 같다(그 함수가 UE float 식을 그대로 옮긴다 — CurveAssets 2.4.2절). 비유한 결과(커브 데이터의 비유한 키)는 V11을 노드 위치에 진단한다. **결정성 예외**: 평가 함수가 `PlatformMath::Pow`(brightnessCurve·vibrance)와 가중 접선 풀이의 `Acos`·`Cos`·`Pow`(KeyCurveMath)를 써서 호스트 libm에 기댄다 — 같은 호스트에서는 런타임 CurveAssets와 비트가 같지만 호스트가 다르면 쿠킹 byte가 다를 수 있다(CompilerFoundation 6.5절 "호스트 libm 금지"의 예외). CurveAssets 평가를 DeterministicMath로 바꾸는 일을 CurveAssets 담당에 요청했고, 바뀌면 이 예외를 지운다.
- **연결 입력**: UE와 같이 커브 평가식이 아니라 채널마다 키 구간 합을 셰이더에서 계산한다(키 보간 방식·접선·색 조정을 보지 않는다 — UE 그대로). x = Input의 첫 성분(UE ComponentMask R — Double은 float로 낮춘다: UE 기존 번역기는 LWC 그대로 빼고 나누고(HT:10797–10803·9548–9569) 새 번역기는 float로 낮춘다(MaterialExpressionsToMIR.cpp:3124) — 편차, Bool·행렬·불투명 입력은 Rocks ComponentMask 문구 "Not enough components in the input for the component mask"). 키 0개는 0(알파도 — 상수 경로의 1과 다르다, UE 그대로), 1개는 그 값, 2개는 `lerp(v0, v1, (x − t0) / (t1 − t0))`(자르지 않아 범위 밖은 늘어난다 — 두 값이 같으면 UE 번역기 Lerp가 끝 값을 그대로 돌려준다, HT:10378 — SurfaceMath NodeLerp, UE가 노드에서 Compiler->Lerp를 쓰는 Desaturation도 같다), 그 밖은 `v0 + Σ (v[i+1] − v[i]) · saturate((x − t[i]) / (t[i+1] − t[i]))`이다. 앞 구간은 넷씩 float4(시간·값 상수 `float4`, `dot(…, 1)` 합 — UE `for (i < NumKeys − 4; i += 4)`), 남은 구간은 스칼라다(시간 차·값 차는 번역 때 float로 계산 — UE `Constant(EndTime − StartTime)`). 시간 차가 0인 구간도 UE처럼 나눈다(검사하지 않는다 — UE Div에 0 검사가 없다, HT:9648). 결과는 `float4(R, G, B, A)`다.
- **시험.** 상수 입력의 비트 대조(조정 포함)·핀 사용자 값, 접히지 않는 연결 입력에서 키 0·1·2·3·4·5·8·9개의 IR 구조(Dot·Saturate·Lerp 수 — float4 묶음과 나머지)와 값(첫 키 아래·위·안), 같은 두 값의 Lerp 생략, 동적 경로에서 조정을 쓰지 않음, 커브 없음·공급에 없음·빈 채널, 번역 의존 기록, Build 의존 hook.

**MS2f5 CustomHlsl**(7.5절 규칙의 구현 세부 — UE ME:12757–12808, HT `CustomExpression`, MaterialExpressionCustom.h).
- **IR.** 코드·선언은 모듈의 Custom 함수 표(`IrCustomFunction` — 노드 NodeId, 번역 문맥 정점·픽셀, 반환 형, 추가 출력(이름·형), 정의(이름·값), include 경로, 코드, 인자 형 목록)에 둔다. 같은 (노드, 문맥, 인자 형)은 한 항목이다. 연산 셋을 더한다(6.2절 연산 집합 — `IrOpCount` 97): `CustomArguments`(94 — 즉시값 [0]은 이 칸의 인자 수 1–3, [1]은 앞 칸이 있으면 1이고, 피연산자는 앞 칸(있으면 [0])과 인자 값이다 — 입력 수 제한 없이 3개씩 잇는다. 원문 값이 아니라 CustomCall이 펼친다), `CustomCall`(95 — 즉시값 [0] 표 번호, 피연산자 [0] 인자 사슬 끝(인자가 없으면 피연산자 없음), 결과 형은 반환 형, 빈도는 문맥 — 정점 Vertex·픽셀 Pixel), `CustomOutput`(96 — 피연산자 [0] CustomCall, 즉시값 [0] 추가 출력 번호, 결과 형은 그 출력 형). 표는 모듈 의미 hash에 든다(쿠킹 키 — 항목이 있을 때만 값·결과 뒤에 섞어 Custom 없는 모듈의 hash는 그대로다). 표는 문자열을 소유한다(번역 결과가 입력 문서보다 오래 산다 — `IrText` 범위). 모듈은 닿는 CustomCall의 항목만 처음 닿은 값 순서로 옮긴다. 픽셀 문맥 항목이 픽셀을 버릴 수 있으면(UE HasPixelDiscard — `containsClipInstruction` Yes, 또는 Search이면서 코드에 `clip(`·`discard` 부분 문자열) 모듈 `UsesCustomPixelDiscard()`가 참이다(UE bUsesCustomHLSLPixelDiscard — 소비는 pass 순열 단계). 접지 않는다. CPU 소비자(굽기·ray)는 미지원이다(7.5절).
- **함수 모양**(UE와 다른 점은 표의 결정): 이름 `MaterialCustom_<NodeId 앞 16 hex>_<항목 번호>`(같은 노드가 문맥·인자 형으로 여러 판이 될 수 있다 — UE `CustomExpression<N>`). 첫 인자는 문맥 `in MaterialInputs c`(픽셀)·`in MaterialVertexInputs c`(정점) — UE `Parameters`(FMaterial*Parameters)와 같은 자리이고 문맥 값은 `MaterialContext*` 접근자로 읽는다(UE 필드 이름과 다르다 — 편차). 다음 입력 순서대로 인자(이름 있는 입력만 — UE처럼 이름 없는 입력은 건너뛴다), 텍스처 입력은 `<형> <이름>, SamplerState <이름>Sampler` 두 인자(UE와 같다 — 모듈 텍스처 slot과 그 자기 샘플러: 그 slot은 `MaterialTexture<k>Sampler`를 선언하고 샘플러 예산 V9에 든다), Double(LWC) 입력은 `MaterialDouble<N> <이름>` 하나(UE는 float 값 + `FWSVector LWC<이름>` 두 인자 — 편차), 마지막에 추가 출력 `inout <형> <이름>`(호출 전 0 — UE). 형은 float다(정밀도 결정과 같다). 정수·Bool 입력은 float로 바꿔 넘기고, 행렬·표면·속성 집합 입력은 UE 문구 "Bad type <형> for <description> input <이름>"(TypeMismatch)이다. 코드에 `return` 부분 문자열이 대소문자 무시로 없으면 `return <코드>;`로 감싼다(UE `FString::Contains` 기본 IgnoreCase — 주석의 "Returns"도 걸린다). 정의는 함수 앞에 `#ifndef <이름>` / `#define <이름> <값>` / `#endif//<이름>`(UE), include는 `#include "<경로>"`(아래 허용 규칙).
- **검사.** 이름 있는 입력이 연결되지 않으면 UE 문구 "Custom material <description> missing input <i> (<이름>)"(MissingInput, i는 1부터). V13(CustomCodeRule, 7.5절 — 생성 원문의 구조를 지킨다: 사용자 텍스트가 생성 함수 밖으로 나가거나 자원·전역·정적 선언·전처리를 만들지 못하게 한다). 검사기는 컴파일러가 보는 것과 같게 읽는다: 주석(`//`·`/* */`)과 문자열 리터럴(`"…"`, 역슬래시 escape) 밖의 식별자 토큰과 `#`·중괄호를 본다. 코드에서 막는 것과 문구:
  - 금지 단어 `register`·`cbuffer`·`tbuffer`·`groupshared`·`static`·`_Pragma`·`__pragma` — "Custom HLSL code must not contain '<단어>'".
  - 전처리 `#`(지시 전부와 `##`·`#` 연산자 — 정의는 `additionalDefines`로만 받는다) — "Custom HLSL code must not contain '#<지시 이름>'"(이름이 없으면 `'#'`).
  - 줄 잇기(`\` 뒤 줄바꿈 — 컴파일러가 토큰을 이어 검사를 우회한다) — "Custom HLSL code must not contain line continuations".
  - 닫히지 않은 `/*` — "Custom HLSL code must not contain an unterminated comment", 닫히지 않은 문자열 — "Custom HLSL code must not contain an unterminated string".
  - 중괄호가 본문 밖으로 닫히면 "Custom HLSL code must not close the function body", 끝에 열린 채 남으면 "Custom HLSL code must not leave a brace open".
  - `containsClipInstruction`이 No인데 주석 밖에 `clip` 호출(식별자 `clip` 뒤 공백·주석을 지나 `(`)이나 식별자 `discard`가 있으면 "Custom HLSL uses clip or discard but containsClipInstruction is No"(UE는 검출해 플래그만 켠다 — Rocks는 선언과 다르면 막는다). Search의 픽셀 버림 판정은 UE 부분 문자열 규칙에 이 토큰 검출을 더한 합이다(UE보다 놓치지 않는다).

  include 경로가 `/`로 시작하는 가상 경로가 아니거나 `..`·따옴표·역슬래시·제어 문자를 담으면 "Custom HLSL include path is not an allowed virtual path: <경로>". 정의 값은 파일 범위로 나가므로 코드와 같은 검사(금지 단어·`#`·줄 잇기·닫히지 않은 주석·문자열·중괄호)를 받고, 더해 줄바꿈이면 "Custom HLSL define value must be a single line: <이름>", 주석이 있으면 "Custom HLSL define value must not contain comments: <이름>"(닫힌 주석도 — 뒤 원문과의 경계를 흐린다). 이름: 입력·추가 출력·정의 이름은 HLSL 식별자여야 하고("Custom HLSL name is not a valid identifier: <이름>"), 함수 인자 이름(입력·텍스처 입력의 `<이름>Sampler`·추가 출력)은 서로 겹치지 않아야 하며("Custom HLSL name is used more than once: <이름>"), 문맥 인자 `c`는 쓸 수 없다. 정의 이름은 더해 생성 원문이 맨 식별자로 쓰는 `c`·`s`·`m<숫자>…`와 `Material`·`MATERIAL_` 접두를 쓸 수 없다("Custom HLSL name is reserved: <이름>" — 그 밖의 생성 식별자와 겹치는 정의는 UE처럼 HLSL 컴파일 오류로 드러난다). 이름 없는 추가 출력은 건너뛴다(UE RebuildOutputs). 출력 형 MaterialAttributes는 UnsupportedCapability "Custom HLSL MaterialAttributes output is not supported"다(Rocks 속성 집합은 기록이라 HLSL 구조체가 없다 — 편차). job 리플렉션 검사(머티리얼 layout 밖 자원)는 쿠킹(MS3)에서 한다.
