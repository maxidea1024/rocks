# 머티리얼 시스템(MaterialSystem) 설계

## 6. IR — MS2e 구현 세부

### 6.12 MS2e 구현 세부(속성 집합·함수·레이어)

근거는 UE 5.8 고전 번역기(`HLSLMaterialTranslator.cpp`(HT)·`MaterialExpressions.cpp`(ME)·`MaterialAttributeDefinitionMap.cpp`(MADM)·`MaterialShared.cpp`(MS)·`Material.cpp`)와 새 번역기(`MaterialExpressionsToMIR.cpp`(MIR)·`MaterialIRModuleBuilder.cpp`)다. 결과 값은 고전, 구조는 새 번역기를 따른다(6.8절). 고전 번역기에만 없는 노드(`Blend`·`Aggregate` — UE `NewMaterialTranslator` 전용)는 MIR 동작이다.

| 묶음 | 내용 |
|---|---|
| MS2e1 | 속성 집합: IR `AttributesRef`·속성 기록, 기본값 규칙, 속성 표(UE 기본 custom 속성 9개 포함), Make/Break/Get/Set/BlendAttributes·`Blend`·`Aggregate`(MaterialAttributes 종류), 실행 중 선택의 칸별 선택, 출력 노드 `useMaterialAttributes` 경로, `SurfaceFromAttributes` |
| MS2e2 | 원본 공급·함수: `MaterialSourceProvider`, 함수 호출 펼치기·`FunctionInput`·`FunctionOutput`, 호출 순환(V3), 함수 안 진단 위치, 파라미터 scope·"공유" 표시·scope별 V8, `MaterialSample`(다른 머티리얼 참조), 번역 의존 목록, 그래프 참조 Build 의존 hook |
| MS2e3 | 레이어: `AttributeLayers`·`LayerStack`·`LayerOutput`, 레이어·혼합 scope, V14 검사, 함수 용도 검사 |

**MS2e1 속성 집합.**
- **값.** 속성 집합 값은 IR `AttributesRef`(번호 92, 타입 `IrScalar::Attributes`(7) 성분 1 — 텍스처·표면과 같은 불투명 규칙: 산술·변환에 들어가지 못한다, V1)다. 즉시값 [0]은 번역기 속성 기록 번호다. 기록은 설정된 칸(속성 Guid → IR 값)의 목록이다. 설정되지 않은 칸은 UE의 INDEX_NONE과 같아 쓰는 곳이 기본값을 넣는다(UE `FMaterialAttributesInput::CompileWithDefault` — MS:750–771). 노드는 평가 문맥마다 따로 번역되므로(6.9절) 정점 문맥의 기록과 픽셀 문맥의 기록이 따로 생긴다. UE가 속성마다 그 빈도로 compile하는 것과 결과가 같다(쓰지 않는 칸의 식은 DCE가 지운다).
- **기본값**(쓰는 곳에서, UE `CompileDefaultValue` — MADM:46–109): 속성 표 기본값. 예외: Normal은 `tangentSpaceNormal`이면 (0, 0, 1), 아니면 정점 노멀. Tangent는 (1, 0, 0) 또는 정점 tangent. ShadingModel은 DefaultLit(UE는 머티리얼 shading model 집합의 첫 값 — Rocks 머티리얼 속성에는 shading model이 없다). Displacement는 −1(UE "연결 없음" 표지). CustomizedUV i는 TexCoord(i). FrontMaterial은 칸 없음(표면 변환이 정한다).
- **속성 표.** 번역 입력 `attributes`(`MaterialAttributeTable` — 없으면 내장 표만)로 찾는다(내장 → 등록 순). 내장 표에 UE 기본 custom 속성 9개를 더한다(MADM:444–452, UE Guid·이름·형·기본값·빈도 그대로): BentNormal·ClearCoatBottomNormal·CustomEyeTangent·TransmittanceColor·ThinTranslucentSurfaceCoverage·FirstPersonInterpolationAlpha(정점)·MaterialCache·TemporalResponsiveness·MotionVectorWorldOffset. 정의에 custom 출력 대응(6.11절 MS2d3 표 이름·번호 — TangentOutput 0·ThinTranslucentMaterialOutput 0/1 등)을 둔다. MaterialCache는 custom 출력이 TODO(MPQ-VirtualTexture)라 그 칸을 쓰면 PrerequisiteMissing이다. Get·Set 동적 핀은 스키마가 내장 표로 타입을 정한다(등록 속성 핀은 Any — 번역이 표 타입으로 맞춘다).
- **칸 값 맞춤.** 칸에 넣을 때 속성 형으로 5.3절 암묵 변환(`Coerce` — UE `ValidCast`, HT:4720–4764: 넓은 벡터는 앞 성분, 스칼라는 복제, 좁은 벡터는 V1)한다. ShadingModel은 UInt, FrontMaterial은 표면 값만 받는다.
- **MakeAttributes**(ME:6123–6171): 연결된 핀만 칸이 된다(연결 없는 핀은 설정 안 됨). 핀 사용자 값은 없다(HideValue).
- **BreakAttributes**(ME:6206–6382): 출력마다 칸 값, 없으면 기본값, 출력 핀 폭으로 맞춘다(Refraction은 float2 — UE 출력 mask RG). 입력이 연결되지 않으면 MissingInput.
- **GetAttributes**(ME:6384–6640): `MaterialAttributesOut`은 그대로 지나가고 나머지 출력은 칸 값·기본값이다. **SetAttributes**(ME:6646–7047): 입력 기록(연결 없으면 빈 기록)을 복사해 연결된 속성 입력으로 덮는다. 두 노드 검사(노드 위치 InvalidProperty): 같은 Guid가 둘이면 "Duplicate attribute types.", 표에 없는 Guid면 "Property type doesn't exist, needs re-mapping?"(UE 문구).
- **BlendAttributes**(ME:7075–7126): A·B 어느 쪽에든 있는 칸마다 속성 빈도로 방식을 고른다(정점 빈도 — WPO·CustomizedUV·FirstPersonInterpolationAlpha — 는 vertexAttributeBlendType, 나머지는 pixelAttributeBlendType). UseA·UseB는 그쪽 칸(없으면 칸 없음), Blend는 양쪽 값(없는 쪽은 기본값)이고 같은 IR 값이면 A(UE `AllowSkipAlphaComputationForMaterialBlend` 기본 참), ShadingModel은 Alpha ≥ 0.5면 B(UE `CompileShadingModelBlendFunction`), FrontMaterial은 섞지 않는다(UE `CompileSubstrateBlendFunction`은 INDEX_NONE — 칸 없음), 그 밖은 lerp(A, B, Alpha). Alpha가 연결되지 않으면 Blend 칸은 없음이다(UE `Lerp`가 INDEX_NONE — 쓰는 곳 기본값).
- **Blend**(다형, UE MIR:3857–3989): A·B 둘 다 없으면 "No input value provided.", 한쪽만 없으면 다른 쪽 타입의 0 상수, Alpha 기본 0. 공통 타입으로 맞춘 뒤 Float·Double은 lerp, 정수·Bool은 Alpha < 0.5면 A 아니면 B, 속성 집합은 칸마다(정점 방식은 WPO만 — MIR `BlendAggregate`:3830–3834, 고전 BlendAttributes와 다르다) 같은 규칙이다(속성 pixelAttributesBlendMode·vertexAttributesBlendMode). 표면은 "Cannot blend values of type 'Surface'."(V1 — MIR은 기본 slab으로 바꾼다, Rocks는 막는다, 편차), 그 밖 "Cannot blend values of type '<형>'.".
- **Aggregate**(MaterialAttributes 종류, UE MIR:3919–3955): PrototypeInput이 속성 집합이면 그 기록에서, 연결이 없으면 빈 기록에서 시작한다(수 값이면 V1). 이름 입력 중 연결된 것이 칸을 덮는다. `Result`는 기록, `<이름>Out`은 칸 값·기본값이다. 이름이 표에 없으면 노드 위치 InvalidProperty "Unknown material attribute '<이름>'". UserDefined 종류는 PrerequisiteMissing(MPQ-MaterialAggregate)이다.
- **실행 중 선택.** Select·Branch가 속성 집합 둘을 고르면 칸마다 고른 새 기록이다(UE 고전은 속성마다 compile하므로 `If`·실행 중 스위치가 속성마다 동작한다 — 한쪽에만 있는 칸은 다른 쪽이 기본값). 번역 때 고르는 스위치·재경유는 값을 그대로 넘긴다(6.9절).
- **출력 노드 `useMaterialAttributes`**(UE `UMaterial::CompilePropertyEx` — Material.cpp:7212–7266): `Attributes` 핀이 활성이고 개별 핀(Surface·Opacity·OpacityMask·AO·WPO·PDO·Refraction·SurfaceThickness·CustomizedUv)은 비활성이다(연결은 V5 경고 — UE는 개별 핀을 읽지 않는다). 진입점은 칸에서 읽는다: WPO·CustomizedUV i(정점·이전 정점 문맥, CustomizedUV는 6.9절 MS2b4a 규칙 — 칸이 없으면 TexCoord(i)), Opacity·OpacityMask·PDO·AO·Refraction·SurfaceThickness(픽셀, 6.10절 활성 규칙 그대로, 칸이 없으면 기본값), Displacement는 지금처럼 늦은 진단(MPQ-VirtualizedGeometry). 표면은 FrontMaterial 칸이 있으면 그 표면, 없으면 `SurfaceFromAttributes`와 같은 변환(shadingModelOverride DefaultLit, 물 계수 기본 — UE 숨은 변환 `SubstrateConvertMaterialAttributes::CompileCommon`, HT:1545–1560)이다. custom 속성 칸은 custom 출력이 된다(UE `CompileMaterialAttributesCustomOutputs` — 같은 종류의 노드가 있으면 노드가 이긴다, 6.11절 MS2d3 규칙).
- **SurfaceFromAttributes**(UE `SubstrateConvertMaterialAttributes` — MaterialExpressionSubstrate.cpp:3957–4156)는 `SurfaceFromShadingModel`과 같은 기록을 만든다. 입력 읽기는 "값 원천"(핀 연결 또는 속성 칸)으로 나눈다: 고전 입력 칸(BaseColor·Metallic·Specular·Roughness·Anisotropy·EmissiveColor·SubsurfaceColor·CustomData0·CustomData1·Opacity·Normal)은 속성 칸, ShadingModel은 칸이 있으면 그 값 아니면 `shadingModelOverride`, Tangent는 Anisotropy 칸이 있을 때만 칸(UE :3993–4003), ClearCoatBottomNormal·CustomEyeTangent·TransmittanceColor·ThinTranslucentSurfaceCoverage는 custom 속성 칸, 물 계수는 노드 핀이다. 속성 입력이 연결되지 않으면 모든 칸이 없음이다(UE `CompileDefaultSlab`).

**MS2e2 원본 공급·함수.**
- **원본 공급.** 번역 입력 `sources`(`MaterialSourceProvider` — 19.4.2절)가 `FindFunction(AssetId)`·`FindMaterial(AssetId)`로 `MaterialGraphSnapshot`(에셋 id, 표시 이름, 그래프 문서, 함수 용도)을 준다. 문서의 Name은 번역 입력 `names`와 같은 pool이어야 한다. 함수 인스턴스는 provider가 기반 함수 snapshot으로 푼다(override 적용은 MS6 — 15장 "함수·인스턴스"). 컬렉션은 MS2c의 값 목록을 그대로 쓴다(19.4.2절 `FindCollection`을 값 목록으로 바꾼다 — 개정).
- **펼치기.** 번역 전에 주 그래프와 호출된 함수 그래프를 펼친 그래프 하나로 만든다(UE 인라인, MIR 서브그래프 문맥 — 호출 경로마다 사본). 함수 그래프의 노드는 id = SHA-256(호출 경로, 원래 id) 앞 128 bit인 사본이 된다. 호출 노드는 남는다. `FunctionInput` 사본은 그 호출 노드의 입력 `P_<입력 id>`를 읽고(간선 없는 의존 — 이름 있는 재경유와 같은 계획 규칙), 호출 노드의 출력 `P_<출력 id>`는 `FunctionOutput` 사본의 `A` 값이다. 출력 핀 타입은 그 값의 타입이다(UE `GetRealInputValueType`). 펼친 노드 수가 상한(`MaxExpandedMaterialNodes` 65536)을 넘거나 호출 깊이가 상한(`MaxFunctionCallDepth` 64)을 넘으면 V9 "Material function expansion is too large"다.
- **FunctionInput**(ME:16545–16629, 14274–14303): 호출 쪽이 연결되면 그 값을 입력 형으로 맞춘다(UE `ValidCast` — MaterialAttributes는 그대로). 연결이 없고 함수 노드의 `usePreviewValueAsDefault`면(호출 노드 사본은 표시용) Preview 핀 연결(함수 안), 없으면 `previewValue` 상수(Scalar·Vector2–4 — 텍스처·Bool·StaticBool·Surface는 "Missing Preview connection for function input '<이름>'", MaterialAttributes는 빈 기록), 아니면 "Missing function input '<이름>'"(MissingInput)이다.
- **FunctionCall 오류**(ME:15774–15824, 14254–14272): 함수 참조 없음 "Missing Material Function", provider에 없음 "Material function asset is not available"(Rocks — UE는 로드 실패), 호출 사본의 입출력 id가 snapshot에 없음 "Function (<이름>) call input with index <i> is unset."·"… call output …", 함수 출력 연결 없음 "Missing function output connection '<이름>'".
- **순환(V3).** 호출 경로에 같은 함수 에셋이 다시 나오면 그 호출 노드 위치 FunctionCycle "Material function call is recursive: <이름>"이다(UE 번역기에는 검사가 없고 편집 때 막는다 — ME:16019–16030, Rocks 문구). 쿠커의 Build 의존 SCC(4.4절 `UnsupportedCycle`)와 함께 둔다.
- **진단 위치.** 함수 안 노드의 진단은 주 그래프의 가장 바깥 호출 노드 위치에 내고, 문구 앞에 "(Function <이름>|<이름>) "와 노드면 "(Node <종류 짧은 이름>) "를 붙인다(UE HT:4392–4437). 같은 (위치, 문구)는 한 번이다.
- **파라미터 scope**(9.2절 MD5). 파라미터의 IR 정체 Guid는 주 그래프면 ParameterId 그대로, 함수 안이면 "공유"면 SHA-256(소유 에셋, ParameterId), 아니면 SHA-256(소유 에셋, ParameterId, 호출 경로) 앞 128 bit다. `IrParameter`·`IrTexture`·static 값(`MaterialStaticParameterValue.parameterId`)은 이 정체 Guid로 찾는다(static 값을 만드는 쪽 — 인스턴스·쿠커 — 도 같은 식으로 정체를 만든다, 9.4절). 함수 사본의 호출 경로는 사본 호출 노드 id 하나에 담긴다(사본 id가 경로 hash이므로). 파라미터 노드 속성(컬렉션 참조 둘을 뺀 21종)에 `shared`(bool, 기본 거짓)를 더한다. V8은 scope별이다: 주 그래프와 "공유" 파라미터는 전역 scope 하나, 공유가 아닌 함수 파라미터는 그 호출 scope다.
- **MaterialSample**(다른 머티리얼 참조): 참조 머티리얼 출력 노드 `Surface` 핀의 그래프를 펼쳐 그 표면 값을 낸다(scope 소유는 그 머티리얼, 번역 traits는 지금 머티리얼). 순환은 V3이다.
- **사본 제외.** `MaterialSample`로 펼친 머티리얼 사본의 custom 출력 노드·출력 노드는 이 머티리얼의 출력이 아니다(펼친 함수 안의 custom 출력 노드는 UE처럼 출력이다 — `GatherCustomOutputExpressions`).
- **의존 목록.** 번역 결과 `dependencies`는 번역이 읽은 snapshot(역할 Function·Material, AssetId)이다(12.2절 의존 입력 — 쿠커가 키를 붙인다).
- **Build 의존 hook.** Material·MaterialFunction 그래프 안의 FunctionCall·MaterialSample·레이어 참조를 Build 의존으로 등록한다(4.6.1절).

**MS2e3 레이어.**
- **AttributeLayers**(ME:7161–7630): 레이어 목록은 노드 `defaultLayers`다(인스턴스 레이어 스택 override는 MS7). 활성 레이어는 layer가 있고 visible인 것이다. 레이어 i는 scope (Layer, layerId), 그 혼합은 scope (LayerBlend, layerId)로 펼친다. 레이어 함수의 첫 입력(정렬 순)은 노드 `Input`이다(연결된 때). 혼합 함수 입력: BlendInputRelevance가 Bottom·Top이면 그것, General이면 정렬 순 0 = 아래(누적)·1 = 위(UE 고전 0/1과 LayerStack relevance를 합친 규칙). 혼합 함수가 없는 레이어는 그 위치에서 새 바닥이 된다(UE "opaque layer"). 결과는 마지막 혼합(없으면 마지막 레이어)의 첫 출력이다. 활성 레이어가 없으면 `Input`을 그대로 낸다.
- **검사(V14, UE 문구 — 접두 "LayerValidation:")**: "Layer <i>, <이름>, not set for layer usage.", "Layer <i>, <이름>, must have one MaterialAttributes input only.", "Blend <i>, <이름>, not set for layer blend usage.", "Blend <i>, <이름>, must have two MaterialAttributes inputs.", "Invalid number of layers (<n>) or blends (<m>) assigned.", "Layer expressions cannot be used within a material function.", 레이어 노드 둘 이상 "Materials can contain only one Material Attribute Layers node."(HT:1456–1466). 레이어 수 상한은 32(`MaxMaterialLayers` — UE에는 상한이 없다, V14 "Material layer count exceeds the limit").
- **LayerStack**(UE Experimental, MaterialExpressionLayerStack.cpp): AttributeLayers 규칙에 더해 availableLayers·availableBlends 밖의 함수는 "Layer <i>, <이름>, is not set as an allowed layer in the base layer stack node."·"Blend …", `layerInputs` 노출 입력은 같은 이름·형의 레이어 함수 입력에 잇고 미연결이면 "LayerStack \"<이름>\" input pin must be connected.", 혼합이 없고 레이어가 여럿이면 위 레이어의 MaterialAttributes 입력에 아래 레이어 결과를 잇는다(UE는 아래 레이어 함수 안의 출력 식에 직접 이어 호출 문맥 없이 compile될 수 있다 — Rocks는 호출 결과를 잇는다, 편차). visible은 AttributeLayers와 같게 본다(UE LayerStack은 무시 — 편차).
- **함수 용도 검사**(UE 5.8 `ValidateFunctionUsage` — ME:14233–14252): 용도가 Layer인 함수는 MaterialAttributes 출력이 하나, 입력이 하나 이하, LayerBlend는 MaterialAttributes 입력이 둘이어야 한다(일반 호출로 써도 — UE 문구 MaterialExpressionLayerStack.cpp:294–383).

**편차·한계(요약).** Blend의 표면 혼합은 막는다(MIR은 기본 slab). 함수 인스턴스 override는 MS6. 레이어 스택 인스턴스 override는 MS7. LayerStack의 레이어 체인은 호출 결과를 잇고 visible을 본다. 함수 재귀는 번역 오류다(UE는 편집 때 막는다).
