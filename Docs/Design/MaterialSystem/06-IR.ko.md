# 머티리얼 시스템(MaterialSystem) 설계

## 6. IR

### 6.1 UE 5.8 방식

| 경로 | 5.8 상태 | 근거 |
|---|---|---|
| 노드가 코드 조각을 직접 내는 번역기(`FHLSLMaterialTranslator`, 진입 함수 `Translate_Legacy`) | **기본값.** 클래스에 deprecation 표시가 없다 | `RE/Private/Materials/HLSLMaterialTranslator.h:233`, 분기 `RE/Private/Materials/MaterialShared.cpp:3683–3704` |
| Material IR + IR→HLSL(`FMaterialIRToHLSLTranslation`) | **실험.** `r.Material.Translator.EnableNew`(기본 false, 설명 "prototype (WIP)")와 머티리얼별 `bEnableNewHLSLGenerator`가 모두 켜져야 쓰인다. 사용 시 "new experimental material translator" 로그, 쿠킹 때 "still experimental" Display 로그 | `MaterialShared.cpp:108–112, 3616`, `RE/Private/Materials/MaterialInterface.cpp:233–237, 342–351`, `RE/Public/Materials/Material.h:1072–1074` |
| 5.1–5.3의 HLSLTree(`MaterialHLSLGenerator`) | **코드 제거.** Runtime·Editor 전체 grep 0건이다. 플래그 이름 `bEnableNewHLSLGenerator`만 IR 스위치로 재사용된다 | grep 결과(2026-11-17) |

UE IR 구조(참고):
- 값 종류는 순수 값(상수·builtin·파라미터 컬렉션·uniform 등)과 명령(연산·분기·텍스처 읽기·Substrate 연산·단계 전환·미분·보간 설정·호출·preshader 파라미터)이다(`RE/Public/Materials/MaterialIR.h:43–90`).
- 값은 POD이고, 빌더가 같은 계산을 해시로 찾아 한 인스턴스로 쓴다(`MaterialIR.h:97–118`).
- 모듈은 단계(정점·픽셀·compute)와 custom 출력마다 진입점을 가진다(`RE/Public/Materials/MaterialIRModule.h:20–63`).
- 빌드 단계는 초기화 → 노드 그래프를 IR로 → Substrate 출력 → 출력 설정 명령 → 의존 순 분석 → 모듈 전체 분석(한도·preshader fixup) → 명령을 가장 좁은 블록에 배치 → 산출 확정이다(`RE/Private/Materials/MaterialIRModuleBuilder.cpp:1532–1598`).
- 상수 접기(`RE/Private/Materials/MaterialIREmitter.cpp:2142, 2755, 2902, 3016`)와 uniform 연산의 preshader 승격(`MaterialIREmitter.cpp:2738`, 설계 설명 `RE/Public/Materials/MaterialIRPreshader.h:12–32`)이 있다. 별도 DCE·CSE 패스가 있는지는 미확인이다.

**Rocks 선택(결정 MD2).**
- UE 기본 번역기는 "이름이 legacy인 기본값"이고 IR 쪽은 실험이다.
- 계획은 처음부터 typed IR을 요구하고(14.1·14.7절), HLSL 말고도 CPU bake(`BakeMaterialProfile`, 계획 14.10절)와 ray profile(M8)이 IR을 소비한다.
- 그래서 Rocks는 IR 하나를 정본으로 두고 HLSL은 그 소비자 가운데 하나로 만든다. 노드가 HLSL 조각을 직접 내는 경로는 두지 않는다.

### 6.2 구조

- **모듈** = (머티리얼 static 변형, 품질 수준)마다 하나다. 진입점은 정점 결과·이전 프레임 정점 결과·표면·opacity·opacity mask·pixel depth offset·custom 출력마다 하나다(7.3절 함수와 1:1).
- **값** = `{ 타입, 연산, 피연산자 값들, 빈도, 단계 집합, 속성(공간·색공간·미분 요구) }`. 피연산자는 값 번호다. (타입, 연산, 피연산자, 속성, 진입점 문맥)이 같으면 한 값으로 공유한다(hash-consing). 진입점 문맥(현재·이전 프레임, 19.3.5절)이 다르면 같은 노드도 다른 값이다.
- **연산 집합**은 UE `Operator` 노드의 연산 전부(`RE/Public/Materials/MaterialExpressionOperator.h:14–100` — 사칙·비교·논리·비트·shift·IsNan·IsInf·초월·쌍곡·Rsqrt·Transpose·행렬곱·LWC 타일 연산)와 텍스처·문맥 값(extern)·조건 값·동적 분기를 담는다. IsNan·IsInf는 생성 원문에서 fast-math가 지우지 않는 형태로 낸다(V11은 상수만 막는다).
- **빈도** 격자: `Constant < Static < Uniform < Instance < Vertex < Pixel`.
  - `Uniform`: 머티리얼 파라미터·컬렉션 값과 그것만으로 된 식. 상수 식 프로그램(9.4절)으로 간다.
  - `Instance`: 그리기 단위 데이터(primitive·instance custom data). Renderer 스펙의 instance 데이터 계약을 따른다.
  - 연산의 빈도는 피연산자 빈도의 최대다. 예외로 미분과 암묵 mip 텍스처 읽기는 `Pixel`이고, 명시 mip 텍스처 읽기는 최소 `Vertex`다(uniform으로 끌어올리지 않는다).
- **조건 값.** 번역 때 정해지지 않는 static 조건(렌더 경로·기능 등급·pass 상태)은 문맥 값 표의 Bool 값을 조건으로 한 `Select`로 남긴다. pass가 그 값을 상수로 정의하므로 하위 컴파일러가 접는다(UE `GenericSwitch`와 같다 — 6.9절 MS2b3). 품질 수준과 static 파라미터는 번역 때 정해진다.

### 6.3 생성(그래프 → IR)

1. **입력 고정.** 그래프 snapshot(계획 14.6절 immutable)과 Build 의존 함수·컬렉션의 snapshot을 받는다. Object 주소는 들고 가지 않는다.
2. **static 해석.** static 파라미터(인스턴스 override 반영), Quality Switch(번역 중인 품질 수준), Static Switch를 풀고, 선택되지 않은 입력은 IR로 만들지 않는다. UE도 Quality Switch는 유효 입력 하나만 컴파일한다(`RE/Private/Materials/MaterialExpressions.cpp:9082–9107`, 검증 때만 모든 입력 `:9088–9102`).
3. **렌더 경로·기능 등급 분기.** Render Path Switch는 Deferred·ForwardPlus·Default 세 입력을 가진다. 경로 전용 pass(`GBuffer`·`ForwardOpaque`·`DepthAux`)는 그 경로 입력을, 두 경로가 함께 쓰는 pass(`Depth`·`ShadowDepth`·`Translucent`·`Velocity` 등)는 Default 입력을 쓴다(Renderer 14.3절 "경로" 열). pass 원문은 Renderer가 pass job에 넣는 `RENDER_PATH_DEFERRED`·`RENDER_PATH_FORWARD_PLUS`로 조건 값 RenderPathDeferred·RenderPathForwardPlus를 정의하고, 하위 컴파일러가 상수 조건을 접는다(6.9절 MS2b3). WPO·마스크·PDO에 닿는 Render Path Switch는 V15 오류다. Render Path Switch와 Capability Tier Switch는 모든 입력을 IR로 만들고 조건 값(Bool 문맥 값의 `Select` — 6.9절)으로 잇는다. UE는 shading path를 플랫폼당 하나로 정해 한쪽만 컴파일한다(`RE/Public/Materials/MaterialExpressionShadingPathSwitch.h:50`). Rocks는 한 실행 안에서 view마다 Deferred·Forward+를 고르므로(계획 11.1절) pass job이 정한다.
4. **함수 펼치기.** 함수 호출은 scope를 쌓고 함수 그래프를 펼친다. 함수 입력은 호출한 쪽의 값이다. UE도 인라인이다(`RE/Private/Materials/MaterialExpressions.cpp:15774–15824`, 호출자 문맥 복귀 `:16564–16594`). 파라미터 scope 경로는 9.2절이다.
5. **레이어 스택 펼치기.** 레이어 i를 펼치고 혼합 함수로 결합한다. 레이어·혼합 scope는 레이어 Guid다. UE는 레이어 index에 연관을 단다(`MaterialExpressions.cpp:7238–7239, 7273–7274`).
6. **출력.** 영역·블렌드 모드가 쓰는 출력 핀만 진입점으로 만든다(V5).

### 6.4 분석

| 분석 | 내용 | 오류 |
|---|---|---|

| 단계 | 진입점에서 거슬러 각 값이 필요한 단계 집합을 구한다. 정점 진입점이 픽셀 전용 값을 쓰면 오류다 | V4 |

| 자원 집계 | 텍스처·샘플러·상수 블록 크기·컬렉션·보간 벡터 수를 센다 | V9 |
| capability | 노드가 요구하는 기능(scene texture 읽기·GBuffer 읽기·dual source blend 등)을 진입점별로 모아 `MaterialShaderTraits`에 기록한다 | V6 |

### 6.5 최적화

| 최적화 | 규칙 |
|---|---|
| 값 공유(CSE) | hash-consing으로 생성 중에 한다 |
| 상수 접기 | **정확히 반올림되는 연산만** 호스트에서 접는다: 사칙·`min`·`max`·`abs`·`floor`·`frac`·비교·선택·swizzle. 초월 함수(`sin`·`pow`·`exp2`·`log2`)는 Core 결정적 수학(A0-C)으로만 접고, 결정적 수학 함수가 없는 연산은 접지 않는다. 호스트 libm으로 접으면 호스트마다 바이트가 달라진다(셰이더 시스템 10절 "상수 접기") |
| 대수 단순화 | `x*1`, `x-0`, 이중 swizzle 합치기만 한다. `x*0 → 0`(NaN)과 `x+0 → x`(−0 부호)처럼 IEEE 결과를 바꾸는 단순화는 하지 않는다 |
| 불필요 값 제거(DCE) | 진입점에서 닿지 않는 값을 버린다. 함수·레이어의 쓰지 않는 출력도 사라진다 |
| uniform 끌어올림 | `Uniform` 빈도 부분식은 상수 식 프로그램의 출력 하나로 바꾸고, 셰이더는 상수 블록 값을 읽는다(9.4절). 텍스처 읽기는 끌어올리지 않는다 |
| static 가지 제거 | 6.3절 2단계 |

**IR hash.** 최적화를 마친 IR을 값 번호 순으로 직렬화한 바이트의 SHA-256이다. 번역 너겟 키는 번역 전에 계산해야 하므로 IR hash를 쓸 수 없다. IR hash는 결과 비교 진단과 시험(15절)에 쓴다. 셰이더 중복 제거는 셰이더 집합 id(8.6절)가 한다.

### 6.6 결정성

- 값 번호는 진입점 순서(7.3절 표 순서) → 핀 순서 → 피연산자 순서로 도는 깊이 우선 후위 순이다(피연산자가 먼저 번호를 받는다 — 생성 원문이 번호 순으로 선언할 수 있다). 해시 표 순회 순서에 기대지 않는다.
- 노드를 훑는 순서는 NodeId 정렬이고, 함수 펼치기는 호출 위치 NodeId 정렬이다.
- 실수 상수는 bit 패턴으로 다루고, 원문에는 최단 왕복 표기(A0-C CRT 없는 숫자 변환)로 쓴다.
- 여러 머티리얼을 병렬로 번역하면 결과를 정렬한 뒤 기록한다(AssetSystem 10절).
- 시험: 노드 저장 순서만 섞은 두 파일의 번역 결과 byte 동일, Windows·macOS 사이 byte 동일(15.3절 MS-T1).

### 6.7 다른 IR 소비자

| 소비자 | 단계 | 계약 |
|---|---|---|
| HLSL 생성(7절) | MAT0 | 이 문서 |
| CPU bake(`BakeMaterialProfile`, 계획 14.10절) | M3–M4 | 같은 IR에서 지원 노드 부분집합을 CPU 평가기로 바꾼다. 지원하지 않는 값(미분·view 의존·임의 HLSL)은 노드 위치 오류다. 상세는 bake 스펙 |

IR은 소비자별 capability 검사를 받는다. 예를 들어 CPU bake는 임의 HLSL 노드를 지원하지 않는다.

### 6.8 MS2a 구현 세부(MaterialCompiler 기반)

MS2a는 세 묶음으로 나눈다. 묶음마다 시험을 함께 넣고, 리뷰는 MS2a 끝에 한 번 받는다.

| 묶음 | 내용 |
|---|---|
| MS2a1 | 모듈 `Engine/Source/Developer/MaterialCompiler`(의존 MaterialSchema·ShaderCore·Core), IR 타입·연산·값 표, hash-consing 빌더, 상수 접기·대수 단순화, 진입점에서 닿는 값(DCE), IR hash |
| MS2a2 | 그래프 → IR 번역기: 입력 snapshot, lowering 표, 출력 노드 스칼라 핀, 상수·수학·`DynamicBranch`·`Operator`·재경유 lowering, V1·V2·V4·V5·V7·V8·V11·V12 진단 |
| MS2a3 | HLSL 생성(7.7절)·`MaterialCommon.rsh`·원문 위치 지도, MS-T1·MS-T2·MS-T3 |

**IR 타입.** `IrType = { kind, components, rows }`다.
- kind: `Float`·`Int`·`UInt`·`Bool`·`Double`(LWC 값, 5.3절)·`Matrix`(Float, rows×components)와 MS2c 뒤의 자원·`Surface`·`MaterialAttributes`.
- 수 타입의 components는 1–4, 행렬은 3×3·4×4만이다(5.3절).
- 핀 타입 `Numeric`·`Any`는 IR 타입이 아니다. lowering이 연결된 값의 타입으로 정한다.

**연산.** `IrOp`은 UE `EMaterialExpressionOperatorKind` 전부(Operator 노드 — 사칙·비교·논리·비트·shift·IsNan·IsInf·초월·쌍곡·Rsqrt·Transpose·행렬곱 등)와 다음을 담는다: `Constant`, `Splat`(스칼라 → 벡터 복제), `Swizzle`(성분 선택 — 즉시값에 성분 번호 넷), `Append`, `Convert`(수 종류 사이 변환), `Select`(조건 선택 — 둘 다 계산), `Branch`(`DynamicBranch` — 조건 분기 표지가 붙은 선택), `Extern`(문맥 값 표 번호, MS2b — 조건 값은 별도 연산 없이 Bool 문맥 값의 `Select`, 6.9절 MS2b3).

**값.** `IrValue = { 타입, 연산, 피연산자 값 번호 최대 MaxIrOperands(3)개, 즉시값, 빈도, 원인 노드 }`.
- 상수의 즉시값은 성분별 비트 패턴이다(float는 32 bit, double은 64 bit). 비교와 hash는 비트로 한다(−0과 0은 다른 상수, NaN은 V11로 막는다).
- 원인 노드(NodeId·PinKey)는 진단과 원문 위치 지도용이다. hash-consing 키에 넣지 않는다. 같은 값을 처음 만든 노드가 남는다.
- 빈도는 6.2절 격자다. MS2a의 값은 `Constant`·`Static`·`Pixel` 정도만 나온다.

**빌더.** 값을 만들 때 (타입, 연산, 피연산자, 즉시값, 진입점 문맥)으로 찾고 있으면 그 번호를 돌려준다(hash-consing, 6.5절 CSE). 표는 Core HashMap이고, 값 번호는 처음 만든 순서다. 순회 순서는 값 번호뿐이라 해시 표 순서에 기대지 않는다(6.6절).

**상수 접기(6.5절).** 피연산자가 모두 상수면 빌더가 바로 접는다. 접는 연산은 정확히 반올림되는 것뿐이다: 사칙·`min`·`max`·`abs`·`floor`·`ceil`·`round`(짝수 쪽)·`trunc`·`frac`·`saturate`·비교·논리·선택·swizzle·append·splat·정수 변환. `sqrt`는 IEEE가 정확한 반올림을 요구하지만 Core 결정적 수학에 함수가 없어 지금은 접지 않는다(호스트 libm을 쓰지 않는다 — 생기면 접기에 더한다). 초월 함수는 Core 결정적 수학 의존이 생길 때까지 접지 않는다(셰이더 시스템 10절 — 호스트 libm 금지). 접은 결과가 NaN·Inf면 접지 않고 남긴다(GPU와 같은 결과를 보장하지 못한다 — 0 나누기 등). 원문 쪽 상수 리터럴은 V11로 NaN·Inf가 없다.

**대수 단순화.** `x*1`·`1*x`·`x-0`·`x/1`·이중 swizzle 합치기·같은 성분 그대로의 swizzle 제거만 한다(6.5절). 정수 `x+0`은 IEEE 문제가 없으므로 한다. float `x+0`·`x*0`은 하지 않는다.

**진입점과 DCE.** 모듈은 진입점(7.3절 함수)마다 결과 값 번호를 가진다. 원문 생성과 IR hash는 진입점에서 닿는 값만 본다. 값 번호는 6.6절대로 진입점 순서 → 핀 순서 → 피연산자 순의 깊이 우선 후위 순으로 다시 매긴다(생성 순서와 다를 수 있다).

**IR hash.** 다시 매긴 번호 순으로 값마다 (타입, 연산, 피연산자 번호, 즉시값)을 고정 형식 little-endian으로 쓰고 진입점 표를 붙인 바이트의 SHA-256이다(Core Sha256).

**번역기(MS2a2).**
- 입력 `MaterialTranslationInput`: 그래프 문서(`GraphDocument`, 도메인 Material), 노드 카탈로그, NamePool, 기본 속성(`MaterialTraitsDesc` — 영역·블렌드 모드·반투명 속성), 진단용 자산 id. 객체 주소는 받지 않는다(6.3절 1항). 품질 수준·static 변형은 MS2b가 더한다.
- 결과 `MaterialTranslation`: IR 모듈, 진단 목록(NodeGraph `GraphDiagnosticList` — 14장 E4), 성공 여부. 오류 진단이 하나라도 있으면 성공이 아니고 모듈은 비어 있다. 번역 함수의 `Result` 실패는 할당·NamePool 같은 시스템 오류뿐이다(그래프 오류는 진단이다). UE도 오류를 모아 보고하고 번역을 실패로 끝낸다.
- 노드 속성은 `NodePropertyReader`로 읽는다(19.13.3절과 같은 경로 — MaterialCompiler는 ObjectSerialization에 의존하지 않는다). 핀 목록은 정의의 정적 핀 + 동적 핀 함수다(NodeTypeRegistry 없이 정의에서 직접 계산한다).
- **번역 순서.** 출력 노드의 활성 핀에서 시작해 간선(과 이름 있는 재경유의 선언)을 거슬러 닿는 노드를 반복 깊이 우선(명시 스택)으로 훑어 의존 후위 순서를 만든다. 훑는 중 방문 중인 노드를 다시 만나면 V2이고 그 입력은 끊는다(재경유 포함). 그 순서로 노드마다 lowering 함수를 한 번 부르고 (노드, 출력 핀)마다 결과를 기억한다. 그래서 함수가 요청하는 입력은 늘 이미 번역된 값이고 그래프 깊이가 C++ 스택을 쓰지 않는다(수천 단계 사슬도 된다). 닿는 노드의 연결된 입력은 모두 번역한다. UE 기본 번역기도 노드가 연결된 입력을 모두 컴파일하므로 쓰지 않는 쪽의 오류도 남는다(예: DynamicBranch의 고르지 않은 쪽). 비활성 노드(`NodeEnableState`)는 통과 쌍이 있으면 그 입력을 그대로 내고, 없으면 연결이 없는 것처럼 다룬다(NodeGraph 6.5절).
- **lowering 표.** 노드 종류 Name → lowering 함수다. 함수는 노드의 입력 값을 요청하고 출력 핀마다 IR 값을 낸다(UE IR `Build`처럼 마스크 출력도 함수가 직접 낸다 — 예: Constant2의 R 핀은 성분 0). 정적 출력 핀 타입은 연결 판정용이고(마스크 출력은 마스크 폭 — 19.13.3절), 실제 값의 타입은 lowering이 낸 값이다(`Numeric`·`Any` 출력). 표에 없는 종류가 진입점에 닿으면: 카탈로그에 없는 종류면 V12, 카탈로그에 있으나 이 단계에서 아직 lowering하지 않는 종류면 `NotYetLowered`(상태가 TODO면 문구에 선행 MPQ 이름을 넣는다). 노드의 단계 이름은 목록 파일(19.2.2절)에만 있으므로 문구에 넣지 않는다. MS2 전체가 끝나면 이 코드는 TODO 노드에만 남는다.
- **의미 기준.** 결과 값은 UE 기본 번역기(`FHLSLMaterialTranslator`, 6.1절)와 같다. 구조(출력마다 값, 입력 기본값 상수)는 UE IR `Build`(`RE/Private/Materials/MaterialExpressionsToMIR.cpp`)를 따른다. 둘이 다르면 기본 번역기를 따르고, 기본 번역기 쪽이 명백한 결함이면 IR `Build`를 따른다(아래 표에 적는다).

**핀 사용자 값.** NodeGraph `PinValueEntry.value`의 Record struct는 `MaterialPinValue { x, y, z, w : float; componentCount : uint8 }`이다(MaterialSchema 공개 리플렉션 struct, 5.3절). componentCount는 1–4이고 타입이 정해진 핀(`Float1`–`Float4`)이면 그 폭 이하다. 연결이 없으면 번역은 이 값을, 없으면 정의 기본값(`MaterialPinDefault`)을 같은 폭의 Float 상수로 낸다. 타입이 정해진 정수·Bool 핀이면 그 수 종류로 바꾼다. 값 편집을 숨긴 핀(`HideValue`)의 값은 남아 있어도 쓰지 않는다(필수면 `MissingInput`). 값이 유한하지 않으면 V11, 폭이 규칙 밖이면 `InvalidPinValue`다.

**입력 값과 변환.**
- 연결이 없는 입력: 핀 사용자 값 → 정의 기본값 → (없고 `Required`면) `MissingInput` 오류, (없고 필수가 아니면) 노드 규칙(UE `Compile`의 기본 처리 — 예: If의 AEqualsB는 없음).
- 출력 노드 핀(UE 속성 타입)과 lowering이 명시한 곳의 암묵 변환(5.3절). 노드 입력 핀 타입은 연결 판정용이라 번역이 값을 그 타입으로 바꾸지 않는다(UE `Compile`도 입력 값을 그대로 쓴다 — 예: UIntToFloat 입력은 핀이 UInt1이어도 폭을 유지한다): 스칼라 → 복제, 긴 벡터 → 앞 성분(`NarrowedValue` 정보 진단), 짧은 벡터 → 긴 벡터 V1, Int·UInt → Float 허용, Double → Float는 낮춤(UE LWC demote), Float → Int·UInt V1, Bool은 Bool 핀만, `StaticBool` → `Bool` 허용. `Numeric`·`Any` 핀은 값 그대로다.
- **오류 전파.** 연결된 입력이 값 없이 들어오면(위쪽 노드가 이미 오류를 진단했다) 그 노드도 실패로 표시하고 다시 진단하지 않는다. 오류 하나는 진단 하나다(UE `INDEX_NONE` 전파와 같다).
- **비활성 노드.** 통과 쌍이 있으면 그 입력을 넘기고, 없으면 연결이 없는 것과 같다. 비활성 노드의 위쪽(통과 쌍 입력 밖)은 번역 순서에 넣지 않는다. 연결 판정(If의 AEqualsB, 출력 핀의 V5·Pending)도 같은 규칙이다.
- **첫 인자 타입(UE `CoerceParameter`).** UE 기본 번역기가 첫 인자 타입을 결과로 쓰는 연산(Clamp의 Input, Fmod·Modulo의 A, Power의 Base)은 다른 입력을 그 타입으로 맞춘다: 수 종류를 바꾸고, 폭은 같으면 그대로, 스칼라는 복제, 대상이 스칼라면 첫 성분이다. 폭이 다른 두 벡터는 V1이다(UE `CastValue`는 스칼라가 아닌 대상으로 자르지 않는다 — `HLSLMaterialTranslator.cpp:4127–4131`).
- **산술 공통 타입**(두 피연산자 이상): 폭은 같거나 한쪽이 스칼라(넓은 쪽으로 복제)여야 하고 아니면 V1("Arithmetic between types … is undefined" — UE `GetArithmeticResultType`). 수 종류는 같으면 그대로, Int·UInt와 Float이면 Float, Double과 Float·Int·UInt면 Double(LWC 승격 — Double을 받는 연산만), Int와 UInt는 V1(HLSL 암묵 규칙에 맡기지 않는다), Bool은 산술 V1이다. UE 기본 번역기는 `UInt1 + Float1`을 UInt로 보지만 Rocks는 Float로 본다(5.3절 "정수 → float 허용"과 같은 방향).
- **연산 묶음별 수 종류**(UE IR 연산 서명 `RE/Private/Materials/MaterialIREmitter.cpp:2303–2420`): (a) Double 허용 — Add·Subtract·Multiply·Divide·Min·Max·Abs·Floor·Ceil·Round·Truncate·Negate(단항은 Negate 말고 Int·UInt를 Float로 — UE `OPF_CastToAnyFloat`). (b) Float 전용(Double은 낮추고 Int·UInt는 Float로) — 삼각·역삼각·쌍곡·Exp·Log·Sqrt·Rsqrt·Reciprocal·Pow·Fmod·Step·Smoothstep·Lerp·Frac·Saturate·Sign·Dot·Cross·Distance·Length·Normalize·ATan2. (c) 정수 전용 — 비트 연산·shift(Float은 V1). (d) Bool 전용 — And·Or·Not. (e) 비교 — 산술 공통 타입, 결과 Bool(같은 폭). Modulo·Clamp는 Double을 받지 않는다(낮춘다 — UE도 Clamp는 min·max가 Double이 아니면 첫 인자를 낮춘다).

### 6.9 MS2b 구현 세부(문맥 값·평가 문맥·스위치·공급 노드)

MS2b는 네 묶음으로 나눈다. 묶음마다 시험을 함께 넣고, 리뷰는 MS2b 끝에 한 번 받는다. 노드별 lowering 표는 묶음마다 이 절 아래에 더한다.

| 묶음 | 내용 |
|---|---|
| MS2b1 | 기반: IR `Extern` 연산, 평가 문맥 셋(정점·이전 정점·픽셀)과 문맥별 노드 결과, 이전 프레임 진입점 번역, 문맥 값 검사(V4 단계·V6 영역), 진입점별 사용 기능·최소 기능 등급 기록, 사용 정의, `MaterialContext.rsh`(표에서 만든 문맥 칸·접근자), 값 하나를 읽는 문맥 노드·`Ddx`·`Ddy`·`StaticBool` |
| MS2b2 | 좌표·벡터·공간 변환과 LWC 표현(Double 값의 원문 — UE tile + offset): `TextureCoordinate`·`WorldPosition`·`ScreenPosition`·`Panner`·`Rotator`·`TransformVector`·`TransformPosition`·경계 노드 등, `MATERIAL_NUM_TEXCOORDS` |
| MS2b3 | 스위치(19.3.4절 해석 시점별): IR `Condition` 연산, 번역 입력의 품질 수준·형식 사실·프로필 기능, `StaticSwitch`·`QualitySwitch`·pass 조건·렌더 경로·기능 등급·실행 중 값 스위치, V7·V15 |
| MS2b4 | 보간기(`VertexInterpolator`·CustomizedUv 출력 핀)와 공급 노드(파티클·데칼·하늘·대기·후처리·distance field·물리장·SpeedTree·Hair·RVT·메시 페인트·글꼴·XR), 표에 없는 문맥 값 추가 |

**평가 문맥.** 번역은 진입점(7.3절)을 셋으로 묶은 평가 문맥마다 따로 한다.

| 문맥 | 진입점 | 근거 |
|---|---|---|
| 정점 | Vertex | UE 속성 컴파일의 `SF_Vertex` |
| 이전 정점 | VertexPrevious | UE는 WPO가 있을 때만 이전 프레임 WPO를 다시 컴파일한다(`bCompilingPreviousFrame` — `RE/Private/Materials/HLSLMaterialTranslator.cpp:1663–1667`). Rocks도 Vertex `WorldPositionOffset` 결과가 있을 때만 이 문맥을 번역한다 |
| 픽셀 | Surface·Opacity·OpacityMask·PixelDepthOffset·CustomOutput·Preview | UE `SF_Pixel` |

- 노드 결과 기억은 (문맥, 노드, 출력 핀)마다다. UE 기본 번역기도 셰이더 단계마다 함수 상태 스택을 따로 두고(`FunctionStacks[SF_NumFrequencies]` — `HLSLMaterialTranslator.h:309`), 노드 결과 키에 이전 프레임 여부가 들어간다(`FMaterialExpressionKey::bCompilingPreviousFrameKey` — `RE/Public/MaterialShared.h:2054–2079`).
- 문맥 순서는 정점 → 이전 정점 → 픽셀이다(진입점 순서). 문맥마다 그 문맥 진입점의 활성 출력 핀에서 번역 순서(6.8절)를 따로 만든다. 순환(V2)도 문맥마다 찾지만 같은 진단은 한 번만 남는다(아래).
- **같은 진단은 한 번.** (코드, 노드, 핀, 문구)가 같은 진단은 한 번만 기록한다. 한 노드가 여러 문맥에서 번역되어도 오류는 하나다. UE도 같은 식의 같은 오류 문구는 다시 넣지 않는다(`HLSLMaterialTranslator.cpp:4446–4455`).
- IR 값은 문맥 사이에 공유한다. 같은 계산은 한 값이고, 생성 원문은 진입점 함수마다 그 함수에서 닿는 값을 다시 낸다(7.7절). 현재·이전 값이 섞이지 않는 것은 `Extern`의 변형 즉시값이 다르기 때문이다(6.2절 "진입점 문맥" — hash-consing 키는 연산·즉시값으로 충분하다).

**`Extern` 연산(문맥 값).**
- `IrOp::Extern`(번호 82 — 끝에 더한다). 즉시값 [0]은 문맥 값 표(19.3.2절) 번호, [1]은 변형(0 현재, 1 이전 프레임)이다. 피연산자는 함수형 값의 인자(표의 `argumentCount`, 최대 3)다. 결과 타입은 표의 타입이다.
- 표 번호는 IR hash·번역 키에 들어가므로 표는 끝에만 더하고 순서를 바꾸지 않는다(문맥 공급 기능 비트와 같은 규칙).
- 이전 변형: 이전 정점 문맥에서 표의 `hasPrevious`가 참인 값은 변형 1이다. 아닌 값은 현재 값 그대로다(UE도 DeltaTime 등은 바꾸지 않는다 — 19.3.5절).
- 빈도(6.2절): 정점 기원 값(공급 기능 vertex·skin·particle·speedtree의 정점 단계 허용 값)은 `Vertex`, 픽셀 단계 전용 값은 `Pixel`, 그 밖(view·primitive·sky·post 등 그리기·view 단위 값)은 `Instance`다. 함수형 값은 인자 빈도와의 최대다. `Instance`는 `Uniform`보다 높으므로 상수 식 프로그램(9.4절)으로 끌어올리지 않는다 — 머티리얼 상수 블록에는 view·그리기 값이 없다.
- 상수 접기·대수 단순화를 하지 않는다(값을 모른다).

**문맥 값 검사.** 진입점 결과에서 닿는 `Extern`마다(DCE 뒤 — UE도 활성 속성에서 닿는 식만 컴파일한다):
- **단계(V4).** 정점·이전 정점 진입점이 픽셀 전용 값(표 `stages`에 정점 없음)을, 픽셀 진입점이 정점 전용 값(`PreSkinned*` 등)을 쓰면 오류다. 문구 `"'<이름>' is not available in the <vertex|pixel> stage"`. 미분 연산(`Ddx`·`Ddy`)도 같은 검사다(6.8절).
- **영역(V6).** 표 `domains`에 기본 속성의 영역이 없으면 오류다. 문구 `"'<이름>' is not available in the <영역> material domain"`. UE도 값마다 허용 영역 밖이면 오류다(외부 코드 선언 `Domains`, `CFG/BaseMaterialExpressions.ini:1038–`).
- **기능 등급.** 번역은 형식을 모르므로(결정 MD4 — 원문 하나) 진입점에서 닿는 값의 `minimumTier` 최대를 모듈에 기록한다. 형식 등급이 그보다 낮은 형식의 job은 거르기에서 V6로 빠진다(MS3 — 8.3절 거르기). UE는 플랫폼별 번역 때 오류다.
- **공급.** 번역은 pass를 모른다. 공급하지 않은 기능의 값은 UE 기본값이다(결정 MD15, 19.3.1절) — 아래 접근자가 낸다.

**모듈 기록.** `IrModule`이 `BuildIrModule` 때 진입점마다 닿는 `Extern`의 공급 기능 비트(`EntryFeatures(entry)`)와 `minimumTier` 최대(`RequiredTier()`)를 계산해 둔다. 값에서 유도되므로 IR hash에 따로 넣지 않는다. 쿠킹(MS3)이 셰이더 특성(`MaterialShaderTraits`)에 옮긴다.

**생성 원문(7.7절에 더함).**
- 사용 정의: 진입점 e가 기능 f를 쓰면 `#define MATERIAL_<E>_USES_<F> 1`을 낸다. E는 `VERTEX`·`VERTEX_PREVIOUS`·`SURFACE`·`OPACITY`·`OPACITY_MASK`·`PIXEL_DEPTH_OFFSET`·`CUSTOM_OUTPUT`·`PREVIEW`, F는 `MaterialContextFeatureDefineName`이다. 쓰지 않는 쌍은 정의하지 않는다(전처리 `#if`에서 정의 없는 이름은 0이다 — 8 × 24 = 192줄을 늘 내지 않는다. 19.3.1절 "0|1 고정 정의"를 이렇게 정한다).
- `Extern` 철자: `MaterialContext<이름>(c)`, 함수형은 `MaterialContext<이름>(c, a0, …)`, 이전 변형은 `MaterialContextPrevious<이름>(c)`다. `c`는 진입점 함수의 문맥 인자다.

**`MaterialContext.rsh`(문맥 칸·접근자).** `Engine/Shaders/Private/Material/MaterialContext.rsh`는 문맥 값 표에서 만든 파일이다. `MaterialCommon.rsh`가 구조체 자리에서 include한다.
- **만들기.** MaterialCompiler 공개 함수 `WriteMaterialContextSource(allocator, out)`가 표로 텍스트를 만든다. 저장소의 파일은 그 출력이고, 시험이 byte로 견준다(어긋나면 실제 텍스트를 실패에 남긴다 — 골든 원문과 같은 방식, 7.7절). 표를 고치면 파일을 함께 고친다. 파일 안 주석은 생성 원문 규칙대로 영어다.
- **공급 표지.** pass 원문은 include 전에 공급하는 기능마다 `#define MATERIAL_SUPPLY_<F> 1`을 둔다(pass 셰이더 타입과 정점 입력 타입의 공급 합집합 — 19.3.1절, 16절 MRD13·MRB9). 정의하지 않은 기능은 공급하지 않은 것이다.
- **칸.** 필드형 값마다 칸 하나다. 이름은 Rocks 이름의 lowerCamel(`Time` → `time`), 이전 변형은 `previous<이름>`이다. 표 `stages`대로 정점 단계 값은 `MaterialVertexInputs`, 픽셀 단계 값은 `MaterialInputs`에 둔다(둘 다면 둘 다). 칸은 공급 여부와 무관하게 늘 있다(구조체 layout이 머티리얼마다 바뀌지 않는다. 쓰지 않는 칸은 하위 컴파일러가 지운다). Double 칸은 LWC 표현 타입이다(MS2b2).
- **접근자.** 값마다 매크로 `MaterialContext<이름>`을 둔다. `MATERIAL_SUPPLY_<F>`이면 필드형은 칸(`((c).time)`), 함수형은 pass 원문이 정의하는 `MaterialPass<이름>(c, …)` 호출이다. 아니면 표의 기본값 리터럴이다(UE 템플릿의 0, 파티클 색 1 — 결정 MD15). 그래서 생성 원문은 어떤 pass에서도 컴파일된다.
- **채울 기능.** 생성 파일 include 뒤에 `MATERIAL_CONTEXT_<F>` = `MATERIAL_SUPPLY_<F>` ∧ (어느 진입점이든 `MATERIAL_<E>_USES_<F>`)를 정의한다. pass가 칸을 채울지·보간할지 묻는 데 쓴다(pass가 부르는 진입점만으로 더 좁힐 수 있다 — 19.3.1절).
- MS2b1은 표의 기존 값만 담는다. MS2b4가 표에 값을 더하면 같은 파일이 다시 만들어진다.

**LWC 표현(MS2b2a — 생성 원문).** UE 5.8 기본 번역기는 tile + offset이다(`WSVECTOR_IS_TILEOFFSET 1` — `HLSLMaterialTranslator.cpp:2539`). Rocks도 같다(5.3절).
- 타입은 `MaterialDouble1`–`4 { tile, offset }`(값 = tile × `MaterialDoubleTileSize` + offset, tile 크기 2097152 — UE `UE_LWC_RENDER_TILE_SIZE`)이고 `Engine/Shaders/Private/Material/MaterialDouble.rsh`에 둔다.
- 연산은 UE `SH/Private/LWCOperations.ush`와 같은 식이다: 더하기·빼기(tile끼리·offset끼리), 곱하기(`tileL × (tileR × T + offsetR) + tileR × offsetL`, `offsetL × offsetR` — `:113–118`), 나누기(곱하기 × 역수), 부정, 최소·최대(비교 선택), 절댓값, 내림·올림·반올림·버림(tile을 정수로 맞춘 뒤 offset — `:103–106`), 비교(`(tileL − tileR) × T` 대 `offsetR − offsetL` — `:23–58`), 선택. IR 연산의 피연산자는 산술 공통 타입으로 모두 Double이므로 Double × Double 판만 둔다. 이름은 `MaterialDoubleAdd` 등이다.
- 변환: Float → Double은 `MaterialDoublePromote`(tile 0), Double → Float는 `MaterialDoubleDemote`(tile × T + offset — UE `WSDemote`), 성분 선택·이어 붙이기·복제는 tile과 offset에 같은 swizzle을 쓴 `MakeMaterialDouble<N>(tile, offset)`이다.
- 상수: 호스트가 double 값 v를 tile = floor(v / T + 0.5)(UE `LWCNormalizeTile`과 같은 정수 tile), offset = float(v − tile × T)로 나눠 `MakeMaterialDouble<N>(float<N>(tile…), float<N>(offset…))`로 쓴다(T가 2의 거듭제곱이라 v − tile × T는 double에서 정확하다). UE는 double 상수를 `%0.8f` 숫자로 내고 uniform 식이 나눈다(`ShaderValue.cpp:373–378`) — 값은 같고 표기만 다르다.
- **Double 뺄셈의 Float 자름.** 같은 Double 타입 둘의 뺄셈 결과는 Float로 바꾼다(상대 공간으로 본다). UE 기본 번역기 `Sub`의 `LWCTruncateMode` 기본 2(`HLSLMaterialTranslator.cpp:9550–9575`, `r.MaterialEditor.LWCTruncateMode`)와 같다. 타입이 다른 둘(Double − Float)은 Double이다.
- `Distance`는 UE처럼 뺄셈 뒤 길이다(`CompileHelperLength` — `MaterialExpressions.cpp:18522`, 6.8절 lowering 표). 그래서 Double 둘의 거리도 이 자름을 거쳐 정밀도를 잃지 않는다.
- MS2a의 생성 원문 `NotYetLowered`(Double)는 없앤다. `WorldPositionTile` 연산만 남는다(UE IR 전용 연산 — 노드가 만들지 않는다).

- **번역 대상(`MaterialTranslationTarget`).** 번역 입력에 더한다. 품질 수준(Low·High·Medium·Epic·None — UE `EMaterialQualityLevel` 순서, None은 UE `Num`: Default 입력), 형식 사실(IsMobile·IsPC·IsConsole — UE DDSPI 스위치가 노출하는 셋, `RHI/Private/DataDrivenShaderPlatformInfo.cpp:213–215`), 형식 샘플러 상한(UE 기본 16), bindless 설정(Disabled·RayTracing·Minimal·All), 프로필 기능(distance field·virtual texture·ray tracing·virtualized geometry), 컴파일러 종류(프록시 굽기·조명 굽기), Low 품질 모바일 흉내(UE `r.Material.SimulateMobileForLowQuality`). 번역은 실제로 읽은 항목을 결과(`MaterialTranslation.consultedTarget`)에 기록한다 — 쿠킹(MS3)은 그 항목만 번역 키에 넣어 형식 등급을 묶는다(19.3.4절 "쓰지 않으면 키에 없음").
- **늦은 입력.** 번역 때 고르는 스위치의 가지 입력은 번역 순서 계획에 넣지 않는다(고른 가지만 IR로 만든다 — 6.3절 2항). lowering 함수가 고른 입력을 요청하면 번역기가 그 입력에서 거슬러 닿는 노드로 작은 번역 순서를 다시 만들어 반복으로 번역한다(재귀는 스위치가 겹친 깊이만큼뿐이다). 계획 밖 요청의 깊이 상한(`MaxLoweringDepth`)은 이 겹침 깊이에 쓴다. 순환은 늦은 계획에서도 V2다.
- **조건 값.** UE 기본 번역기의 pass·렌더러 상태 스위치는 셰이더 함수(`GetShadowReplaceState()` 등 — `Common.ush:2152–2309`)를 조건으로 한 삼항이다. Rocks도 같게 문맥 값 표의 Bool 값(공급 기능 view·meshpaint·pathtracing, pass가 상수로 정의하면 하위 컴파일러가 접는다)을 조건으로 한 IR `Select`로 낸다. 6.2절·6.8절이 예고한 별도 `Condition` 연산은 두지 않는다(하위 컴파일러가 상수 조건 삼항을 `#if`와 같은 코드로 줄인다 — 자원 layout은 MS2c에서 실제로 닿는 텍스처만 센다).

**MS2b4a 보간기.**
- **문맥 사이 번역.** 노드 결과 기억을 평가 문맥마다 따로 둔다(문맥을 바꿀 때 지우지 않는다). 픽셀 문맥의 VertexInterpolator lowering은 입력을 정점 문맥에서 번역해 달라고 요청하고(번역기가 문맥을 잠시 정점으로 바꿔 그 입력의 늦은 계획을 번역한다), 그 값을 피연산자로 한 IR `Interpolate`(번호 83)를 낸다. UE도 보간기 입력을 정점 단계로 컴파일한다(`HLSLMaterialTranslator.cpp:771–809, 1433–1451`). UE는 그래프의 보간기를 모두 미리 컴파일하고 오류를 픽셀에서 쓸 때만 보고한다 — Rocks는 픽셀에서 닿는 보간기만 번역하므로 결과가 같다.
- **`Interpolate` 값.** 결과 타입은 입력과 같은 폭의 Float다(Double은 낮춘다 — UE `ValidCast`, Bool·정수는 V1 "Bad type … for VertexInterpolator" — `:14446–14448`). 빈도는 Pixel이다. 입력 연결이 없으면 "VertexInterpolator> Input missing"(MissingInput). 정점 문맥에서 VertexInterpolator 출력을 쓰면 "Custom interpolator outputs only available in pixel shaders."(V4 — `:9161`).
- **검사·사용 기능.** 픽셀 진입점에서 거슬러 갈 때 `Interpolate`의 피연산자 쪽은 정점 단계다: V4 검사는 그 아래를 정점 단계로 보고(정점 전용 PreSkinnedPosition 등이 허용된다), 그 아래 문맥 값의 공급 기능은 Vertex 진입점 사용 기능에 넣는다.
- **보간 배정(6.4절).** `BuildIrModule`이 픽셀 진입점에서 닿는 `Interpolate`를 모듈 번호 순(6.6절 — 노드 저장 순서와 무관)으로 모아 성분을 앞에서부터 이어 붙인다(UE도 성분을 이어 채운다 — `GetVertexInterpolatorsOffsets`, `:2615–2681`). 즉시값 [0]에 첫 성분 번호(성분 단위 오프셋)를 둔다. 같은 입력의 두 보간기는 hash-consing으로 한 슬롯이다.
- **생성 원문.** `MaterialVertexResult`에 `float4 interpolants[MaterialMaxInterpolantVectors]`(상한은 V9 보간 예산 — 16 벡터로 시작, 셰이더 시스템 7.2절 7항 `TEXCOORDn` n ≤ 15)를 둔다. 정점 함수는 `Interpolate` 피연산자를 계산해 `r.interpolants[k].<성분> = …;`로 쓰고, 픽셀 함수는 `c.interpolants[k].<성분>`을 읽는다(pass가 `MaterialInputs.interpolants`로 넘긴다). 픽셀 함수는 `Interpolate` 아래를 내지 않는다. `MATERIAL_NUM_INTERPOLANT_VECTORS`는 ⌈성분 수 / 4⌉다. 넘으면 V9("Maximum number of custom vertex interpolators exceeded").

**CustomizedUv 출력 핀.** UE는 픽셀 속성을 모두 번역한 뒤 픽셀이 쓰는 UV 채널 수(가장 큰 TexCoord 색인 + 1)만큼 CustomizedUV를 정점 단계로 컴파일한다. i < `NumCustomizedUVs`이고 연결이 있으면 그 값, 아니면 정점의 TexCoord(i) 그대로다(`HLSLMaterialTranslator.cpp:1684–1697`, `Material.cpp:7254–7268`). Rocks:
- 픽셀 문맥 뒤에 정점 문맥에서 i < (픽셀 진입점의 TexCoord 최대 색인 + 1)인 CustomizedUv<i>를 번역해 Vertex 결과 `CustomizedUv<i>`(Float2)로 둔다. 연결은 i < `traits.customizedUvCount`일 때만 쓴다(넘는 연결은 V5 경고 — UE는 조용히 버린다, 편차).
- 생성 원문: `MaterialVertexResult.customizedUvs[MaterialMaxTexCoords]`(8)에 정점 함수가 쓴다. pass는 그것을 픽셀 TexCoord로 보간한다. `MATERIAL_NUM_CUSTOMIZED_UVS` = 결과 수. 정점 진입점의 TexCoord는 원래 정점 UV다(UE와 같다).

**MS2b4b 공급 노드.** 남은 MS2b 노드 29개다. 렌더러 자원을 읽는 값은 모두 pass가 공급하는 문맥 함수 값이고(19.3.2절 — 자원 수는 Renderer가 기능별로 선언, MRD13), lowering은 UE 기본 번역기의 인자 기본값·검사·식을 맞춘다. 근거 줄은 `MaterialExpressions.cpp`(ME)·`HLSLMaterialTranslator.cpp`(HT)·`BaseMaterialExpressions.ini`(ini)·`MaterialTemplate.ush`(MT)다.
- **피연산자 상한.** 인자가 많은 함수형 값(DistanceFieldApproxAo·SpeedTree)을 위해 `MaxIrOperands`를 4로 올린다(6.8절 값 정의 — IR hash 형식은 피연산자 수를 이미 쓰므로 형식 표지만 올린다). 상수 인자 여럿은 Float 벡터 하나로 묶어 넘긴다(pass 함수가 푼다 — UE 함수 서명과 인자 순서는 같고 묶음만 다르다).
- **위치 기본값.** WorldPosition 입력이 없으면 `worldPositionOriginType`이 Absolute면 WorldPosition(Double3), CameraRelative면 TranslatedWorldPosition이다(UE `GetWorldPositionOrDefault` — HT:3316–3329).
