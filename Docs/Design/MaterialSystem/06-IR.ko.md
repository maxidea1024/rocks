# 머티리얼 시스템(MaterialSystem) 설계

## 6. IR

### 6.1 UE 5.8 방식

| 경로 | 5.8 상태 | 근거 |
|---|---|---|
| 노드가 코드 조각을 직접 내는 번역기(`FHLSLMaterialTranslator`, 진입 함수 `Translate_Legacy`) | **기본값.** 클래스에 deprecation 표시가 없다 | `RE/Private/Materials/HLSLMaterialTranslator.h:233`, 분기 `RE/Private/Materials/MaterialShared.cpp:3683–3704` |
| Material IR + IR→HLSL(`FMaterialIRToHLSLTranslation`) | **실험.** `r.Material.Translator.EnableNew`(기본 false, 설명 "prototype (WIP)")와 머티리얼별 `bEnableNewHLSLGenerator`가 모두 켜져야 쓰인다. 사용 시 "new experimental material translator" 로그, 쿠킹 때 "still experimental" Display 로그 | `MaterialShared.cpp:108–112, 3616`, `RE/Private/Materials/MaterialInterface.cpp:233–237, 342–351`, `RE/Public/Materials/Material.h:1072–1074` |
| 5.1–5.3의 HLSLTree(`MaterialHLSLGenerator`) | **코드 제거.** Runtime·Editor 전체 grep 0건이다. 플래그 이름 `bEnableNewHLSLGenerator`만 IR 스위치로 재사용된다 | grep 결과(2026-11-17) |

UE IR 구조(참고):
- 값 종류는 순수 값(상수·builtin·파라미터 컬렉션·uniform 등)과 명령(연산·분기·텍스처 읽기·Substrate 연산·단계 전환·미분·보간 설정·호출·preshader 파라미터)이다(`RE/Public/Materials/MaterialIR.h:43–90`).
- 값은 POD이고, 빌더가 같은 계산을 해시로 찾아 한 인스턴스로 쓴다(`MaterialIR.h:97–118`).
- 모듈은 단계(정점·픽셀·compute)와 custom 출력마다 진입점을 가진다(`RE/Public/Materials/MaterialIRModule.h:20–63`).
- 빌드 단계는 초기화 → 노드 그래프를 IR로 → Substrate 출력 → 출력 설정 명령 → 의존 순 분석 → 모듈 전체 분석(한도·preshader fixup) → 명령을 가장 좁은 블록에 배치 → 산출 확정이다(`RE/Private/Materials/MaterialIRModuleBuilder.cpp:1532–1598`).
- 상수 접기(`RE/Private/Materials/MaterialIREmitter.cpp:2142, 2755, 2902, 3016`)와 uniform 연산의 preshader 승격(`MaterialIREmitter.cpp:2738`, 설계 설명 `RE/Public/Materials/MaterialIRPreshader.h:12–32`)이 있다. 별도 DCE·CSE 패스가 있는지는 미확인이다.

**Rocks 선택(결정 MD2).**
- UE 기본 번역기는 "이름이 legacy인 기본값"이고 IR 쪽은 실험이다.
- 계획은 처음부터 typed IR을 요구하고(14.1·14.7절), HLSL 말고도 CPU bake(`BakeMaterialProfile`, 계획 14.10절)와 ray profile(M8)이 IR을 소비한다.
- 그래서 Rocks는 IR 하나를 정본으로 두고 HLSL은 그 소비자 가운데 하나로 만든다. 노드가 HLSL 조각을 직접 내는 경로는 두지 않는다.

### 6.2 구조

- **모듈** = (머티리얼 static 변형, 품질 수준)마다 하나다. 진입점은 정점 결과·이전 프레임 정점 결과·표면·opacity·opacity mask·pixel depth offset·custom 출력마다 하나다(7.3절 함수와 1:1).
- **값** = `{ 타입, 연산, 피연산자 값들, 빈도, 단계 집합, 속성(공간·색공간·미분 요구) }`. 피연산자는 값 번호다. (타입, 연산, 피연산자, 속성, 진입점 문맥)이 같으면 한 값으로 공유한다(hash-consing). 진입점 문맥(현재·이전 프레임, 19.3.5절)이 다르면 같은 노드도 다른 값이다.
- **연산 집합**은 UE `Operator` 노드의 연산 전부(`RE/Public/Materials/MaterialExpressionOperator.h:14–100` — 사칙·비교·논리·비트·shift·IsNan·IsInf·초월·쌍곡·Rsqrt·Transpose·행렬곱·LWC 타일 연산)와 텍스처·문맥 값(extern)·조건 값·동적 분기를 담는다. IsNan·IsInf는 생성 원문에서 fast-math가 지우지 않는 형태로 낸다(V11은 상수만 막는다).
- **빈도** 격자: `Constant < Static < Uniform < Instance < Vertex < Pixel`.
  - `Uniform`: 머티리얼 파라미터·컬렉션 값과 그것만으로 된 식. 상수 식 프로그램(9.4절)으로 간다.
  - `Instance`: 그리기 단위 데이터(primitive·instance custom data). Renderer 스펙의 instance 데이터 계약을 따른다.
  - 연산의 빈도는 피연산자 빈도의 최대다. 예외로 미분과 암묵 mip 텍스처 읽기는 `Pixel`이고, 명시 mip 텍스처 읽기는 최소 `Vertex`다(uniform으로 끌어올리지 않는다).
- **조건 값.** 번역 때 정해지지 않는 static 조건(렌더 경로·기능 등급)은 IR의 조건 값으로 남기고 생성 원문에서 `#if`로 낸다(6.3절). 품질 수준과 static 파라미터는 번역 때 정해진다.

### 6.3 생성(그래프 → IR)

1. **입력 고정.** 그래프 snapshot(계획 14.6절 immutable)과 Build 의존 함수·컬렉션의 snapshot을 받는다. Object 주소는 들고 가지 않는다.
2. **static 해석.** static 파라미터(인스턴스 override 반영), Quality Switch(번역 중인 품질 수준), Static Switch를 풀고, 선택되지 않은 입력은 IR로 만들지 않는다. UE도 Quality Switch는 유효 입력 하나만 컴파일한다(`RE/Private/Materials/MaterialExpressions.cpp:9082–9107`, 검증 때만 모든 입력 `:9088–9102`).
3. **렌더 경로·기능 등급 분기.** Render Path Switch는 Deferred·ForwardPlus·Default 세 입력을 가진다. 경로 전용 pass(`GBuffer`·`ForwardOpaque`·`DepthAux`)는 그 경로 입력을, 두 경로가 함께 쓰는 pass(`Depth`·`ShadowDepth`·`Translucent`·`Velocity` 등)는 Default 입력을 쓴다(Renderer 14.3절 "경로" 열). 생성 원문은 Renderer가 pass job에 넣는 `RENDER_PATH_DEFERRED`·`RENDER_PATH_FORWARD_PLUS`로 `#if`를 고른다. WPO·마스크·PDO에 닿는 Render Path Switch는 V15 오류다. Render Path Switch와 Capability Tier Switch는 모든 입력을 IR로 만들고 조건 값으로 잇는다. UE는 shading path를 플랫폼당 하나로 정해 한쪽만 컴파일한다(`RE/Public/Materials/MaterialExpressionShadingPathSwitch.h:50`). Rocks는 한 실행 안에서 view마다 Deferred·Forward+를 고르므로(계획 11.1절) pass job이 정한다.
4. **함수 펼치기.** 함수 호출은 scope를 쌓고 함수 그래프를 펼친다. 함수 입력은 호출한 쪽의 값이다. UE도 인라인이다(`RE/Private/Materials/MaterialExpressions.cpp:15774–15824`, 호출자 문맥 복귀 `:16564–16594`). 파라미터 scope 경로는 9.2절이다.
5. **레이어 스택 펼치기.** 레이어 i를 펼치고 혼합 함수로 결합한다. 레이어·혼합 scope는 레이어 Guid다. UE는 레이어 index에 연관을 단다(`MaterialExpressions.cpp:7238–7239, 7273–7274`).
6. **출력.** 영역·블렌드 모드가 쓰는 출력 핀만 진입점으로 만든다(V5).

### 6.4 분석

| 분석 | 내용 | 오류 |
|---|---|---|
| 타입 | 노드 lowering이 낸 타입과 암묵 변환을 확정한다 | V1 |
| 단계 | 진입점에서 거슬러 각 값이 필요한 단계 집합을 구한다. 정점 진입점이 픽셀 전용 값을 쓰면 오류다 | V4 |
| 미분 | 암묵 미분(암묵 mip 샘플·`ddx`)은 픽셀 단계에서만 허용한다. 미분 요구를 값에 기록한다. 후속 visibility 기반 shading이 analytic 미분을 요구할 때 쓰려는 것이다(UE는 analytic 미분 모드를 따로 둔다, `RE/Private/Materials/HLSLMaterialTranslator.cpp:150–178`) | V4 |
| 공간 | 벡터 값의 좌표 공간 표지(local·world·translated world·view·tangent 등)를 따라가 잘못된 공간 결합을 경고한다. 노멀 출력은 tangent 공간이 기본이고 표지로 확인한다 | 계획 14.7절 "잘못된 normal 공간" |
| 색공간 | 텍스처 샘플 종류가 sRGB 해제를 정하고 값에 선형 표지를 단다 | V10 |
| 보간 배정 | 정점 → 픽셀 값(customized UV·Vertex Interpolator)을 `Float4` 묶음에 채운다. 순서는 핀 번호·NodeId 순이다 | V9 |
| 자원 집계 | 텍스처·샘플러·상수 블록 크기·컬렉션·보간 벡터 수를 센다 | V9 |
| capability | 노드가 요구하는 기능(scene texture 읽기·GBuffer 읽기·dual source blend 등)을 진입점별로 모아 `MaterialShaderTraits`에 기록한다 | V6 |

### 6.5 최적화

| 최적화 | 규칙 |
|---|---|
| 값 공유(CSE) | hash-consing으로 생성 중에 한다 |
| 상수 접기 | **정확히 반올림되는 연산만** 호스트에서 접는다: 사칙·`min`·`max`·`abs`·`floor`·`frac`·비교·선택·swizzle. 초월 함수(`sin`·`pow`·`exp2`·`log2`)는 Core 결정적 수학(A0-C)으로만 접고, 결정적 수학 함수가 없는 연산은 접지 않는다. 호스트 libm으로 접으면 호스트마다 바이트가 달라진다(셰이더 시스템 10절 "상수 접기") |
| 대수 단순화 | `x*1`, `x-0`, 이중 swizzle 합치기만 한다. `x*0 → 0`(NaN)과 `x+0 → x`(−0 부호)처럼 IEEE 결과를 바꾸는 단순화는 하지 않는다 |
| 불필요 값 제거(DCE) | 진입점에서 닿지 않는 값을 버린다. 함수·레이어의 쓰지 않는 출력도 사라진다 |
| uniform 끌어올림 | `Uniform` 빈도 부분식은 상수 식 프로그램의 출력 하나로 바꾸고, 셰이더는 상수 블록 값을 읽는다(9.4절). 텍스처 읽기는 끌어올리지 않는다 |
| static 가지 제거 | 6.3절 2단계 |

**IR hash.** 최적화를 마친 IR을 값 번호 순으로 직렬화한 바이트의 SHA-256이다. 번역 너겟 키는 번역 전에 계산해야 하므로 IR hash를 쓸 수 없다. IR hash는 결과 비교 진단과 시험(15절)에 쓴다. 셰이더 중복 제거는 셰이더 집합 id(8.6절)가 한다.

### 6.6 결정성

- 값 번호는 진입점 순서(7.3절 표 순서) → 핀 순서 → 피연산자 순서로 도는 깊이 우선 후위 순이다(피연산자가 먼저 번호를 받는다 — 생성 원문이 번호 순으로 선언할 수 있다). 해시 표 순회 순서에 기대지 않는다.
- 노드를 훑는 순서는 NodeId 정렬이고, 함수 펼치기는 호출 위치 NodeId 정렬이다.
- 실수 상수는 bit 패턴으로 다루고, 원문에는 최단 왕복 표기(A0-C CRT 없는 숫자 변환)로 쓴다.
- 여러 머티리얼을 병렬로 번역하면 결과를 정렬한 뒤 기록한다(AssetSystem 10절).
- 시험: 노드 저장 순서만 섞은 두 파일의 번역 결과 byte 동일, Windows·macOS 사이 byte 동일(15.3절 MS-T1).

### 6.7 다른 IR 소비자

| 소비자 | 단계 | 계약 |
|---|---|---|
| HLSL 생성(7절) | MAT0 | 이 문서 |
| CPU bake(`BakeMaterialProfile`, 계획 14.10절) | M3–M4 | 같은 IR에서 지원 노드 부분집합을 CPU 평가기로 바꾼다. 지원하지 않는 값(미분·view 의존·임의 HLSL)은 노드 위치 오류다. 상세는 bake 스펙 |
| ray profile(계획 14.4절 RayScene 재질표) | M8 | 후속 |

IR은 소비자별 capability 검사를 받는다. 예를 들어 CPU bake는 임의 HLSL 노드를 지원하지 않는다.

### 6.8 MS2a 구현 세부(MaterialCompiler 기반)

MS2a는 세 묶음으로 나눈다. 묶음마다 시험을 함께 넣고, 리뷰는 MS2a 끝에 한 번 받는다.

| 묶음 | 내용 |
|---|---|
| MS2a1 | 모듈 `Engine/Source/Developer/MaterialCompiler`(의존 MaterialSchema·ShaderCore·Core), IR 타입·연산·값 표, hash-consing 빌더, 상수 접기·대수 단순화, 진입점에서 닿는 값(DCE), IR hash |
| MS2a2 | 그래프 → IR 번역기: 입력 snapshot, lowering 표, 출력 노드 스칼라 핀, 상수·수학·`DynamicBranch`·`Operator`·재경유 lowering, V1·V2·V4·V5·V7·V8·V11·V12 진단 |
| MS2a3 | HLSL 생성(7.7절)·`MaterialCommon.rsh`·원문 위치 지도, MS-T1·MS-T2·MS-T3 |

**IR 타입.** `IrType = { kind, components, rows }`다.
- kind: `Float`·`Int`·`UInt`·`Bool`·`Double`(LWC 값, 5.3절)·`Matrix`(Float, rows×components)와 MS2c 뒤의 자원·`Surface`·`MaterialAttributes`.
- 수 타입의 components는 1–4, 행렬은 3×3·4×4만이다(5.3절).
- 핀 타입 `Numeric`·`Any`는 IR 타입이 아니다. lowering이 연결된 값의 타입으로 정한다.

**연산.** `IrOp`은 UE `EMaterialExpressionOperatorKind` 전부(Operator 노드 — 사칙·비교·논리·비트·shift·IsNan·IsInf·초월·쌍곡·Rsqrt·Transpose·행렬곱 등)와 다음을 담는다: `Constant`, `Splat`(스칼라 → 벡터 복제), `Swizzle`(성분 선택 — 즉시값에 성분 번호 넷), `Append`, `Convert`(수 종류 사이 변환), `Select`(조건 선택 — 둘 다 계산), `Branch`(`DynamicBranch` — 조건 분기 표지가 붙은 선택), `Extern`(문맥 값 표 번호, MS2b), `Condition`(조건 값, 6.2절 — MS2b).

**값.** `IrValue = { 타입, 연산, 피연산자 값 번호 최대 MaxIrOperands(3)개, 즉시값, 빈도, 원인 노드 }`.
- 상수의 즉시값은 성분별 비트 패턴이다(float는 32 bit, double은 64 bit). 비교와 hash는 비트로 한다(−0과 0은 다른 상수, NaN은 V11로 막는다).
- 원인 노드(NodeId·PinKey)는 진단과 원문 위치 지도용이다. hash-consing 키에 넣지 않는다. 같은 값을 처음 만든 노드가 남는다.
- 빈도는 6.2절 격자다. MS2a의 값은 `Constant`·`Static`·`Pixel` 정도만 나온다.

**빌더.** 값을 만들 때 (타입, 연산, 피연산자, 즉시값, 진입점 문맥)으로 찾고 있으면 그 번호를 돌려준다(hash-consing, 6.5절 CSE). 표는 Core HashMap이고, 값 번호는 처음 만든 순서다. 순회 순서는 값 번호뿐이라 해시 표 순서에 기대지 않는다(6.6절).

**상수 접기(6.5절).** 피연산자가 모두 상수면 빌더가 바로 접는다. 접는 연산은 정확히 반올림되는 것뿐이다: 사칙·`min`·`max`·`abs`·`floor`·`ceil`·`round`(짝수 쪽)·`trunc`·`frac`·`saturate`·비교·논리·선택·swizzle·append·splat·정수 변환. `sqrt`는 IEEE가 정확한 반올림을 요구하지만 Core 결정적 수학에 함수가 없어 지금은 접지 않는다(호스트 libm을 쓰지 않는다 — 생기면 접기에 더한다). 초월 함수는 Core 결정적 수학 의존이 생길 때까지 접지 않는다(셰이더 시스템 10절 — 호스트 libm 금지). 접은 결과가 NaN·Inf면 접지 않고 남긴다(GPU와 같은 결과를 보장하지 못한다 — 0 나누기 등). 원문 쪽 상수 리터럴은 V11로 NaN·Inf가 없다.

**대수 단순화.** `x*1`·`1*x`·`x-0`·`x/1`·이중 swizzle 합치기·같은 성분 그대로의 swizzle 제거만 한다(6.5절). 정수 `x+0`은 IEEE 문제가 없으므로 한다. float `x+0`·`x*0`은 하지 않는다.

**진입점과 DCE.** 모듈은 진입점(7.3절 함수)마다 결과 값 번호를 가진다. 원문 생성과 IR hash는 진입점에서 닿는 값만 본다. 값 번호는 6.6절대로 진입점 순서 → 핀 순서 → 피연산자 순의 깊이 우선 후위 순으로 다시 매긴다(생성 순서와 다를 수 있다).

**IR hash.** 다시 매긴 번호 순으로 값마다 (타입, 연산, 피연산자 번호, 즉시값)을 고정 형식 little-endian으로 쓰고 진입점 표를 붙인 바이트의 SHA-256이다(Core Sha256).

**번역기(MS2a2).**
- 입력 `MaterialTranslationInput`: 그래프 문서(`GraphDocument`, 도메인 Material), 노드 카탈로그, NamePool, 기본 속성(`MaterialTraitsDesc` — 영역·블렌드 모드·반투명 속성), 진단용 자산 id. 객체 주소는 받지 않는다(6.3절 1항). 품질 수준·static 변형은 MS2b가 더한다.
- 결과 `MaterialTranslation`: IR 모듈, 진단 목록(NodeGraph `GraphDiagnosticList` — 14장 E4), 성공 여부. 오류 진단이 하나라도 있으면 성공이 아니고 모듈은 비어 있다. 번역 함수의 `Result` 실패는 할당·NamePool 같은 시스템 오류뿐이다(그래프 오류는 진단이다). UE도 오류를 모아 보고하고 번역을 실패로 끝낸다.
- 노드 속성은 `NodePropertyReader`로 읽는다(19.13.3절과 같은 경로 — MaterialCompiler는 ObjectSerialization에 의존하지 않는다). 핀 목록은 정의의 정적 핀 + 동적 핀 함수다(NodeTypeRegistry 없이 정의에서 직접 계산한다).
- **번역 순서.** 출력 노드의 활성 핀에서 시작해 간선(과 이름 있는 재경유의 선언)을 거슬러 닿는 노드를 반복 깊이 우선(명시 스택)으로 훑어 의존 후위 순서를 만든다. 훑는 중 방문 중인 노드를 다시 만나면 V2이고 그 입력은 끊는다(재경유 포함). 그 순서로 노드마다 lowering 함수를 한 번 부르고 (노드, 출력 핀)마다 결과를 기억한다. 그래서 함수가 요청하는 입력은 늘 이미 번역된 값이고 그래프 깊이가 C++ 스택을 쓰지 않는다(수천 단계 사슬도 된다). 닿는 노드의 연결된 입력은 모두 번역한다. UE 기본 번역기도 노드가 연결된 입력을 모두 컴파일하므로 쓰지 않는 쪽의 오류도 남는다(예: DynamicBranch의 고르지 않은 쪽). 비활성 노드(`NodeEnableState`)는 통과 쌍이 있으면 그 입력을 그대로 내고, 없으면 연결이 없는 것처럼 다룬다(NodeGraph 6.5절).
- **lowering 표.** 노드 종류 Name → lowering 함수다. 함수는 노드의 입력 값을 요청하고 출력 핀마다 IR 값을 낸다(UE IR `Build`처럼 마스크 출력도 함수가 직접 낸다 — 예: Constant2의 R 핀은 성분 0). 정적 출력 핀 타입은 연결 판정용이고(마스크 출력은 마스크 폭 — 19.13.3절), 실제 값의 타입은 lowering이 낸 값이다(`Numeric`·`Any` 출력). 표에 없는 종류가 진입점에 닿으면: 카탈로그에 없는 종류면 V12, 카탈로그에 있으나 이 단계에서 아직 lowering하지 않는 종류면 `NotYetLowered`(상태가 TODO면 문구에 선행 MPQ 이름을 넣는다). 노드의 단계 이름은 목록 파일(19.2.2절)에만 있으므로 문구에 넣지 않는다. MS2 전체가 끝나면 이 코드는 TODO 노드에만 남는다.
- **의미 기준.** 결과 값은 UE 기본 번역기(`FHLSLMaterialTranslator`, 6.1절)와 같다. 구조(출력마다 값, 입력 기본값 상수)는 UE IR `Build`(`RE/Private/Materials/MaterialExpressionsToMIR.cpp`)를 따른다. 둘이 다르면 기본 번역기를 따르고, 기본 번역기 쪽이 명백한 결함이면 IR `Build`를 따른다(아래 표에 적는다).

**핀 사용자 값.** NodeGraph `PinValueEntry.value`의 Record struct는 `MaterialPinValue { x, y, z, w : float; componentCount : uint8 }`이다(MaterialSchema 공개 리플렉션 struct, 5.3절). componentCount는 1–4이고 타입이 정해진 핀(`Float1`–`Float4`)이면 그 폭 이하다. 연결이 없으면 번역은 이 값을, 없으면 정의 기본값(`MaterialPinDefault`)을 같은 폭의 Float 상수로 낸다. 타입이 정해진 정수·Bool 핀이면 그 수 종류로 바꾼다. 값 편집을 숨긴 핀(`HideValue`)의 값은 남아 있어도 쓰지 않는다(필수면 `MissingInput`). 값이 유한하지 않으면 V11, 폭이 규칙 밖이면 `InvalidPinValue`다.

**입력 값과 변환.**
- 연결이 없는 입력: 핀 사용자 값 → 정의 기본값 → (없고 `Required`면) `MissingInput` 오류, (없고 필수가 아니면) 노드 규칙(UE `Compile`의 기본 처리 — 예: If의 AEqualsB는 없음).
- 출력 노드 핀(UE 속성 타입)과 lowering이 명시한 곳의 암묵 변환(5.3절). 노드 입력 핀 타입은 연결 판정용이라 번역이 값을 그 타입으로 바꾸지 않는다(UE `Compile`도 입력 값을 그대로 쓴다 — 예: UIntToFloat 입력은 핀이 UInt1이어도 폭을 유지한다): 스칼라 → 복제, 긴 벡터 → 앞 성분(`NarrowedValue` 정보 진단), 짧은 벡터 → 긴 벡터 V1, Int·UInt → Float 허용, Double → Float는 낮춤(UE LWC demote), Float → Int·UInt V1, Bool은 Bool 핀만, `StaticBool` → `Bool` 허용. `Numeric`·`Any` 핀은 값 그대로다.
- **오류 전파.** 연결된 입력이 값 없이 들어오면(위쪽 노드가 이미 오류를 진단했다) 그 노드도 실패로 표시하고 다시 진단하지 않는다. 오류 하나는 진단 하나다(UE `INDEX_NONE` 전파와 같다).
- **비활성 노드.** 통과 쌍이 있으면 그 입력을 넘기고, 없으면 연결이 없는 것과 같다. 비활성 노드의 위쪽(통과 쌍 입력 밖)은 번역 순서에 넣지 않는다. 연결 판정(If의 AEqualsB, 출력 핀의 V5·Pending)도 같은 규칙이다.
- **첫 인자 타입(UE `CoerceParameter`).** UE 기본 번역기가 첫 인자 타입을 결과로 쓰는 연산(Clamp의 Input, Fmod·Modulo의 A, Power의 Base)은 다른 입력을 그 타입으로 맞춘다: 수 종류를 바꾸고, 폭은 같으면 그대로, 스칼라는 복제, 대상이 스칼라면 첫 성분이다. 폭이 다른 두 벡터는 V1이다(UE `CastValue`는 스칼라가 아닌 대상으로 자르지 않는다 — `HLSLMaterialTranslator.cpp:4127–4131`).
- **산술 공통 타입**(두 피연산자 이상): 폭은 같거나 한쪽이 스칼라(넓은 쪽으로 복제)여야 하고 아니면 V1("Arithmetic between types … is undefined" — UE `GetArithmeticResultType`). 수 종류는 같으면 그대로, Int·UInt와 Float이면 Float, Double과 Float·Int·UInt면 Double(LWC 승격 — Double을 받는 연산만), Int와 UInt는 V1(HLSL 암묵 규칙에 맡기지 않는다), Bool은 산술 V1이다. UE 기본 번역기는 `UInt1 + Float1`을 UInt로 보지만 Rocks는 Float로 본다(5.3절 "정수 → float 허용"과 같은 방향).
- **연산 묶음별 수 종류**(UE IR 연산 서명 `RE/Private/Materials/MaterialIREmitter.cpp:2303–2420`): (a) Double 허용 — Add·Subtract·Multiply·Divide·Min·Max·Abs·Floor·Ceil·Round·Truncate·Negate(단항은 Negate 말고 Int·UInt를 Float로 — UE `OPF_CastToAnyFloat`). (b) Float 전용(Double은 낮추고 Int·UInt는 Float로) — 삼각·역삼각·쌍곡·Exp·Log·Sqrt·Rsqrt·Reciprocal·Pow·Fmod·Step·Smoothstep·Lerp·Frac·Saturate·Sign·Dot·Cross·Distance·Length·Normalize·ATan2. (c) 정수 전용 — 비트 연산·shift(Float은 V1). (d) Bool 전용 — And·Or·Not. (e) 비교 — 산술 공통 타입, 결과 Bool(같은 폭). Modulo·Clamp는 Double을 받지 않는다(낮춘다 — UE도 Clamp는 min·max가 Double이 아니면 첫 인자를 낮춘다).
