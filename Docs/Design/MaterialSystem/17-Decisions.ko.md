# 머티리얼 시스템(MaterialSystem) 설계

## 17. 결정 사항

2026-11-18 사용자 지시("결정사항들은 권장안대로 하면됨")로 MD1–MD9를 확정했다. MD4는 처음에 같은 날 확정된 Renderer 결정 RN13 (가)에 맞췄고, 같은 날 사용자 결정으로 RN13과 함께 형식별 상한으로 개정했다. 결정 대기로 남은 항목은 없다. MD10–MD16(개정 10)은 2026-11-25 사용자 지시(전체 구현, 선행이 필요한 것은 TODO 뼈대)와 권장안·UE 우선 원칙(애매하면 UE 5.8 방식)으로 확정했다. 설계 교차 검증 1회를 반영했다.

| ID | 결정 | 선택지 | 결정 | 근거 |
|---|---|---|---|---|
| MD1 | **Substrate 채택 형태** | (가) 고전 shading model enum만. (나) Substrate형 BSDF 그래프 + closure 하나로 접어 `SurfaceAttributes`로 내보냄, 여러 closure는 연구 gate. (다) Substrate 전체(여러 closure·Adaptive형 저장) | **결정됨(2026-11-18, 권장안 (나))** | UE 5.8 새 프로젝트 기본(Substrate + Blendable)과 같은 조합이다(10.2절). UE는 고전 셰이더 함수를 5.7부터 "Deprecated by Substrate"로 표시했다. Renderer도 Blendable과 같은 고정 배치로 시작한다(Renderer 7.1절). Rocks 형식 가운데 Adaptive 대상은 `D3D12_SM6`뿐이라 (다)는 한 형식만 이득을 본다. (나)는 그래프·에셋을 처음부터 Substrate형으로 두어 나중에 여러 closure로 갈 때 에셋 변환이 없다 |
| MD2 | **번역기 구조** | (가) typed IR → HLSL. (나) 노드가 HLSL 조각을 직접 내는 번역기(UE 5.8 기본) | **결정됨(2026-11-18, 권장안 (가))** | 계획이 typed IR을 요구하고(14.1·14.7절), CPU bake·ray profile이 같은 IR을 소비한다(6.7절). Rocks는 하위 호환할 노드 구현이 없다. 결정성(상수 접기·번호 매김)도 IR에서 한 번에 지킨다 |
| MD3 | **셰이더 결정 4와의 관계** | 셰이더 결정 4는 (A) MetaCompiler 파라미터 종류 또는 (B) UE 매크로 방식이다. 머티리얼 layout은 어느 쪽이든 실행 중 데이터로 만든다 | **결정됨(2026-11-18, 권장안): (A)를 고르고 그 layout 표를 `ShaderParameterLayout` 데이터 형식으로 정해 머티리얼 컴파일러도 같은 형식을 낸다** | 바인딩 지도·서명 검증·GLES 복사 표가 C++ 구조체와 머티리얼에 같은 경로 하나로 동작한다(RenderBase 9.3절). (B)는 매크로 메타데이터와 머티리얼 동적 layout이 두 형식이 되어 변환층이 필요하다. UE도 머티리얼 uniform buffer는 매크로가 아니라 실행 중 layout으로 만든다(`RE/Private/Materials/MaterialUniformExpressions.cpp:524`). 셰이더 시스템 결정 4도 같은 날 (A)로 확정되었다(셰이더 시스템 개정 12, 15절). 이 요구는 셰이더 시스템 13절에 적혀 있다(MSR4) |
| MD4 | **텍스처·샘플러 한도** | (가) 짝 규칙 유지, 머티리얼 텍스처 = (pass, 퍼뮤테이션)별 `16 − 렌더러 합계`(= Renderer RN13 (가)). (나) 16-SRV 형식용 pass 셰이더 타입을 따로 두어 데스크톱은 높은 상한(RN13 (나)). (다) 공유 샘플러 + 데스크톱 SRV 상한을 높인 장치 요구 형식(이 문서 초안 권장) | **결정됨(2026-11-18), 같은 날 사용자 결정으로 개정: 형식별 상한(Renderer RN13 개정과 같다)** | 생성 원문은 모든 형식에 하나이고 짝 규칙을 유지한다. 머티리얼 텍스처 상한은 (pass, 퍼뮤테이션, 형식)별 `형식 상한 − 렌더러 합계`이며 형식 상한은 형식 정의가 정한다(D3D12·Vulkan·Metal 넓게, GLES·D3D11 SM5 16, MSR12). 데스크톱에서 쿠킹되는 머티리얼도 모바일 형식에서 넘으면 그 형식을 쿠킹할 때 명시 오류다(UE 모바일 머티리얼 제약과 같은 성격). 16장을 넘으려면 공유 샘플러가 필요하다(MSR13). 초안 권장 (다)와 방향이 같다. 처음 확정한 (가)는 GLES 16이 데스크톱까지 묶어 일반 PBR 머티리얼도 무거운 퍼뮤테이션에서 쿠킹 오류가 날 수 있었다(10.4절 D3). 측정 MM5는 모바일 형식 오류 비율과 공유 샘플러 시점을 본다 |
| MD5 | **함수 안 파라미터 범위** | (가) 계획 14.7절대로 호출 위치마다 독립 + 명시 "공유" 표시. (나) UE처럼 같은 이름이면 공유 | **결정됨(2026-11-18, 권장안 (가))** | 계획 결정을 따른다. UE 에셋을 들일 때 차이는 변환 도구가 다룬다 |
| MD6 | **사용 대상 결정 방식** | (가) 선언 + 쿠킹 유도(8.4절). (나) UE처럼 에디터가 자동으로 켜고 저장 | **결정됨(2026-11-18, 권장안 (가))** | 에셋을 동의 없이 바꾸지 않고, 참조로 알 수 있는 조합은 쿠커가 빠뜨리지 않는다 |
| MD7 | **품질 수준** | (가) Low·Medium·High·Epic 4단계(UE와 같음). (나) 프로젝트 정의 | **결정됨(2026-11-18, 권장안 (가))** | 프로필이 쿠킹 수준을 고른다 |
| MD8 | **이름** | 2절 대응표의 Rocks 이름, 에셋 모듈 이름 `Material`(계획 MaterialAssetBridge 대신). 영역·블렌드 모드·shading model 이름은 Renderer 14.2절 | **결정됨(2026-11-18, 권장안)** | — |
| MD9 | **상수 식 평가 위치** | (가) 렌더 lane(UE와 같음). (나) 게임 lane이 최종 바이트를 만들어 packet으로 넘김 | **결정됨(2026-11-18, 권장안 (가))** | 텍스처·스트리밍 상태와 같은 lane에서 해석하고, 게임 lane은 바뀐 값만 보낸다. 병렬화는 측정 MM2 뒤 |
| MD10 | **IR 번역기 전용 노드** | (가) UE 기본 번역기에 없는 `Operator`·`Blend`·`Aggregate`·`IfThenElse`를 제외. (나) Rocks 번역기가 IR이므로 넷 모두 받는다. `Aggregate`의 UserDefined 종류만 속성 TODO | **결정됨(2026-11-25, 권장안 (나))** | 넷은 UE IR 번역기의 노드다(`meta=(NewMaterialTranslator)`). `IfThenElse`는 값 입력의 지연 분기(`MaterialExpressionsToMIR.cpp:1189–1222`)라 `DynamicBranch`로 받는다. deprecated인 것은 머티리얼 속성 `bEnableExecWire`다(`Material.h:1068–1070`). `Operator`는 연산 집합이 넓어(6.2절) IR 연산 목록을 그만큼 늘린다. `Blend`는 MaterialAttributes까지 받으므로 MS2e다 |
| MD11 | **노드 범위** | (가) 1차 범위만(개정 9까지). (나) UE 5.8 클래스 전부에서 deprecated·exec 전용만 빼고, Experimental 표지 노드도 넣는다 | **결정됨(2026-11-25, 사용자 지시 "모든 MaterialExpression")** | 19장. Experimental은 레거시가 아니다. 레거시 제외 원칙은 deprecated에만 적용한다 |
| MD12 | **선행 없는 노드의 형태** | (가) 선행이 생길 때 노드를 만든다. (나) 정의·속성·lowering 자리를 지금 만들고, lowering이 선행 ID를 담은 `PrerequisiteMissing`을 낸다. 코드 표기는 `TODO(MPQ-<이름>)` 하나다 | **결정됨(2026-11-25, 사용자 지시 "TODO로 해놓는 식으로라도 뼈대")** | 19.2절. 대체 값(0·검은색)은 내지 않는다(계획 11.1절). 진단은 static 해석·DCE 뒤에 살아 있는 노드에만 내고, 조건 값 가지는 조합별로 낸다(19.2.1절). 속성 하나만 막히면 속성 TODO다. 표·등록·진단은 단일 원본과 policy 검사로 대조한다(19.2.2절) |
| MD13 | **렌더러 공급 값의 경계** | (가) 공급자가 없는 노드도 TODO로 둔다. (나) 머티리얼 쪽은 문맥 값을 읽는 원문까지 구현하고, 공급은 pass·정점 입력 타입이 선언한 문맥 공급 기능으로 판정한다 | **결정됨(2026-11-25, 권장안 (나))** | UE 외부 코드 선언의 `Domains`·`ShaderFrequency`·`USES_*`와 같은 구조다(19.3절). 사용 집합은 진입점·단계별 고정 정의로 내 셰이더 집합 id를 지킨다. 공급자가 생겨도 머티리얼 쪽은 바뀌지 않는다 |
| MD14 | **플러그인 노드 위치** | (가) Landscape·MaterialX 등도 머티리얼 모듈에 둔다. (나) UE처럼 그 모듈이 `RegisterMaterialNode`로 등록한다 | **결정됨(2026-11-25, 권장안 (나))** | 엔진 층에는 핵심만 둔다. 모듈이 없는 동안 그 노드는 모르는 노드로 보존된다(19.7절) |
| MD15 | **공급하지 않은 문맥 값** | (가) 엄격: 머티리얼이 쓰는 기능을 파이프라인이 공급하지 않으면 V6로 그 조합을 뺀다. (나) UE와 같게: 공급하지 않은 값은 UE 기본값(0, 파티클 색은 1)이고, 오류는 UE가 거부하는 조건(영역·블렌드 모드·단계·기능 등급·렌더 경로)뿐이다 | **결정됨(2026-11-25, (나) — 애매하면 UE 방식, 사용자 지시 2026-11-19)** | UE `MaterialTemplate.ush:665–670, 761`. (가)는 파티클 색을 쓴 메시 머티리얼이 메시 조합에서 빠져 UE와 다르게 그려진다. 계획 11.1절 "검은 표면 금지"는 셰이더·머티리얼을 잃을 때의 대체 규칙이라 기본값과는 다른 문제다. 기본값을 쓴 조합은 쿠킹 보고서에 정보로 남긴다 |
| MD16 | **형식에 따라 갈리는 스위치** | (가) 형식 등급마다 번역해 정적으로 푼다(UE와 같음). (나) `#if`로 내고 layout·V9가 형식별 살아 있는 자원 집합을 쓴다 | **결정됨(2026-11-25, 권장안 (가))** | UE는 플랫폼별 번역 때 푼다(19.3.4절 근거). (나)는 한 layout에 두 가지 자원이 모두 남아 `SamplerBudgetSwitch`가 예산을 줄이지 못한다. 결정 MD4 "생성 원문은 하나"의 좁은 예외다. 이 노드를 쓰지 않는 머티리얼은 번역이 하나다 |
