### 3.4 에디터 전용 데이터와 메타 컴파일

**선언 규칙(BD6)**: UHT처럼 어휘 규칙을 둔다.
- 리플렉션 선언(`ROCKS_CLASS`·`ROCKS_STRUCT`·`ROCKS_ENUM`·`ROCKS_ENUMERATOR`·`ROCKS_PROPERTY`·`ROCKS_FUNCTION` 등)은 원칙적으로 전처리 조건 블록 밖에만 쓴다. 예외는 둘이다.
  - `ROCKS_PROPERTY`는 `#if ROCKS_WITH_EDITOR_DATA` 블록 안에 쓸 수 있고, 이때 `EditorOnly`를 명시해야 한다.
  - `ROCKS_FUNCTION`은 `#if ROCKS_WITH_EDITOR` 블록 안에 쓸 수 있고, 이때 함수 지정자 `EditorOnly`를 명시해야 한다. UE도 `WITH_EDITOR` 안의 UFUNCTION을 허용하고 EditorOnly 플래그를 붙인다(`EpicGames.UHT/Parsers/UhtHeaderFileParser.cs:123`, `EpicGames.UHT/Parsers/UhtFunctionParser.cs:150`).
- 타입 선언(`ROCKS_CLASS`·`ROCKS_STRUCT`·`ROCKS_ENUM`)과 열거자는 어떤 조건 블록 안에도 둘 수 없다. 그래서 타입 집합은 모든 조합에서 같다.
- 다른 조건 블록(`ROCKS_WITH_SERVER_CODE`·`ROCKS_WITH_CLIENT_CODE`·플랫폼·구성·간접 매크로 등) 안의 리플렉션 선언은 메타 컴파일러 오류다. Client와 Server, 플랫폼 사이에 스키마가 갈라지지 않게 하기 위해서다.
- 양방향 일치: 블록 안의 필드·함수는 `EditorOnly`를 명시해야 하고, `EditorOnly` 필드·함수는 그 블록 안에 있어야 한다. UHT는 블록 밖 리플렉션 선언을 거부하고(`UhtHeaderFileParser.cs:731-736`), `WITH_EDITORONLY_DATA` 안의 필드에 EditorOnly를 자동으로 붙인다(`EpicGames.UHT/Parsers/UhtPropertyParser.cs:649-669`). Rocks는 자동으로 붙이지 않고 명시와 위치를 맞춘다.
- 이에 따라 "항상 컴파일되고 플래그만 다는" 지금의 `EditorOnly`([리플렉션 기반](../../ReflectionFoundations.ko.md) 134행)는 없어진다. 기존 fixture의 블록 밖 `EditorOnly` 필드(`ReflectionFixture.h`, `CombinationAssets.h` 등)는 구현 때 블록 안으로 옮긴다(하위 호환은 두지 않는다). 중첩 struct·배열 안 값에 대한 유효 플래그 전파([리플렉션 기반](../../ReflectionFoundations.ko.md) 6.1절)는 그대로다. 전파는 저장 정책이고, 이 규칙은 선언 위치 규칙이다.

**판정 수단**:
- 지금 메타 컴파일러는 Clang `-ast-dump=json`만 쓰고(`Programs/Rocks.MetaCompiler/CompilerDriver.cs:36-37`), 이 출력에는 조건 블록 정보가 없다. 그래서 UHT처럼 메타 컴파일러가 리플렉션 헤더를 **어휘 스캔**한다.
- 스캔은 `#if`·`#ifdef`·`#ifndef`·`#elif`·`#else`·`#endif` 중첩을 따라가며, 각 리플렉션 매크로를 감싼 조건 블록의 조건식 철자를 본다. 허용되는 조건은 정확히 `#if ROCKS_WITH_EDITOR_DATA`(필드)와 `#if ROCKS_WITH_EDITOR`(함수) 두 철자다. 그 밖의 조건식(간접 매크로 `#if X` 포함)과 `#else`·`#elif` 가지 안의 리플렉션 선언은 오류다.
- 리플렉션 선언은 빌드가 찾는 리플렉션 헤더(표지 헤더 — [리플렉션·빌드 보강](../../ReflectionFoundations.ko.md) 1.10절)에만 쓸 수 있으므로(정책 `reflection-annotation-unscanned` 등), include를 거쳐 다른 파일에 숨은 선언은 이미 거부된다.

**두 변형 비교(보강 검사)**: 메타 컴파일러는 모든 빌드에서 리플렉션 헤더의 AST를 에디터 조합(`ROCKS_WITH_EDITOR=1`, `ROCKS_WITH_EDITOR_DATA=1`)과 게임 조합(둘 다 0)으로 만든다. 두 결과의 차이는 정확히 `EditorOnly` 필드·함수여야 한다. 차이가 없어야 하는 것은 타입 집합, 기반 타입, 나머지 필드의 순서·형식·지정자, enum 값이다. 어휘 스캔을 빠져나가는 경우를 잡는 방어선이다. 서버·클라이언트·플랫폼 조건은 어휘 스캔이 막으므로 비교 축에 넣지 않는다.

**생성 코드**: 생성 헤더·등록 표·offset 표의 `EditorOnly` 필드·함수 항목은 같은 조건(`ROCKS_WITH_EDITOR_DATA`·`ROCKS_WITH_EDITOR`)으로 감싼다(UE `IF_WITH_EDITORONLY_DATA` — `EpicGames.UHT/Exporters/CodeGen/UhtUsedDefineScopes.cs:611-614`). [UI 툴킷](../../UiToolkit.ko.md) 7.3절의 편집 메타데이터 블록도 `ROCKS_WITH_EDITOR_DATA`로 생성한다.

**descriptor와 안정 ID**:
- 메타 컴파일러가 내는 descriptor(`.rocksmeta.json`)와 `.rocksids.json`은 두 변형의 합집합이다. `EditorOnly` 필드·함수도 담고 표시한다.
- `ids verify`는 합집합으로 검사하므로, 게임 조합에 없는 필드·함수를 "사라진 것"으로 보지 않는다. 설치 SDK도 합집합 descriptor를 싣는다.

**로드와 저장(BD26)**:
- `ROCKS_WITH_EDITOR_DATA=0` 빌드의 레지스트리는 타입마다 `EditorOnly` 필드의 FieldId 목록(ID만, 배치 정보 없음)을 가진다.
- 이 빌드가 에디터가 저장한 패키지를 읽으면, 목록에 있는 FieldId의 값은 건너뛴다. 목록에 없는 모르는 FieldId는 지금 규칙을 따른다. 쿠킹 데이터 로드(`excludedFlags`)는 지금과 같다.
- **`ROCKS_WITH_EDITOR_DATA=0` 빌드는 에디터 패키지(쿠킹하지 않은 패키지)를 저장하지 않는다.** 저장 API가 Unsupported로 거부한다. 건너뛴 `EditorOnly` 값을 잃기 때문이다. 에디터 패키지를 쓰는 에셋 도구는 `WithEditorData` Program이어야 한다.
- UE는 Game·Client·Server가 쿠킹 데이터만 읽는다(`bBuildRequiresCookedData`, `TargetRules.cs:1190-1195`). Rocks는 이 축을 채택하지 않는다(9.1절). Development Game이 에디터 패키지를 바로 읽는 개발 흐름을 유지하기 위해서다.

**시험**: `ROCKS_WITH_EDITOR_DATA=0` 조합(Game·기본 Program)과 1 조합(`WithEditorData` Program) 모두 시험 빌드를 둔다(BS2).

**BS2c 구현 세부(개정 32).** 둘로 나눈다. BS2c1은 메타 컴파일러와 fixture, BS2c2는 로드 건너뛰기와 저장 거부다.
- **매크로 조합은 메타 컴파일러가 정한다.**
  - MetadataRunner와 `test`의 meta 검사는 타깃 매크로를 넘기지 않는다(BS2a에서 넘기던 것을 거둔다).
  - 메타 컴파일러는 `--clang-arg`에 `ROCKS_WITH_` 정의(`-D`·`/D`·`-U`)가 있으면 RMC1000으로 거부한다.
  - 주 AST·탐침·생성 코드 검증 컴파일은 에디터 조합(`ROCKS_WITH_EDITOR=1`·`ROCKS_WITH_EDITOR_DATA=1`·서버·클라이언트 1)으로 돈다.
  - 그래서 descriptor·`.rocksids.json`·생성물은 타깃과 무관한 합집합 하나다(같은 모듈을 여러 타깃이 빌드해도 메타데이터가 같다).
- **어휘 스캔(RMC2501)**: 입력 리플렉션 헤더를 주석·문자열을 지우고(줄 번호 유지) 논리 줄(`\` 이음)로 읽는다.
  - `#if`·`#ifdef`·`#ifndef`·`#elif`·`#elifdef`·`#elifndef`·`#else`·`#endif`의 중첩을 따른다.
  - 리플렉션 매크로(`ROCKS_CLASS`·`ROCKS_STRUCT`·`ROCKS_ENUM`·`ROCKS_ENUMERATOR`·`ROCKS_PROPERTY`·`ROCKS_FUNCTION`·`ROCKS_NATIVE`·`ROCKS_GENERATED_BODY`) 철자가 조건 블록 안에 있으면 오류다.
  - 예외는 깊이 1인 블록 둘뿐이다: `#if ROCKS_WITH_EDITOR_DATA`(공백 정규화 뒤 정확한 철자)의 첫 가지 안 `ROCKS_PROPERTY`, `#if ROCKS_WITH_EDITOR`의 첫 가지 안 `ROCKS_FUNCTION`.
  - include guard(`#ifndef`)도 블록이다. 리플렉션 헤더는 `#pragma once`를 쓴다(지금 저장소와 같다).
- **양방향 일치(RMC2502)**: 이 모듈이 선언한 타입의 자기 필드마다, 필드 위치(AST의 필드 줄)가 `ROCKS_WITH_EDITOR_DATA` 블록 안인지와 `EditorOnly` 지정 여부가 같아야 한다. 함수 리플렉션(`ROCKS_FUNCTION`)은 아직 없으므로 함수 쪽은 그때 같은 규칙을 단다.
- **두 변형 비교(RMC2503)**: 게임 조합(에디터 두 매크로 0)으로 Clang AST를 한 번 더 만들어 같은 파서로 읽는다. 그리고 에디터 조합 결과와 다음이 같은지 본다.
  - 타입 집합, 종류(class·struct·enum), base
  - `EditorOnly`를 뺀 자기 필드의 이름·순서·형식 철자
  - enum의 열거자 이름·값
  - 비용은 모듈마다 Clang 한 번이다(정규 형식 탐침 등은 에디터 조합 한 번만).
- **조건부 생성**: `EditorOnly` 필드(상속·import 필드 포함 — 필드 플래그로 판정)를 다루는 생성 줄은 모두 `#if ROCKS_WITH_EDITOR_DATA` … `#endif`로 감싼다.
  - 대상: 필드 스키마 표, RuntimeFieldOps·struct 필드 ops, Trace·ReferenceLayout·VisitFields 문장, bitfield 접근자, 원소 struct 검사, ValueCopy·ValidateTree, Settings 표.
  - 표 길이는 `ROCKS_WITH_EDITOR_DATA ? 전체 : 게임` 식이다. 게임 조합에서 항목이 하나도 없으면 표 선언 전체를 감싸고 빈 Span을 쓴다.
  - 문장이 모두 빠질 수 있는 함수는 매개변수를 `(void)`로 쓴다(경고 없음).
  - 메타 컴파일러의 생성 코드 검증은 에디터 조합으로 한다. 게임 조합은 아래 시험 타깃의 native 빌드가 컴파일한다.
- **EditorOnly FieldId 목록(BD26의 앞 반)**: `TypeSchema`·struct 스키마의 새 칸 `editorOnlyFieldIds`(Span<const FieldId>)에 그 타입의 `EditorOnly` 필드 ID를 조합과 무관하게 싣는다. 두 조합 모두 같은 값이고, 에디터 조합에서는 그 필드가 `fields`에도 있다. 레지스트리는 등록 때 0·중복 ID와, `fields`에 있는데 EditorOnly가 아닌 ID를 거부한다. `fields`의 EditorOnly 필드가 목록에 없는 것은 받는다(수동 등록 — 아는 필드라 로드가 건너뛸 대상이 아니다). 리플렉션 조상의 필드를 빌리는 native 클래스(`RegisterNativeClass`)는 조상의 목록을 물려받는다.
- **fixture와 런타임 코드**: 블록 밖 `EditorOnly` 필드를 모두 `#if ROCKS_WITH_EDITOR_DATA` 블록으로 옮긴다(리플렉션·에셋 fixture, Animation). 그 필드를 읽는 코드·시험은 같은 조건으로 감싼다.
- **시험 타깃 조합**:
  - 에디터 데이터 1: `Foundation`·`EngineTests`·`EngineModular`·`Commandlet`(에셋 도구 — 에디터 패키지를 읽고 쓴다)과 그 동반 `ShaderCompileWorker`가 `WithEditorData`다(동반 타깃은 주 타깃과 매크로 조합이 같아야 한다 — 3.1절).
  - 에디터 데이터 0: `FoundationModular`(Foundation 시험 전부 — 리플렉션·직렬화의 0 조합 실행)·`Core`·`ReflectionFixtures`·`Sandbox`·`Engine`(SDK).
  - 엔진 시험은 에셋 도구 시험이 EditorOnly 필드를 많이 쓰므로 1 조합만 실행한다. 엔진 층의 0 조합은 `Engine`·`Sandbox` 컴파일이, 0 조합의 실행 동작(로드 건너뛰기)은 Core 층(ObjectSerialization)이라 `FoundationModular`가 본다.
  - 0 조합 시험 빌드에서 EditorOnly 필드를 쓰는 시험 줄은 `#if ROCKS_WITH_EDITOR_DATA`로 감싼다.
- **BS2c2 로드와 저장**:
  - 그래프 로드와 struct Record 디코드는 스키마에 없는 FieldId가 그 타입의 `editorOnlyFieldIds`에 있으면 진단 없이 건너뛴다(모르는 필드 정책 Reject여도). 쿠킹 로드(`excludedFlags`)는 그대로다.
  - 에디터 패키지 저장(AssetDatabase의 저장 진입점)은 `ROCKS_WITH_EDITOR_DATA=0`이면 Unsupported다.

**BS2c 시험**:
- 어휘 스캔 양성·음성: 허용 철자 두 개, `#ifdef`·`#if defined(...)`·간접 매크로·`#else`·`#elif` 가지·중첩, 타입·열거자·GENERATED_BODY·NATIVE의 블록 안 선언, 주석·문자열 안 철자와 줄 이음.
- 양방향 일치 둘.
- 두 변형 비교(간접 매크로로 스캔을 빠져나간 필드·base 변화).
- 예약 `--clang-arg`.
- 생성물이 조합과 무관함(같은 입력, 두 타깃 빌드의 descriptor·ids 같음).
- 게임 조합 native 빌드에서 표 길이·`editorOnlyFieldIds`.
- 로드 건너뛰기(Reject 정책 포함)와 저장 Unsupported.
