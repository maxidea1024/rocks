### 3.10 쿠커와 대상 타깃의 모듈 집합

쿠커(`Programs/Commandlet`의 `asset-cook`)는 셰이더 타입을 쿠킹한다. 쿠킹하려면 그 타입을 정의한 모듈이 쿠커 프로세스 안에서 등록되어 있어야 한다([셰이더 시스템](../../ShaderSystem/12-FormatDefinitionsCooking.ko.md) SSD3 — 셰이더 타입은 모듈 수명 객체의 `Startup`에서 등록부에 들어간다). 그래서 쿠커가 적재한 모듈 집합은 쿠킹 대상 출시 타깃이 실행할 때 쓰는 모듈 집합과 같아야 한다(BD43). 다르면 런타임이 셰이더 집합을 열 때 `IncompatibleCook`이다. 라이브러리 머리에 셰이더 타입 해시 목록의 SHA-256을 두고 런타임 등록부의 값과 대조한다(SSD3).

UE는 쿠커가 에디터 실행 파일 안(`UnrealEditor-Cmd -run=cook`)에서 돌고, 에디터가 프로젝트와 켠 플러그인의 모든 모듈을 적재하므로 이 문제가 따로 드러나지 않는다. Rocks의 쿠커는 별도 Program이라 모듈 집합을 빌드 규칙으로 맞춰야 한다.

**대상 모듈 집합(정의)**: 쿠킹 프로필이 가리키는 출시 타깃(Game·Client — 기본 Game. Server는 셰이더를 쿠킹하지 않는다, 3.7절)의 Release 구성 해석 결과다.
- 엔진 모듈: 그 타깃의 링크 폐포에 든 엔진 Runtime·ClientOnly 모듈(3.3절 `ModuleTypeRules.Allows(Game 또는 Client, Release)` — Developer·Editor 모듈은 들어가지 않는다).
- 플러그인 모듈: 그 타깃 문맥(타깃 종류·쿠킹 플랫폼·Release)으로 켠 플러그인의 모듈(3.6절 조건 해석).
- 프로젝트 모듈: 게임 프로젝트의 모듈(기술자 type으로 거른 것).

**빌드 규칙**:
1. **엔진 모듈(지금 정할 수 있는 몫)**: Commandlet 타깃은 엔진 저장소의 출시 타깃(Game·Client — 지금은 Sandbox) 링크 폐포 가운데 엔진 Runtime·ClientOnly 모듈을 모두 링크한다. 정책 검사 `cooker-module-set`(Release 배제와 같은 규칙 평가)이 `폐포(Commandlet) ⊇ 폐포(출시 타깃)의 Runtime·ClientOnly 엔진 모듈`을 확인한다. 빠지면 그 모듈의 셰이더 타입이 엔진 라이브러리에서 빠진다. Engine 타깃(SDK)은 기준이 아니다: 코어 묶음(ObjectSerialization·Localization·CoreTypeBindings·Launch)이라 셰이더 타입을 정의하는 렌더러·그래픽 backend 모듈을 담지 않는다(개정 35 — 개정 34의 "Engine 타깃 폐포"는 늘 참이라 고쳤다). 이 규칙은 Commandlet이 그래픽 backend 모듈까지 링크하게 하므로 SH2d에서 넣는다.
2. **프로젝트·플러그인 모듈(ML5b 뒤)**: 게임 프로젝트의 쿠킹은 쿠커가 대상 모듈 집합의 프로젝트·플러그인 모듈을 모듈 로더로 적재한다(쿠커를 프로젝트마다 다시 링크하지 않는다 — UE 에디터가 프로젝트 모듈을 적재하는 것과 같은 자리). 그래서 [모듈 로더](../../ModuleLoader/README.ko.md) ML5b(프로젝트·플러그인 모듈 적재)가 선행이다. 대상 모듈 집합 계산은 게임 빌드 계획(`GamePlanning.Layout`)과 같은 함수를 쓴다(쿠킹 플랫폼·Release로). 그 전에는 쿠커가 `Engine` 라이브러리(엔진 모듈의 셰이더 타입)만 쿠킹하고, 프로젝트·플러그인 셰이더 타입이 있으면 쿠킹 오류다(조용히 빼지 않는다).
3. **대조**: 쿠커는 적재한 모듈 집합과 대상 모듈 집합을 이름으로 대조하고, 다르면 쿠킹을 시작하지 않는다(빠진 모듈·남는 모듈 이름). 런타임 대조(SSD3의 해시)는 쿠킹 뒤 바뀐 빌드를 잡는 마지막 방어선이다.

4. **구현(BS10 1항, 개정 37 — 셰이더 시스템 SH2d와 함께)**:
   - **링크**: Commandlet 모듈 규칙(`Programs/Commandlet/Commandlet.Build.cs`)이 엔진 저장소 출시 타깃(지금 Sandbox)의 Release 폐포에 든 엔진 모듈을 직접 의존으로 적는다(Engine·Gameplay·Collision·PlatformWindow·RenderBase·RenderGraph·EngineAssets·D3D12Graphics·D3D11Graphics·VulkanGraphics·OpenGLGraphics 등). OpenGLGraphics는 모든 플랫폼에서 링크한다 — Windows 출시 타깃에는 없지만(셰이더 시스템 9절) 규칙이 ⊇라 남는 것은 허용이고, Android·macOS 출시 타깃에는 있다.
   - **정책 `cooker-module-set`**(`Rocks.Tooling.Checks/CookerModuleSet.cs`, `policy`에 포함): Commandlet이 빌드되는 호스트(Windows x64·macOS arm64)마다 저장소 규칙을 Release로 평가한다. 출시 타깃(Game·Client — 3.3절 `Evaluates`와 같은 대상, Server 제외)마다 링크 폐포(켠 플러그인 모듈 포함, Release 배제 검사와 같은 `LinkClosure.Reachable`)에서 종류가 Runtime·ClientOnly이고 실행 파일이 아니며 엔진 저장소 모듈(`Core/Source`·`Engine/Source` — 플러그인 모듈은 2항 몫)인 모듈을 고른다. 그 가운데 Commandlet 타깃 폐포에 없는 모듈마다 실패 `cooker-module-set: target <출시 타깃> (<플랫폼> Release) module <모듈> is not linked into the Commandlet`이다. 음성 대조는 순수 함수 `Analyze`로 시험한다(Rocks.ToolTests).
   - **시작 순서**: Commandlet 호스트가 `asset-cook`을 감싸 ShaderCompiler 모듈을 `Load`한 뒤 명령을 부른다(모듈 시작 hook이 셰이더 라이브러리 단계를 등록 — 셰이더 시스템 SSD44). 단계의 제품 등록부 원천(`ModuleShaderCookRegistrySource`)이 쿠킹할 때 셰이더 타입 등록부를 호스트 서비스로 올리고 엔진 묶음을 출시 타깃 실행과 같은 단계까지 시작한다(`StartEngineGroup` → `StartPhase(PostEngineInit)` — UE의 엔진 초기화가 모든 모듈을 적재한 뒤 전역 셰이더 맵을 만드는 자리, 렌더 기반 9.12절 1항의 Freeze 자리). 모듈 `Startup`이 셰이더 타입을 등록하면 Freeze해 쿠킹하고, 끝나면 엔진 묶음을 내리고 서비스를 뗀다. 호스트 묶음(PostConfigInit) 모듈은 `StartPhase`가 앞 단계부터 돌므로 함께 시작한다(Commandlet 프로세스가 끝날 때 내린다). 호스트에 이미 등록부 서비스가 있으면 그것을 쓴다(Freeze되어 있지 않으면 `NotReady`).
   - **한계**: 3항 이름 대조 전에는 Commandlet에만 있는 셰이더 타입 모듈(Commandlet 폐포 ∖ 출시 폐포)이 생기면 타입 집합이 달라 런타임이 `TypeSetMismatch`로 잡는다(마지막 방어선). 지금 셰이더 타입을 정의하는 모듈은 RenderBase 하나다.
   - **버린 대안**: 쿠커가 셰이더 타입 모듈 이름을 적어 두고 `Load` — 새 모듈마다 쿠커를 고쳐야 하고 출시 타깃과 집합이 갈린다. 쿠커를 시작할 때 늘 엔진 묶음을 시작 — 셰이더와 무관한 명령(`log`·`trace-report`)까지 엔진 모듈 시작 비용을 낸다.

**버린 안**:
- 쿠커를 대상 타깃마다 따로 링크(Program 타깃을 Game 타깃마다 생성): 타깃 수만큼 쿠커가 생기고, 게임 프로젝트마다 쿠커를 빌드해야 한다.
- 셰이더 타입 목록을 별도 manifest로 빌드가 내보내고 쿠커가 모듈 없이 쿠킹: 셰이더 타입의 거르기 함수·퍼뮤테이션 도메인(SSD2·SSD4)이 코드라 모듈 없이는 평가할 수 없다.

**단계**: BS10(셰이더 시스템 SH2d와 함께 — 렌더 세션이 SH2d를 시작할 때). 1은 4항으로 구현했고(개정 37), 2·3은 ML5b 뒤다.
