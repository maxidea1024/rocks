### 3.45 AU7f — 믹서 버스 graph·send·plan 교체(개정 48)

AU7f는 UE submix(`USoundSubmix`·`FMixerSubmix`)와 source의 submix send를 `MixBus`로 들인다. 범위가 믹서 코어와 엔진 라우팅 둘로 나뉘므로 두 단계로 한다.

| 단계 | 내용 | 선행 |
|---|---|---|
| AU7f1 | 믹서: 버스 슬롯·버스 파라미터, plan 게시·교체·ACK, voice 라우팅(pre/post 감쇠 send, send별 LPF·HPF, send level ramp), 블록 처리 순서(버스 → 마스터) | AU7e2 |
| AU7f2 | 엔진: `MixBus` 에셋, 사운드·분류·감쇠의 버스 필드, 기본 버스 결정, send 합치기, 거리 기반 send level, 제어 쪽 버스 표·수명, 엔진·컴포넌트 API | AU7f1 |

효과 체인(`AudioEffect`)·wet level의 실제 적용·자동 비활성(꼬리)·효과 상태 넘기기·체인 교차 페이드는 AU7g다(3.45.10절). 리버브 send와 `ReverbReturn`은 AU7h다.

약칭: SM = `Engine/Classes/Sound/SoundSubmix.h`·`Engine/Private/SoundSubmix.cpp`, SSS = `Sound/SoundSubmixSend.h`·`SoundSubmixSend.cpp`, SB = `Sound/SoundBase.h`·`SoundBase.cpp`, SW = `Engine/Private/SoundWave.cpp`, AS = `Engine/Private/ActiveSound.cpp`, AC = `Components/AudioComponent.cpp`, MSub = `AudioMixer/Private/AudioMixerSubmix.cpp`, MS = `AudioMixer/Private/AudioMixerSource.cpp`, MSM = `AudioMixer/Private/AudioMixerSourceManager.cpp`, MSO = `AudioMixer/Private/AudioMixerSourceOutputBuffer.cpp`.

#### 3.45.1 UE 동작(근거)

- **submix 계층**: `USoundSubmixWithParentBase::ParentSubmix`(SM 285)로 부모를 가리키고, 부모가 없는 submix는 장치의 Main submix에 붙는다. 장치 필수 submix는 Main·BaseDefault·Reverb·EQ다(`ERequiredSubmixes`). BaseDefault가 없으면 Main이다.
- **submix 값**(SM 365–374, 기본값 SM.cpp 35–37):
  - `OutputVolumeModulation` 0 dB, `WetLevelModulation` 0 dB, `DryLevelModulation` −96 dB. 셋 다 [−96, 0] dB다.
  - `bMuteWhenBackgrounded`(SM 347), `bAutoDisable` true·`AutoDisableTime` 0.01 s(SM 184–189)
  - 실행 중 배수 `SetSubmixOutputVolume`·`SetSubmixWetLevel`·`SetSubmixDryLevel`(SM 463–471)은 선형 배수로 dB 값에 곱한다.
- **submix 처리 순서**(MSub 1333–1830 `ProcessAudio`):
  1. 입력 버퍼를 0으로 비운다.
  2. 자식 submix를 처리해 입력에 더한다.
  3. 이 submix로 오는 source를 send level로 더한다.
  4. dry가 의미 있으면(목표와 현재가 다르거나 현재가 거의 0이 아님) 입력을 dry 버퍼로 복사한다.
  5. 효과 체인이 있으면 효과를 거치고, 그 출력에 wet level을 건다. 체인이 없으면 wet level을 걸지 않는다.
  6. dry 버퍼 × dry level을 더한다.
  7. background mute면 0으로 채운다.
  8. output volume을 건다.
  9. 부모 버퍼에 더한다.
  - 레벨 변화는 한 블록에 걸쳐 선형으로 바꾼다(`ArrayFade`). 같은 값이면 상수를 곱한다.
- **source의 기본 submix**(SW 3796–3844):
  - 분류의 `DefaultSubmix`(SoundClass.h 146)가 있으면 그것을 쓴다. 이 값은 부모 분류로 내려가지 않는다(`RecurseIntoSoundClasses`는 volume·pitch·UI·music만 전한다 — AudioDevice.cpp 2512–2518).
  - 사운드의 `SoundSubmixObject`가 있으면 그것이 이긴다.
  - 둘 다 없으면 BaseDefault다(MS 503–511).
  - 기본 send의 level은 `bEnableBaseSubmix`(기본 true — SB.cpp 25)의 0·1이고 단계는 post다(MS 514–520).
- **submix send**(`FSoundSubmixSendInfo` — SSS 81–195, 기본값 SSS.cpp 6–19):
  - 대상 `SoundSubmix`
  - level 방법 `SendLevelControlMethod`: Manual(상수, 기본)·Linear·CustomCurve
  - `SendLevel` 1과 `DisableManualSendClamp` false
  - `MinSendLevel` 0, `MaxSendLevel` 1, `MinSendDistance` 100, `MaxSendDistance` 1000
  - `CustomSendLevelCurve`
  - `bEnableLPFCutoff`·`LPFCutoff` 20000, `bEnableHPFCutoff`·`HPFCutoff` 20, 범위 [20, 20000]
  - `SendStage`: PostDistanceAttenuation(기본)·PreDistanceAttenuation
- **send level 계산**(MS 1554–1597):
  - Manual은 `DisableManualSendClamp`가 아니면 [0, 1]로 자른다.
  - 거리 방법은 `α = clamp((d − MinSendDistance) / max(MaxSendDistance − MinSendDistance, 1), 0, 1)`다. `d`는 리스너까지의 거리(`ListenerToSoundDistance`)다.
  - Linear는 `clamp(lerp(MinSendLevel, MaxSendLevel, α), 0, 1)`, CustomCurve는 `clamp(curve(α), 0, 1)`다.
- **send 출처와 합치기**:
  - 사운드의 `SoundSubmixSends`는 `bEnableSubmixSends`(기본 true)로 켠다(MS 1691–1697).
  - 감쇠 설정의 `SubmixSendSettings`는 `bEnableSubmixSends`(기본 false)로 켜고 단계는 늘 post다(AS 2064–2074, MS 1684–1689).
  - 컴포넌트 `SetSubmixSend(submix, level)`(AC 1577–1598)는 Manual send다. 사운드 send에 같은 submix가 있으면 level만 바꾸고, 없으면 덧붙인다(AS 570–584·723–747). 재생 전이면 다음 재생에 쓴다.
  - 음성 쪽 `SetSubmixSendInfo`는 submix마다 칸 하나다. 기본 send → 리버브 → 감쇠 send → 사운드 send 순서로 쓰므로, 같은 submix가 겹치면 나중 값이 level·단계를 덮는다(MS 1606–1697).
- **pre/post 신호 경로**(MSM 3370–3660):
  - pre 버퍼 = 원본 × volume(정지 fade 포함) → source 효과다. LPF·HPF 전이다.
  - post 버퍼 = pre에 LPF·HPF를 거친 뒤 거리 감쇠(`GetDistanceAndOcclusionAttenuation` = 거리 감쇠 × 차폐 볼륨 — MS 1509, Audio.cpp 1262)를 건 것이다.
  - 두 버퍼는 같은 채널 맵으로 pan한다(MSO 283–298).
  - send마다 필터가 켜져 있으면 pan한 출력에 send 필터를 건 뒤 level을 곱해 더한다(MSM 3765–3798).

#### 3.45.2 기본 graph(3.14.1절 고침)

- 엔진이 두는 버스는 **Master** 하나다(UE Main).
  - `ReverbReturn`(UE Reverb 필수 submix)은 AU7h에서 엔진이 더한다.
  - UE의 EQ 필수 submix는 레거시라 들이지 않는다(3.43절).
- 프로젝트가 정할 수 있는 것:
  - `AudioEngineSubsystem::SetMasterBus(MixBusRef)`: Master의 값(볼륨·dry·wet, AU7g부터 효과)을 정한다. UE `UAudioSettings::MasterSubmix`에 대응한다.
  - `SetBaseDefaultBus(MixBusRef)`: 버스를 지정하지 않은 재생의 기본 버스다. UE `BaseDefaultSubmix`에 대응한다.
- 부모가 없는 `MixBus`는 Master에 붙는다. 3.14.1절 그림의 Music·Sfx·Dialogue·Ui는 프로젝트 graph의 예다. Sandbox TestContent가 이 예를 만든다.

#### 3.45.3 AU7f1 — 믹서 버스 슬롯과 파라미터

**설정**(`AudioMixerConfig`)
- `maxBuses`: 기본 `DefaultMaxBuses` 64, 범위 [1, `MaxMixerBuses` 256]. Master 칸을 포함한다.
- 슬롯마다 입력 버퍼(Q × 출력 채널)와 dry 사본 버퍼를 `TryCreate`에서 미리 잡는다. 블록 처리 중 할당은 0이다.

**handle**
- `AudioBusHandle {index, generation}`이고 generation 0은 무효다.
- `AudioMixer::MasterBus()`는 칸 0이다. 늘 plan에 있고 놓을 수 없다.

**제어 쪽 API**
- `AcquireBus()`: 빈 칸을 Acquired로 잡는다. 칸이 없으면 CapacityExceeded다. Acquired 칸은 plan에 넣기 전까지 RT가 보지 않는다.
- `PublishBusParams(bus, AudioBusParams)`: 버스 seqlock에 쓴다.
  - 값은 `outputGain`(1)·`wetGain`(1)·`dryGain`(0)이고 선형이다. 범위는 [0, `MaxBusGain` 4]다.
  - 범위 밖은 InvalidArgument, 낡은 handle은 StaleHandle이다.
  - 다음 블록 시작에 읽고, 한 블록(Q frame)에 걸쳐 선형 ramp한다(UE `ArrayFade`). 칸이 새 generation으로 plan에 처음 들어올 때는 ramp 없이 바로 쓴다.
- `PublishBusPlan(links)` — 3.45.4절.
- `ReleaseBus(bus)`: 칸을 비우고 generation을 올린다. 가장 최근에 게시한 plan에 없고, RT가 그 칸이 빠진 plan을 채택했다고 ACK했을 때만 된다. 아니면 Busy다.
- background mute는 믹서 필드가 아니다. 제어 쪽이 `outputGain`에 0을 곱해 낸다. UE는 블록 단위로 바로 0을 채우지만 Rocks는 한 블록 ramp로 줄인다(클릭 방지 — 07장).

**버스 처리**(블록마다, plan 순서 — 자식이 부모보다 먼저)
- `x`는 입력 버퍼(이 블록에 더해진 voice send + 자식 출력)다.
- dry 경로는 `dryGain`의 현재값과 목표값이 모두 `NegligibleBusGain`(1e−4, UE `KINDA_SMALL_NUMBER`) 미만이면 건너뛴다. 아니면 `x`를 dry 사본에 복사한다. 기본 −96 dB(1.58e−5)는 건너뛰는 쪽이다(UE와 같다).
- wet 경로는 AU7f1에서 `x` 그대로다. 효과 체인이 생기는 AU7g에서 효과 출력에 `wetGain`을 건다. 체인이 비면 `wetGain`을 걸지 않는다(UE).
- `y = outputGain × (wet + dryGain × dry 사본)`. 세 gain은 각자 ramp다.
- Master가 아니면 `y`를 부모 입력에 더한다. Master의 `y`는 마스터 단계(3.45.6절)로 간다.
- 입력이 이 블록에 한 번도 더해지지 않은 버스(`touched` 거짓)는 처리를 건너뛴다. 출력이 0이고 ramp만 한 블록 진행한다. 자동 비활성(꼬리)은 AU7g다.

#### 3.45.4 plan 게시·교체·ACK

- **내용**: plan은 구조만 담는다.
  - 일련번호
  - 처리 순서(칸 번호 배열 — 자식 먼저, Master 마지막)
  - 칸마다 부모 칸과 generation
  - AU7g부터 효과 체인 묶음
  - 레벨은 버스 seqlock으로 따로 낸다(plan 재작성 없이 바뀐다).
- **`PublishBusPlan(Span<const AudioBusLink> links)`**:
  - `AudioBusLink {bus, parent}`다. parent는 Master거나 links 안의 다른 버스다. Master는 넣지 않는다.
  - 오류: 버스 중복·없는 부모·순환은 InvalidArgument, 낡은 handle은 StaleHandle, Acquired가 아닌 칸은 InvalidArgument다.
  - 아직 채택되지 않은 plan이 `MaxPendingPlans`(2, 3.5절) 개면 Busy다. 제어 쪽은 다음 묶음에 다시 낸다.
  - 성공하면 미리 잡은 plan 버퍼(`MaxPendingPlans` + 1 = 3개, 각 `maxBuses` 칸)에 위상 정렬로 쓰고, 원자 포인터로 게시한다(release).
- **채택**:
  - RT는 블록 시작에서 stop-all → mailbox → seqlock(voice 파라미터·라우팅·버스) 다음, 명령 앞에서 plan 포인터를 읽는다(acquire).
  - 그래서 RT가 본 라우팅이 새 버스를 가리키면 그 버스를 넣은 plan도 보인다. 제어 쪽은 plan을 게시한 뒤에 그 버스를 쓰는 라우팅·Play를 낸다.
  - 새 plan을 채택하면 일련번호를 ACK로 게시한다.
  - generation이 바뀐 칸은 RT 상태(ramp·`touched`, AU7g 효과 상태)를 초기화한다.
  - plan에서 빠진 칸은 그 블록부터 처리하지 않는다.
- **해제**: plan 버퍼는 채택 ACK가 그보다 새 일련번호에 닿으면 다시 쓴다. RT는 블록 동안 채택한 plan 하나만 읽는다.
- **낡은 라우팅**:
  - 라우팅 칸의 버스 generation이 채택된 plan의 칸 generation과 다르면 RT는 그 send를 건너뛰고 `staleBusSends`를 센다.
  - 정상 흐름에서는 0이다. 제어 쪽은 버스를 그 버스를 라우팅하는 voice가 모두 놓인 뒤에야 plan에서 뺀다.

#### 3.45.5 voice 라우팅과 신호 경로

**라우팅 값**
- `AudioVoiceRoute {sendCount, sends[MaxVoiceSends]}`이고 `MaxVoiceSends`는 8이다. 기본 버스 send도 여기 들어간다.
- `AudioVoiceSend`의 필드:
  - `bus` (`AudioBusHandle`)
  - `level` [0, `MaxVoiceGain`]
  - `stage` `AudioSendStage {PostAttenuation, PreAttenuation}`
  - `lowPassEnabled`·`lowPassCutoffHz`, `highPassEnabled`·`highPassCutoffHz`: 켜졌을 때 범위는 [`MinSendFilterHz` 20, `MaxSendFilterHz` 20000]이다.
- 같은 버스가 둘 이상이면 InvalidArgument다. 합치기는 제어 쪽 일이다(3.45.7절).

**게시**
- voice마다 라우팅 seqlock을 따로 둔다. 파라미터 seqlock은 블록마다 바뀌지만 라우팅은 드물게 바뀐다.
- `PreparePlay(..., params, route)`가 Play와 함께 첫 라우팅을 쓴다. 시작 때는 ramp 없이 적용한다.
- `PublishRoute(voice, route)`는 바뀐 라우팅을 쓴다. 다음 블록 시작에 읽는다.
  - 같은 버스 칸의 level·필터 변화는 `DefaultParamRampFrames`로 ramp한다.
  - 새로 생긴 send는 level 0에서 ramp한다.
  - 빠진 send는 0으로 ramp한 뒤 칸을 비운다. 그 사이 칸은 `MaxVoiceSends`를 넘지 않게 따로 센다(빠지는 중 칸 포함 상한 `MaxVoiceSendSlots` 16).
- 낡은 generation·범위 밖 값은 `MakeSetParams`와 같은 규칙으로 거부한다.

**파라미터**
- `AudioVoiceParams`에 `attenuationGain`([0, 1], 기본 1)을 더한다. 거리 감쇠 × 차폐 볼륨이다(UE `GetDistanceAndOcclusionAttenuation`).
- `gain`은 나머지(사용자·사운드·분류·focus·resume·동시 발음·steal 등)다. seqlock 내용 word가 하나 는다.

**구간 렌더**(UE 순서, chunk마다)
1. 리샘플한다.
2. `gain` ramp, 정지 fade, pause gain을 건다. 이것이 **pre** 신호다.
3. pre send가 하나라도 있으면 pre 신호를 scratch에 복사한다.
4. LPF·HPF를 건다(공기 흡수·차폐·분류·재생 값).
5. `attenuationGain` ramp를 건다. 이것이 **post** 신호다.
6. post를 채널 이득 ramp로 pan해 출력 채널 scratch에 둔다. pre가 있으면 같은 시작 ramp 상태의 사본으로 pan한다(두 단계가 같은 채널 맵 구간을 쓴다 — UE `CopyDestinationToStart`).
7. send마다 단계의 pan 출력을 고른다. 필터가 켜져 있으면 send 필터 상태(출력 채널 수만큼)를 거친 사본을 쓴다. 그것에 level ramp를 곱해 대상 버스 입력의 같은 offset에 더한다.

- level이 0이고 ramp가 끝난 send는 건너뛴다. 필터 상태는 그 동안 멈춘다(다시 켜지면 이어 간다).
- 바뀌는 점(07장): 지금은 이득 하나를 필터 뒤에 건다. AU7f1부터는 UE처럼 `gain`을 필터 앞, `attenuationGain`을 필터 뒤에 건다. 선형이라 값은 반올림 차이만 난다. 다만 두 ramp가 겹치는 동안의 곡선은 곱의 ramp와 다르다. 기존 시험 기대값은 이 순서로 다시 맞춘다.

#### 3.45.6 블록 처리 순서(3.6절 고침)

1. 블록 시작:
   1. plan의 버스 입력 버퍼를 비우고 `touched`를 내린다.
   2. stop-all → mailbox → seqlock(파라미터·라우팅·버스)을 처리한다.
   3. plan을 채택한다.
   4. 명령을 구간별로 적용한다.
2. 구간마다 voice를 렌더한다(3.45.5절). 마스터 gain은 구간마다 1로 채운 `masterGainCurve_` 구간에 곱해 둔다. 블록 중간 `SetMasterGain`의 frame 정확성을 지금처럼 지킨다.
3. 블록 끝에서 plan 순서대로 버스를 처리한다(3.45.3절). Master의 출력이 `master_`가 된다.
4. `master_ × masterGainCurve_` → 비유한 값 0 바꿈·계수 → limiter → 자르기 → 출력 형식(3.22절과 같다).
5. mix clock, 채택 plan ACK, 계수를 게시한다.

- 계수에 `staleBusSends`(누적)와 `activeBuses`(현재 plan 칸 수, gauge)를 더한다.
- 장면 일시정지는 버스를 멈추지 않는다(UE submix는 pause가 없다). voice 쪽 pause gain이 send 전에 걸린다.

#### 3.45.7 AU7f2 — 에셋과 라우팅 결정

**`MixBus`**(UE `USoundSubmix`, AudioAssets)

| 필드(UE) | 기본 | 비고 |
|---|---|---|
| `parent` `ObjectRef<MixBus>`(`ParentSubmix`) | null | null이면 Master. 순환·깊이 `MaxMixBusDepth` 16 초과는 `MakeRef`가 InvalidArgument·CapacityExceeded로 막는다. |
| `outputVolumeDb`(`OutputVolumeModulation`) | 0 | [−96, 0] |
| `wetLevelDb`(`WetLevelModulation`) | 0 | [−96, 0], AU7g부터 효과 출력에 건다 |
| `dryLevelDb`(`DryLevelModulation`) | −96 | [−96, 0] |
| `muteWhenBackgrounded`(`bMuteWhenBackgrounded`) | false | 3.45.8절 |

- 선형 값은 `10^(dB/20)`이다(UE `ConvertToLinear`).
- `MixBus::MakeRef(allocator, registry, access)` → `MixBusRef`(`SharedPtr<const MixBusChain>`). 자기부터 루트까지의 {키 `AudioObjectKey`, 선형 값 셋, mute 표지}를 담는 불변 사슬이다.
- `MixBusSend`(UE `FSoundSubmixSendInfo`, 구조체)의 필드:
  - `bus`
  - `levelMethod` `MixBusSendLevelMethod {Constant, DistanceLinear, DistanceCurve}`(기본 Constant)
  - `level` 1, `disableLevelClamp` false
  - `minLevel` 0, `maxLevel` 1
  - `minDistance` 100, `maxDistance` 1000(cm)
  - `levelCurve` `FloatCurveSource`
  - `lowPassEnabled` false·`lowPassHz` 20000, `highPassEnabled` false·`highPassHz` 20
  - `stage` `MixBusSendStage {PostAttenuation, PreAttenuation}`
- 범위 밖 값은 `MakePlayable`이 InvalidArgument로 막는다. UE의 UI 범위를 검사로 옮긴 것이다.

**필드 추가**
- `SoundSource`:
  - `bus` `ObjectRef<MixBus>`(`SoundSubmixObject`)
  - `enableBaseBus` true(`bEnableBaseSubmix`)
  - `busSends` `StructRefArray<MixBusSend>`(`SoundSubmixSends`)
  - `enableBusSends` true(`bEnableSubmixSends`)
- `SoundCategory::defaultBus` `ObjectRef<MixBus>`(`DefaultSubmix`). 사슬에 넣되 자기 칸 값만 쓴다(부모로 내려가지 않는다 — UE).
- `AttenuationSettings::enableBusSends` false·`busSends`(`bEnableSubmixSends`·`SubmixSendSettings`). 단계는 늘 post다. `stage`가 Pre면 `MakePlayable`이 Warning 로그를 내고 post로 쓴다(UE 구조체에 단계가 없다).
- 스냅숏은 각 버스를 `MixBusRef`로, 곡선을 평가용 사본으로 평탄화한다.

**기본 버스**(재생 수락 때, 분류 재정의 뒤)
- 순서는 사운드 `bus` → 자기 분류의 `defaultBus` → 엔진 `BaseDefaultBus` → Master다.
- level은 `enableBaseBus`의 0·1이고 단계는 post다. 필터는 없다.

**send 합치기**(재생마다, UE 쓰기 순서 — 같은 버스면 나중 값이 level·단계·필터를 덮는다)
1. 기본 버스 send
2. (AU7h) 리버브 send
3. 감쇠 send(`enableBusSends`일 때)
4. 사운드 send(`enableBusSends`일 때)
5. 재생 단위 send: `SetBusSend`. Constant이고 [0, 1]로 자른다. 같은 버스가 이미 있으면 level만 바꾸고, 없으면 덧붙인다(UE `SetSubmixSend`).

- 합친 결과가 `MaxVoiceSends`를 넘으면 순서 뒤쪽을 버린다. 재생마다 한 번 Warning 로그를 내고 `droppedBusSends`를 센다.

**거리 기반 level**
- 묶음마다 공간 재생의 리스너 거리 `d`로 UE 식(3.45.1절)을 평가한다. 위치 없는 재생은 `d = 0`이다.
- Constant는 `disableLevelClamp`가 아니면 [0, 1], 맞으면 [0, `MaxVoiceGain`]으로 자른다. 믹서 범위다.
- 값이 바뀐 재생만 `PublishRoute`를 낸다.

#### 3.45.8 AU7f2 — 제어 쪽 버스 표와 수명

**버스 표**(`AudioDeviceContext`, `AudioBuses.cpp`): 키 `AudioObjectKey`마다 다음을 둔다.
- 최신 `MixBusRef`
- 믹서 handle
- 부모 키
- 참조 수: 재생 기록의 라우팅과 자식 버스가 쥔다.
- 실행 배수(volume·wet·dry)
- 상태 {Pending(칸을 잡고 plan 게시 전), Live, Retiring(plan에서 빠짐, 해제 대기)}

**등록**
- 재생을 수락하면 라우팅의 모든 버스와 그 조상을 등록하고 참조를 올린다. plan이 더러워진다.
- 같은 키의 새 스냅숏(에셋을 고친 뒤 만든 재생)은 값을 바꾼다. 부모가 바뀌었으면 plan이 더러워진다. 스냅숏 원칙의 예외다. 버스는 재생마다가 아니라 장치에 하나다(UE도 에셋 편집을 장치에 바로 반영한다).

**plan 게시**
- 묶음 처리 끝에 더러우면 `PublishBusPlan`을 낸다. Busy면 다음 묶음에 다시 낸다.
- Pending 버스를 쓰는 Play는 게시까지 Deferred로 남는다. 기존 미룬 Play 재시도(3.41.1절)를 쓴다.
- 실행 중 `SetBusSend`로 새 버스가 생기면 그 send는 게시 뒤 라우팅에 넣는다.

**해제**
- 참조가 0이 된 버스(기록이 voice를 놓은 뒤 — 3.45.4절)는 다음 plan에서 뺀다. 채택 ACK 뒤 `ReleaseBus`한다.
- AU7g부터는 효과 꼬리가 끝날 때까지 남긴다(UE는 에셋이 살아 있는 동안 남긴다 — 07장).

**칸 부족**
- `AcquireBus`가 CapacityExceeded면 그 버스로 가는 send를 버리고, 기본 버스였다면 Master로 보낸다.
- 버스 키마다 처음 한 번 Warning 로그(키·칸 수)를 내고 `busCapacityFallbacks`를 센다.

**실행 배수**
- `SetBusOutputVolume`·`SetBusWetLevel`·`SetBusDryLevel`(선형 ≥ 0, UE 배수)은 게임 쪽 표에 키로 남는다. 버스가 아직 없어도 유지된다.
- 묶음에 바뀐 것만 싣는다. 제어 쪽은 `outputGain = 10^(dB/20) × 배수 × (mute ? 0 : 1)`처럼 곱해 `PublishBusParams`한다. 믹서 범위 밖은 자른다.

**background mute**
- `SetApplicationForeground(false)`일 때 `muteWhenBackgrounded` 버스의 output을 0으로 한다.
- 마스터의 `audio.unfocused.volume`(3.35.9절)과 따로 곱한다(UE도 둘이 따로다).

**계수**(`AudioControlStats`): `liveBuses`, `busPlanPublishes`, `busPlanRetries`, `busCapacityFallbacks`, `droppedBusSends`.

#### 3.45.9 API(AU7f2)

- `AudioEngineSubsystem`:
  - `SetMasterBus(MixBusRef)`: parent가 있으면 InvalidArgument다.
  - `SetBaseDefaultBus(MixBusRef)`
  - `SetBusOutputVolume`·`SetBusWetLevel`·`SetBusDryLevel(MixBusRef, float)`: 음수·비유한은 InvalidArgument다.
  - `SetBusSend(PlaybackHandle, MixBusRef, float level)`: 끝난 재생은 Ignored다.
- `AudioComponent::SetBusSend(MixBusRef, float)`: 재생 중이면 그 재생에 내고, 아니면 다음 `Play`에 쓴다(UE `PendingSubmixSends`).
- 모두 게임 스레드 전용이다. 버스 키는 `MixBusRef`의 첫 칸 키다.

#### 3.45.10 뒤 단계와 들이지 않는 것

- AU7g:
  - `AudioEffect` 인터페이스와 버스 효과 체인(`MixBus::effects`)
  - wet level 적용, `autoDisable`·`autoDisableTime`(꼬리 길이 판정)
  - plan 교체 때 효과 상태 넘기기(3.14.4절), 체인 교차 페이드(UE `SetSubmixEffectChainOverride`)
- AU7h: 리버브 send(`bReverb`·`ReverbSendLevel`), `ReverbReturn` 필수 버스, 영역 send·효과 교체(3.15절)
- AU8: submix 계량(envelope follower·spectrum), 버스 녹음(UE `StartRecordingOutput`)
- AU10: UE Audio Bus·Source Bus(`BusSends`·`PreEffectBusSends`·`PostAttenuationBusSends` — 합성 신호 경로는 `SignalBus`), soundfield·endpoint submix, AudioLink, 동적 submix(`DynamicConnect`)
- 들이지 않음: `bOutputToBusOnly`(레거시), EQ 필수 submix와 분류 `bApplyEffects`(3.43절)

#### 3.45.11 시험

**AU7f1**(Audio, Inline 믹서 — 시간 대기 없음, 값은 식으로 단언)
- 기본 라우팅(Master, level 1, post)의 출력이 감쇠·필터 분리 전 경로와 허용 오차 안에서 같다.
- 버스 하나를 거친 출력이 `outputGain`만큼 바뀌고, 한 블록 ramp 모양이 식과 같다.
- pre send는 `attenuationGain`·LPF의 영향을 받지 않고, post는 받는다.
- send별 LPF·HPF가 그 send만 바꾼다.
- 두 버스 합, 자식 → 부모 → Master 연쇄, dry(−96 dB 건너뜀·−6 dB 적용) 식을 확인한다.
- send 추가·제거·level 변경이 ramp로 이어진다(블록 경계 불연속 없음). 빠지는 send가 ramp 뒤 칸을 비운다.
- plan:
  - 순환·없는 부모·중복은 거부한다.
  - pending 2개면 Busy다.
  - 채택 전 `ReleaseBus`는 Busy, 채택 뒤 성공한다.
  - 칸을 다시 쓰면 상태가 초기화된다.
  - 찢어진 plan·라우팅 읽기를 hook으로 주입해도 낡은 send가 건너뛰어지고 센다.
- 블록 중간 `SetMasterGain`이 버스가 있어도 frame 정확하다.
- 장면 일시정지 pause gain이 모든 send에 걸린다.
- 버스·send가 있는 `RenderBlock`의 할당이 0이다(할당 hook).

**AU7f2**(EngineAudio, Inline 제어 + Manual 렌더)
- 기본 버스 순서(사운드 > 분류 자기 값 > BaseDefault > Master)와 분류 부모의 `defaultBus`를 쓰지 않음을 확인한다.
- send 합치기 순서와 같은 버스 덮어쓰기, `SetBusSend` 재생 중·재생 전, `MaxVoiceSends` 초과 로그·계수를 확인한다.
- 거리 level(Constant 자르기·`disableLevelClamp`·Linear·Curve, 2D는 거리 0), 감쇠 send의 Pre는 Warning + post를 확인한다.
- 버스 수명:
  - 마지막 재생을 놓은 뒤 plan에서 빠지고 해제된다.
  - Pending 동안 Play가 Deferred였다가 게시 뒤 시작한다.
  - Busy 재시도가 일어난다.
- 칸 부족 대체와 로그·계수를 확인한다.
- 실행 배수가 버스 생성 전 호출에도 남는다.
- background mute와 Master 에셋 값, 같은 키 새 스냅숏의 값 교체를 확인한다.
- Thread 제어에서 같은 이벤트 순서를 확인한다.
