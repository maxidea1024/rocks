### 3.44 AU7e2 — 장면 일시정지

UE의 다음 부분을 들인다. 3.43.10절의 요구를 모두 정한다.
- `FAudioDevice::HandlePause`(AD 4113–4157)
- pause 중 갱신(AD 4227–4240·4311–4329·4569–4570)
- `FMixerSource::Pause`(AMS 1223–1240)

약어:
- AD = `Engine/Private/AudioDevice.cpp`, A = `Audio.cpp`, AS = `ActiveSound.cpp`, SW = `SoundWave.cpp`, AVL = `AudioVirtualLoop.cpp`, SC = `SoundConcurrency.cpp`
- AMS = `AudioMixer/Private/AudioMixerSource.cpp`, AMSM = `AudioMixerSourceManager.cpp`

#### 3.44.1 입력

- **scene 일시정지 값** = World 값 OR `AudioEngineSubsystem::SetScenePaused(scene, bool)`(코드가 직접 거는 값)이다.
  - **World 값** = `World::IsPaused() && !World::LastStep().singleStep`이다.
    - 디버그 단일 스텝 frame은 "pause가 아닌 것처럼" 한 frame을 돈다(`GameClock.h` StepPlan). UE도 그 frame에 `bDebugPauseExecution`을 풀어 오디오가 한 frame 흐른다(`DebuggerCommands.cpp:1741`, `LevelTick.cpp:443–451`).
    - UE `bGameTicking`(`GameEngine.cpp:2096`)에 대응한다.
  - **갱신 지점**: `AudioWorldSubsystem`은 tick하는 World Subsystem이 된다(`IsTickable`·`TickWhenPaused` true). `OnTick`에서 World 값을 scene 칸에 적는다. 같은 frame의 `OnFrameEnd` 제출 묶음에 실린다.
  - **스냅숏**: `SceneUpdate`에 `paused`를 싣는다. 값이 바뀌면 scene dirty를 세운다. 두 갱신이 합쳐지면 마지막 값이 이긴다.
    - 새 scene과 재사용한 scene 칸(epoch가 바뀐 칸)은 `paused = false`로 연다.
    - World가 처음부터 paused이면 첫 묶음에 `paused = true`가 실린다.
  - **엔진 scene**(엔진 소유 재생)은 일시정지하지 않는다. `SetScenePaused(엔진 scene)`은 `InvalidArgument`다. UE에는 scene 개념이 없다(장치 전체 + `IsGameOnly`). 7절.
- 들이지 않는 것(9장):
  - UE `bGlobalPause`(AD 4129–4152): 앱 Suspend 경로다(AD 1017–1020). UI까지 멈춘다.
  - UE 재생별 pause(`UAudioComponent::SetPaused` → `SetPauseManually`, AD 4505·4603): 후속에서 들인다.

#### 3.44.2 대상

- **일시정지되는 재생**은 일시정지된 scene에 있는 재생 가운데 UI가 아닌 재생이다.
  - UI 판정은 3.43.4절 실효값 `PlayOptions::isUiSound || 분류 계층 OR`이다(UE `IsGameOnly` — A 522–525. 컴포넌트 값 OR class 값 — SW 3790·3827).
  - 정지 요청 중·steal fade 중인 재생도 일시정지한다.
    - UE도 steal fade(`ComponentVolumeFader` — SC 1098–1102)와 컴포넌트 FadeOut은 pause 중 delta 0이라 멈춘다(AS 1080–1099). source도 bIsStopping이 아니라 HandlePause가 멈춘다.
    - 분리 voice(3.41.3절 — scene 칸을 가진다)도 그 scene을 따른다.
- **판정 시점**: scene이 일시정지되는 묶음과 재생이 그 scene에서 수락되는 묶음(`ApplyPlay`)에 정한다. 기록의 `paused`는 scene이 풀릴 때까지 유지한다.
  - pause 중 Stop·steal이 와도 `paused`를 풀지 않는다. 묶음마다 다시 정하면 Stop이 pause를 풀어 소리가 샌다.
  - pause 중 분류가 바뀌어도(`SetCategory`) UI 판정을 다시 하지 않는다. 다음 pause 전환에 반영한다.
- **UI 재생**은 모든 시계가 흐른다.
  - UE는 시계 동결을 `ActiveSound->bIsUISound`(컴포넌트 값)만으로 판정한다(AD 4227–4231).
  - UE에서는 pause 중 UI 소리의 `PlaybackTime`도 멈춘다(AD 4311–4329).
  - Rocks는 실효 UI 값 하나로 voice와 시계를 함께 판정한다(7절).

#### 3.44.3 재생 시계

- **정의**
  - 기록마다 `paused`, `pausedFrames`(누적), `pauseStartMixFrame`(이번 pause가 걸린 mix frame)을 둔다.
  - `RecordTime(record, now) = now − pausedFrames − (paused ? now − pauseStartMixFrame : 0)`
  - 전환 뒤의 mix frame `m`(믹서가 게시한 시작 frame 등)은 `m − pausedFrames`로 바꾼다. 전환 전 frame은 쓰지 않는다.
- **기록 필드의 시계**
  - record 시계: `volume`·`pitch`·사용자 fade-in ramp, `resume` ramp, `focusMixFrame`, `occlusionCheckFrame`, 차폐 ramp, `cursorMixFrame`, `playbackMixFrame`, voicedTime
  - mix 시계: `stealFader`, 동시 발음 링크 scale(`link.scale`)과 ramp, retrigger `lastPlayMixFrame`, `virtualCheckFrame`, 분리 fader, 믹스·분류 배수
  - 위치 일치 확인: 기록에 붙은 각 frame 필드 이름 옆 주석에 도메인을 적는다.
- **record 시각으로 평가하는 곳**
  - `ApplyPlay`: fade-in 시작, focus·차폐 첫 frame, 첫 차폐 결과
  - `ApplySetParameter`
  - `UpdateSpatial`: focus 초
  - `PublishParams`의 ramp 판정(`IsRamping`)
  - `CollectStarted`: resume 시작과 커서 시작(게시 frame을 record 시각으로 바꾼다)
  - `UpdateEstimates`·`UnscaledEstimate`: 커서·재생 시간·voicedTime
  - `AssignVoices`의 상승 판정(`volume.IsRising`)
  - `StartVoice`·`DetachVoice`·`ReleaseDeferredVoice`: 파라미터·커서
  - 차폐: 검사 due·요청 frame·ramp 시작. pause 중 도착한 응답은 record 시각(멈춘 시각)에서 ramp를 연다. pause 중 disable 전환도 같다.
  - `StealImmediate`의 voicedTime(UE `PlaybackTimeNonVirtualized`도 pause 중 멈춘다)
- **`ParamsFor(record, recordNow, mixNow)`**: 사용자·resume·차폐·pitch는 `recordNow`로, `stealFader`·링크 scale은 `mixNow`로 평가한다. 두 값이 한 곱 안에 있기 때문이다.
- **mix 시계로 흐르는 것**
  - 동시 발음 ducking: UE는 `GetGameDeltaTime`(FApp delta — AD 2687)이라 pause 중에도 흐른다.
  - 가상 검사·실현: UE 가상 loop는 device delta로 검사하고 pause 중에도 실현한다(AD 7469). 실현된 재생은 3.44.4절로 voice를 기다린다.
  - 믹스·override·분류 거리 배수: 장치 단위다(3.43.7절).
  - steal fader·분리 fader·정지 fade: pause 중에도 진행해 무음으로 끝난다(3.44.5절). UE는 멈춘다(7절).
- **가상 재생의 커서**: 일시정지된 가상 재생의 커서·재생 시간은 멈춘다. UE는 가상 loop의 `PlaybackTime`과 SeekRestart 시간을 pause 중에도 device delta로 진행한다(AVL 302–337). 7절.
- 공간 값(리스너·emitter 변환, 감쇠·공간화)은 pause 중에도 다시 계산한다. UE도 delta 0으로 감쇠를 다시 계산한다. 멈추는 것은 시간으로 움직이는 값뿐이다.

#### 3.44.4 voice 배정

UE PausedUpdate도 정렬·컬링·동시 발음을 한다(AD 4887·4236–4240). Rocks도 일시정지된 재생을 후보로 남긴다.
- 상한 밖으로 밀리면 지금처럼 voice를 잃는다. UE는 paused source를 멈춘다(AD 4486–4497). 끝내는 경로는 3.44.5절 정지 규칙이라 소리가 없다.
- **자리 안**
  - voice가 없는 재생은 자리를 차지하되 시작하지 않는다(UE AD 4570 — `bGameTicking || bIsUISound`일 때만 시작). 풀린 묶음에 voice를 잡는다.
  - Deferred(준비만 함)는 `AbandonPreparedPlay`로 놓고 Voiceless로 둔다. 자리는 그대로 차지한다.
  - pause 중 Deferred에 정지가 오면 `ReleaseDeferredVoice` → `EndVoiceless`로 끝낸다. Started는 내지 않는다.
- 무음 컬링은 그대로다. 그래서 pause 메뉴 믹스가 분류를 0으로 만들면 one-shot은 `Inaudible`로 끝난다(UE와 같다 — SW 4003–4023).
- voice가 있는 재생은 믹서 일시정지(3.44.5절)로 간다.
  - 시작 전인 voice(`awaitingStart_`·스트림 시작 대기)는 믹서가 시작을 미룬다.
  - Started는 풀린 뒤 실제 시작에서 낸다.
- 일시정지 상태로 수락된 재생(`ApplyPlay`)은 시계가 처음부터 멈춘 채 연다. voice는 위 규칙을 따른다.
- `CutStoppingVoice`는 바꾸지 않는다.

#### 3.44.5 믹서 일시정지

- **파라미터**
  - `AudioVoiceParams::paused`다.
  - seqlock은 pan mode word의 bit로 싣는다. `PausedShift` 16(omni mode bit 8–15 위)으로 둔다. word는 11개 그대로다.
  - 시각 지정 SetParams 명령(`MakeSetParams`)도 같은 `ApplyParams` 경로다. 그래서 명령의 frame에서 블록 중간에도 바뀐다. seqlock 값은 블록 시작에 한 번 읽으므로 한 블록 안의 켜짐·꺼짐은 마지막 값만 남는다.
- **voice 상태**: voice 칸에 `PauseState` {Running, PausingOut, Paused, ResumingIn}과 일시정지 전용 gain ramp를 둔다. ramp는 `slot.gain`과 따로다(공간 재생은 묶음마다 gain을 다시 낸다).
  - **켜짐**: Running·ResumingIn에서 paused가 켜지면 PausingOut이다. `PauseFadeFrames`(64) 길이 기준 기울기로 지금 값에서 0까지 내린다. 그동안 원본은 계속 읽는다.
  - **PausingOut 끝**: ramp가 0이 되는 frame에서 chunk를 자르고 Paused가 된다. Stopping의 `fadeRemaining` 분할과 같은 방식이다.
  - **Paused**
    - 원본을 읽지 않는다. 리샘플러 위치·비 ramp, 커서, 스트림 소비, 필터 상태와 cutoff ramp, `slot.gain` ramp가 모두 멈췄다가 이어진다.
    - 출력은 0이다.
    - 이 동안 들어온 파라미터는 ramp 목표만 바꾼다.
  - **꺼짐**: paused가 꺼지면 ResumingIn이다. Paused에서는 그 frame부터 다시 읽는다. PausingOut 중이면 지금 값에서 되돌린다. 같은 기울기로 1까지 올린 뒤 Running이다.
  - **자연 끝**: PausingOut·ResumingIn 중 원본이 끝나면 지금처럼 끝낸다. 같은 frame에서 PausingOut이 끝나면 자연 끝이 이긴다.
  - UE는 fade 없이 바로 멈추고 다시 낸다(AMSM 2059–2071, paused source는 `ComputeSourceBuffer`를 건너뛴다 — AMSM 2621). Rocks는 클릭을 막으려고 짧은 fade를 둔다(7절).
- **시작 미룸**
  - paused인 Play는 시작을 미룬다. `PublishStart`도 원본 소비도 하지 않는다.
  - 풀리면 최신 파라미터를 ramp 없이 바로 적용한다. 그다음 기존 시작 규칙을 따른다.
    - 비스트림은 그 frame에서 시작을 게시한다.
    - 스트림은 `awaitingStream` 대기로 돌아간다.
    - 시작 fade는 기존 규칙(복귀 fade-in은 제어 쪽)이다.
  - 시작 미룸 voice에 Stop이 오면 바로 끝낸다(스트림 대기의 `ApplyStop`과 같다).
- **정지**
  - Stopping voice도 paused를 따른다. 정지 fade gain과 pause gain을 곱한다.
  - Paused voice에 정지(Stop·StopAll·여유 부족 끊기)가 오거나, Stopping voice가 Paused가 되면 원본을 읽지 않고 fade frame만 진행한 뒤 terminal을 낸다. 꼬리 소리가 없다.
  - 정지가 걸린 Paused voice는 paused가 꺼져도 다시 읽지 않는다.
  - ResumingIn·Running 중 정지는 지금처럼 꼬리를 낸다(일시정지가 아니다).
  - UE는 Stop에서 pause를 풀고 512 frame 꼬리를 낸다(AMS 1182–1189). UE는 해제 때 paused이면서 stopping인 source를 바로 끝낸다(AMS 1091–1096). Rocks는 pause 중 소리가 새지 않게 둔다(7절).
- **계수**
  - 굶음(`streamStarvedFrames`)은 읽는 상태(Running·PausingOut·ResumingIn)에서만 센다.
  - 시작 지연(`streamStartDelayFrames`)은 시작 미룸 동안 세지 않는다.
  - `pausedVoices`는 지금 Paused·시작 미룸인 voice 수(gauge)다. `CounterSnapshot`의 칸 수 static_assert를 갱신한다.
- **읽지 않은 frame 게시**
  - voice마다 "읽지 않은 누적 mix frame"(`unreadFrames`, 단조 증가)을 센다. Paused 동안의 frame이다.
  - 그 값이 맞는 블록 끝 frame(`unreadAsOfFrame`)과 그때 Paused였는지를 voice별 작은 seqlock(`SharedVoice`)으로 게시한다.
  - 쓰는 쪽은 AudioRT라 기다리지 않는다. 읽는 쪽은 제어이고 찢어지면 다시 읽는다.
  - Running이고 이번 블록에 바뀌지 않았으면 쓰지 않는다.
  - `QueryVoice`의 `AudioVoiceStatus`에 `unreadFrames`·`unreadAsOfFrame`·`pausedAtAsOf`로 나온다.
  - pause·해제가 여러 번 있었거나, Thread 모드에서 mailbox·seqlock이 합쳐졌거나, PausingOut 중에 되돌렸어도 누적값 하나로 맞는다.

#### 3.44.6 논리 커서

- 제어 쪽 논리 커서(3.41.1절)는 voice가 있으면 "읽은 mix frame"만 적분한다.
  - 읽은 frame = Δmix − Δunread다.
  - 시점 `now`의 unread 값은 다음과 같다.
    - `unreadAsOfFrame ≤ now`이면 게시값 + (`pausedAtAsOf` ? `now − unreadAsOfFrame` : 0)
    - `unreadAsOfFrame > now`이면(Thread 모드에서 믹서가 앞섬) 게시값 − (`pausedAtAsOf` ? `unreadAsOfFrame − now` : 0). 0 미만은 0으로 자른다.
  - 읽는 순서: `CompletedMixFrame` → `QueryVoice`(지금 `Process`의 순서).
- voice가 없으면 record 시계로 적분한다. `DetachVoice`는 now까지 게시 구간으로 적분하고, 그 뒤는 record 시계로 잇는다.
- **정확도**
  - 제어 적분은 `EffectivePitch × 경과`라 원래 근사다. 믹서는 비 ramp(`MaxRatioInterpFrames` 256)를 쓴다.
  - 그래서 bit 일치는 pitch가 일정하고 비가 1일 때로 한정한다. 3.41.1절의 기존 기준과 같다.
  - pitch가 바뀌거나 pause 중 분류·믹스 pitch가 바뀌면 허용 오차를 둔다.
  - 원본 위치(sourceCursor + 리샘플러 위상)를 믹서가 직접 게시하는 방식은 9장에 둔다. loop·pitch ramp까지 정확해지지만 seqlock이 커진다.

#### 3.44.7 구조·계수

- 제어 쪽
  - 기록에 `paused`·`pausedFrames`·`pauseStartMixFrame`을 둔다.
  - scene 칸에 `paused`를 둔다.
  - 처리 순서: 스냅숏 적용 뒤(3.41.4절 1단계 앞)에 scene 전환을 기록마다 반영한다. 바뀐 재생은 파라미터를 다시 낸다.
  - 분리 voice는 scene 전환 때 paused를 다시 낸다.
- 계수: `pausedPlaybacks`(제어 쪽 gauge), `pausedVoices`(믹서 gauge).
- 결정적 시험은 Inline·Manual로 한다. Thread 모드는 결과(terminal·Started 수, 무음 여부)만 단언한다.

#### 3.44.8 시험

- **입력**
  - World `SetPaused` → 같은 frame 제출 묶음에서 scene 일시정지
  - `SetScenePaused`와 OR, 엔진 scene은 `InvalidArgument`
  - 단일 스텝 frame에 한 frame 흐름
  - 처음부터 paused인 World, scene 칸 재사용 때 초기화
- **대상**
  - UI 재생(옵션·분류)은 계속
  - pause 중 Stop 뒤에도 paused 유지(소리 없음, Started 없음)
  - steal fade 중 재생·분리 voice도 멈춤
- **voice 재생**
  - 64 frame fade 뒤 출력 0, 풀면 64 frame에 걸쳐 이어짐
  - 원본 위치가 멈춘 곳에서 이어짐(커서 bit 일치 — 비 1, 반복 pause 뒤 SeekRestart 복귀 포함)
  - PausingOut 중 해제, ResumingIn 중 다시 pause에서 커서 일치
  - fade 중 자연 끝(PausingOut·ResumingIn)
- **시작 전**
  - paused로 수락한 재생은 Started가 없고 출력도 0이다. 풀면 Started
  - Deferred는 자리를 쥔 채 voice를 놓는다. pause 중 Deferred + Stop은 Started 없이 끝난다
  - 스트림 시작 대기도 같다. 시작 미룸 voice의 Stop은 바로 terminal
- **정지**
  - Paused voice의 Stop은 꼬리 없이 terminal(fade 길이 뒤)
  - PausingOut 중 Stop, Stopping voice의 pause, StopAll·종료 drain
  - steal fade가 pause 중 무음으로 끝남
- **시계**
  - 사용자 fade-in·SetParameter ramp·차폐 간격·focus 보간이 멈췄다 이어짐
  - pause 중 차폐 응답 도착
  - 동시 발음 ducking·가상 검사·실현·믹스 fade는 흐름
  - 가상 재생의 커서 동결, pause 중 실현 뒤 자리 대기
  - pause 중 분류 pitch 변경(허용 오차)
- **배정**
  - 일시정지된 voice 없는 재생이 자리를 차지해 UI 재생과 경쟁
  - 무음 믹스로 one-shot이 끝남
  - 상한 밖 paused 재생이 소리 없이 끝남
- **믹서**
  - 한 블록 안의 켜짐·꺼짐(seqlock은 마지막 값, SetParams 명령은 그 frame)
  - 굶음·시작 지연 계수 불변, `pausedVoices` gauge
  - seqlock 찢어진 읽기에서 paused bit가 다른 값과 함께 맞음
  - Thread 모드에서 합쳐진 pause·해제 뒤 결과
