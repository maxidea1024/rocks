### 3.36 AU4 구현 세부 — 사운드 에셋 모듈·`SoundClipImporter`·에디터 재생(개정 33)

원본 디코더(WAV·AIFF·FLAC·Vorbis·Opus·MP3 — 3.25–3.29절)와 쿠킹 리샘플러·코덱 계층(3.30–3.32절)은 앞당겨 끝났다. AU4에 남은 일은 넷이고, 이 순서로 한다(설계 교차 검증 1회 반영).

| 단계 | 내용 |
|---|---|
| AU4a | 사운드 에셋 클래스를 새 Runtime 모듈 `AudioAssets`로 옮긴다(동작 불변 이동 커밋) |
| AU4b | `SoundClip` 필드를 임포트 결과·사용자 설정·에디터 원본으로 나누고, `SoundClipImportOptions`와 경고 `IgnoredSourceChunks`를 더한다 |
| AU4c | `SoundClipImporter`(원본 bulk 부호화)와 명령 호스트 연결 |
| AU4d | 에디터 재생(AD25): 쿠킹하지 않은 `SoundClip`의 원본 bulk로 재생 PCM을 만든다. 재임포트는 새 재생부터 새 revision이다 |

#### 3.36.1 모듈 `AudioAssets`(AU4a)

에셋 명령 세션은 에셋 타입 모듈 목록(`AssetTypeModules` — 지금 `Animation`·`Texture`)을 시작해 그 의존 폐포의 타입을 등록한다. `EngineAudio`에는 World 컴포넌트(`AudioComponent` — `SceneComponent` 파생)도 있어서, 그 모듈을 목록에 넣으면 명령 세션이 World·Engine 타입까지 등록해야 한다. 텍스처가 자기 모듈(`Texture`)을 가진 것과 같이, 사운드 에셋 클래스를 World를 모르는 모듈로 뗀다.

- `Engine/Source/Runtime/AudioAssets`, 유형 Runtime(서버도 링크 — 재생 API·에셋 클래스가 있어야 게임 코드가 빌드된다, 3.1절).
- Public 의존은 `AssetRuntime`, `Audio`다. 이 둘은 World·Engine을 모른다. 그래서 명령 세션이 이 모듈만 시작하면 World 타입이 등록되지 않는다(의존 선언으로 지킨다).
- 옮기는 것:
  - `SoundPcm`, `SoundSourceRef`(`SoundAttenuation`·`SoundPlayable`).
  - `SoundSource`, `SoundClip`, `AttenuationSettings`.
  - 타입 등록 함수(`RegisterAudioAssetsTypes`).
- `EngineAudio`는 `AudioAssets`에 의존하고, 자기 타입(`AudioComponent`)만 `RegisterEngineAudioTypes`로 등록한다.
- ID는 `ids move`로 옮긴다(ID 그대로).
- `AssetTypeModules`에 `AudioAssets`를 더하는 일은 AU4c에서 한다(동작 변경이다).

#### 3.36.2 `SoundClip` 필드(AU4b)

UE `USoundWave`처럼 셋으로 나눈다. 임포트가 쓰는 필드는 매번 전부 쓴다(A2f 계약). 사용자 설정은 새 임포트·재임포트 모두 임포터가 건드리지 않는다.

| 구분 | 필드 | 뜻 |
|---|---|---|
| 임포트 결과(런타임) | `channelCount`, `sampleRate`, `frameCount` | 원본 형식. `frameCount`는 uint32로 충분하다(PCM 상한 2 GiB = mono float 2^29 frame) |
| | `sourceCodec`(`SoundSourceCodec` — Pcm·Flac·Vorbis·Opus·Mp3) | 원본 코덱(3.10.1절) |
| | `hasFileLoop`·`fileLoopBegin`·`fileLoopEnd` | 파일 loop(첫 `smpl` loop) |
| | `cues`(`SoundCuePoint { id, frame, name }` 배열) | 파일 cue·marker(UE `CuePoints`. UE는 EditorOnly로 두고 쿠킹 때 따로 직렬화하지만, Rocks는 런타임 필드로 둔다 — 더 단순하다) |
| 사용자 설정 | `looping` | loop 재생. 임포터는 켜지 않는다(UE도 `bLooping`을 켜지 않는다) |
| | `loopOverride`(`SoundLoopOverride { enabled, begin, end }`) | 사용자 loop 구간(3.10.2절) |
| | `volume`·`pitch`·`attenuation` | `SoundSource` |
| 에디터 원본(`EditorOnly`) | `source`(`SoundClipSource { format, bulk }`) | 디코드한 PCM bulk(`BulkDataRef`), 채널 비교차, 헤더 없음, little-endian |

- **재생 loop 구간**: `loopOverride.enabled`면 그 구간, 아니면 `hasFileLoop`면 파일 구간, 둘 다 아니면 clip 전체다. 실제 loop 여부는 `looping`이 정한다.
  - UE와 다르다(7절): UE `USoundWave`의 looping은 늘 파형 전체이고, loop region은 cue point로만 남는다(믹서가 쓰지 않는다).
  - Rocks는 게임 음악의 intro + loop 구간을 별도 그래프 없이 쓰려고 파일 loop를 기본 구간으로 쓴다.
- **`source.format`(`SoundSourceStorage`)** — 3.10.1절 저장 규칙:
  - `None`: 원본 없음(기본값).
  - `Int16`: 8·16비트 원본.
  - `Int24`: 24비트 원본, packed little-endian.
  - `Float32`: 32비트 정수·float·손실 원본, 그리고 downmix·normalize한 결과. 변환된 값을 정수로 다시 줄이지 않는다.
- 이전 AU3의 `loopBegin`·`loopEnd`(설정)는 `loopOverride`로 바꾼다. 하위호환은 두지 않는다.
- **`SetPcm`**(메모리 생성 — 시험·Sandbox)은 PCM에서 `channelCount`·`sampleRate`·`frameCount`도 채운다. 그래서 `MakePlayable`은 어느 경로든 같은 필드를 본다. 에디터 PCM 키(3.36.4절)는 지운다.
- **`MakePlayable` 검사**:
  - 필드(`channelCount`·`sampleRate`·`frameCount`)와 쥔 PCM의 차원이 다르면 `NotReady`다. 재임포트 직후 `LoadEditorPcm` 전에 새 loop 구간이 옛 PCM과 섞이지 않게 하려는 것이다.
  - PCM 범위를 넘는 loop 구간은 `InvalidArgument`다.

`SoundClipImportOptions`(`AudioAssets`의 ROCKS_STRUCT — 텍스처 옵션이 `Texture` 모듈에 있는 것과 같은 이유로, 명령 세션이 등록하는 모듈에 둔다):
- `channelHandling`(`SoundImportChannelHandling` — Keep·DownmixToMono).
- `loopFromFile`(true).
- `normalize`(false)·`normalizePeakDb`(−1.0, 유한하고 [`MinNormalizePeakDb` −96, 0]. 아니면 `InvalidImportOption` — 하한 아래는 사실상 무음을 만드는 값이다).

이름은 `SoundClip` 노출 속성·A2f 예약 이름과 겹치지 않는다(등록 때 A2f가 검사한다).

경고 `IgnoredSourceChunks`(detail = 건너뛴 chunk 수)를 `AssetDiagnosticCode` 끝에 더한다. 고치는 곳은 enum·`AssetDiagnosticName`·`AssetDiagnosticIsWarning`, 그리고 진단 이름 시험의 마지막 값이다.

#### 3.36.3 `SoundClipImporter`(AU4c)

- **`AssetImporterInfo`의 값**:
  - 이름 `sound_clip`(텍스처 `texture`와 같은 소문자 규칙 — 3.10.2절도 이것으로 고친다). 고정 Guid, 버전 1.
  - 출력 `SoundClip`.
  - 확장자 `wav`·`aif`·`aiff`·`flac`·`ogg`·`opus`·`mp3`.
  - 역할은 빈 목록(원본 하나 `source`). 옵션 타입은 `SoundClipImportOptions`.
- **디코더 고르기**: 확장자로 고르되 `ogg`·`opus`는 첫 Ogg page의 식별 header를 본다(`OpusHead`면 Opus, `\x01vorbis`면 Vorbis). Opus를 `.ogg`로 저장한 파일이 흔하기 때문이다. `OggS`로 시작하지 않거나 첫 page가 잘렸으면 손상(`InvalidSource`·`CorruptData`), page는 온전한데 다른 codec(Ogg FLAC 등)이면 `UnsupportedSourceFormat`이다(구현 리뷰).
- **디코더 오류 → 진단**(3.10.2절):
  - `InvalidArgument`·`CapacityExceeded`·`CorruptData`는 `InvalidSource`다.
  - `Unsupported`는 `UnsupportedSourceFormat`이다.
  - `OutOfMemory`는 그대로 낸다.
  - frame 0은 `InvalidSource`다.
- **처리 순서**:
  1. downmix: DownmixToMono는 채널 평균이다(같은 가중치 — UE 임포트에는 downmix가 없다. 다채널 출력 downmix 행렬은 AU9). mono 원본이면 하지 않는다(정수 저장 유지).
  2. normalize: 모든 채널 공통 peak가 0이 아니면 `10^(normalizePeakDb/20) / peak`를 곱한다. 배율은 double로 계산하고, 비정규수 peak에서도 비유한이면 건너뛴다(사실상 무음).
  3. 둘 중 하나라도 표본을 바꿨으면 저장은 `Float32`다.
- **정수 저장**: float에 **저장 형식 비트**의 2^(비트−1)(16비트 32768, 24비트 8388608)을 곱하고 반올림한 뒤 자른다. 배율·byte 수·부호 비트는 `SoundClipData.h`의 공용 상수라 임포터 양자화와 에디터 재생 역변환이 같은 값을 쓴다.
  - 디코더는 컨테이너 byte(WAV·AIFF) 또는 실제 bit 수(FLAC)로 나누어 [−1, 1)을 만든다. 저장 형식 비트로 곱하면 12·20비트 FLAC, AIFF 좌정렬, uint8 모두 정확히 왕복한다(원본 bit 수로 곱하면 틀린다).
- **결과 쓰기**: bulk를 `AddBulk`로 넣고 임포트 결과 필드를 모두 쓴다. `loopFromFile`이 false거나 파일에 없으면 loop·cue를 비운다. `IgnoredChunks() > 0`이면 경고를 낸다.
- **명령 호스트 연결**(Commandlet):
  - 임포터 칸이 하나다(`AssetCommandContext::importers`). 그래서 묶음 등록 함수를 둔다. 텍스처 임포터 9개와 사운드 임포터 하나를 차례로 등록하고, state는 두 묶음을 담은 구조다.
  - 타입 hook 칸은 텍스처 것을 그대로 쓴다(사운드 hook은 없다). 번역기도 텍스처 것을 쓴다.
  - 쿠킹 처리기 칸은 AU5다. 그 전 `asset-cook`은 기본 처리기로 `SoundClip`을 PCM 없이 쿠킹하므로, 쿠킹된 실행에서 `MakePlayable`은 `NotReady`다.
  - Commandlet 의존에 `AudioAssets`·`AudioTools`를 명시한다. `AudioTools`의 Public 의존에 `AssetRuntime`·`AssetDatabase`·`AudioAssets`를 더한다(지금은 `Core`·`Audio`뿐).
- **한계 `--volume=`**: `volume`은 A2f 예약 이름이자 텍스처 번역 예약 인자라서, `asset-import a.wav --volume=0.5`가 사용법 오류이고 `asset-reimport`에서도 거부된다. 사운드 volume은 `asset-edit`로 정한다. 번역 예약 이름을 번역기를 선언한 임포터에만 적용하도록 A2f를 고치는 일은 후속이다(시험으로 지금 동작을 고정한다).
- **한계 메모리**: 2 GiB 원본이면 디코드 float, bulk, 압축 버퍼가 동시에 메모리에 있다(A2f 원본 통째 읽기와 같은 성격).

#### 3.36.4 에디터 재생(AU4d, AD25)

- **`SoundClip::LoadEditorPcm(Allocator&, PackageBulkSource&)`**: `#if ROCKS_WITH_EDITOR_DATA`에서만 있다. `source.bulk`를 읽어 float `SoundPcm`을 만들고 `pcm_`에 둔다.
- **재사용 키**: (`source.bulk`의 같은 내용 — `BulkDataRef::SameContent`, `source.format`, `channelCount`, `sampleRate`, `frameCount`).
  - 키가 같으면 다시 올리지 않는다.
  - 다르면 새 PCM으로 바꾸고 `pcmRevision`을 올린다. byte가 같아도 rate·채널만 바뀐 재임포트가 있으므로 형식도 키에 넣는다.
  - 키는 `ROCKS_NATIVE`다.
  - 이미 시작한 재생은 이전 스냅숏(자기 `SharedPtr`)을 끝까지 쓰므로, 재임포트는 새 재생부터 새 revision이다(6.2절 AU4 완료 기준).
- **부르는 쪽**: 에디터·Tryout 재생 경로가 `MakePlayable` 전에 부른다. AU4에서는 시험·Sandbox만 부르고, 에디터 미리듣기 UI는 AU10이다. 게임 스레드에서 동기로 읽는다(한계).
- **오류**:
  - 원본 없음(`NotReady`).
  - bulk 크기가 형식·채널·frame과 맞지 않거나 float32 표본이 비유한 손상(`CorruptData` — Core `ErrorCode`에 더한 범용 손상 데이터 값, 사용자 결정 2026-11-26).
  - 채널이 2보다 많음(`Unsupported` — 믹서 clip은 1–2채널, 다채널은 AU9).
  - bulk 읽기 오류는 그대로 낸다.
- **AD25와의 차이**: PCM 플랫폼 데이터는 PCM16이라(3.30절), int24·float 원본과 rate 재정의가 있으면 원본 bulk 재생과 결과가 다르다. AU4는 원본 정밀도로 미리 듣는다. AU5·AU6(플랫폼 데이터 쿠킹·런타임 읽기) 뒤 에디터 재생을 실행 플랫폼 데이터 경로로 바꾼다(3.9절 AD25 원안 — 쿠킹 결과와 같은 소리를 듣는다).

#### 3.36.5 시험

- **AU4a**: 이동 뒤 AU3 시험(EngineAudio 43개)이 그대로 통과하고, ID가 바뀌지 않는다(빌드의 `ids verify-set`).
- **AU4b**:
  - 필드 기본값.
  - 재생 loop 구간 우선순위(override > 파일 > 전체).
  - 차원이 다를 때 `MakePlayable`이 `NotReady`.
  - 옵션 등록이 A2f 이름 검사를 통과한다.
  - 진단 이름·경고 분류.
- **AU4c**(3.19절 임포트 행):
  - WAV 8·16·24·32비트·float에서 필드·저장 형식, bulk byte가 고정값과 같다.
  - 12·20비트 FLAC과 AIFF 좌정렬의 정확한 왕복.
  - FLAC·Ogg Vorbis·Ogg Opus·MP3 fixture의 frame 수(delay·padding 제거 뒤)와 `sourceCodec`.
  - 손실 fixture의 bulk(Float32) SHA가 디코더 고정 SHA(3.26·3.29절)와 같다. "디코드 SHA 고정값" 완료 기준이다.
  - `.ogg` 안의 Opus.
  - 파일 loop·cue와 `loopFromFile` false.
  - DownmixToMono(mono 원본은 그대로)·normalize 값, `normalizePeakDb` 범위 밖은 `InvalidImportOption`.
  - 손상 원본·frame 0은 `InvalidSource`, 9채널·rate 범위 밖은 `UnsupportedSourceFormat`, 모르는 확장자.
  - 모르는 chunk 경고.
  - 재임포트가 임포트 필드는 다시 쓰고 `looping`·`loopOverride`·`volume`은 보존한다.
  - 명령 호스트 묶음 등록: Commandlet 실행 파일 시험이 `.wav`·`.png`를 둘 다 임포트하고, `--volume=`은 사용법 오류다.
- **AU4d**:
  - int16·int24·float32 bulk가 원래 표본으로 정확히 바뀐다.
  - 같은 키는 다시 올리지 않고, rate만 바뀐 재임포트는 다시 올린다.
  - 재임포트로 bulk가 바뀌면 revision이 오르고, 재생 중인 소리는 이전 PCM, 새 재생은 새 PCM이다(Null capture).
  - 3채널 이상은 `Unsupported`, 잘린 bulk·비유한 float는 `CorruptData`.

#### 3.36.6 버린 안

- **`EngineAudio`를 에셋 타입 모듈 목록에 넣기**: 명령 세션이 World·Engine 타입과 그 의존을 모두 등록해야 한다. 쿠커·임포트 명령이 게임 런타임 모듈에 묶인다.
- **UE처럼 16비트 WAV byte를 bulk로**: 3.10.1절(AD12)대로 24비트·float 정밀도를 지킨다.
- **에디터 재생을 지금 쿠킹 처리기·AssetNugget으로(AD25 원안)**: AU5 쿠킹 처리기와 런타임 플랫폼 데이터 읽기(AU6)가 아직 없다. 그 전까지 원본 bulk로 미리 듣는다.
- **명령 호스트 임포터 칸을 목록으로 바꾸기**: 모든 호스트가 함께 바뀐다. 묶음 등록 함수 하나로 같은 일을 한다.
- **확장자만으로 Ogg 디코더 고르기**: `.ogg` 안의 Opus가 `InvalidSource`가 된다.
