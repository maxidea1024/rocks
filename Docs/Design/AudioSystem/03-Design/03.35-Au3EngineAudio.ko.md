### 3.35 AU3 구현 세부 — `EngineAudio`(개정 32)

AU3을 셋으로 나눈다(AU3b는 Sparks 바인딩 이름으로 이미 쓰므로 AU3a1–AU3a3로 붙인다).
- **AU3a1**: 모듈 `EngineAudio`, 실행 판정(PR7 임시), 사운드 데이터·에셋 클래스, `AudioEngineSubsystem`, 제어 pipe, `AudioDeviceContext`, 엔진 소유 `Play2D`, 결과, 마스터·비활성 창 볼륨, 종료 drain.
- **AU3a2**: `AudioWorldSubsystem`(scene·emitter·리스너), `PlayAt`·`PlayAttached`·World 소유 `Play2D`, 거리 감쇠·패닝, World 제거 정리(Tryout 정리 계약 포함), `AudioComponent`.
- **AU3a3**: Sandbox 연결. 키 입력으로 UI음, 움직이는 부착 loop, 좌우 방향, 창 포커스 볼륨을 넣고 사용자가 확인한다.

선행 정리:
- **PR7**: AppInfo가 아직 없으므로 3.8.4절대로 `EngineAudio` 안에 판정을 둔다(3.35.2절).
- **PR8**: 오디오에는 필요 없다(3.35.9절). AU2b의 backend `Stop`이 콜백 장벽을 직접 지키고(3.34.2절) AudioRT join도 시간 상한이 있어서, 오디오 `CompleteInFlightWork`가 소유자를 풀지 못할 경로가 없다. [엔진 런타임](../../EngineRuntime/06-Engine.ko.md) AD23 게이트는 일반 설계로 남긴다. 실제로 필요한 쪽이 생기면 그쪽이 구현한다.

#### 3.35.1 모듈

`Engine/Source/Runtime/EngineAudio`, 유형 Runtime(서버도 링크 — 3.1절).
- Public 의존: Engine, World, AssetRuntime, Audio.
- Private 의존: Task(`DedicatedLane`), ModuleLoader(`HostServices`), Config.
- 3.1절 표의 EngineAssets·SpatialIndex는 쓰는 단계(AU6 로딩·AU7 리버브 존)에 더한다.
- 리플렉션 모듈이다. 생성 헤더는 `<EngineAudio/*.generated.h>`, ID 명세는 `EngineAudio.rocksids.json`이다.
- `AudioMiniaudio`는 참조하지 않는다. backend는 `HostServices`의 `AudioOutputBackendRegistry`로만 찾는다.
- Engine에 `ModuleLoader* Modules() const`를 더한다. `EngineConfig::modules`를 그대로 돌려주는 접근자이며, Subsystem이 `HostServices`를 찾는 길이다.

#### 3.35.2 실행 판정(`EngineAudio/AudioRunTraits.h`)

```cpp
struct AudioRunTraits { bool audioOutput = true; bool audioMuted = false; };
AudioRunTraits ResolveAudioRunTraits(build::TargetType target, Span<const StringView> arguments) noexcept;
```

- `audioOutput` = false인 경우:
  - `TargetType::Server`.
  - `TargetType::Program`(commandlet·도구). `--allow-commandlet-audio`가 있으면 켠다.
  - `--no-sound`.
  - `--benchmark`.
- `audioMuted` = true: `--mute-audio`.
- 뒤에 나온 같은 플래그가 앞의 것을 덮을 일은 없다(모두 켜기만 한다).
- `--allow-commandlet-audio`·`--benchmark`는 Release 구성에서 무시한다(AppInfo 10.2절 표의 "출시 빌드 받지 않음"). `--no-sound`·`--mute-audio`는 Release에서도 받는다.
- 인자는 `ProcessCommandLine::Get().Arguments()`를 그대로 본다. `--name`만 맞추며 `=값`을 붙인 꼴은 받지 않는다(플래그는 값이 없다).
- 순수 함수라 시험에서 바로 단언한다. AppInfo AP1 구현 때 이 함수의 판정을 `RunTraits`로 옮기고, `EngineAudio`는 `AppInfo::Get().Traits()`를 읽는다(동작 불변 이동).

#### 3.35.3 사운드 데이터와 에셋 클래스

재생 경로는 Object를 건드리지 않는다(3.2절 — 제어 pipe·AudioRT는 Object 접근 금지). 그래서 재생 요청은 **불변 공유 스냅숏**을 넘긴다.
- `SoundPcm`(`EngineAudio/SoundPcm.h`): planar float PCM(채널 1–2), rate, frame 수를 가진다. 한 번 만든 뒤 바꾸지 않는다. `SharedPtr<const SoundPcm>`로만 쥔다. 채널 배열은 같은 할당 안에 둔다(`TryCreate(allocator, channels, frames, rate)`).
- `SoundSourceRef`: `SharedPtr<const SoundPlayable>` 하나를 감싼 값이다(빈 값 = 사운드 없음). `SoundPlayable`의 내용:
  - `pcm`.
  - `looping`·loop 구간.
  - 기본 volume·pitch.
  - 감쇠 스냅숏(`Optional<SoundAttenuation>`, 없으면 비공간화).
  - 에셋 id·revision(진단용).
- 재생 중 원본 객체가 GC되거나 다시 임포트되어도, 이미 시작한 재생은 시작 때의 스냅숏을 끝까지 쓴다. 새 재생부터 새 내용이 나온다(6.2절 AU4 완료 기준 "재생 중 재임포트 시 새 재생부터 새 revision"과 같다).
- PCM 해제 시점: 제어 쪽이 clip 등록을 풀고(ACK 뒤 — 3.5.5절) 마지막 `SharedPtr`를 놓을 때다. 놓는 스레드가 제어 pipe일 수 있으므로, `SoundPcm` 할당자는 스레드 안전해야 한다(엔진 기본 할당자 — 시험은 `SystemAllocator`).

리플렉션 에셋 클래스(3.9절 중 AU3 몫):

| 클래스 | 기반 | 필드(AU3) |
|---|---|---|
| `SoundSource`(Abstract) | `Asset` | `volume`(1.0, [0, 4]), `pitch`(1.0, [0.4, 2]), `attenuation`(`ObjectRef<AttenuationSettings>` — 같은 에셋 Registry 안 간선) |
| `SoundClip` | `SoundSource` | `looping`, `loopBegin`·`loopEnd`(frame, 둘 다 0이면 전체). 실행 데이터 `ROCKS_NATIVE() SharedPtr<const SoundPcm> pcm_`. 채널 수·rate·frame 수는 PCM에서 읽는다 |
| `AttenuationSettings` | `Asset` | `attenuate`(true — 거리 감쇠), `spatialize`(true — 패닝. UE `bAttenuate`·`bSpatialize`처럼 따로다), `model`(`DistanceAttenuationModel`, Linear — UE 기본), `innerRadius`(400 cm — UE `AttenuationShapeExtents.X` 기본), `falloffDistance`(3600 cm — UE 기본), `naturalSoundAttenuationDb`(−60), `naturalSoundFalloffMode`(Continues), `nonSpatializedRadiusStart`·`nonSpatializedRadiusEnd`(0·0 — UE 기본) |

- `SoundClip::SetPcm(SharedPtr<const SoundPcm>)`는 게임 스레드에서 부른다. 비유한 표본만 거부한다(`InvalidArgument`). loop 구간·volume·감쇠는 `MakePlayable`이 스냅숏을 만들 때 `SoundSourceRef::TryCreate` 규칙으로 검사한다(loop 필드는 PCM보다 먼저·나중에 바뀔 수 있다).
- `SoundSource::MakePlayable(Allocator&) → Result<SoundSourceRef>`는 게임 스레드에서 부른다. `attenuation`이 가리키는 객체의 값을 복사해 스냅숏을 만든다. PCM이 없으면 `NotReady`다.
- AU3 `SoundClip`의 PCM은 실행 중 메모리 생성뿐이다(시험·Sandbox). 에디터 bulk·플랫폼 데이터 필드는 AU4·AU5가 더하고, 그때 `pcm_`은 플랫폼 데이터에서 만든다.
- 로딩·스트리밍 없이 메모리 PCM만 쓰므로 AU3에는 준비 티켓(3.12.4절)이 없다. `PlayOptions::notReady`는 AU6.

#### 3.35.4 재생 handle·상태·결과(`EngineAudio/AudioPlayback.h`)

- `PlaybackHandle { uint32 slot; uint32 generation; }`. generation 0은 무효다.
- 게임 쪽 재생 표의 용량은 `MaxPlaybacks` = 1024다. 차면 `CapacityExceeded`다(3.5.1절).
- `PlaybackStatus { Pending, Playing, Ignored, Finished }`.
  - Pending: 수락했고 아직 시작 결과가 없다.
  - Playing: 시작 frame을 받았다.
  - Ignored: 장치 없음·무음 실행이다(3.8.3절).
  - Finished: terminal을 받았거나, 이미 수거되어 handle이 낡았다.
- `PlaybackEndReason { None, NaturalEnd, Stopped, SceneRemoved, EmitterRemoved, VoiceLimit, Ignored, ShuttingDown, Failed }`.
- `PlaybackEvent { PlaybackHandle handle; enum { Started, Ended } kind; PlaybackEndReason reason; uint64 mixFrame; }`. 재생마다 Started 0–1번, Ended 정확히 1번이다(3.5.4절). 예외: scene 해제(World 파괴)와 엔진 종료는 콜백을 부르지 않는다. scene을 해제하는 순간 게임 쪽에서 그 scene 재생의 `onEvent`를 비우고 `Status`를 `Finished`로 둔다(파괴된 World의 객체를 잡은 콜백이 1–2프레임 뒤에 불리지 않게 — 3.5.4절 소유자 확인과 같은 목적). 슬롯은 제어 쪽 Ended가 온 뒤 놓는다. 예외: scene 해제(World 파괴)와 엔진 종료는 콜백을 부르지 않는다. scene을 해제하는 순간 게임 쪽에서 그 scene 재생의 `onEvent`를 비우고 `Status`를 `Finished`로 둔다(파괴된 World의 객체를 잡은 콜백이 1–2프레임 뒤에 불리지 않게 — 3.5.4절 소유자 확인과 같은 목적). 슬롯은 제어 쪽 Ended가 온 뒤 놓는다.
- 결과 콜백은 `PlayOptions::onEvent`(`Function<void(const PlaybackEvent&)>`, 비어도 됨)다. 게임 스레드의 `OnFrameBegin`에서 부른다.
  - Ended를 전달한 뒤 슬롯을 놓는다(generation 증가).
  - 콜백이 잡은 대상의 수명은 호출자 책임이다. `AudioComponent`는 콜백을 쓰지 않고 handle 상태를 본다(3.35.8절).
- `PlayOptions`(AU3): `volume`·`pitch` 배수(1.0), `startFrame`(0), `fadeInFrames`(0 — 사용자 gain ramp 0→1, 3.35.6절), `onEvent`. 시작 시각 지정·동시 발음 재정의는 AU7·AU10. 배수와 사운드 값의 곱은 믹서 범위로 자른다(UE처럼 곱을 clamp — PreparePlay가 범위 밖을 거부하기 때문이다).
- 즉시 실패: `InvalidArgument`(빈 사운드, NaN 위치, 범위 밖 배수, 끝을 넘은 `startFrame`), `CapacityExceeded`, `ShuttingDown`(`BeginShutdown` 뒤).
- 장치가 없으면 `Ignored` 상태의 유효 handle을 돌려주고, 다음 `OnFrameBegin`에 `Ended(Ignored)`를 낸다.

#### 3.35.5 제어 pipe

실행기는 `DedicatedLane`(lane `TaskLane::Audio`, 스레드 이름 `AudioControl`, `Normal` 우선순위)이다. 모드는 Thread와 Inline 두 가지다. Inline은 `OnFrameEnd`를 부른 스레드에서 바로 돈다(3.2절 Inline 모드 — 시험).

게임 쪽과 제어 쪽은 **일괄 묶음(`ControlBatch`) 순환**으로만 주고받는다. 공유 잠금은 없다.
- 묶음 수는 `ControlBatchCount` = 3이다. 묶음마다 다음을 담는다:
  - 게임 명령 배열.
  - scene별 리스너 스냅숏.
  - emitter 위치 갱신 배열.
  - 마스터 gain 목표.
  - 제어 쪽이 채우는 결과 배열.
- 게임은 그 프레임의 명령을 현재 묶음에 모은다. `OnFrameEnd`에 스냅숏을 덧붙여 lane에 `Post`한다(묶음 포인터만 잡는 task).
- 제어 쪽은 묶음을 처리하고 결과를 같은 묶음에 쓴 뒤, 반환 큐(`BoundedSpscQueue<ControlBatch*>`, 용량 4)에 넣는다.
- 게임은 `OnFrameBegin`에 반환된 묶음을 순서대로 꺼내 결과를 지역 목록에 복사하고 묶음을 비워 빈 목록에 되돌린 뒤, 지역 목록을 전달한다. 콜백이 Play·Stop을 부르거나 World를 즉시 파괴해도(Tick 밖 `DestroyWorld`) 전달 중인 표가 흔들리지 않는다. 슬롯 해제는 각 Ended 콜백이 돌아온 뒤다.
- `Post`가 실패하면(할당 실패) 묶음을 현재 묶음으로 되돌리고 다음 프레임에 다시 보낸다.
- 같은 handle·같은 파라미터의 `SetParameter`는 현재 묶음 안에서 최신값 하나로 합친다(묶음이 밀려도 명령 배열이 끝없이 자라지 않는다).
- 빈 묶음이 없으면(제어 쪽이 밀림) 그 프레임은 보내지 않는다. 명령은 현재 묶음에 남아 다음 프레임에 함께 간다(`deferredFrames` 계수). 게임은 기다리지 않는다.
- Thread 모드에서 제어 쪽만 `AudioDeviceContext`·믹서 제어 면·`AudioOutputDevice::Submit`을 부른다(믹서의 제어 스레드 하나 계약 — 3.23절). 게임은 종료 drain에서 lane이 멈춘 뒤에만 직접 닿는다.

#### 3.35.6 `AudioDeviceContext`(제어 쪽, Private)

- **Deferred**는 voice를 잡고 `PreparePlay`까지 한 뒤 `Submit`만 못 한 상태다. Reserved voice에는 `RequestStop`을 낼 수 없으므로(믹서 `CheckCommandTarget`), Deferred 중 받은 Stop은 fade만 적어 두었다가 `Submit` 성공 직후 낸다. `AcquireVoice`의 `CapacityExceeded`(놓기 대기가 여유를 다 씀)는 `VoiceLimit`이다.
- **Deferred**는 voice를 잡고 `PreparePlay`까지 한 뒤 `Submit`만 못 한 상태다. Reserved voice에는 `RequestStop`을 낼 수 없으므로(믹서 `CheckCommandTarget`), Deferred 중 받은 Stop은 fade만 적어 두었다가 `Submit` 성공 직후 낸다. `AcquireVoice`의 `CapacityExceeded`(놓기 대기가 여유를 다 씀)는 `VoiceLimit`이다.
- 재생 기록의 내용:
  - 게임 handle.
  - scene.
  - emitter(없으면 고정 위치 또는 2D).
  - `SoundSourceRef`.
  - voice handle.
  - 기본 파라미터.
  - 상태(Deferred·Submitted·Releasing).
- **clip 등록 캐시**: (`SoundPcm*`, loop 시작, loop 끝) → {`AudioClipId`, 사용 voice 수, `SharedPtr`}. loop 구간이 믹서 clip 등록에 들어가므로 같은 PCM이라도 구간이 다르면 다른 항목이다.
  - 처음 쓰일 때 `RegisterClip`한다.
  - 사용 voice가 0이 되고 그 voice들을 모두 `ReleaseVoice`한 뒤에 `UnregisterClip`하고 `SharedPtr`를 놓는다.
  - `UnregisterClip`이 `Busy`면 다음 묶음에서 다시 한다.
  - 표가 차면(`DefaultMaxClips`) 그 재생은 `Failed`다.
- **voice 상한**: 살아 있는 재생 voice 수가 `audio.voices.max`(기본 32)를 넘으면 새 재생은 `Ended(VoiceLimit)`다. 동시 발음·steal·가상화는 AU7.
  - 믹서 voice 표는 `2 × audio.voices.max`로 만든다. 놓기 대기(ACK 전 `ReleaseVoice` `Busy`) 중인 voice가 새 재생을 막지 않게 하는 여유분이다.
- **명령 링 포화**(`Submit` `Busy`): 그 재생은 Deferred로 남고 다음 묶음에서 먼저 보낸다. voice마다 명령 순서는 유지한다.
- **결과 수거**: 묶음마다 처리한다.
  - `CollectFinished`로 terminal을 모은다. 믹서 사유는 `NaturalEnd`·`Stopped`로, 장치 stop-all은 `ShuttingDown`으로 바꿔 결과 배열에 쓴다.
  - Submitted 재생은 `QueryVoice`로 시작 frame을 보고 `Started`를 한 번 낸다.
  - 끝난 voice는 `ReleaseVoice`가 될 때까지 Releasing 목록에 둔다(3.5.5절).
- **사용자 gain·pitch ramp**: `SetParameter(..., rampFrames)`와 `fadeInFrames`는 제어 쪽이 mix clock(`CompletedMixFrame`) 기준으로 평가한다. 기록마다 {시작값, 목표값, 시작 frame, 길이}를 두고, 묶음마다 지금 값을 계산해 감쇠 gain과 곱한 뒤 `PublishParams`로 보낸다. 해상도는 묶음 간격(게임 프레임)이고, 그 사이는 seqlock 적용 ramp(`DefaultParamRampFrames`)가 잇는다. 믹서 gain이 `AudioVoiceParams::gain` 하나뿐이라, 시각 명령(`MakeSetParams`)으로 낸 긴 ramp는 다음 묶음의 공간 갱신이 덮는다. 그래서 2D·공간 모두 이 경로 하나로 둔다. sample 단위 정밀 ramp가 필요한 기능(박자 전환 — AU10)은 믹서에 사용자 gain 단을 더하는 개정으로 한다.
- **2D 재생**: `AudioPanMode::Direct`, gain = 사용자 volume(ramp 평가값) × 사운드 volume.
- **공간 재생**(감쇠 스냅숏이 있고 `spatialize`가 true): 묶음마다 다시 계산해 `PublishParams`한다(3.35.7절 식).
- **마스터 gain**은 `audio.master.volume`, 음소거(`audioMuted` → 0), 비활성 창 배수(`audio.unfocused.volume`, 포커스 없을 때)를 곱한 값이다. 바뀐 묶음에서만 `MakeSetMasterGain`(ramp `DefaultParamRampFrames`)을 보낸다. 첫 묶음은 ramp 0으로 보낸다(음소거·비활성으로 시작할 때 처음 256 frame이 새지 않게). 첫 묶음은 ramp 0으로 보낸다(음소거·비활성으로 시작할 때 처음 256 frame이 새지 않게).

#### 3.35.7 World 연결(AU3a2)

`AudioWorldSubsystem`(WorldSubsystem, 이름 "Audio", 기본 생성 판정 — Game·Editor·Tryout):
- **Initialize**: `GetEngineSubsystem<AudioEngineSubsystem>`로 엔진 쪽을 찾아 포인터를 보관한다. 엔진 Subsystem은 모든 World보다 오래 산다(World 파괴가 `CompleteInFlightWork` 전 — Engine.h 종료 순서, 바깥 조회 창 계약 World.h `OuterSubsystemLookup`). World.h가 권하는 "바깥 정리는 `OnWorldEndPlay`에서"와 달리 `Deinitialize`에서도 보관 포인터로 해제하는 이유는, 편집 World처럼 `OnWorldEndPlay`가 없는 World도 scene을 놓아야 하기 때문이다. 그다음 `RegisterScene`으로 `AudioSceneId { index, epoch }`를 받는다. 엔진 쪽이 없으면(엔진 목록에 `AudioEngineSubsystemType`이 없음) scene 없이 시작하고, 재생은 성공 + 빈 handle(generation 0, `Status`는 Finished)이다 — handle 표가 엔진 쪽에 있어 Ignored handle을 만들 수 없다. 엔진 쪽은 있는데 scene이 끝났으면 Ignored handle이다. World 쪽 `Stop`·`SetParameter`·`Status`는 그 World scene 소유 handle만 다룬다(다른 World·엔진 소유는 낡은 handle처럼 다룬다).
- **scene 해제**: `OnWorldEndPlay`와 `Deinitialize` 중 먼저 오는 쪽에서 한다(멱등). 해제한 scene에는 등록·재생이 더 들어가지 않는다(`OnWorldEndPlay` 뒤 Spawn된 컴포넌트의 emitter 등록은 무효 id, 재생은 `Ignored`).
  - 엔진 쪽이 scene을 닫는다. 그 scene의 재생은 짧은 fade(`SceneRemoveFadeFrames` = 256)로 모두 `RequestStop`(mailbox, 포화 없음)되고 `Ended(SceneRemoved)`가 된다.
  - 3.4절의 scene epoch는 제어 쪽 scene 표의 epoch로 둔다. RT에는 voice별 mailbox로 전한다(믹서가 voice 단위 stop을 이미 가진다). RT에 scene 단위 원자값을 더할 이유는 voice 수가 커질 때(AU9 측정)이다.
- **emitter 표**(게임 쪽): `AudioEmitterId { slot, generation }` → 위치·전방 축·생존. `AudioComponent`가 등록·갱신·해제한다.
  - 해제하면 그 emitter에 붙은 재생이 `Ended(EmitterRemoved)`가 된다(UE `bStopWhenOwnerDestroyed` 기본 true와 같은 결과).
  - 표는 엔진 쪽 하나다(구현 개정 32 — World마다 두지 않고 `MaxAudioEmitters` = 4096을 모든 World가 나눠 쓴다, scene 표 `MaxAudioScenes` = 64는 엔진 scene 0 포함). 제어 쪽이 emitter id 하나로 위치를 찾게 하려는 것이다. 위치 갱신은 같은 묶음 안에서 emitter마다 하나로 합친다.
- **리스너**: World마다 하나다. `SetListener(const Vec3d& position, const Quatd& rotation)`를 게임·호스트가 프레임마다 부른다. UE에서도 `GameViewportClient`·`PlayerController`가 리스너를 밀어 넣는 쪽이다.
  - 부르지 않았으면 원점·항등 회전이다.
  - Gameplay `PlayerController` 카메라 자동 연결은 Gameplay 쪽 후속이다(Gameplay가 EngineAudio를 모르므로 Sandbox·게임 코드가 연결한다).
- **스냅숏**: `AudioEngineSubsystem::OnFrameEnd`가 등록 scene마다 리스너와 바뀐 emitter 위치를 묶음에 복사한다. 이 시점에는 그 프레임의 World 파괴까지 반영돼 있다(3.8.1절).
- **재생 API**(3.8.3절 모양):
  - `Play2D(sound, options)`.
  - `PlayAt(sound, position, options)`.
  - `PlayAttached(emitter, sound, options)`.
  - `SetParameter(handle, Volume|Pitch, value, rampFrames)`.
  - `Stop(handle, fadeFrames)`.
  - `Status(handle)`.

  World 쪽 호출은 그 World scene 소유다. 엔진 쪽 `Play2D(..., Ownership::Engine)`는 엔진 scene(0번, 종료까지)에 둔다.
- **공간 식**(제어 쪽, 3.13절):
  1. 리스너 기준 상대 위치를 double로 빼고, 리스너 회전의 역으로 돌려 float로 내린다.
  2. 거리 d = |상대|로, 감쇠 gain = `EvaluateDistanceAttenuation(설정, SphereAttenuationDistance(d, innerRadius))`.
  3. mono는 `Azimuth` 모드로, `ComputeAzimuthDegrees(+X, +Y, 상대/d)`를 쓴다. d가 0이면 방위각 0이고 비공간화 1이다.
  4. 비공간화 비율은 UE `FWaveInstance` 갱신(`Engine/Private/Audio.cpp:739–779`)과 같다. S = `nonSpatializedRadiusStart`, E = min(S, `nonSpatializedRadiusEnd`)라 하자.
     - S = 0이면 0이다.
     - E > 0이면 d < S에서 clamp((S − d) / max(S − E, 1), 0, 1)이고, 그 밖은 0이다.
     - E = 0이면 r = clamp(S / d, 0, 10⁶)으로, r > 1에서 1 − 1/r², 그 밖은 0이다.
     - d = 0은 방향이 없으므로 S와 상관없이 1이다(먼저 본다). UE는 이 경우 값을 갱신하지 않는다(Rocks만의 규칙, 7절).
  5. stereo 원본은 `Direct` 모드에 거리 감쇠만 쓴다(stereo spread는 AU7).
  6. `attenuate`가 false면 감쇠 gain 1, `spatialize`가 false면 `Direct` 모드다(둘은 따로 — UE와 같다).
- **Tryout 정리 계약**: Tryout World도 같은 경로다. Tryout Stop = World 파괴 → scene 해제로 그 World 재생과 PCM 참조가 모두 끝난다. World별 장치 분리(`audio.tryout.newdevice`)는 AU9(PR15).

#### 3.35.8 `AudioComponent`(AU3a2)

`ROCKS_CLASS() AudioComponent : SceneComponent`:
- 영속 필드: `volumeMultiplier`(1.0), `pitchMultiplier`(1.0), `autoActivate`(true — UE `bAutoActivate` 기본), `stopOnDisable`(true).
- 실행 데이터(`ROCKS_NATIVE`): `SoundSourceRef sound_`, `PlaybackHandle playback_`, `AudioEmitterId emitter_`.
- 영속 사운드 참조(`SoftObjectRef<SoundSource>` + `AssetLease`)는 AU6에서 준비 티켓과 함께 더한다. World 객체는 에셋을 `ObjectRef`로 가리킬 수 없고([에셋 시스템](../../AssetSystem/06-AssetTypes.ko.md)), AU3에는 비동기 로딩 경로가 없다. AU3은 `SetSound(SoundSourceRef)`로만 정한다(UE `SetSound`).
- API:
  - `Play(startFrame = 0)`: 재생 중이면 먼저 멈춘다(UE `Play`가 이전 재생을 멈추는 것과 같다).
  - `Stop(fadeFrames = DefaultStopFadeFrames)`.
  - `IsPlaying()`: Pending·Playing이다.
  - `SetVolumeMultiplier`·`SetPitchMultiplier`: 재생 중이면 `SetParameter`다.
- 수명:
  - emitter는 컴포넌트의 오디오 시스템 상태다(`SystemStateKind::Audio` — EngineRuntime 23.2절, UE render·physics state와 같은 자리). `CreateSystemState(Audio)`가 등록 직후 emitter를 잡고 현재 world 위치를 넣는다(subsystem이 없거나 scene이 끝났으면 emitter 없이 등록 — 재생은 고정 위치 `PlayAt`·Ignored).
  - `OnTransformUpdated`: emitter 위치를 갱신한다.
  - `OnStart`: `autoActivate`이고 사운드가 있으면 `Play`한다(편집 World는 OnStart가 없어 자동 재생하지 않는다).
  - `OnDisable`: `stopOnDisable`이면 `Stop`한다.
  - `DestroySystemState(Audio)`(해제 직전, `OnUnregister` 전): `Stop(DefaultStopFadeFrames)`과 emitter 해제다(멱등). `MarkSystemStateDirty(Audio)`로 다시 만들면 붙은 재생도 끝난다(emitter가 바뀌므로). fade 0은 click이 나고, 스냅숏이 PCM을 쥐므로 fade 동안 수명 문제가 없다(UE `au.SourceFadeMin`과 같은 최소 fade). 파괴·맵 교체·GC 모두 이 경로를 지난다.
- 위치는 `WorldLocation()`, 방향은 `WorldQuaternion()`이다. shear로 TRS 분해가 실패해도 `WorldLocation`은 행렬 이동 성분이라 그대로 쓴다(3.8.3절).

#### 3.35.9 `AudioEngineSubsystem`과 종료

- **Initialize**:
  1. 실행 판정(3.35.2절)을 한다. 호스트 선택값 `AudioEngineHostOptions`(`HostServices`에 선택 등록 — 시험·도구용)가 있으면 그 재정의를 쓴다. 담는 값은 다음과 같다:
     - render 방식(Thread·Manual).
     - Null 방식.
     - 제어 방식(Thread·Inline).
     - 판정 재정의.
     - 시험용: AudioRT 명령 링 칸 수(`commandCapacity` — Deferred 재현), 제어 묶음 처리 직전 hook(`beforeControlBatch` — 이벤트 gate로 제어 쪽을 멈춰 묶음 부족 재현). 장치 옵션 `AudioOutputDeviceOptions::commandCapacity`가 AudioRT에 넘긴다.
  2. `audioOutput`이면 registry에서 backend를 만들어 `AudioOutputDevice::TryOpen`한다(실패는 Null — 3.33.4절). 장치 열기 로그에 협상값·backend·우선순위를 남긴다.
  3. 끝으로 lane을 시작한다.
  - 실패는 할당 실패·lane 시작 실패뿐이다. 잘못된 부팅 값은 보정하고 Warning을 남기며(아래 "부팅 값 보정"), 장치 실패는 Null로 넘어가므로 초기화 실패가 아니다. 엔진에 설정 문맥이 있으면 그 문맥에 `RegisterEngineAudioSettings`가 되어 있어야 한다(모듈 RegisterSettings — 없으면 CVar 읽기가 Fatal), 없으면 기본값이다.
- **OnFrameBegin**: 반환 묶음을 수거해 결과를 전달하고 슬롯을 놓는다. `Ignored` handle의 Ended도 여기서 낸다. 제어 쪽 계수(`AudioControlStats`)는 제어 쪽이 묶음마다 사본을 실어 보낸 것을 둔다(Thread 제어에서 게임이 원자값 없이 읽어도 경합이 없다. Inline·drain 뒤에는 바로 읽는다).
- **OnFrameEnd**: scene 스냅숏·마스터 gain을 붙여 묶음을 보낸다(3.35.5절).
- **BeginShutdown**: 새 재생을 닫는다(`ShuttingDown`). World 파괴가 내는 scene 해제는 받는다.
- **CompleteInFlightWork**:
  1. 남은 명령과 scene 해제를 마지막 묶음으로 보낸다.
  2. lane `Shutdown`으로 Drain한다. 이 뒤로 제어 쪽 작업이 없으므로 게임 스레드가 context를 직접 쓴다.
  3. `StopAll(DefaultStopFadeFrames)`을 낸다.
  4. render Thread 방식이고 Null Manual이 아니면 두 가지를 차례로 기다린다. 상한은 둘을 합쳐 `ShutdownDrainTimeoutMs` = 500이고 1 ms 대기로 확인한다.
     - 묶음을 처리하며 모든 voice가 terminal을 내고 놓일 때까지.
     - 출력 링이 낸 렌더 frame(`consumedFrames − underrunFrames` — underrun 무음은 렌더한 소리가 아니다)이 idle을 본 순간 한 번 잡은 `CompletedMixFrame`에 닿을 때까지(`IsOutputTailPlayed`). AudioRT는 빈 칸마다 무음 블록도 계속 렌더하므로 목표를 매번 다시 읽으면 늘 앞서 있어 상한까지 기다리게 된다(구현 리뷰). AudioRT가 링을 미리 채우므로(렌더 선행) `CompletedMixFrame`만 보면 fade가 링에 남은 채 끊긴다. 둘 다 장치를 연 순간 0에서 세므로 소비 frame이 렌더 frame을 따라잡은 것이 "fade까지 다 냈다"는 뜻이다.
     이 대기는 꼬리 click을 막는 것일 뿐 수명 장벽이 아니다.
  5. 장치 `Close`를 부른다. backend `Stop`이 콜백 장벽이고, AudioRT join, 그다음 backend `Close` 순이다(3.33.4절).
  6. 제어 쪽 모든 `SharedPtr`를 놓고(믹서는 부르지 않는다 — RT에 닿지 못한 Deferred Play는 terminal이 없어 `UnregisterClip`이 Busy로 남으므로, 믹서는 장치와 함께 파괴하고 참조만 직접 놓는다) 남은 handle을 버린다. 종료 뒤에는 콜백을 부르지 않는다. UE도 종료 때 완료 delegate를 부르지 않는다.
  - 시간 상한을 넘어도 5단계는 그대로 해도 안전하다. 그래서 `CompleteInFlightWork`가 실패를 돌려줄 경로가 없다(PR8 불필요). backend `Stop`이 오류를 돌려줘도 gate는 닫히므로 `Close`를 계속한다. 한계: gate 대기는 진행 중 콜백 하나를 기다리는 상한 없는 spin이다(3.34.2절). OS 콜백이 돌아오지 않는 드라이버 결함이면 해제 뒤 접근이 아니라 종료 멈춤으로 드러난다.
- **Deinitialize**: `CompleteInFlightWork`를 거치지 않았으면(엔진 초기화 실패 정리는 `BeginShutdown`·`CompleteInFlightWork` 없이 Deinitialize만 부른다 — Engine.cpp) 같은 drain(lane Shutdown → 장치 Close → 참조 해제)을 먼저 한다. 실행 중인 `DedicatedLane`을 파괴하면 Fatal이기 때문이다. 그 뒤 묶음·표를 해제한다. `Initialize`가 도중에 실패하면 스스로 만든 것을 역순으로 되돌린다(실패한 Subsystem은 Deinitialize를 받지 않는다 — Subsystem.h).
- **부팅 값 보정**: `audio.mixer.blockframes`가 허용값(64·128·256·512·1024)이 아니면 가장 가까운 허용값으로 바꾸고 Warning을 남긴다(UE가 잘못된 오디오 설정을 clamp하는 것과 같다 — 초기화 실패보다 낫다). `audio.mixer.samplerate`가 0이 아니고 [8000, 192000] 밖이면 0(장치 기본)으로 둔다.
- **호스트 선택값 범위**: `AudioEngineHostOptions`는 프로세스 `HostServices`에 있어 같은 프로세스의 엔진들이 함께 본다. 시험은 엔진마다 등록·해제하는 RAII 보조로 감싼다. Subsystem 생성 정보는 allocator만 넘기므로 이 길을 쓴다.
- **비활성 창**: `SetApplicationForeground(bool)`을 호스트가 창 포커스 사건에서 부른다. Engine에 `IsForeground`가 생기면(AppInfo 8.6절) 그것을 읽는다.

#### 3.35.11 Sandbox(AU3a3)

- `--engine` 실행이 `AudioEngineSubsystem`과 World `AudioWorldSubsystem`을 넣는다. `AudioOutputBackendRegistry`를 `HostServices`에 올리는 일은 `--audio-tone`과 같은 호스트 코드로 한다.
- 소리는 시작 때 만든 메모리 PCM `SoundClip` 둘이다:
  - 짧은 UI 클릭(880 Hz, 80 ms, 감쇠 envelope).
  - mono loop(220 Hz 톱니를 1 kHz LPF로 걸러 방향을 듣기 쉽게 한다).
- 키:
  - `1`: `Play2D` UI음.
  - `2`: 플레이어 주위 반지름 600 cm 원을 4초 주기로 도는 Actor의 `AudioComponent` loop를 켜고 끈다.
  - `3`: 그 Actor를 플레이어 오른쪽(+Y 600 cm)에 고정해 좌우를 확인한다.
- 리스너는 프레임마다 Pawn 카메라 위치·회전으로 넣는다. 창 포커스 사건은 `SetApplicationForeground`로 넘긴다.
- 개발 PC 확인(2026-11-26): `--audio-tone`이 WASAPI 48 kHz·콜백 480 frame·링 3칸으로 열려 2초 동안 underrun 0, `--engine` 헤드리스가 실장치로 열고 닫음(종료 꼬리 40 ms 이내).
- 사용자 확인 항목:
  - 1번 키에 클릭이 들린다.
  - 2번 키에 소리가 좌→우로 돈다.
  - 3번 키에 오른쪽에서만 크게 들린다.
  - 창을 내리면 소리가 끊긴다.
- **서버 미링크**: Server 타깃 실행 파일은 아직 없다(BS7). AU3은 빌드 규칙으로 판정한다.
  - `EngineAudio`는 Runtime 유형이며 ClientOnly에 의존하지 않는다. BD25 의존 규칙이 거부하는 꼴이 아니다.
  - `AudioMiniaudio`는 ClientOnly라 Server 타깃 폐포에 들어가지 못한다(ModuleTypeRules).
  - 실제 서버 실행 파일 확인은 BS7 때 한다.

#### 3.35.12 시험

모두 Inline 제어 + Manual render + Null Manual 장치로 결정적으로 단언한다. 시간 대기 없이 `Pump`·`RenderAvailable`·프레임 진행으로 순서를 만든다.

AU3a1:
- 실행 판정: 대상 5종 × 플래그 조합. Release에서 개발 플래그를 무시한다.
- `SoundPcm`·`SoundClip` 검증: 채널·loop 구간·NaN.
- `MakePlayable`의 감쇠 스냅숏 복사. 원본을 바꿔도 스냅숏은 그대로다.
- 같은 PCM에 loop 구간이 다른 스냅숏 둘: clip 등록 둘, 각자의 구간으로 돈다.
- 사용자 ramp: 긴 `SetParameter` ramp와 `fadeInFrames`가 공간·2D 모두에서 묶음마다 중간값으로 출판된다.

#### 3.35.13 버린 안

- **제어 pipe를 `SerialTaskChain`으로**(3.2절 원안): Engine에 공용 `WorkerScheduler`가 없고(EngineAssets·GC가 각자 둔다), `WorkerScheduler`는 worker 0을 거부하며, Inline 모드가 없다. 순차 실행만 필요하므로 Thread·Inline을 다 가진 `DedicatedLane`이 같은 계약을 더 적은 부품으로 만든다. 3.2절 표의 실행 칸을 이 절로 고친다.
- **게임과 제어가 공유 표를 잠금으로 나눔**: 매 호출 잠금과 우선순위 역전이 생긴다. 묶음 순환은 잠금이 없고, 결과가 묶음 순서대로 와서 시험이 결정적이다.
- **재생 요청에 `SoundClip` 객체 handle을 넘기고 제어 쪽이 PCM을 읽음**: 제어 pipe의 Object 접근 금지(3.2절)를 어기고, GC와 재생 수명이 얽힌다. 불변 공유 스냅숏은 GC와 무관하게 ACK 뒤에 풀린다.
- **AU3에서 PR8 게이트 구현**: 오디오가 Busy를 낼 경로가 없어졌다(3.35.9절). 쓰는 쪽 없는 일반 기능을 먼저 넣지 않는다.
- **scene epoch를 RT 원자값으로**: 믹서가 voice별 stop mailbox(포화 없음)를 이미 가지므로, scene 해제를 voice 수만큼의 mailbox 쓰기로 충분히 표현한다. 측정이 필요해지면 AU9.
