### 3.43 AU7e — 분류·믹스 스냅숏

AU7e는 UE `USoundClass`·`USoundMix`(3.14.2절)를 `SoundCategory`·`MixSnapshot`으로 들인다. 설계 교차 검증 1회를 반영해 두 단계로 나눈다.
- **AU7e1**(3.43.1–3.43.9절):
  - 분류 계층(재생마다 자기 사슬로 계산)
  - 사용자 볼륨 CVar, always-play, UI·Music 분류 값
  - 믹스 스냅숏(push·pop·base, 분류 override, passive 믹스, fade 상태 기계)
  - 분류 감쇠 거리 배수, 기본 분류·기본 base 믹스
  - 앞 단계가 AU7e로 넘긴 것: 컴포넌트 LPF·HPF(3.42.3절), 차폐 검사 간격 재정의(3.42.9절), 스테레오 정규화(3.42.6절)
- **AU7e2**(3.43.10절 — 요구만, 세부는 착수 전 절): 장면 일시정지와 믹서 일시정지

뒤 단계로 넘기는 것:
- 출력 버스(`DefaultSubmix`): AU7f
- 리버브 send(`bReverb`·`Default2DReverbSendAmount`·`bIsMusic`의 리버브 끔), interior 볼륨(`bApplyAmbientVolumes`): AU7h
- 다채널 채널 맵(`LFEBleed`·`VoiceCenterChannelVolume`·조정자 `VoiceCenterChannelVolumeAdjuster`·`bCenterChannelOnly`): AU9
- 레거시(`RadioFilter*`·`bApplyEffects`·SoundMix EQ·`OutputTarget`)는 들이지 않는다(9장). UE 5.8 mixer에서 동작하지 않거나 기본으로 꺼져 있다(`au.DisableSubmixEffectEQ` 1 — `AudioMixerDevice.cpp:61`).

약어:
- SC = `Engine/Private/SoundClass.cpp`, SCh = `Engine/Classes/Sound/SoundClass.h`
- SMx = `SoundMix.cpp`, SMh = `SoundMix.h`
- SW = `SoundWave.cpp`, AD = `AudioDevice.cpp`, AS = `ActiveSound.cpp`, A = `Audio.cpp`
- AMS = `AudioMixer/Private/AudioMixerSource.cpp`, AVL = `AudioVirtualLoop.cpp`

#### 3.43.1 에셋과 스냅숏

**`SoundCategory`**(UE `USoundClass`, 기본값 SC 18–38):

| 필드(UE) | 기본 | 비고 |
|---|---|---|
| `parent` `ObjectRef<SoundCategory>`(`ParentClass`) | null | 루트는 null이다. 순환은 `MakePlayable`이 `InvalidArgument`로 막는다(UE는 에디터가 막는다 — SC 122–145). |
| `volume`(`Volume`, ≥ 0) | 1 | |
| `pitch`(`Pitch`) | 1 | UE는 범위를 두지 않는다. Rocks는 (0, `MaxPitch`]를 받는다. 최종 값은 3.43.2절에서 자른다. |
| `lowPassFrequency`(`LowPassFilterFrequency`) | 20000 | UE는 범위가 없다. Rocks는 [0, 20000]을 받는다. |
| `attenuationDistanceScale`(≥ 0) | 1 | 3.43.6절 |
| `alwaysPlay`(`bAlwaysPlay`) | false | 3.43.4절 |
| `isUiSound`(`bIsUISound`) | false | AU7e2에서 일시정지 면제로 쓴다. AU7e1은 계층 OR만 한다. |
| `isMusic`(`bIsMusic`) | false | AU7h에서 리버브를 끈다. AU7e1은 계층 OR만 한다. |
| `userVolume` `SoundUserVolume` {None, Music, Effects, Dialogue, Interface} | None | Rocks — 3.43.3절 |
| `loadingBehavior`(`LoadingBehavior`) | Inherited | 3.12절 `Inherited`의 계층 탐색 대상이다. |
| `passiveMixes` 배열 {`mix` `ObjectRef<MixSnapshot>`, `minVolumeThreshold` 0, `maxVolumeThreshold` 10}(`PassiveSoundMixModifiers` — SCh 167–190) | 빈 배열 | 3.43.7절 |

- `ChildClasses`는 두지 않는다. Rocks는 자식이 `parent`를 가리키는 한 방향 그래프다. UE는 에디터가 두 방향을 동기화한다.
- **`MixSnapshot`**(UE `USoundMix`, 기본값 SMx 21–33)의 필드:
  - `adjusters` 배열 `MixCategoryAdjuster`(UE `FSoundClassAdjuster` — SMh 129–167)
    - `category`
    - `volume` 1(≥ 0), `pitch` 1([0, 8]), `lowPassFrequency` 20000([0, 20000])
    - `applyToChildren` false
  - `initialDelay` 0, `fadeInTime` 0.2, `duration` −1(음수 = 무한), `fadeOutTime` 0.2(초, 0 이상)
- **분류 사슬**:
  - `SoundSource::category`(`ObjectRef<SoundCategory>` — UE `SoundClassObject`)다.
  - 재생 단위 재정의는 `PlayOptions::category`(`SoundCategoryChainRef`)·`AudioComponent::SetCategory`다(UE `UAudioComponent::SoundClassOverride` — `AudioComponent.cpp:766`, AS 551–562).
  - 둘 다 없으면 엔진 기본 분류다: `AudioEngineSubsystem::SetDefaultCategory`(UE `UAudioSettings::DefaultSoundClass` — `SoundBase.cpp:113–130`, 호스트가 프로젝트 설정에서 단다). 그것도 없으면 "분류 없음"(모든 값 기본)이다.
- **스냅숏**:
  - `SoundCategory::MakeChain(allocator, registry, access)`와 `MakePlayable`은 자기부터 루트까지의 사슬을 `SharedPtr<const SoundCategoryChain>`(`SoundCategoryChainRef`)으로 만든다. 최대 `MaxSoundCategoryDepth` 16이고, 넘으면 `CapacityExceeded`다.
  - 원소는 {키 `AudioObjectKey`, 속성 값 사본}이다. passive 목록의 믹스는 `MixSnapshotRef`로 평탄화한다.
  - 재생은 수락 때의 사슬을 끝까지 쓴다. 에셋을 고치면 새 재생부터 바뀐다(3.35.3절 스냅숏 원칙).
  - passive 믹스가 자기 사슬의 분류를 조정하면 `MakeChain`이 Warning 로그를 낸다(UE 에디터 경고 — SMx 83–130, 막지는 않는다).
- **`MixSnapshotRef`**: `MixSnapshot::MakeRef(allocator, registry, access)` → 불변 공유 값 {키, 조정 목록(분류 키·값), 시간}이다. push·base·override API가 이것을 받는다.
- **재생 옵션**(UE `UAudioComponent` — 분류 값과 OR·min·max로 합친다):
  - `PlayOptions::alwaysPlay`·`isUiSound`(`bAlwaysPlay`·`bIsUISound`)
  - `PlayOptions::lowPassFrequency`·`highPassFrequency`(`Optional<float>` — `bEnableLowPassFilter`·`LowPassFilterFrequency`, `bEnableHighPassFilter`·`HighPassFilterFrequency`, 3.42.3절의 min·max 합성에 들어간다)
  - `PlayOptions::occlusionCheckInterval`(`Optional<float>` — UE `OcclusionCheckInterval`, 3.42.7절)
  - `AudioComponent`도 같은 필드를 가진다.
  - 실행 중 바꾸기: `PlaybackParameter::LowPassFrequency`·`HighPassFrequency`(UE `SetLowPassFilterFrequency`·`SetHighPassFilterFrequency`). 20000·0이 끔이다.
- **스테레오 정규화**: `SoundSource::normalizeStereo`(false — UE `bApplyNormalizationToStereoSounds`, SW 3881–3885). 켜면 2채널 원본의 볼륨이 ×0.5다.

#### 3.43.2 분류 실효값 계산

UE는 오디오 스레드가 프레임마다 다음을 한다.
- `ParseSoundClasses`(AD 2567–2602)로 등록된 모든 분류를 에셋 값으로 되돌리고 계층을 내려간다.
- 활성 믹스마다 `ApplyClassAdjusters`(AD 3021–3179)를 한다.

Rocks는 공유 분류 표를 두지 않는다. 재생마다 자기 사슬로 같은 결과를 계산한다(교차 검증 반영). 같은 사슬 포인터는 묶음 안에서 한 번만 계산한다(캐시). 잎(사슬 0번) 분류의 실효값은 다음과 같다.
1. **사슬 곱**
   - `volume = Π(사슬 원소 volume × 사용자 볼륨(원소의 userVolume))`, `pitch = Π(원소 pitch)`
   - `isUiSound = OR(원소)`, `isMusic = OR(원소)`
   - 계층은 Volume·Pitch만 곱하고 UI·Music만 OR한다(UE `RecurseIntoSoundClasses` — AD 2499–2531). 나머지(`lowPassFrequency`·`alwaysPlay`·`attenuationDistanceScale`·`loadingBehavior`·`passiveMixes`)는 잎 값만 쓴다(AD 2518–2519).
2. **믹스 조정**: 활성 믹스마다 보간 계수 t(3.43.7절)로 계산한다. 대상 조정은 (키가 잎인 조정) ∪ (`applyToChildren`이고 키가 사슬 안에 있는 조정)이다. UE `RecursiveApplyAdjuster`(AD 2604–2635)와 결과가 같다.
   - `volume ×= a·t + 1 − t`, `pitch ×= a·t + 1 − t`(UE `InterpolateAdjuster` — 진폭 선형, AD.h 1673–1676)
   - `lowPassFrequency = min(lowPassFrequency, 20000^(1−t) · clamp(a_lpf, 20, 20000)^t)`(UE `GetInterpolatedFrequency` — 로그 주파수, [`MinFilterFrequency` 20, `MaxFilterFrequency` 20000]로 자른다, AD 3015–3019, `Dsp.h:334–373`)
   - 조정은 이미 계층 전파가 끝난 값에 곱한다. `applyToChildren`이 꺼진 부모 조정은 자식에게 가지 않는다.
   - 믹스끼리는 곱과 min이라 순서와 상관없다. EQ 우선순위는 두지 않는다(레거시).
   - 한 분류에 한 믹스의 조정이 여럿이면 UE처럼 모두 곱한다.
3. **override**: 분류 override(3.43.6절)가 걸린 (믹스, 분류) 쌍은 그 믹스의 조정 값 대신 override의 현재 값을 쓴다. 이 값은 믹스의 t를 받지 않는다.

**재생에 적용** (UE SW 3700–3833, AMS 1405–1424·1505–1532, A 575–592)
- gain에 분류 `volume`(그리고 `normalizeStereo` × 0.5)을 곱한다. 크기 추정 `v`와 W(3.41.1절)에도 곱한다. UE 우선순위는 분류·믹스 볼륨을 포함하고 master는 뺀다(A 1328–1360). Rocks master는 믹서 master gain이라 같다.
- pitch = `ClampPitch(사용자 × 사운드 × 분류 pitch)`다. UE는 장치 `GlobalMinPitch`·`GlobalMaxPitch` 0.4·2.0으로 자른다(AD 381–382). Rocks는 `[MinPitch, MaxPitch]`다. 논리 커서와 재생 시간(3.41.1절)도 이 실효 pitch로 진행한다(UE `MinCurrentPitch` — AD 4324, 가상 seek — AVL 318–327). 3.41.1절의 "실효 pitch"를 이렇게 고친다.
- LPF = `min(공기 흡수, 차폐, 분류 lowPassFrequency, 재생 LPF)`, HPF = `max(공기 흡수, 재생 HPF)`다(A 575–623).
- **dirty**: 그 재생의 분류 실효값이 이번 묶음에 바뀌면 `paramsDirty`다. 활성 믹스가 fade 중이거나, override·거리 배수 ramp가 진행 중이면 영향받는 재생은 묶음마다 dirty다.
- 무음 컬링(3.41.1절)은 분류 볼륨 0도 0으로 본다. UE처럼 always-play도 보호받지 못한다(A 1107–1145). 그래서 사용자 볼륨 0인 분류의 one-shot은 `Inaudible`로 끝난다. UE 관행(사용자 믹스 override)과 같은 결과다.
- 수락 때도 같은 계산을 쓴다(짧은 소리 판정·동시 발음·가상 판정이 분류 값을 본다).

#### 3.43.3 사용자 볼륨

UE에는 분류별 사용자 볼륨 기능이 없다. 관행은 사용자 믹스에 `SetSoundMixClassOverride`를 거는 것이다(GameplayStatics). Rocks는 엔진 기능으로 둔다(7절).
- CVar는 `audio.volume.music`·`effects`·`dialogue`·`interface`다. 모두 1, [0, 1], `UserSetting()`(사용자 설정 층에 저장)이다.
- 게임 쪽이 묶음마다 읽어 넘긴다(`UserVolumeSettings`).
- 사슬 원소의 `userVolume`이 None이 아니면 그 원소의 자기 볼륨에 곱한다(3.43.2절 1단계). 조상과 자손이 같은 `userVolume`을 가지면 두 번 곱해진다. 계층 곱이라 그대로 둔다(자산 작성 규칙 — 한 갈래에 한 번만 단다).
- 믹스보다 먼저 곱하므로 믹스가 사용자 볼륨을 바꾸지 않는다(3.14.2절).
- `audio.master.volume`(3.35.9절)은 지금처럼 믹서 master gain이다.

#### 3.43.4 always-play

실효값은 `PlayOptions::alwaysPlay || 잎 분류 alwaysPlay`다(계층 전파 없음 — SW 3817).
- **voice 배정 W**:
  - always-play면 `W = AlwaysPlayWeight`(UE `FLT_MAX / MAX_VOLUME` — SW 3846–3850)다. 볼륨 가중과 정지 강등이 없다(A 1330–1334).
  - always-play끼리는 동률이다. UE는 불안정 정렬이 순서를 정한다. Rocks는 기존 동률 규칙(먼저 수락한 쪽 — 3.41.1절)이 정한다(7절).
  - 3.41.1절의 "always-play는 P > 100"은 이 규칙으로 바꾼다.
- **동시 발음 우선순위**: `P_c = clamp(H × fps, 0, 100) × P + 101`(UE `GetConcurrencyPriority` — AS 433–443, `GetHighestPriority(true)`). always-play끼리도 상대 순서가 남는다.
- **수락 직후**:
  - UE `GetAlwaysPlay`(AS 1908–1929)는 wave instance가 생기기 전에는 컴포넌트 플래그만 본다. 그래서 첫 동시 발음 평가에서 분류의 `bAlwaysPlay`가 보이지 않는다.
  - Rocks는 수락 때 이미 사슬이 있으므로 처음부터 분류 값을 본다(7절 — 첫 평가만 다르다).
- 가상화(3.41.3절)와 무음 컬링에는 영향이 없다(UE 그대로).

#### 3.43.5 기본 base 믹스

- UE는 장치 생성 때 `UAudioSettings::DefaultBaseSoundMix`(AD 516–519)를 base로 건다.
- World가 바뀌면 `WorldSettings::DefaultBaseSoundMix`가 대신한다(AD 2448–2496, `World.cpp:9000`).
- Rocks는 다음과 같이 둔다.
  - 호스트가 프로젝트 설정에서 `SetBaseMix`를 부른다.
  - 엔진 기본은 `AudioEngineSubsystem::SetDefaultBaseMix`다. 제어가 서기 전에 걸어도 제어가 서면 싣는다.
  - `AudioWorldSubsystem::SetBaseMix`(World 단위 값)는 지금 base를 바꾸고, World가 끝나면 엔진 기본으로 되돌린다. 엔진 기본이 없으면 World 값이 남는다(UE `SetBaseSoundMix(null)`이 아무 일도 하지 않는 것과 같다).

#### 3.43.6 분류 감쇠 거리 배수와 분류 override

**감쇠 거리 배수**(UE `AttenuationDistanceScale`·`SetSoundClassDistanceScale` — AD 2400–2413·7150–7157·7608–7627)
- UE는 장치 수명 동안 모든 분류의 동적 값을 둔다. Rocks는 제어 쪽 영속 표(키 → ramp, `MaxCategoryDistanceScales` 256)에 둔다.
- 표에 칸이 없으면 재생 사슬 잎의 에셋 값을 쓴다.
- `AudioEngineSubsystem::SetCategoryDistanceScale(const SoundCategory&, scale, seconds)`는 게임 쪽에서 키와 에셋 값을 읽어 명령에 싣는다.
  - 칸이 없으면 에셋 값에서 시작해 `seconds` 동안 선형으로 `scale`에 간다(시간은 mix clock — UE device delta와 같은 셈, 7절).
  - 칸은 장치 수명 동안 남는다. 재생 전에 걸어도 남는다.
  - 표가 차면 무시하고 `categoryScaleRejects`를 센다.
- 계층 전파와 믹스 조정이 없다.
- 3.42.2절 거리 배수 s의 "분류 감쇠 배수"가 이 값의 `max(값, 0)`이다(AS 2136–2145).
- 감쇠 gain에만 들어가고 가청 판정(`IsAudible`·가상 판정·짧은 소리)에는 들어가지 않는다. UE는 지역 사본 `FocusDataToApply`에만 곱하고, 가상 판정은 `FocusData.DistanceScale`만 쓴다(AS 2052·2143, AVL 258–272, AD 6272–).

**분류 override**(UE `SetSoundMixClassOverride`·`ClearSoundMixClassOverride` — AD 3839–3964·2955–3013·3039–3114)
- API: `SetMixCategoryOverride(mix, category key, volume, pitch, fadeSeconds, applyToChildren)`·`ClearMixCategoryOverride(mix, category key, fadeSeconds)`
- 볼륨·피치만 덮는다. LPF는 믹스 원래 값을 따른다.
- 그 믹스가 활성일 때만 적용된다. 활성이 아니면 저장만 한다(한 번도 push하지 않은 믹스의 override도 남는다 — AD 3858).
- 저장소는 제어 쪽 고정 표 `MaxMixOverrides` 128이다. 넘치면 무시하고 `mixOverrideRejects`를 센다.
- 처음 적용할 때는 지금 보간된 조정 값(항목이 없으면 1)에서 시작해 override 값으로 `fadeSeconds` 동안 선형으로 간다(mix clock).
- 이미 적용된 override를 다시 Set하면 지금 값에서 새 목표로 새 fade를 시작한다. Clear 진행 중이면 그것을 취소한다(AD 2962–2966·3866).
- `applyToChildren`은 그 항목 값을 덮는다(새 항목·기존 항목 모두 — AD 2997–2998). 믹스에 그 분류 항목이 없으면 기본 1인 항목을 만든다.
- override 값은 믹스 fade의 t를 받지 않는다(UE 그대로). 믹스가 사라지면 적용이 풀리고 저장된 override는 남아 다음 활성 때 다시 fade-in한다.
- Clear: 적용 중이면 믹스 **원래 조정값**(t로 보간하지 않은 값, 없으면 1)으로 `fadeSeconds` 동안 돌아간 뒤 지운다(AD 3928–3943). 그래서 믹스가 fade 중일 때 지우면 값이 튄다(UE 그대로, 7절). 적용 전이면 바로 지운다.

#### 3.43.7 믹스 스냅숏 상태와 push·pop

UE `FSoundMixState`·`UpdateSoundClassProperties`(AD 3181–3246)다.
- 시간은 제어 쪽 mix clock(mix frame)이고 pause와 상관없이 흐른다. UE도 AudioClock이다.
- override·거리 배수 fade는 UE가 device delta(0.5 s로 자름 — AD 7394–7398)를 쓰고 Rocks는 mix clock이다(7절 — 끊긴 프레임에서만 다르다).

**표**
- 제어 쪽 고정 표 `MaxActiveMixes` 64다. 넘치면 그 push·passive 활성화·base를 무시하고 `mixRejects`를 센다.
- 칸은 {키, `MixSnapshotRef`, active 참조, passive 참조, base 여부, 상태 시각}이다.
- 같은 키의 다른 `MixSnapshotRef`(에셋을 고친 뒤의 push, 사슬의 passive 사본)가 오면 가장 최근 push·base·passive 활성화의 ref로 바꾼다. 시각과 참조는 그대로다.

**상태**
- 상태는 `Inactive`·`FadingIn`·`Active`·`FadingOut`·`AwaitingRemoval`이다.
- 시작하면 다음 시각을 잡는다(UE `ApplySoundMix` — AD 2692–2719).
  - `FadeInStart(FIS) = now + initialDelay`, `FadeInEnd(FIE) = FIS + fadeIn`
  - `duration ≥ 0`이면 `FadeOutStart(FOS) = FIE + duration`, `End = FOS + fadeOut`이다. 아니면 둘 다 없음이다.
- t는 상태별로 다음과 같다.
  - Inactive 0
  - FadingIn `(now − FIS) ÷ (FIE − FIS)`
  - Active 1
  - FadingOut `1 − (now − FOS) ÷ (End − FOS)`
  - AwaitingRemoval 0
- `Active` 조건: `now ≥ FIE`이고, (base이거나, 참조 > 0이고 FOS 없음, 또는 `now < FOS`)다. base도 지연과 fade-in을 거친다(AD 3197–3208).
- `AwaitingRemoval`이고 passive 참조가 0이면 지운다(active 참조가 남아 있어도 — UE 그대로, AD 3236–3245).

**API** (`AudioEngineSubsystem` — 엔진 전역, UE 장치 단위. 모두 제어 쪽 명령이다)
- `PushMix`(active 참조 +1)
  - 처음이면 상태를 시작한다.
  - 이미 있으면 다시 걸기다(UE `UpdateSoundMix` — AD 2721–2773).
    - Inactive(지연 중): 아무 일도 없다. UE는 `StartTime`만 바꾸고 `FadeInStartTime`은 그대로 둔다(AD 2724–2729). 그래서 지연이 있는 passive 믹스가 새 재생마다 다시 걸려도 시작한다.
    - `duration < 0`이고 FadingIn·Active: 잡힌 fade-out이 있으면 거둔다(UE `FOS = End = −1` — AD 2721–2734). 같은 묶음의 pop 뒤 push가 이 경우다.
    - `duration ≥ 0`이고 FadingIn·Active: `FOS = now + fadeIn + duration`, `End = FOS + fadeOut`으로 늘린다(UE 그대로).
    - FadingOut·AwaitingRemoval: Rocks는 지금 레벨에서 이어 다시 fade-in한다.
      - 식: `FIS = now − t × fadeIn`, `FIE = FIS + fadeIn`
      - `duration ≥ 0`이면 `FOS = FIE + duration`, `End = FOS + fadeOut`
      - UE는 두 경우 모두 레벨이 튄다. `duration ≥ 0`은 `FIS = now`로 두고 FIE를 고치지 않아 다음 갱신에 바로 t = 1이다(AD 2744–2754). `duration < 0`은 `1 − t`로 역전된다(AD 2763). Rocks는 연속으로 둔다(7절).
- `PopMix`(active 참조 −1)
  - 참조가 0이면 아무것도 하지 않는다(AD 3984–3997).
  - 무한(`duration < 0`)이고 참조가 모두 0이며 base가 아니면 끝낸다(UE `TryClearingSoundMix` — AD 2832–2879).
    - `fadeOut ≤ 0`이거나 Inactive면 바로 지운다.
    - FadingIn이면 지금 레벨에서 이어 fade-out한다: `FOS = now − (1 − t) × fadeOut`, `End = FOS + fadeOut`. fade-in은 여기서 끝낸다(`FIS = FIE = FOS` — UE AD 2853–2856).
    - Active면 `FOS = now`다.
    - FadingOut이면 아무것도 하지 않는다(AD 2865–2868).
  - `duration ≥ 0`인 믹스는 pop으로 지우지 않는다(스스로 끝난다).
  - fade-out을 잡으면 상태를 바로 FadingOut으로 바꾼다(t는 그대로). 같은 묶음의 다시 걸기가 연속 경로를 탄다.
- `ClearMix`(active 참조 0, passive·base는 둔다)와 `ClearAllMixes`
- `SetBaseMix`(UE `SetBaseSoundMix` — AD 3735–3783)
  - null이면 아무것도 하지 않는다. 같은 믹스를 다시 base로 정해도 아무 일도 없다(AD 3751).
  - 이전 base는 base를 풀고 pop 규칙대로 끝낸다.
  - base는 duration·pop·clear를 무시한다. 상태가 없으면 시작한다. fade-out 중인 믹스를 base로 정하면 UE는 t = 1로 튄다. Rocks는 다시 걸기 규칙(연속)을 쓴다(7절).

**passive 믹스**(UE `UpdatePassiveSoundMixModifiers` — AD 2775–2830)
- 제어 쪽이 voice 배정 뒤에 계산한다.
- 대상은 이번 묶음에 배정 자리 안에 든 재생이다(UE `FirstActiveIndex` 이상 — 아직 시작하지 않은 것도 들어간다, AD 2780–2783).
- 그 재생의 **잎 분류** `passiveMixes`(부모는 보지 않는다)마다 `v`(분류·믹스·감쇠·차폐 포함, master 제외)를 본다. `[min, max]`(경계 포함) 안이면 활성이다.
- 이번 묶음 집합과 지난 묶음 집합을 비교해 새것은 passive push, 사라진 것은 passive pop을 한다. 그래서 passive 참조는 0 또는 1이다.
- 집합 안의 재생이 이번 묶음에 처음 배정됐으면 다시 걸기를 한다(UE `PlaybackTime == 0` — duration 연장).
- 반영은 다음 묶음이다(UE도 한 프레임 늦다). 믹스가 그 분류 볼륨을 바꿔 생기는 되먹임은 UE처럼 막지 않는다.

#### 3.43.8 구조·처리 순서·계수

- **파일**
  - 에셋: `AudioAssets`의 `SoundCategory`·`MixSnapshot`·`SoundCategoryPassiveMix`·`MixCategoryAdjuster`·`SoundCategoryChain`·`MixSnapshotData`(`MixSnapshotRef`)·`SoundCategoryTypes`(한 클래스 한 파일), 값 검사 공용 `AudioAssetsValidation.h`
  - 제어 쪽: `AudioCategories.cpp`(사슬 실효값·캐시·거리 배수 표), `AudioMixes.cpp`(믹스 표·상태·override·passive)
- **게임 → 제어**
  - 명령: `PushMix`·`PopMix`·`ClearMix`·`ClearAllMixes`·`SetBaseMix`·`SetMixCategoryOverride`·`ClearMixCategoryOverride`·`SetCategoryDistanceScale`. 믹스 명령은 `MixSnapshotRef`를 싣는다.
  - 묶음 값: `UserVolumeSettings`가 더해진다.
  - Play 명령은 사슬 ref와 재생 옵션 필드를 싣는다.
- **묶음 처리 순서**(3.41.4절)
  1. 명령 앞에 "믹스 상태 갱신"을 둔다(UE `UpdateSoundClassProperties`가 parse 앞). 그래야 수락 판정이 이번 묶음 값을 본다.
  2. 믹스 명령은 그 자리에서 상태를 바꾼다.
  3. 공간 갱신(3단계) 앞에서 재생마다 분류 실효값을 다시 계산한다(사슬 캐시).
  4. passive 집합은 voice 배정 뒤에 계산한다.
- **계수**: `activeMixes`, `mixRejects`, `mixOverrideRejects`, `categoryScaleRejects`
- **구현 세부**(개정 43):
  - 믹스 명령은 명시 판정(`IsMixCommand`)으로 묶음 앞에서 따로 적용한다.
  - passive 대상은 배정 자리 안이면서 정지 요청·steal fade 중이 아닌 재생이다.
  - "처음 배정"은 수락 뒤 첫 배정(재생 시간 0)이다. 가상에서 실현된 재생은 아니다(UE `PlaybackTime == 0`).
  - passive 믹스는 표에 실제로 걸렸을 때만 집합에 넣는다.
  - override는 그 분류의 첫 조정만 덮는다(UE는 첫 항목에서 멈춘다). Clear 중에 믹스가 사라지면 해제가 끝난 것으로 지운다.
  - base 교체는 새 base를 둘 칸이 없으면 이전 base도 건드리지 않는다.
  - 믹스 시간은 `MaxMixSnapshotSeconds`(하루) 이하다.
  - `SetDefaultCategory`는 사슬을 검사하고, `MakeChain`은 만들 때 전체 규칙을 검사한다.
  - override·거리 배수 API는 등록되지 않은 분류(null handle)를 거부한다.
  - `AudioComponent::SetLowPassFilter`·`SetHighPassFilter`가 재생 중에도 바로 반영한다.
  - 분류의 로딩 동작은 `SoundSource::CategoryLoadingBehavior`로 읽어 `SoundCookedLoadOptions::categoryLoading`에 넣는다(로드는 호스트가 부른다).

#### 3.43.9 시험(AU7e1)

- **에셋**: 필드 리플렉션·기본값·범위 밖 `InvalidArgument`, 순환 부모 `InvalidArgument`, 깊이 초과 `CapacityExceeded`, 사슬 스냅숏(에셋을 고친 뒤 새 재생만 바뀜), passive 되먹임 Warning.
- **계층**: Volume·Pitch 곱, UI·Music OR, LPF·alwaysPlay·감쇠 배수는 잎 값만, 기본 분류·`PlayOptions::category`·컴포넌트 재정의의 우선순위.
- **사용자 볼륨**: CVar 넷이 분류와 자손에 곱해지고 믹스가 그 값을 바꾸지 않음, None 분류는 영향 없음, 사용자 볼륨 0의 one-shot은 `Inaudible`.
- **믹스 상태 기계**: 지연·fade-in·active·duration·fade-out·제거. 경계 frame은 손으로 계산한 표와 비교한다.
- **보간**: 진폭 선형, LPF 로그 보간과 20 Hz 하한(조정값 0), 여러 믹스의 곱·min, `applyToChildren` 켜짐·꺼짐.
- **push·pop**
  - 참조 수
  - 다시 걸기: duration ≥ 0 연장, 무한 Active 다시 걸기 무시, Inactive 시작 시각만, fade-out 중 다시 걸기의 연속(duration 양수·음수)
  - pop: 연속, 없는 믹스·참조 0 pop 무시, duration ≥ 0은 pop 무시
  - Clear·ClearAll
  - base: 지연·fade-in을 거침, 같은 믹스 재설정 무시, 교체 때 이전 base가 끝남
  - 표 가득 `mixRejects`
- **override**: 적용 전 저장, 활성 때 현재 값에서 fade-in, 믹스 t 무시, 다시 Set하면 현재 값에서 ramp, clearing 중 Set은 취소, 기존 항목의 `applyToChildren` 덮기, Clear 목표는 원래 값, 적용 전 Clear는 즉시, 표 가득 계수.
- **passive**: 임계 경계 포함, 잎 분류만, 배정 자리 안(시작 전 포함), 다음 묶음 반영, 새 재생의 duration 연장, 사라지면 pop.
- **always-play**: W 상수, 동률은 수락 순, `P_c + 101`, 무음 컬링 보호 없음.
- **pitch**: 분류 pitch가 voice pitch·논리 커서·재생 시간에 들어간다. 분류 pitch가 있을 때 SeekRestart 복귀가 bit까지 같다.
- **dirty**: 믹스 fade 중 voice gain이 묶음마다 따라간다.
- **감쇠 배수**: ramp가 거리 감쇠 gain에 반영됨, 가청·가상 판정에는 반영 안 됨, 재생이 없을 때 걸어도 남음, 표 가득 계수.
- **재생 옵션**: 컴포넌트 LPF·HPF와 SetParameter, 차폐 간격 재정의, 스테레오 정규화 ×0.5.
- **회귀**: 분류가 없는 재생의 출력은 AU7d와 bit까지 같다.

#### 3.43.10 AU7e2 — 장면 일시정지(요구, 세부는 착수 전 절)

교차 검증이 찾은 요구를 남긴다. AU7e2 절이 이것을 모두 정해야 한다.
- **입력**
  - `AudioWorldSubsystem`이 `World::IsPaused()`를 scene 스냅숏에 싣는다. 지금은 tick이 없어 갱신 지점이 필요하다.
  - `SetScenePaused`와 World 값을 어떻게 합칠지(OR 등), 단일 스텝 frame(`World.h:706–714`)을 어떻게 다룰지 정한다.
  - UE `bGlobalPause`(AD 4129–4152)를 들일지 정한다.
- **대상**: UI가 아닌 재생이다(UE `IsGameOnly` — `Audio.cpp:524`, wave의 class OR 값).
  - UE는 재생 시간 동결을 `ActiveSound->bIsUISound`만으로 판정한다(AD 4227–4231). 또 pause 중 UI 소리의 PlaybackTime도 멈춘다(AD 4310). 이 차이를 어떻게 할지 정한다.
- **시계**: 재생 단위 ramp·기한은 절대 mix frame이다(`ValueRamp`·`DecibelRamp`·`virtualCheckFrame`·`occlusionCheckFrame`). scene clock(mix frame − 일시정지 누적)으로 평가할지 항목마다 정하고 UE와 다른 것은 7절에 적는다. UE는 다음과 같다.
  - 멈추는 것: 컴포넌트 fader·focus(delta 0), 차폐(PlaybackTime 기준 — AS 1592, AD 4310)
  - 계속 가는 것: 동시 발음 scalar(게임 delta — AD 2687), 가상 loop(device delta로 갱신되고 pause 중에도 실현 — AD 7469)
- **배정**
  - UE PausedUpdate도 정렬·컬링·동시 발음을 한다(AD 4887·4236–4240).
  - 상한 밖 paused source는 멈춘다. 자리 안의 UI 아닌 재생은 자리를 차지하되 시작하지 않는다(AD 4570).
  - 무음 one-shot은 끝난다(SW 4003–4023).
  - Deferred는 `AbandonPreparedPlay`한다.
- **시작 전 voice**: Deferred·`awaitingStart_`·스트림 `awaitingStream`(`AudioMixer.cpp:1310–1318`)은 pause 중 `PublishStart`·원본 소비를 하지 않고, Started는 풀릴 때 낸다.
- **믹서 일시정지**
  - pause fade는 `slot.gain`과 다른 ramp다(공간 재생은 묶음마다 gain을 다시 낸다).
  - Stopping voice는 pause를 무시한다(UE `FMixerSource::Pause` — AMS 1223–1240).
  - paused voice에 Stop이 오면 원본을 읽지 않고 fade frame만 진행한 뒤 terminal을 낸다. UE는 pause를 풀고 512 frame 꼬리를 낸다(AMS 1182–1189). 이 차이를 7절에 적는다.
  - pause 중에는 굶음·시작 지연 계수를 세지 않는다.
  - seqlock은 pan mode word의 bit로 싣는다(11 word 유지).
  - UE는 fade 없이 바로 멈춘다(`AudioMixerSourceManager.cpp:2059–2071`). Rocks는 짧은 fade(`PauseFadeFrames`)를 둔다(7절).
- **커서**: 믹서가 pause가 실제로 걸린 frame과 풀린 frame을 SharedVoice에 게시하고(startMixFrame처럼) 제어 쪽 논리 커서가 그 값으로 맞춘다(반복 pause 뒤 SeekRestart bit 일치).
- **시험**
  - Deferred·시작 대기 재생은 Started 없이 머물다 풀릴 때 Started
  - pause 중 Stop의 terminal(꼬리 없음), fade 중 자연 끝, StopAll
  - 한 블록 안의 pause·해제, Stopping voice의 pause 무시, 굶음 계수 불변
  - 기한 동결 표, 반복 pause 뒤 커서 일치
  - paused 재생과 UI 재생의 자리 경쟁, pause 중 무음 믹스로 one-shot이 끝남
  - World·`SetScenePaused` 우선순위
