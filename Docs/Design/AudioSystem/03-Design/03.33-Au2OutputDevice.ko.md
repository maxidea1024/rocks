### 3.33 AU2 구현 세부 — 출력 장치·AudioRT(개정 28)

AU2를 둘로 나눈다. **AU2a**(이 절)는 Audio 모듈 안의 장치 경로다. backend 인터페이스, 출력 링, AudioRT 스레드, 명령 링과 정렬 pending 배열, `NullAudioOutput`, 그리고 이것을 묶는 `AudioOutputDevice`가 들어간다. **AU2b**는 ThirdParty `Miniaudio`와 ClientOnly 모듈 `AudioMiniaudio`(Windows WASAPI 먼저), `HostServices` 등록, Sandbox 시험음이다. 선행(PR3 SY7, PR21 SY12)은 [동기화](../../Synchronization/15-Phases.ko.md) 병합(46dd9f81)으로 풀렸다.

#### 3.33.1 공개 형식(`Audio/AudioOutput.h`)

- `AudioSampleFormat { Float32, Int16 }`. AU2는 backend에 Float32를 요청한다(miniaudio가 장치 형식으로 바꾼다). Int16은 backend가 Float32를 못 줄 때만이고 변환은 출력 링 복사에서 한다.
- `AudioDeviceId`: 고정 크기 UTF-8 칸(`MaxAudioDeviceIdBytes` = 256 + NUL). 빈 값 = 기본 장치. 장치 id는 backend가 만든 불투명 문자열이다(WASAPI endpoint id 등).
- `AudioDeviceInfo { AudioDeviceId id; 이름(MaxAudioDeviceNameBytes = 256); bool isDefault; }`.
- `AudioOutputRequest { sampleRate(0 = 장치 기본), layout, callbackFrames(= Q), AudioDeviceId device }`.
- `AudioOutputFormat { sampleRate, layout, callbackFrames, sampleFormat }`(협상 결과). `callbackFrames`는 backend가 정한 주기(최대값)이고, 콜백은 그보다 적은 frame을 달라고 할 수 있다.
- `AudioOutputView { void* data; uint32 frames; uint32 channels; AudioSampleFormat format; }` — 교차(interleaved) 버퍼.
- `class AudioOutputCallback { virtual void Fill(const AudioOutputView&) noexcept = 0; }` — 장치 콜백 스레드에서 불린다. 잠금·할당·대기·로그가 없어야 한다.
- `class AudioOutputBackend`(3.7.1절 그대로): `Open(request, callback) → Result<AudioOutputFormat>`, `Start`, `Stop`(돌아오면 콜백이 진행 중이지 않고 다시 불리지 않는다), `Close`, `EnumerateDevices(Span<AudioDeviceInfo>) → Result<uint32>`(기록한 수, 모자라면 앞에서부터), `const char* Name()`(실제 선택된 OS backend 이름 — 로그용).
- `using AudioOutputBackendFactory = Result<UniquePtr<AudioOutputBackend>> (*)(Allocator&) noexcept;`, 그리고 `HostServices`에 등록하는 `AudioOutputBackendRegistry`(factory 하나를 쥔다, 3.33.6절).

#### 3.33.2 출력 링(`Audio/AudioOutputRing.h`)

- 칸 `bufferCount`개 × Q frame × 채널 float. 생산자(AudioRT)는 블록 하나를 통째로 쓰고 소비자(장치 콜백)는 아무 frame 수나 복사한다(블록 안 읽기 위치 `readOffset`은 소비자 지역 상태 — 3.2절).
- 순번: `written`(쓴 블록 누계)·`read`(다 읽은 블록 누계) `Atomic<uint64>`. 생산자는 칸을 다 쓴 뒤 `written`을 release로 올리고, 소비자는 acquire로 읽은 뒤 칸을 읽는다. 소비자는 칸을 다 읽은 뒤 `read`를 release로 올리고 생산자는 acquire로 본다(BoundedSpscQueue와 같은 짝).
- 칸 수: `ChooseOutputBufferCount(callbackFrames, Q, requested)` = `max(MinOutputBufferCount, ceil(callbackFrames/Q) + 1, requested)`를 `MaxOutputBufferCount`(16)로 자른다(3.2절).
- 소비 `Read(view)`: 칸이 있으면 복사하고, 비면 나머지를 무음으로 채우고 `underrunFrames`·`underrunCallbacks`를 센다. 블록 하나 이상을 비웠으면 끝에서 깨우기 신호를 한 번 보낸다(`RealtimeWakeSignal::Signal`). 장치 형식이 Int16이면 [−1, 1]로 자른 뒤 32767을 곱해 0에서 먼 쪽으로 반올림한다(NaN은 0 — 믹서가 비유한 값을 이미 정리하지만 float→int 변환에 NaN을 넘기지 않는다).
- 열기 때 모든 칸을 무음으로 채우지 않는다. 대신 AudioRT가 backend Start 전에 링을 다 채운다(3.33.4절 순서). 그래서 첫 콜백은 underrun이 아니다.

#### 3.33.3 AudioRT(`Audio/AudioRenderThread.h`)

- 전용 `platform::Thread`, 이름 `AudioRT`, `ThreadPriority::Highest`. 시작 직후 실제 우선순위를 읽어 기록한다(`platform::TryGetCurrentThreadPriority` — PlatformBase에 더한다. OS가 거부해도 Start는 성공하므로 장치 열기 로그가 이 값을 남긴다, 3.2절).
- 루프 전체를 `RunWithRealtimeAudioFloatingPoint` 안에서 돈다(FTZ, 3.22절). 루프 안에서 할당·잠금·로그가 없다.
- 한 바퀴: 링에 빈 칸이 있는 동안 [명령 링에서 꺼내 pending에 정렬 삽입 → `ImmediateMixFrame`을 블록 시작으로 바꿈 → `RenderBlock(pending 앞부분, 칸)` → 소비한 앞부분 제거 → 칸 공개]. 빈 칸이 없으면 `RealtimeWakeSignal::Wait(RenderWaitTimeoutMs)`.
  - Immediate 변환은 pending에 넣을 때 한다. 넣는 순간의 다음 블록 시작 frame이다. 그래서 Immediate 명령은 그 뒤 블록에서 늦지 않게 실행되고, 이미 pending에 있는 미래 명령 뒤에 갇히지 않는다.
  - pending 배열: 용량 `AudioRtPendingCapacity` = 명령 링 용량. (mixFrame, sequence) 오름차순을 유지하는 삽입이다(이진 탐색 + 뒤로 밀기 — 할당 없음). 차면 명령 링 소비를 멈추고 `pendingFullStalls`를 센다. 꺼내지 않은 명령은 링에 남아 다음 블록에서 다시 본다.
- 명령 링: `BoundedSpscQueue<AudioRtCommand>`, 용량 `AudioRtCommandCapacity` = 1024(2의 거듭제곱). 생산자는 제어 쪽 한 스레드다(Inline이면 호출 스레드, 스레드 모드면 제어 pipe). 가득 차면 `Submit`이 `Busy`다(제어 쪽이 미룬다 — 3.22.1절).
- 대기 시간 초과: `RenderWaitTimeoutMs` = 500. 링이 찬 채로 이 시간 동안 깨우기가 없으면 장치 콜백이 멈춘 것으로 보고 `stalledWaits`를 세고 계속 기다린다. 장치 교체·Null 전환은 AU9의 제어 쪽 일이다(3.7.3절).
- 정지: `stopRequested`를 release로 세우고 깨우기를 보낸 뒤 Join한다. AudioRT는 바퀴마다 이 값을 acquire로 본다.
- 계수(`AudioRenderCounters`, 원자값 스냅샷): 렌더 블록 수, pending 가득 참, 대기 시간 초과. 링 underrun·소비 frame은 소비자 쪽 값이라 출력 링의 `AudioOutputRingCounters`로 따로 둔다(장치는 둘을 `RenderCountersSnapshot`·`RingCountersSnapshot`으로 낸다). `Initialize`가 계수와 기록한 우선순위를 0으로 되돌린다(Null로 다시 열 때 앞 시도 값을 남기지 않는다).

#### 3.33.4 장치 묶음(`Audio/AudioOutputDevice.h`)

`AudioOutputDevice::TryOpen(mixerConfig, backend, request, options, allocator)`:
0. 믹서 설정의 layout이 Mono·Stereo가 아니면(3.22.2절, 다채널은 AU9) `InvalidArgument`다(Null로도 열 수 없는 설정 오류). backend에는 믹서 설정의 layout을 요청한다(`request.layout`은 쓰지 않는다).
1. backend가 있으면 `Open(request, ringCallback)`. 믹서는 협상 rate·layout으로 만든다(장치가 rate와 출력 채널 수를 정한다 — UE `FMixerDevice`가 장치 채널 수로 믹서를 여는 것과 같다). 협상 layout이 Mono·Stereo가 아니거나 rate가 믹서 범위 밖이면 backend를 닫고 Null로 간다.
2. backend가 없거나 `Open`·`Start`가 실패하면 `NullAudioOutput`(3.33.5절)으로 연다. 요청 rate가 0(장치 기본)이면 Null에는 믹서 설정의 rate를 준다. 실패 코드와 원래 OS 코드는 결과 정보(`AudioOutputDeviceInfo`)에 남기고 Warning 로그를 한 번 남긴다. 상태는 `Unavailable`(Null로 진행)이다. backend가 돌려준 `InvalidArgument`는 장치 설정 오류가 아니므로 `Unsupported`로 바꿔 남긴다.
3. 믹서·출력 링·명령 링·pending을 만든다(만든 것을 되돌린다). `InvalidArgument`(믹서 설정)와 `OutOfMemory`는 Null로도 같으므로 Null로 가지 않고 그대로 돌려준다.
4. AudioRT를 시작하고 링이 다 찰 때까지 기다린다(첫 바퀴는 대기 전에 링을 채운다. 시작 대기는 `ManualResetEvent` 하나 — 제어 쪽 대기라 허용). 수동 방식은 같은 자리에서 `RenderAvailable`을 한 번 돈다.
5. backend `Start`. 실패하면 backend를 먼저 닫고(Start가 콜백을 시작한 뒤 실패했을 수 있다 — `Close`는 콜백 종료 장벽을 포함한다) AudioRT를 멈추고 링·믹서를 거둔 뒤 Null로 다시 연다.
- `Close()`: backend `Stop`(콜백 종료 확인) → AudioRT 정지·Join → backend `Close` → 할당 반환. 장치 콜백이 끝난 뒤에만 링을 지운다(3.7.1절의 Stop 장벽).
- 제어 쪽 API: `Mixer()`(제어 쪽 메서드만 — `PreparePlay`·`Make*`·`PublishParams`·`RequestStop`·`CollectFinished`·`CountersSnapshot`), `Submit(const AudioRtCommand&) → Result<void>`(Busy), `Info()`(협상값·backend 이름·실제 우선순위·bufferCount), `RenderCountersSnapshot()`.
- 장치 로그는 열기·닫기 때 제어 쪽에서 한 번 남긴다(영어, 협상 rate·layout·callbackFrames·bufferCount·backend 이름·AudioRT 우선순위).

#### 3.33.5 NullAudioOutput

- `AudioOutputBackend` 구현이다. 두 방식이다.
  - **타이머**(기본, 장치가 없을 때 시간 진행): 자체 스레드(`AudioNullOutput`, `Normal` 우선순위)가 `callbackFrames` 블록 기간마다 콜백을 부른다. 기간은 단조 시계로 누적 시한을 계산하고 남은 시간만 `platform::PreciseSleeper`로 잔다. 일찍 깨면 다시 자고(돌며 기다리지 않는다), 늦어도 다음 시한은 누적이라 드리프트가 쌓이지 않으며 주기 몇 개 늦음은 이어 부르며 따라잡는다. `NullResyncNanoseconds`(100 ms)를 넘게 늦으면(절전 복귀·디버거 정지) 시한을 지금으로 다시 맞춘다. 실시간 재생의 시간 진행 자체가 목적이라 시간 기반 동작이 맞는 자리다.
  - 대기 해상도: Windows `Sleep`은 기본 timer tick(약 15.6 ms)으로 깨어 128–256 frame 주기(2.7–5.3 ms)를 지킬 수 없다(리뷰 지적 — 매 주기 재정렬로 Null 시계가 실시간보다 느려지고, ms 아래 남은 시간을 양보로 돌면 코어를 쓴다). UE는 프로세스 전체에 `timeBeginPeriod(1)`을 걸어 이 문제를 피한다. Rocks는 프로세스 전역 설정을 바꾸지 않고 `PreciseSleeper`(PlatformBase)가 고해상도 waitable timer(`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`, Windows 10 1803+, 없으면 보통 waitable timer)로 잔다. POSIX는 `nanosleep`이다. 버린 안: `timeBeginPeriod(1)`(전역 전력 비용·다른 코드에 영향), 남은 시간 spin(코어 낭비).
  - **수동**(시험): 스레드 없이 `Pump(frames)`를 부르는 스레드가 콜백을 부른다. 시험은 이것으로 링 소비·underrun·깨우기를 결정적으로 만든다.
- 버퍼는 Float32 교차, 크기 `callbackFrames` × 채널을 `Open`에서 할당한다. 소비한 PCM은 버린다(시험용 캡처 칸을 선택으로 둔다: `CaptureTo(Span<float>)`).
- UE `FMixerNullCallback`과 같다(UE는 장치 실패 때 자동으로 Null로 바꾼다).

#### 3.33.6 backend 등록(AU2b와의 경계)

- `AudioOutputBackendRegistry`는 `HostServices` 서비스다(`ROCKS_DECLARE_HOST_SERVICE`). 호스트(엔진)가 만들어 등록하고, ClientOnly 모듈 `AudioMiniaudio`의 Startup이 factory를 넣는다(AD24 — Runtime 모듈 `Audio`는 ClientOnly 모듈을 링크하지 않는다).
- factory가 없으면(서버·장치 모듈 없음) `AudioOutputDevice`는 backend 없이 열고 Null로 진행한다.

#### 3.33.7 시험(AU2a)

| 범주 | 내용 |
|---|---|
| 링 | 칸 수 계산 표(Q·callbackFrames 조합, 상한·하한·요청값), 블록 경계와 다른 콜백 크기의 연속 복사가 블록 순서·내용과 같음, 빔 → 무음·underrun 수, Int16 변환(자르기·반올림), 깨우기 신호 횟수 |
| pending | 정렬 삽입 순서(같은 mixFrame은 sequence), Immediate 변환 시점, 가득 참 → 링에 남김·계수, 다음 블록에서 이어 소비 |
| AudioRT | 수동 Null로 링을 결정적으로 소비하며: 명령 시각대로 Play가 시작(Inline `OfflineAudioRender`와 mix frame 지정 명령의 PCM 일치 — 3.2절), 정지·Join 뒤 자원 반환, 우선순위 기록 |
| 장치 | backend 없음 → Null, `Open` 실패 backend(시험 가짜) → Null·오류 코드 보존, `Start` 실패 → Null, 협상 rate ≠ 믹서 rate → 믹서를 협상 rate로, 지원하지 않는 layout → Null, `Close`가 `Stop`을 먼저 부름(가짜 backend 호출 순서 기록), Q ≠ callbackFrames(256·480)에서 underrun 0(수동 Pump로 결정적으로) |
| 타이머 Null | 짧은 실제 실행: 블록 기간 누적 시한으로 콜백 수가 경과 시간에 맞음(허용 범위는 넉넉히 — 시간 운에 기대는 단언은 하지 않고 "적어도 한 번 불림·멈춘 뒤 다시 불리지 않음"만 본다) |

#### 3.33.8 버린 안

- AudioRT가 `ManualResetEvent`로 대기: Signal이 내부 잠금을 잡는다(3.2절, D27). `RealtimeWakeSignal`을 쓴다.
- 출력 링을 장치 형식(Int16 등)으로 저장: 믹서는 늘 float이고 장치마다 형식이 다르므로 변환은 마지막 복사 한 곳이 맞다.
- pending을 힙 정렬(우선순위 큐): 앞부분을 통째로 `RenderBlock`에 넘기려면 정렬된 연속 배열이 필요하다. 명령 수가 블록당 수십 개라 삽입 비용이 작다.
