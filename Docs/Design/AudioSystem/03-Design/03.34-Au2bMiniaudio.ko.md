### 3.34 AU2b 구현 세부 — miniaudio 장치 backend(개정 31)

AU2b는 3.33절의 `AudioOutputBackend`를 실제 장치에 잇는다. ThirdParty `Miniaudio`, ClientOnly 모듈 `AudioMiniaudio`(`MiniaudioOutput`), `HostServices` 등록, Sandbox 시험음이 들어간다. 장치 교체·재시도(3.7.3절)와 엔진 연결(`AudioEngineSubsystem`)은 AU3 이후다.

#### 3.34.1 ThirdParty `Miniaudio`

- 판: miniaudio 0.11.26(2026-10-31 태그, commit `877ea4a7c260`). GitHub 태그 archive를 받아 SHA-256을 기록한다. 들여오는 파일은 `miniaudio.h`와 `LICENSE`뿐이다(`miniaudio.c`는 구현 매크로를 켜고 머리를 include하는 두 줄이라 glue가 대신한다. 예제·시험·extras·외부 디코더는 들여오지 않는다).
- 사용권: Unlicense 또는 MIT-0 중 택일(SPDX `Unlicense OR MIT-0`), 바이너리 고지 불필요.
- glue `MiniaudioGlue.c`가 `MINIAUDIO_IMPLEMENTATION`으로 구현을 한 번 컴파일한다.
- 정의: 장치 IO만 쓴다(3.7.2절 — 고수준 engine·resource manager·decoder·node graph는 Rocks 책임과 겹친다).
  - `MA_NO_DECODING`·`MA_NO_ENCODING`·`MA_NO_GENERATION`·`MA_NO_RESOURCE_MANAGER`·`MA_NO_NODE_GRAPH`·`MA_NO_ENGINE`.
  - `MA_ENABLE_ONLY_SPECIFIC_BACKENDS` + `MA_ENABLE_WASAPI`·`MA_ENABLE_COREAUDIO`·`MA_ENABLE_AAUDIO`·`MA_ENABLE_OPENSL`. 다른 backend(DirectSound·WinMM·ALSA·PulseAudio·JACK·miniaudio null)는 끈다. Linux 장치는 Linux 대상 재개 때 정한다(BS6 보류) — 지금 Linux는 backend가 없어 `NotFound`로 Null에 간다.
- 링크: Windows는 miniaudio 기본 런타임 링크(ole32·avrt 등을 LoadLibrary)라 시스템 라이브러리가 없다. Apple은 `MA_NO_RUNTIME_LINKING`을 켜고 `CoreFoundation`·`CoreAudio`·`AudioToolbox` framework를 링크한다(런타임 dlopen은 notarization을 막는다 — miniaudio 문서). Android는 런타임 링크를 유지한다(AAudio는 API 26+라 dlopen으로 고르고, 없으면 OpenSL ES).
- 전역 상태: 있다(`globalState: true` — 난수 LCG `g_maLCG`, Core Audio 장치 추적 전역, OpenSL 초기화 spinlock). 그래서 이 서드파티를 쓰는 Rocks 모듈은 `AudioMiniaudio` 하나다([빌드 대상](../../BuildTargets/03-Design/03.08-LinkType.ko.md) BD29).

#### 3.34.2 `MiniaudioOutput`(`AudioMiniaudio`)

- 공개 헤더에는 factory만 둔다(miniaudio 타입을 공개 헤더에 두지 않는다 — 3.7.1절): `Result<UniquePtr<AudioOutputBackend>> CreateMiniaudioOutput(Allocator&)`, `RegisterMiniaudioOutput(AudioOutputBackendRegistry&)`·`UnregisterMiniaudioOutput(...)`.
- 할당: miniaudio의 `ma_allocation_callbacks`를 factory가 받은 `Allocator`로 잇는다. realloc은 할당 앞 머리(16 byte, 크기 기록)로 옛 크기를 알아 새로 할당·복사·해제한다. miniaudio는 context·device 초기화 때만 할당하고 데이터 콜백에서는 하지 않는다.
- `Open(request, callback)`:
  1. `ma_context_init`(backend 목록은 기본 우선순위 — 켠 backend 중 플랫폼에 맞는 것). context 설정의 `threadPriority`는 miniaudio 기본(`ma_thread_priority_highest`)이다.
  2. 장치 고르기: `request.device`가 비면 기본 장치, 아니면 `ma_context_get_devices`로 찾은 같은 id(3.34.3절). 없으면 `NotFound`(장치가 Null로 진행한다).
  3. `ma_device_config`(playback): 형식 `ma_format_f32`, 채널 수 = layout 채널 수, `sampleRate` = 요청값(0이면 장치 기본 rate — 믹서가 그 rate로 돈다, 3.33.4절), `periodSizeInFrames` = `callbackFrames`, `performanceProfile` = low latency, `noPreSilencedOutputBuffer`·`noClip` = true(링이 매번 다 채우고 믹서가 clamp한다), `noFixedSizedCallback` = true(링이 아무 크기나 받으므로 miniaudio 중간 버퍼·복사를 끈다). 자동 reroute는 끈다(`wasapi.noAutoStreamRouting`·`aaudio.noAutoStartAfterReroute` = true): miniaudio 알림 스레드가 장치를 멈췄다 다시 시작하고 형식을 바꾸며 그 스레드에서 할당하기 때문이다. 교체는 AU9 제어 쪽 일이다. Core Audio는 기본 장치 추적을 끌 설정이 없어 OS 기본 장치가 바뀌면 miniaudio가 따라간다(한계 — 형식이 바뀌면 underrun이 늘 수 있고 AU9에서 다룬다).
  4. 협상 결과: rate = `device.sampleRate`, layout = 요청 layout(miniaudio가 장치 채널로 바꾼다), 형식 Float32. callbackFrames는 콜백 한 번의 상한이다. 장치 내부 주기(`playback.internalPeriodSizeInFrames`)는 장치 rate 기준이라, 요청 rate가 장치 내부 rate와 다르면 miniaudio가 변환하며 한 주기에 그만큼 더 가져간다. 그래서 `ceil(주기 × rate / internalRate) + 1`(miniaudio 변환 입력 계산의 반올림 여유, 순수 함수 `CallbackFramesUpperBound`)을 낸다(리뷰 지적 — 내부 주기를 그대로 내면 256 frame@44.1k ↔ 48k에서 주기당 약 279 frame이 나가 링 칸이 모자라 구조적 underrun). 실제 OS backend 이름(`ma_get_backend_name` — 예 "WASAPI")을 `Name()`으로 낸다.
- 데이터 콜백은 진행 중 수를 올린 뒤 수락 gate를 보고, 열려 있으면 `AudioOutputCallback::Fill`에 그대로 넘기고(frameCount frame, Float32 교차) 닫혀 있으면 무음만 쓴다. 콜백 안에서 할당·잠금·로그가 없다.
- 콜백 장벽: miniaudio 0.11.26은 비동기 backend(Core Audio·AAudio·OpenSL ES)에서 `onDeviceStop` 실패를 삼키고 상태를 stopped로 두며, `ma_device_uninit`은 먼저 멈추지 않는다(`#if 0`). AAudio는 시작 상태 대기가 시간 초과로 실패해도 스트림이 돌 수 있다. 그래서 3.7.1절 Stop 장벽을 miniaudio에 기대지 않고 이 backend가 둔다: `Start`는 gate를 연 뒤 `ma_device_start`, 실패면 gate를 닫는다. `Stop`은 stopped 상태가 아니면 `ma_device_stop`을 부르고(실패면 native 코드와 함께 알린다) gate를 닫은 뒤 진행 중 콜백이 끝날 때까지 기다린다(콜백 한 번 길이 이내, SpinBackoff — 제어 쪽 대기). gate와 진행 중 수는 seq_cst라 gate가 열린 것을 본 콜백은 진행 중 수에 보인다. 콜백 안에서 부르지 않는다.
- `Close`: `Stop`(gate 장벽) → `ma_device_uninit` → `ma_context_uninit`. 두 번 불러도 된다.
- 오류: `ma_result`를 `LastNativeError`로 남기고 `ErrorCode`로 바꾼다. `MA_OUT_OF_MEMORY` → `OutOfMemory`, `MA_NO_BACKEND`·`MA_NO_DEVICE`·`MA_DOES_NOT_EXIST` → `NotFound`, `MA_BUSY` → `Busy`, 그 밖 → `Unsupported`.
- 장치 상태 통지(`notificationCallback` — 기본 장치 변경·분리·reroute)는 AU2b에서 받지 않는다. 교체 흐름(3.7.3절)과 함께 AU9에서 제어 pipe로 넘긴다.

#### 3.34.3 장치 id

`AudioDeviceId`는 backend가 만든 불투명 UTF-8 문자열이다(3.33.1절). `ma_device_id`는 backend별 union이라 그 backend의 값을 문자열로 옮긴다.

| backend | `ma_device_id` | 문자열 |
|---|---|---|
| WASAPI | `ma_wchar_win32[64]`(UTF-16) endpoint id | UTF-16 → UTF-8(짝 없는 대리 값은 U+FFFD) |
| Core Audio | `char[256]` UID | 그대로(NUL까지) |
| AAudio | `int32` | 10진수 |
| OpenSL ES | `uint32` | 10진수 |

`EnumerateDevices`는 같은 변환으로 id·이름(UTF-8, 잘리면 문자 경계에서 자른다)·기본 여부를 채운다. id가 `MaxAudioDeviceIdBytes`에 들어가지 않는 장치는 고를 수 없으므로 내지 않고 전체 수에서도 뺀다. 선택은 같은 변환 결과의 byte 비교이고, 목록 조회가 실패하면 그 `ma_result`를, 없으면 `MA_DOES_NOT_EXIST`를 남긴다.

#### 3.34.4 모듈 `AudioMiniaudio`와 등록

- ClientOnly(AD24): 공개 의존 `Core`·`Audio`, 비공개 `Miniaudio`·`ModuleLoader`. 서버 대상은 넣지 않는다.
- 수명 객체 Startup: `HostServices`에 `AudioOutputBackendRegistry`가 있고 factory가 비었으면 `CreateMiniaudioOutput`을 넣는다(이미 다른 factory가 있으면 존중하고 Info만 남긴다 — DevelopmentShaderProvider와 같은 규칙). Shutdown: 자기 factory일 때만 지운다. `SupportsUnload`는 false다(backend vtable과 콜백이 이 모듈 코드다).
- 호스트: 레지스트리를 만들어 `HostServices`에 올리는 것은 호스트다. AU2b는 Sandbox가 한다. 엔진 호스트(`AudioEngineSubsystem`)는 AU3에서 같은 서비스를 올린다.

#### 3.34.5 Sandbox 시험음

- `Sandbox --audio-tone [--seconds N]`(기본 3초, 최대 60초): 레지스트리를 서비스로 올리고 엔진 모듈 묶음을 시작한 뒤 factory로 backend를 만들어 `AudioOutputDevice`를 스레드 방식으로 연다(factory가 없으면 Null). 440 Hz 사인 1초 clip(loop, gain −12 dBFS)을 재생하고, 끝에 협상값·backend 이름·AudioRT 우선순위·콜백 수·렌더 블록·underrun을 로그로 남긴다.
- 성공 판정: 장치를 열었고(Null이 아님) 시작 뒤 underrun 0. Null로 열렸으면 원래 오류를 남기고 종료 코드 2(장치 없음 — 판정 불가)다. 사람이 소리를 들어 확인하는 단계는 사용자 확인으로 둔다.

#### 3.34.6 시험

| 범주 | 내용 |
|---|---|
| 오류 대응 | `ma_result` → `ErrorCode` 표 전부, native 코드 보존 |
| 장치 id | 네 backend의 변환(UTF-16 대리 쌍·잘림·빈 값), 같은 장치의 왕복 비교 |
| 할당 다리 | malloc·realloc(늘림·줄임·nullptr)·free가 Rocks allocator로 가고 내용이 보존됨, 할당 실패 → nullptr |
| 등록 | 빈 레지스트리에 넣음, 다른 factory가 있으면 그대로, 해제는 자기 것만 |
| 실장치(있을 때만) | 기본 장치 열기 → 협상값 범위, 콜백이 적어도 두 번 불림(시한 10초 — 멈춤 검출), Stop이 돌아온 뒤 Fill이 오면 세어 끝에 0을 단언(재시작 뒤 두 번째 Stop 포함), Close 두 번, 열거 id로 다시 열기·없는 id는 NotFound. 장치가 없으면(`NotFound`·`Unsupported`) 단언하지 않지만, 출력 장치가 열거되는데 기본 장치를 열지 못하면 실패다(CI 허용과 회귀를 가른다). gate의 Start·Stop 실패 경로는 miniaudio 실패를 일으킬 수 없어 시험하지 않는다(장치 묶음의 Start 실패 순서는 AU2a 가짜 backend 시험이 본다) |

#### 3.34.7 버린 안

- miniaudio 고수준 `ma_engine`: 믹서·스트리밍·공간화가 Rocks 설계와 겹친다(3.7.2절).
- miniaudio 고정 크기 콜백(`noFixedSizedCallback` = false): 링이 이미 크기 차이를 흡수하므로 중간 버퍼·복사·지연만 는다.
- 장치 id를 `ma_device_id` byte의 16진수로: union 크기(256 byte)가 `MaxAudioDeviceIdBytes`를 넘고 사람이 읽을 수 없다.
- Apple 런타임 링크 유지: notarization 실패(miniaudio 문서).
