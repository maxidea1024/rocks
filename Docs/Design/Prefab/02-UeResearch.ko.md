# prefab 설계 — UE 5.8 조사

[목차](README.ko.md)

## 2. UE 5.8 조사

### 2.0 제외한 레거시·deprecated 코드

`FObjectInitializer`의 remote override 생성자와 `FStaticConstructObjectParameters::RemoteSubObjectOverrides`(UE_DEPRECATED 5.7 — CUO/Public/UObject/UObjectGlobals.h:1333-1337, 1842-1843), `USCS_Node::bIsNative_DEPRECATED`·`NativeComponentName_DEPRECATED`·`bVariableNameAutoGenerated_DEPRECATED`(ENG/Classes/Engine/SCS_Node.h:70-82), `ELevelInstanceRuntimeBehavior::Embedded_Deprecated`(ENG/Public/LevelInstance/LevelInstanceTypes.h:60), `APackedLevelActor::CreateOrUpdateBlueprint`·`UpdateBlueprint`(UE_DEPRECATED 5.3 — ENG/Public/PackedLevelActor/PackedLevelActor.h:47-52)는 대조하지 않았다.

### 2.1 원형·CDO·템플릿

- **archetype 찾기.** `UObject::GetArchetypeFromRequiredInfo`(CUO/Public/UObject/Object.h:1457, 구현 CUO/Private/UObject/UObjectArchetype.cpp). CDO의 archetype은 부모 클래스 CDO다(`GetArchetypeForCDO`, UObjectArchetype.cpp:88-92, Class.cpp:6398-6402). 일반 객체는 Outer의 archetype을 재귀로 구한 뒤(:104·123) 그 아래에서 **같은 Class·같은 FName** 객체를 찾는다(`FindObjectWithOuter(ArchetypeToSearch, Class, Name)`, :127). 없고 `RF_InheritableComponentTemplate`이면 BP 부모 체인을 찾고(:132-146), 그 밖에는 `UClass::FindArchetype`(:149), 끝까지 없으면 클래스 CDO다(:173-186). 즉 **템플릿과 인스턴스는 "Outer의 archetype 아래 같은 이름"으로 대응한다.** cooked·게임 빌드는 이 결과를 캐시한다(`UE_CACHE_ARCHETYPE (1 && !WITH_EDITORONLY_DATA)`, :19·235-271).
- **템플릿으로 생성.** `FStaticConstructObjectParameters::Template` — "property values from this object will be copied … If nullptr, the class default object is used"(CUO/Public/UObject/UObjectGlobals.h:1820-1824). 같은 구조체에 `bCopyTransientsFromClassDefaults`(:1815)·`bAssumeTemplateIsArchetype`(:1818)·`InstanceGraph`(:1827). 생성은 `FObjectInitializer(Result, Params)`로 클래스 생성자를 부르고(CUO/Private/UObject/UObjectGlobals.cpp:4851), 이 initializer가 `ObjectArchetype = Params.Template`, `bShouldInitializePropsFromArchetype = true`를 둔다(:3926-3940).
- **값 복사.** `FObjectInitializer::PostConstructInit`이 archetype(없으면 CDO)에서 `InitProperties`로 속성을 복사하고(:4233-4244), `InitSubobjectProperties`(:4247), 조건이 맞으면 `InstanceSubobjects`(:4279-4300)를 부른다. `InitProperties`(:4450-4579)는 instanced 하위 객체를 담은 Transient·DuplicateTransient·NonTryoutDuplicateTransient 속성을 복사에서 뺀다(:4501-4532·4543-4570).
- **default subobject.** `CreateDefaultSubobject`는 **생성자 안에서** 하위 객체를 만든다. 이름이 필수이고(:5847), 소유자의 템플릿이 CDO가 아니면 `ObjectArchetype->GetDefaultSubobjectByName(이름)`을 하위 객체 템플릿으로 쓴다(:5891-5900). 이름 주석은 "this will be the same for all instances of this class"다(UObjectGlobals.h:1381). 파생 클래스는 `SetDefaultSubobjectClass`·`DoNotCreateDefaultSubobject`로 상속 subobject의 클래스를 바꾸거나 없앤다(UObjectGlobals.h:1459-1485). Rocks는 생성자가 다른 객체를 만들 수 없으므로(RCM 59행) 이 구조를 선언형으로 옮긴다(3.2절).
- **생성 출처.** 컴포넌트는 `EComponentCreationMethod`(Native·SimpleConstructionScript·UserConstructionScript·Instance — ENG/Public/ComponentInstanceDataCache.h:25-35)를 `UActorComponent::CreationMethod`(ENG/Classes/Components/ActorComponent.h:431)에 기록해 어디서 만들어졌는지 구분한다.

### 2.2 원형 대비 차이 직렬화

- **기준 객체.** `UObject::SerializeScriptProperties`는 기준으로 `Ar.GetArchetypeFromLoader(this)`, 없으면 `GetArchetype()`을 쓴다(CUO/Private/UObject/Obj.cpp:2053-2057). CDO는 부모 클래스를 기준 클래스로 쓴다(:2061).
- **속성별 판정.** `UStruct::SerializeVersionedTaggedProperties`는 `bDoDeltaSerialization = Ar.DoDelta() && !IsTransacting() && (Defaults || bIsUClass)`이다(CUO/Private/UObject/Class.cpp:1992). 저장 여부는 override 추적이 꺼져 있으면 `!Property->Identical(DataPtr, DefaultValue)`, 켜져 있으면 `GetOverriddenPropertyOperation(...) != None`이다(:2014-2018, 직접 확인). 비태그(UPS) 경로도 `Identical`로 기본값을 건너뛴다(CUO/Private/Serialization/UnversionedPropertySerialization.cpp:197-199·1067·1075).
- **컨테이너 안 차이.** 표준 TMap 차이 저장은 이미 **key 단위**다 — 기준에 있고 인스턴스에 없는 key를 "Removed" 목록에 쓴다(CUO/Private/UObject/PropertyMap.cpp:355-368). 아카이브가 `ArNoIntraPropertyDelta`를 켜서 `DoIntraPropertyDelta()`가 false이고 실험 override 로직이 없을 때만 기준을 버리고 통째로 쓴다(PropertyMap.cpp:286-289, 플래그 CORE/Public/Serialization/Archive.h:908-909·459-462). 그 밖의 플래그: `ArNoDelta`·`DoDelta()`(Archive.h:905-906·453-456), `ArUseCustomPropertyList`(:947-948).
- **텍스트.** `FProperty::ExportText_Direct(…, Data, Delta, …)`(CUO/Public/UObject/UnrealType.h:725)는 `Data == Delta`(기준 없음 뜻)이면 늘 출력하고, 그 밖에는 `!Identical(Data, Delta)`일 때만 출력한다(CUO/Private/UObject/Property.cpp:1021-1026, 직접 확인).

### 2.3 인스턴스 대응표·복제·이름

- **`FObjectInstancingGraph`**(CUO/Public/UObject/Class.h:5094-5350): `SourceRoot`·`DestinationRoot`(:5306-5322), `SourceToDestinationMap`(:5341)·`DestinationToSourceMap`(:5346). `GetInstancedSubobject`(CUO/Private/UObject/CoreNative.cpp:212-423)는 원형 하위 객체가 맵에 없으면 Outer의 대응 객체를 먼저 확보하고 **같은 FName**으로 `StaticConstructObject_Internal(Template = 원형 하위 객체, InstanceGraph = this)`를 부른다(:282-301·360-374).
- **내부 참조 재연결.** `FObjectPropertyBase::InstanceSubobjects`가 object 속성 값을 `InstancePropertyValue` 결과로 바꾼다(CUO/Private/UObject/PropertyBaseObject.cpp:73-94). 호출은 `UStruct::InstanceSubobjectTemplates`의 참조 링크 순회다(Class.cpp:2703-2729).
- **복제.** `StaticDuplicateObjectEx`(UObjectGlobals.cpp:2935-3205)는 루트를 `Template = Source->GetArchetype()`로 만들고(:3001-3004) `FDuplicateDataWriter`로 쓴 뒤 읽는다. default subobject는 이름으로 미리 대응한다(`GetDefaultSubobjectByName(Src->GetFName())`, :2840-2864). `DuplicationSeed`(UObjectGlobals.h:224)는 "복제하지 않을 객체" 대응이다.
- **제외 플래그.** `FDuplicateDataWriter::operator<<(UObject*&)`는 `RF_DuplicateTransient` 객체와 UE PIE가 아닐 때의 `RF_NonPIEDuplicateTransient` 객체를 null로 쓴다(CUO/Private/Serialization/DuplicateDataWriter.cpp:69-86, 직접 확인). 속성 플래그 `CPF_DuplicateTransient`·`CPF_NonPIEDuplicateTransient`는 `PPF_Duplicate`일 때 `ShouldSerializeValue`가 뺀다(Property.cpp:1069-1079). **템플릿 객체 자신은 그 값을 그대로 보존한다** — 제외는 복제·인스턴싱 때만 일어난다.
- **이름 충돌.** 템플릿에서 컴포넌트를 만들 때 이름이 없으면 `FindFirstFreeName(this, Template->GetFName())`으로 빈 이름을 찾는다(ENG/Private/ActorConstruction.cpp:1126, 직접 확인). 이름은 Outer 안에서만 유일하면 되고 정체성이 아니다.

### 2.4 Blueprint 컴포넌트 트리(SCS·ICH)

- **`USCS_Node`**(ENG/Classes/Engine/SCS_Node.h): `ComponentTemplate`(:30), `ParentComponentOrVariableName`(:48), `ChildNodes`(:61), `VariableGuid`(:68), `InternalVariableName`(:211-212). 주석은 "All instances route back to the archetype through the variable name"이다(:206-210, 직접 확인). **SCS는 생성자가 아니라 선언(노드 트리)이다** — 생성자가 만든 native 컴포넌트 뒤에 그 선언을 실행한다.
- **실행.** `AActor::FinishSpawning`(ENG/Private/Actor.cpp:4374) → `AActor::ExecuteConstruction`(ENG/Private/ActorConstruction.cpp:818)이 가장 위 BP부터 `SCS->ExecuteScriptOnActor`를 부른다(:901). `USimpleConstructionScript::ExecuteScriptOnActor`(ENG/Private/SimpleConstructionScript.cpp:696) → `USCS_Node::ExecuteNodeOnActor`(ENG/Private/SCS_Node.cpp:84)가 컴포넌트를 만들어 변수 속성에 넣고 자식을 재귀로 처리한다. 느린 경로는 `AActor::CreateComponentFromTemplate`(ActorConstruction.cpp:1112)이 템플릿을 `StaticDuplicateObjectEx`로 복제한다.
- **상속 override(ICH).** `FComponentKey`의 필드는 `OwnerClass`·`SCSVariableName`·`AssociatedGuid`다(ENG/Classes/Engine/InheritableComponentHandler.h:57-65). SCS 노드 키는 `AssociatedGuid = SCSNode->VariableGuid`(ENG/Private/InheritableComponentHandler.cpp:573)이고, `Match`는 `OwnerClass`와 `AssociatedGuid`만 비교한다(:586-589, 직접 확인). **즉 상속 override는 이름이 아니라 GUID로 대응한다.** `CreateOverridenComponentTemplate`(:102)는 부모 체인에서 가장 가까운 템플릿(`FindBestArchetype`, :415)을 archetype으로 삼아 `RF_ArchetypeObject|RF_Public|RF_InheritableComponentTemplate` 객체를 만든다(:158). 부모 템플릿과 같으면 기록이 필요 없다(`IsRecordNecessary`, :379). 실행 때는 `USCS_Node::GetActualComponentTemplate`가 실제 클래스부터 ICH override를 찾는다(SCS_Node.cpp:29).
- **cooked 빠른 경로.** `FBlueprintCookedComponentInstancingData`(ENG/Classes/Engine/BlueprintGeneratedClass.h:341-395 — `ChangedPropertyList`·`bHasValidCookedData`). cook 때 `BuildComponentInstancingData`가 차이 속성 목록을 만들며, 기준은 `bUseTemplateArchetype`이면 템플릿의 archetype, 아니면 클래스 CDO다(ED/UnrealEd/Private/Kismet2/BlueprintEditorUtils.cpp:10481-10486, 직접 확인). 로드 때 바이너리로 캐시하고(ENG/Private/BlueprintGeneratedClass.cpp:2822-2865), 생성은 `AActor::CreateComponentFromTemplateData`가 새 객체에 그 바이너리를 읽혀 만든다(ActorConstruction.cpp:1155). 사용 조건은 `UseFastPathComponentInstancing()`(BlueprintGeneratedClass.cpp:1877-1880). **원형을 실행 중 비교·복제하지 않고 미리 계산한 차이 블록을 바로 적용하는 구조**다. UE에서 실행 중 "원형으로 만든 묶음을 spawn"하는 일은 이 BP 클래스 spawn이 맡는다.

### 2.5 Level Instance

- **인터페이스·Actor.** `ILevelInstanceInterface`(ENG/Public/LevelInstance/LevelInstanceInterface.h:32 이하 — `GetLevelInstanceID`·`GetWorldAsset`·`GetDesiredRuntimeBehavior`·`SupportsPropertyOverrides`). `ALevelInstance`(LevelInstanceActor.h:18-60)는 `WorldAsset`(에디터 전용)·`CookedWorldAsset`·`LevelInstanceSpawnGuid`·`DesiredRuntimeBehavior`를 갖는다. **묶음은 World 에셋 하나이고, 배치는 그것을 가리키는 Actor 하나**다.
- **ID.** `FLevelInstanceID`는 "computed from the Hash of LevelInstance Actor Guid and all its ancestor LevelInstance Actor Guids"(LevelInstanceTypes.h:11-12, 직접 확인). 계산은 조상과 자신의 `GetLevelInstanceGuid()`를 모아 조상부터 `FActorContainerID(Parent, Guid)`(= `FGuid::Combine`, ENG/Public/WorldPartition/WorldPartitionActorContainerID.h:58-60)로 누적하고, 이름이 네트워크 안정이면 Actor 이름과(게임 World에서는) 패키지 짧은 이름의 해시를 seed로 써서 `CityHash64WithSeed`로 끝낸다(ENG/Private/LevelInstance/LevelInstanceSubsystem.cpp:156-191). 같은 묶음을 여러 번 배치해도 ID가 다르다.
- **런타임 동작.** `ELevelInstanceRuntimeBehavior`(LevelInstanceTypes.h:56-65): `Partitioned`(표시 "Embedded"), `LevelStreaming`(표시 "Standalone"), `None`(숨김). 기본값은 Partitioned다(LevelInstanceActor.cpp:33).
  - **Partitioned는 실행 중 spawn이 아니다.** WorldPartition 액터 기술자가 Partitioned Level Instance를 하위 컨테이너로 다루고(`IsChildContainerInstanceInternal`, ENG/Private/WorldPartition/LevelInstance/LevelInstanceActorDesc.cpp:220-243, ClusterMode Partitioned :257), 생성·쿡 때 그 안의 액터를 메인 WorldPartition 셀에 편입한다. LI Actor 자신은 런타임에 쓰이지 않는다 — "World Partition Embedded Level Instances don't get loaded as they aren't runtime relevant"(LevelInstanceActor.cpp:220-225, 직접 확인). 즉 UE는 **쿡 때 펼친다**(4절 D9 (b)).
  - LevelStreaming은 `ULevelStreamingLevelInstance`로 임시 패키지 레벨을 런타임에 로드한다(LevelInstanceLevelStreaming.cpp:389-445).
- **안의 Actor ID.** 스트리밍 때 `FSetActorInstanceGuid(Actor, ContainerID.GetActorGuid(ActorGuid))`(LevelInstanceLevelStreaming.cpp:262) — 컨테이너 ID와 원래 ActorGuid를 결합한다(WorldPartitionActorContainerID.h:112-115). 런타임도 OwnerLevel 체인의 GUID를 재귀로 결합한다(ENG/Private/WorldPartition/ActorInstanceGuids.cpp:66-112·133-166). **배치마다 결정적으로 파생된 ID**다.
- **순환 검사.** `ULevelInstanceSubsystem::CheckForLoop`(LevelInstanceSubsystem.cpp:886)는 조상과 자신이 속한 레벨 패키지가 WorldAsset과 같으면 순환이다. 호출은 스트리밍 로드(LevelInstanceLevelStreaming.cpp:393)와 편집 검증(LevelInstanceActorImpl.cpp:448)이며 둘 다 `WITH_EDITOR` 안이다. 쿡 쪽 WorldPartition 검증은 별도 함수 `FLevelInstanceActorDesc::ValidateCircularReference`(LevelInstanceActorDesc.cpp:327, 호출 :292·354)다.
- **속성 override(5.4+, 실험).** `ULevelInstancePropertyOverrideAsset : UWorldPartitionPropertyOverride`(ENG/Public/LevelInstance/LevelInstancePropertyOverrideAsset.h:30-79). 자료는 `컨테이너 경로 → ActorGuid → 하위 객체 경로 문자열 → 태그 직렬화 바이트`이고 전부 `WITH_EDITORONLY_DATA`다(ENG/Public/WorldPartition/WorldPartitionPropertyOverride.h:15-102). 저장은 원형 월드의 Actor를 기준으로 한 `SerializeTaggedProperties` 차이다(LevelInstancePropertyOverrideAsset.cpp:71·122-127). 실험 설정과 정책이 있어야 켜진다(LevelInstanceSettings.cpp:15-30). 런타임 데이터가 아니므로 쿡 때 적용되는 것으로 보이나 최종 경로는 확인하지 못했다(8절).

### 2.6 Packed Level Actor

`APackedLevelActor : ALevelInstance`(ENG/Public/PackedLevelActor/PackedLevelActor.h:24-110)는 기본 런타임 동작이 None이고(:75) 속성 override를 지원하지 않으며(:43), 에디터 밖에서는 원본 레벨을 로드하지 않는다(ENG/Private/PackedLevelActor/PackedLevelActor.cpp:42-49, 직접 확인). 빌더는 StaticMeshComponent를 ISM 기술자 해시로 묶어 2개 이상이고 non-Nanite면 HISM, 아니면 ISM으로 만들고(PackedLevelActorISMBuilder.cpp:26-104), 결과를 SCS 노드로 Blueprint에 저장한다(PackedLevelActorBuilder.cpp:411-525). **묶음을 렌더 instancing 데이터로 굽는 편집기 도구**다.

### 2.7 속성 단위 override 추적(실험)

- 헤더가 "Overridable serialization is experimental, not supported"라고 적는다(CUO/Public/UObject/OverriddenPropertySet.h:34-38, OverridableManager.h:17-21).
- `EOverriddenPropertyOperation`: None·Modified·Replace·Add·Remove·SubObjectsShadowing·Externalized(OverriddenPropertySet.h:229-238, 직접 확인). 노드는 `FOverriddenPropertyNodeID{Path, Object}`(:327-380, 맵 키용 `FromMapKey` :345)와 하위 노드 트리다(:389-463).
- `FOverridableManager`는 객체별 sparse annotation이며 `WITH_EDITORONLY_DATA` 전용이다(OverridableManager.h:23-60, 비에디터 `IsEnabled`는 false — OverridableManager.cpp:26-33). 클래스 플래그가 아니라 객체 단위로 켜지고 Outer·archetype에서 상속된다(`InheritEnabledFrom`, .cpp:71-83 — `InitProperties`가 부른다, UObjectGlobals.cpp:4456-4459).
- 컨테이너: 배열은 `CPF_ExperimentalOverridableLogic`이 없으면 통째 Replace이고(OverriddenPropertySet.cpp:1172-1189), 있으면 instanced 원소만 Add(추가된 하위 객체 ID)·Remove(**원형 하위 객체 ID**)로 기록한다(:1235-1326). 맵은 key 기반 Add·Remove·Replace다(:1497-1569).
- 저장: 추적이 켜지면 op ≠ None인 속성만 쓴다(Class.cpp:2017). **값이 원형과 같아도 "일부러 넣은 값"이 남는다** — RCM의 명시 override 집합과 같은 목적이다.
- 전파: 이 객체들은 값 전파를 하지 않고 "propagation is done via reinstantiation"이다(ED/PropertyEditor/Private/PropertyHandleImpl.cpp:629-639).

### 2.8 원형 변경 전파

- `UObject::GetArchetypeInstances`(Obj.cpp:1079-1111)가 archetype의 인스턴스를 모은다. `PreEditChange`·`PostEditChangeChainProperty`는 알림만 전파한다(Obj.cpp:586-676).
- **"원형과 같으면 따라가고, 바꿨으면 유지"의 실제 위치**는 편집기 `FPropertyNode::PropagatePropertyChange`(ED/PropertyEditor/Private/PropertyNode.cpp:4188-4317)다. 인스턴스의 현재 값을 `ExportText(PPF_ForDiff)`로 만들어 **이전 원형 값 문자열과 같을 때만** 새 값을 넣는다(:4294-4303, 직접 확인). 컨테이너는 `Identical(PPF_DeepComparison)`로 판정한다(:3874-4043). 컴포넌트 템플릿용 `FComponentEditorUtils::PropagateDefaultValueChange`도 같은 규칙이다(ED/UnrealEd/Public/Kismet2/ComponentEditorUtils.h:146).
- BP 재컴파일은 옛 archetype 대비 차이만 기록해 새 archetype으로 만든 객체에 덮어쓴다(ENG/Private/UnrealEngine.cpp:18035-18090 `FCPFUOWriter`, ED/UnrealEd/Private/Kismet2/KismetReinstanceUtilities.cpp:3342-3383). 즉 UE의 전파는 **값 비교식 제자리 갱신(편집기)** 과 **차이 재적용식 재생성(재컴파일·override 추적)** 두 갈래다.

### 2.9 클러스터

`ULevel::CreateCluster`(ENG/Private/Level.cpp:1526-1561)는 cooked이고 액터 클러스터링이 켜졌을 때 `CanBeInCluster` 액터를 `ULevelActorContainer`로 묶는다(Level.cpp:1528-1531 주석 — Level 자신은 루트가 아니다). 호출은 로드 때 컴포넌트 증분 갱신을 마칠 때 한 번이다(Level.cpp:1930). 그래서 **실행 중 spawn한 Actor는 Level 클러스터에 들어가지 않는다.** 클러스터 생성 자체가 cooked 전용이다(CUO/Private/UObject/UObjectClusters.cpp:26-37·854-857). UE에 "prefab 단위 클러스터"는 없다.

### 2.10 Unity 비교(짧게)

Unity는 소스가 공개되지 않아 직렬화 YAML의 공개 필드 이름 기준으로만 적는다(파일:행 근거 없음).

- **PropertyModification**: `{target(원형 객체 fileID + 원형 에셋 guid), propertyPath(문자열, 배열은 `Array.data[i]`), value(문자열), objectReference}`. 인스턴스(`PrefabInstance`)의 `m_Modification`에 목록으로 둔다.
- **추가·삭제**: `m_RemovedComponents`·`m_RemovedGameObjects`(원형 객체 참조), `m_AddedComponents`·`m_AddedGameObjects`(붙일 원형 객체 + 추가 객체).
- **중첩·variant**: 중첩 prefab은 원형 안의 `PrefabInstance`이고, variant는 루트가 다른 prefab의 `PrefabInstance`인 prefab이다. 인스턴스 안 객체의 fileID는 인스턴스 fileID와 원형 객체 fileID에서 결정적으로 만든다.
- **약점**: 배열 원소 override가 index 경로라 원형에 원소를 끼우면 다른 원소를 고친다(EIP 20.3절이 지적한 위험). 값이 문자열이라 타입 변경을 늦게 알아챈다.

### 2.11 Rocks가 가져갈 구조

| UE 구조 | Rocks 결론 |
|---|---|
| 원형과 인스턴스의 대응은 "Outer 원형 아래 같은 이름"(2.1), 상속 override는 GUID(2.4), 이름 충돌은 빈 이름 찾기(2.3) | 정체성은 처음부터 **GUID**(NodeGuid·SubobjectGuid), 이름은 Outer 안 유일성만 지키는 표시값(3.4절) |
| `CreateDefaultSubobject`는 생성자 안 생성, SCS는 선언 트리(2.1·2.4) | 생성자는 객체를 만들 수 없으므로(RCM 59행) **선언형 subobject 표**(SCS와 같은 꼴)(3.2절) |
| CDO·archetype이 살아 있는 객체 | Rocks는 클래스 기본값을 객체로 두지 않는다(RCM). 원형도 **불변 데이터**로 둔다(3.1절, 4절 D2) |
| cooked는 차이 블록을 미리 계산해 바로 적용(2.4) | 해석된 원형을 revision마다 한 번 만들어 spawn은 적용만 한다(3.9절) |

| override 추적은 명시 기록, 전파는 재생성(2.7) | override는 명시 집합 ∪ 원형과 다른 값(RCM 62행), 전파는 차이 재적용(3.7절) |
| 편집기 제자리 전파(2.8) | 노드 구조가 같으면 제자리 갱신, 다르면 재생성(3.7절) |
