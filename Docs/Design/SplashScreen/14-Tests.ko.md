# 시작 화면(스플래시) — 14. 시험

[목차](README.ko.md)

## 14. 시험

자동 시험은 OS 창 없이 돈다(요구 7). 시계는 주입하고 스레드 순서는 gate로 만든다.

1. **표시 판정**: 4절 표의 사유마다 양성·음성, 여러 사유가 겹칠 때 순서, 호스트별 입력 표의 여섯 행(Sandbox 창 없는 자식은 `NoMainWindow`).
2. **이미지 찾기**: 설정 경로(있음·없음 — 다른 자리로 안 넘어감), 프로젝트가 엔진을 이김, 확장자 순서, 프로젝트 없는 봉인 모드, `@2x`만 있음(짝수·홀수 크기)·둘 다·크기 불일치(`ImageInvalid`), 한도 경계(4096·4097 px, 32 MiB±1), 경로 변수 펼침. 파일 시스템은 시험용 임시 폴더.
3. **DPI 고르기**: 배율 1.0·1.25·1.5·2.0·3.0과 변형 유무 조합의 원본·창 크기(1.0 초과면 `@2x` 우선).
4. **배치**: 기본 칸 사각형(논리·배율), 오른쪽 맞춤, 글자 띠 안. 덮어쓰기(6.5절): 네 기준 모서리의 사각형, 폭 0, 배율, Custom 칸은 배치가 있을 때만, 막대 덮어쓰기, 범위 밖·중복 칸 거부(Show `InvalidArgument`).
4a. **설정**: `ui.splash.*` 기본값과 층 대입이 `ReadSplashSettings`로 읽힌다(Engine 모듈 시험).
5. **진행 연결**: 실제 `ProgressHub`(가짜 시계)에 `StartupProgress`를 열고 단계·중첩 구간·다른 스레드의 단계 계수로 보고한 뒤 원천 `poll` 결과를 단언한다 — 단계 가중치대로의 비율, 문구 우선순위, 기본 문구, 99% 막기, 끝난 시작 작업, 잘림 UTF-8 경계, 하위 작업이 생겨도 비율이 단계 밖으로 섞이지 않음(원천은 하위 작업을 보지 않는다).
6. **막대 보간**: 가짜 시계로 수렴·단조·settle·불확정 → 비율 전환.
7. **보정**: 프로필 읽기·지수 평균·바닥 2%·들어가지 않은 단계·없는 단계 채움·깨진 파일·버전 불일치·실패 실행은 안 씀·임시 파일 이름 바꾸기.
8. **스레드 계약**: 가짜 presenter의 생성 gate에서 스플래시 스레드를 세운 채 `Hide` → gate 해제 → 교착 없이 끝나고 `release`가 한 번 불림(UE 1.4절 경쟁). 생성 실패 presenter → `State() == Failed`, Hide 정상. 여러 스레드 `SetText`와 Hide 겹침.
8a. **최소 표시 시간**: 주입 시계로 창이 뜬 뒤 1.9초에는 `CanHide()` 거짓, 2.0초에는 참, 최소 0이면 뜨자마자 참, 생성 실패면 참, `Starting` 동안 거짓.
9. **대화상자 hook**: 등록·해제, 두 번째 등록 `AlreadyExists`, Show 전·Hide 뒤 `NotifySystemDialogOpening`이 아무 일 없음, 가짜 presenter에서 숨김 요청 기록.
10. **창 연기 시험(Windows, 대화형 데스크톱만)**: `Sandbox --splash-self-test`(창을 띄우는 시험은 Sandbox 자체 시험에 둔다 — PlatformWindow 시험과 같은 관례). 실제 presenter로 `Show`(최소 표시 0)→`Shown`→`SetText`·`Suspend`·`Resume`→`Hide`를 세 번 되풀이한다(창 클래스 등록·해제 반복). 데스크톱 세션이 `Disconnected`이거나 창을 만들 수 없으면 NOT RUN(종료 코드 2). GDI·USER 객체 수 누수 검사는 플랫폼 조회 API가 생길 때(후속).
11. **사람 확인**: `Sandbox --engine --window`에서 스플래시·막대·주 창 전환, `--no-splash`, 배율 100·150·200%, 다중 모니터, 시작 중 다른 앱으로 옮기기, macOS Retina·다른 앱 전환, Studio(생기면) 작업 표시줄 진행.
