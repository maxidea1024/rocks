# prefab(원형 기반 재사용 객체 묶음) 설계

기준일: 2026-11-19, 개정 4(결정 D1–D21 확정 — 4절, 편집 위치 규칙 반영 — 9절). 개정 1은 사용자 지시("설계문서만 작성해놔")로 쓴 첫 초안이고, 개정 2는 교차검증 1차(치명 1·중요 14·사소 13·추가 2) 결과를 반영했다(9절). 구현하지 않는다. 착수 시점은 고정 구현 순서(리플렉션 B9j–B9m → Curve 데이터 계층 → A0-G → A1–A6 → 화면 마일스톤)를 따르며 이 문서는 그 순서를 바꾸지 않는다.

근거: [엔진 구현 계획](EngineImplementationPlan.ko.md)(이하 EIP) 5.3절(클래스 기본값·서브오브젝트·공통 instancing)·20.3절(프리팹·중첩·변형·인스턴스 오버라이드)·20.5절(프리팹 식별자), [런타임 클래스 메타데이터](RuntimeClassMetadata.ko.md)(이하 RCM) '클래스 기본값 결정', [리플렉션 B9](ReflectionExtensions.ko.md)(이하 RX), [리플렉션·빌드 보강](ReflectionFoundations.ko.md)(이하 RF), [객체·그래프 보강](ObjectFoundations.ko.md)(이하 OF), [에셋 시스템](AssetSystem.ko.md)(이하 AS), [엔진 런타임](EngineRuntime.ko.md)(이하 ER), [GC 대규모 처리](GarbageCollectionScale.ko.md)(이하 GCS — 13절 클러스터는 개정 2, `experiment/gc-scale` 브랜치 `b293feb`), [Sparks 언어](SparksLanguage.ko.md)(이하 SL), 현재 코드(`Core/Source/Runtime/ObjectRuntime`·`ObjectSerialization`, `Engine/Source/Runtime/World`). UE 대조는 UE 5.8(5.8.4, `Engine/Build/Build.version` 5.8.4) 원본을 파일:행으로 확인했다(2절). 레거시·deprecated 코드는 대조에서 뺐다(2.0절).

원칙(RF·OF와 같다): 실패 원자성(spawn은 전부 공개 또는 전부 rollback, 공개 뒤 실패는 정상 파괴 경로), 결정성(같은 원형·override·spawn 인자 → 같은 객체 그래프와 같은 파생 ID), 모든 길이·개수·깊이에 이름 붙은 한도, 하위호환 없음. 구조는 UE 5.8을 따르고 이름은 Rocks식 서술형으로 짓는다. UE 이름은 6절 대응표에만 둔다(업계 공용어 prefab·archetype·variant는 그대로 쓴다). 좌표·단위·Transform은 UE 5.8과 같다(3.10절). 객체 규모는 엔진이 감당한다 — 1M+ 객체를 기준으로 하며 "객체 수를 줄이라"는 처방을 1차 해법으로 두지 않는다(3.9절).

약어:

- UE: `CUO/` = Engine/Source/Runtime/CoreUObject/, `ENG/` = Engine/Source/Runtime/Engine/, `ED/` = Engine/Source/Editor/, `CORE/` = Engine/Source/Runtime/Core/.
- Rocks: `OR` = Core/Source/Runtime/ObjectRuntime/Public/Object, `WD` = Engine/Source/Runtime/World/Public/World.

## 1. 목적·범위·비범위

### 1.1 목적

편집기에서 만든 Actor·Component 묶음을 **원형(archetype)** 으로 저장하고, 원형에서 인스턴스를 여러 번 만들며, 인스턴스마다 원형과 다른 부분만 **override** 로 기록한다. 원형이 바뀌면 override하지 않은 값은 새 원형을 따르고 override한 값은 유지된다. 원형은 다른 원형을 품을 수 있고(중첩), 다른 원형을 기준으로 차이만 저장할 수 있다(variant).

이 기능은 여러 문서가 "prefab 단계"로 미뤄 둔 일을 한곳에서 정한다.

- default subobject와 SubobjectGuid, 인스턴스별 clone·remap(EIP 5.3절, RCM 43·73행, OF 0절, SL 4.5절).
- 차이 저장 기준의 일반화 — "prefab이 생기면 기준이 archetype 사슬이 된다"(RCM 72행, EIP 5.3절).
- Map·Set의 key 단위 차이(RX 20절 열린 문제), 배열 원소 안정 ID(RF 1044행).
- Instanced 하위 객체(RX 0절, OF 0절).
- 부착 계층 영속(ER 4.6절 "레벨·prefab 저장 전에 영속한다").
- 원형의 Transient 클래스 예외(RX 9.2절 694행·20절).

### 1.2 범위

| 항목 | 이 문서가 정하는 것 |
|---|---|
| 클래스 원형 | 선언형 default subobject(MetaCompiler subobject 표), SubobjectGuid, subobject 기본값 레코드, 파생 클래스의 상속 subobject 기본값 덮기 |
| prefab 에셋 | 노드 표·NodeGuid·원형 데이터 형식, 패키지(A1) 안 위치, 두 가지 revision, 해석된 원형 캐시 |
| 인스턴스 생성 | 그래프 복원·내부 참조 재연결·그래프 사이 참조·제외 플래그·이름·소유 목록·Transform 합성·World 등록·hook 순서 |
| override | 필드 경로 기반 값 override, Map·Set key 추가·제거, 노드 추가·삭제, 명시 override 집합, 통째 단위 값의 적용 |
| 저장 | 원형 대비 차이, 레벨 배치 인스턴스 기록, 펼친 객체의 저장 제외 |
| 전파 | revision 변경 시 3-way 재기준(rebase), 충돌 분류, override 마이그레이션 |
| 중첩·variant | 원형 사슬, 순환 금지, 깊이·개수 한도 |
| 실행 비용 | spawn 경로 비용, 원형 캐시, 인스턴스 장부, GC·클러스터 관계 |
| 진단·스레드·수명 | 오류 코드, 단계별 스레드, lease 수명 |

### 1.3 비범위

- 편집기 UI(prefab 편집 모드·override 표시·Apply/Revert 버튼의 화면) — UI 툴킷 CU 단계와 편집기 단계가 정한다. 이 문서는 그 명령이 부르는 API와 결과 규칙만 정한다.
- Undo·transaction 기록 형식(CU4), setter·통지 hook(CU5) — 선행 조건으로만 적는다.
- 네트워크 복제 spawn(EIP 20.3절 마지막 문단) — 원형 ID·revision·spawn 인자 검증 규칙만 3.13절에 자리로 둔다.
- 세이브게임 형식(EIP 951행) — 파생 ID 규칙(3.4절)만 제공한다.
- 렌더 instancing으로 굽기(UE Packed Level Actor 대응) — 렌더 instancing 기반이 생긴 뒤의 후속이다(4절 D1, 5.2절 PF9).
- 별도 Level로 로드하는 묶음(UE Level Instance의 LevelStreaming 동작)과 WorldPartition 셀 편입 — 레벨 패키지·스트리밍 단계와 함께 정한다(4절 D1·D9, EIP 2064행 P2·M7).

## 2. UE 5.8 조사

### 2.0 제외한 레거시·deprecated 코드

`FObjectInitializer`의 remote override 생성자와 `FStaticConstructObjectParameters::RemoteSubObjectOverrides`(UE_DEPRECATED 5.7 — CUO/Public/UObject/UObjectGlobals.h:1333-1337, 1842-1843), `USCS_Node::bIsNative_DEPRECATED`·`NativeComponentName_DEPRECATED`·`bVariableNameAutoGenerated_DEPRECATED`(ENG/Classes/Engine/SCS_Node.h:70-82), `ELevelInstanceRuntimeBehavior::Embedded_Deprecated`(ENG/Public/LevelInstance/LevelInstanceTypes.h:60), `APackedLevelActor::CreateOrUpdateBlueprint`·`UpdateBlueprint`(UE_DEPRECATED 5.3 — ENG/Public/PackedLevelActor/PackedLevelActor.h:47-52)는 대조하지 않았다.

### 2.1 원형·CDO·템플릿

- **archetype 찾기.** `UObject::GetArchetypeFromRequiredInfo`(CUO/Public/UObject/Object.h:1457, 구현 CUO/Private/UObject/UObjectArchetype.cpp). CDO의 archetype은 부모 클래스 CDO다(`GetArchetypeForCDO`, UObjectArchetype.cpp:88-92, Class.cpp:6398-6402). 일반 객체는 Outer의 archetype을 재귀로 구한 뒤(:104·123) 그 아래에서 **같은 Class·같은 FName** 객체를 찾는다(`FindObjectWithOuter(ArchetypeToSearch, Class, Name)`, :127). 없고 `RF_InheritableComponentTemplate`이면 BP 부모 체인을 찾고(:132-146), 그 밖에는 `UClass::FindArchetype`(:149), 끝까지 없으면 클래스 CDO다(:173-186). 즉 **템플릿과 인스턴스는 "Outer의 archetype 아래 같은 이름"으로 대응한다.** cooked·게임 빌드는 이 결과를 캐시한다(`UE_CACHE_ARCHETYPE (1 && !WITH_EDITORONLY_DATA)`, :19·235-271).
- **템플릿으로 생성.** `FStaticConstructObjectParameters::Template` — "property values from this object will be copied … If nullptr, the class default object is used"(CUO/Public/UObject/UObjectGlobals.h:1820-1824). 같은 구조체에 `bCopyTransientsFromClassDefaults`(:1815)·`bAssumeTemplateIsArchetype`(:1818)·`InstanceGraph`(:1827). 생성은 `FObjectInitializer(Result, Params)`로 클래스 생성자를 부르고(CUO/Private/UObject/UObjectGlobals.cpp:4851), 이 initializer가 `ObjectArchetype = Params.Template`, `bShouldInitializePropsFromArchetype = true`를 둔다(:3926-3940).
- **값 복사.** `FObjectInitializer::PostConstructInit`이 archetype(없으면 CDO)에서 `InitProperties`로 속성을 복사하고(:4233-4244), `InitSubobjectProperties`(:4247), 조건이 맞으면 `InstanceSubobjects`(:4279-4300)를 부른다. `InitProperties`(:4450-4579)는 instanced 하위 객체를 담은 Transient·DuplicateTransient·NonTryoutDuplicateTransient 속성을 복사에서 뺀다(:4501-4532·4543-4570).
- **default subobject.** `CreateDefaultSubobject`는 **생성자 안에서** 하위 객체를 만든다. 이름이 필수이고(:5847), 소유자의 템플릿이 CDO가 아니면 `ObjectArchetype->GetDefaultSubobjectByName(이름)`을 하위 객체 템플릿으로 쓴다(:5891-5900). 이름 주석은 "this will be the same for all instances of this class"다(UObjectGlobals.h:1381). 파생 클래스는 `SetDefaultSubobjectClass`·`DoNotCreateDefaultSubobject`로 상속 subobject의 클래스를 바꾸거나 없앤다(UObjectGlobals.h:1459-1485). Rocks는 생성자가 다른 객체를 만들 수 없으므로(RCM 59행) 이 구조를 선언형으로 옮긴다(3.2절).
- **생성 출처.** 컴포넌트는 `EComponentCreationMethod`(Native·SimpleConstructionScript·UserConstructionScript·Instance — ENG/Public/ComponentInstanceDataCache.h:25-35)를 `UActorComponent::CreationMethod`(ENG/Classes/Components/ActorComponent.h:431)에 기록해 어디서 만들어졌는지 구분한다.

### 2.2 원형 대비 차이 직렬화

- **기준 객체.** `UObject::SerializeScriptProperties`는 기준으로 `Ar.GetArchetypeFromLoader(this)`, 없으면 `GetArchetype()`을 쓴다(CUO/Private/UObject/Obj.cpp:2053-2057). CDO는 부모 클래스를 기준 클래스로 쓴다(:2061).
- **속성별 판정.** `UStruct::SerializeVersionedTaggedProperties`는 `bDoDeltaSerialization = Ar.DoDelta() && !IsTransacting() && (Defaults || bIsUClass)`이다(CUO/Private/UObject/Class.cpp:1992). 저장 여부는 override 추적이 꺼져 있으면 `!Property->Identical(DataPtr, DefaultValue)`, 켜져 있으면 `GetOverriddenPropertyOperation(...) != None`이다(:2014-2018, 직접 확인). 비태그(UPS) 경로도 `Identical`로 기본값을 건너뛴다(CUO/Private/Serialization/UnversionedPropertySerialization.cpp:197-199·1067·1075).
- **컨테이너 안 차이.** 표준 TMap 차이 저장은 이미 **key 단위**다 — 기준에 있고 인스턴스에 없는 key를 "Removed" 목록에 쓴다(CUO/Private/UObject/PropertyMap.cpp:355-368). 아카이브가 `ArNoIntraPropertyDelta`를 켜서 `DoIntraPropertyDelta()`가 false이고 실험 override 로직이 없을 때만 기준을 버리고 통째로 쓴다(PropertyMap.cpp:286-289, 플래그 CORE/Public/Serialization/Archive.h:908-909·459-462). 그 밖의 플래그: `ArNoDelta`·`DoDelta()`(Archive.h:905-906·453-456), `ArUseCustomPropertyList`(:947-948).
- **텍스트.** `FProperty::ExportText_Direct(…, Data, Delta, …)`(CUO/Public/UObject/UnrealType.h:725)는 `Data == Delta`(기준 없음 뜻)이면 늘 출력하고, 그 밖에는 `!Identical(Data, Delta)`일 때만 출력한다(CUO/Private/UObject/Property.cpp:1021-1026, 직접 확인).

### 2.3 인스턴스 대응표·복제·이름

- **`FObjectInstancingGraph`**(CUO/Public/UObject/Class.h:5094-5350): `SourceRoot`·`DestinationRoot`(:5306-5322), `SourceToDestinationMap`(:5341)·`DestinationToSourceMap`(:5346). `GetInstancedSubobject`(CUO/Private/UObject/CoreNative.cpp:212-423)는 원형 하위 객체가 맵에 없으면 Outer의 대응 객체를 먼저 확보하고 **같은 FName**으로 `StaticConstructObject_Internal(Template = 원형 하위 객체, InstanceGraph = this)`를 부른다(:282-301·360-374).
- **내부 참조 재연결.** `FObjectPropertyBase::InstanceSubobjects`가 object 속성 값을 `InstancePropertyValue` 결과로 바꾼다(CUO/Private/UObject/PropertyBaseObject.cpp:73-94). 호출은 `UStruct::InstanceSubobjectTemplates`의 참조 링크 순회다(Class.cpp:2703-2729).
- **복제.** `StaticDuplicateObjectEx`(UObjectGlobals.cpp:2935-3205)는 루트를 `Template = Source->GetArchetype()`로 만들고(:3001-3004) `FDuplicateDataWriter`로 쓴 뒤 읽는다. default subobject는 이름으로 미리 대응한다(`GetDefaultSubobjectByName(Src->GetFName())`, :2840-2864). `DuplicationSeed`(UObjectGlobals.h:224)는 "복제하지 않을 객체" 대응이다.
- **제외 플래그.** `FDuplicateDataWriter::operator<<(UObject*&)`는 `RF_DuplicateTransient` 객체와 UE PIE가 아닐 때의 `RF_NonPIEDuplicateTransient` 객체를 null로 쓴다(CUO/Private/Serialization/DuplicateDataWriter.cpp:69-86, 직접 확인). 속성 플래그 `CPF_DuplicateTransient`·`CPF_NonPIEDuplicateTransient`는 `PPF_Duplicate`일 때 `ShouldSerializeValue`가 뺀다(Property.cpp:1069-1079). **템플릿 객체 자신은 그 값을 그대로 보존한다** — 제외는 복제·인스턴싱 때만 일어난다.
- **이름 충돌.** 템플릿에서 컴포넌트를 만들 때 이름이 없으면 `FindFirstFreeName(this, Template->GetFName())`으로 빈 이름을 찾는다(ENG/Private/ActorConstruction.cpp:1126, 직접 확인). 이름은 Outer 안에서만 유일하면 되고 정체성이 아니다.

### 2.4 Blueprint 컴포넌트 트리(SCS·ICH)

- **`USCS_Node`**(ENG/Classes/Engine/SCS_Node.h): `ComponentTemplate`(:30), `ParentComponentOrVariableName`(:48), `ChildNodes`(:61), `VariableGuid`(:68), `InternalVariableName`(:211-212). 주석은 "All instances route back to the archetype through the variable name"이다(:206-210, 직접 확인). **SCS는 생성자가 아니라 선언(노드 트리)이다** — 생성자가 만든 native 컴포넌트 뒤에 그 선언을 실행한다.
- **실행.** `AActor::FinishSpawning`(ENG/Private/Actor.cpp:4374) → `AActor::ExecuteConstruction`(ENG/Private/ActorConstruction.cpp:818)이 가장 위 BP부터 `SCS->ExecuteScriptOnActor`를 부른다(:901). `USimpleConstructionScript::ExecuteScriptOnActor`(ENG/Private/SimpleConstructionScript.cpp:696) → `USCS_Node::ExecuteNodeOnActor`(ENG/Private/SCS_Node.cpp:84)가 컴포넌트를 만들어 변수 속성에 넣고 자식을 재귀로 처리한다. 느린 경로는 `AActor::CreateComponentFromTemplate`(ActorConstruction.cpp:1112)이 템플릿을 `StaticDuplicateObjectEx`로 복제한다.
- **상속 override(ICH).** `FComponentKey`의 필드는 `OwnerClass`·`SCSVariableName`·`AssociatedGuid`다(ENG/Classes/Engine/InheritableComponentHandler.h:57-65). SCS 노드 키는 `AssociatedGuid = SCSNode->VariableGuid`(ENG/Private/InheritableComponentHandler.cpp:573)이고, `Match`는 `OwnerClass`와 `AssociatedGuid`만 비교한다(:586-589, 직접 확인). **즉 상속 override는 이름이 아니라 GUID로 대응한다.** `CreateOverridenComponentTemplate`(:102)는 부모 체인에서 가장 가까운 템플릿(`FindBestArchetype`, :415)을 archetype으로 삼아 `RF_ArchetypeObject|RF_Public|RF_InheritableComponentTemplate` 객체를 만든다(:158). 부모 템플릿과 같으면 기록이 필요 없다(`IsRecordNecessary`, :379). 실행 때는 `USCS_Node::GetActualComponentTemplate`가 실제 클래스부터 ICH override를 찾는다(SCS_Node.cpp:29).
- **cooked 빠른 경로.** `FBlueprintCookedComponentInstancingData`(ENG/Classes/Engine/BlueprintGeneratedClass.h:341-395 — `ChangedPropertyList`·`bHasValidCookedData`). cook 때 `BuildComponentInstancingData`가 차이 속성 목록을 만들며, 기준은 `bUseTemplateArchetype`이면 템플릿의 archetype, 아니면 클래스 CDO다(ED/UnrealEd/Private/Kismet2/BlueprintEditorUtils.cpp:10481-10486, 직접 확인). 로드 때 바이너리로 캐시하고(ENG/Private/BlueprintGeneratedClass.cpp:2822-2865), 생성은 `AActor::CreateComponentFromTemplateData`가 새 객체에 그 바이너리를 읽혀 만든다(ActorConstruction.cpp:1155). 사용 조건은 `UseFastPathComponentInstancing()`(BlueprintGeneratedClass.cpp:1877-1880). **원형을 실행 중 비교·복제하지 않고 미리 계산한 차이 블록을 바로 적용하는 구조**다. UE에서 실행 중 "원형으로 만든 묶음을 spawn"하는 일은 이 BP 클래스 spawn이 맡는다.

### 2.5 Level Instance

- **인터페이스·Actor.** `ILevelInstanceInterface`(ENG/Public/LevelInstance/LevelInstanceInterface.h:32 이하 — `GetLevelInstanceID`·`GetWorldAsset`·`GetDesiredRuntimeBehavior`·`SupportsPropertyOverrides`). `ALevelInstance`(LevelInstanceActor.h:18-60)는 `WorldAsset`(에디터 전용)·`CookedWorldAsset`·`LevelInstanceSpawnGuid`·`DesiredRuntimeBehavior`를 갖는다. **묶음은 World 에셋 하나이고, 배치는 그것을 가리키는 Actor 하나**다.
- **ID.** `FLevelInstanceID`는 "computed from the Hash of LevelInstance Actor Guid and all its ancestor LevelInstance Actor Guids"(LevelInstanceTypes.h:11-12, 직접 확인). 계산은 조상과 자신의 `GetLevelInstanceGuid()`를 모아 조상부터 `FActorContainerID(Parent, Guid)`(= `FGuid::Combine`, ENG/Public/WorldPartition/WorldPartitionActorContainerID.h:58-60)로 누적하고, 이름이 네트워크 안정이면 Actor 이름과(게임 World에서는) 패키지 짧은 이름의 해시를 seed로 써서 `CityHash64WithSeed`로 끝낸다(ENG/Private/LevelInstance/LevelInstanceSubsystem.cpp:156-191). 같은 묶음을 여러 번 배치해도 ID가 다르다.
- **런타임 동작.** `ELevelInstanceRuntimeBehavior`(LevelInstanceTypes.h:56-65): `Partitioned`(표시 "Embedded"), `LevelStreaming`(표시 "Standalone"), `None`(숨김). 기본값은 Partitioned다(LevelInstanceActor.cpp:33).
  - **Partitioned는 실행 중 spawn이 아니다.** WorldPartition 액터 기술자가 Partitioned Level Instance를 하위 컨테이너로 다루고(`IsChildContainerInstanceInternal`, ENG/Private/WorldPartition/LevelInstance/LevelInstanceActorDesc.cpp:220-243, ClusterMode Partitioned :257), 생성·쿡 때 그 안의 액터를 메인 WorldPartition 셀에 편입한다. LI Actor 자신은 런타임에 쓰이지 않는다 — "World Partition Embedded Level Instances don't get loaded as they aren't runtime relevant"(LevelInstanceActor.cpp:220-225, 직접 확인). 즉 UE는 **쿡 때 펼친다**(4절 D9 (b)).
  - LevelStreaming은 `ULevelStreamingLevelInstance`로 임시 패키지 레벨을 런타임에 로드한다(LevelInstanceLevelStreaming.cpp:389-445).
- **안의 Actor ID.** 스트리밍 때 `FSetActorInstanceGuid(Actor, ContainerID.GetActorGuid(ActorGuid))`(LevelInstanceLevelStreaming.cpp:262) — 컨테이너 ID와 원래 ActorGuid를 결합한다(WorldPartitionActorContainerID.h:112-115). 런타임도 OwnerLevel 체인의 GUID를 재귀로 결합한다(ENG/Private/WorldPartition/ActorInstanceGuids.cpp:66-112·133-166). **배치마다 결정적으로 파생된 ID**다.
- **순환 검사.** `ULevelInstanceSubsystem::CheckForLoop`(LevelInstanceSubsystem.cpp:886)는 조상과 자신이 속한 레벨 패키지가 WorldAsset과 같으면 순환이다. 호출은 스트리밍 로드(LevelInstanceLevelStreaming.cpp:393)와 편집 검증(LevelInstanceActorImpl.cpp:448)이며 둘 다 `WITH_EDITOR` 안이다. 쿡 쪽 WorldPartition 검증은 별도 함수 `FLevelInstanceActorDesc::ValidateCircularReference`(LevelInstanceActorDesc.cpp:327, 호출 :292·354)다.
- **속성 override(5.4+, 실험).** `ULevelInstancePropertyOverrideAsset : UWorldPartitionPropertyOverride`(ENG/Public/LevelInstance/LevelInstancePropertyOverrideAsset.h:30-79). 자료는 `컨테이너 경로 → ActorGuid → 하위 객체 경로 문자열 → 태그 직렬화 바이트`이고 전부 `WITH_EDITORONLY_DATA`다(ENG/Public/WorldPartition/WorldPartitionPropertyOverride.h:15-102). 저장은 원형 월드의 Actor를 기준으로 한 `SerializeTaggedProperties` 차이다(LevelInstancePropertyOverrideAsset.cpp:71·122-127). 실험 설정과 정책이 있어야 켜진다(LevelInstanceSettings.cpp:15-30). 런타임 데이터가 아니므로 쿡 때 적용되는 것으로 보이나 최종 경로는 확인하지 못했다(8절).

### 2.6 Packed Level Actor

`APackedLevelActor : ALevelInstance`(ENG/Public/PackedLevelActor/PackedLevelActor.h:24-110)는 기본 런타임 동작이 None이고(:75) 속성 override를 지원하지 않으며(:43), 에디터 밖에서는 원본 레벨을 로드하지 않는다(ENG/Private/PackedLevelActor/PackedLevelActor.cpp:42-49, 직접 확인). 빌더는 StaticMeshComponent를 ISM 기술자 해시로 묶어 2개 이상이고 non-Nanite면 HISM, 아니면 ISM으로 만들고(PackedLevelActorISMBuilder.cpp:26-104), 결과를 SCS 노드로 Blueprint에 저장한다(PackedLevelActorBuilder.cpp:411-525). **묶음을 렌더 instancing 데이터로 굽는 편집기 도구**다.

### 2.7 속성 단위 override 추적(실험)

- 헤더가 "Overridable serialization is experimental, not supported"라고 적는다(CUO/Public/UObject/OverriddenPropertySet.h:34-38, OverridableManager.h:17-21).
- `EOverriddenPropertyOperation`: None·Modified·Replace·Add·Remove·SubObjectsShadowing·Externalized(OverriddenPropertySet.h:229-238, 직접 확인). 노드는 `FOverriddenPropertyNodeID{Path, Object}`(:327-380, 맵 키용 `FromMapKey` :345)와 하위 노드 트리다(:389-463).
- `FOverridableManager`는 객체별 sparse annotation이며 `WITH_EDITORONLY_DATA` 전용이다(OverridableManager.h:23-60, 비에디터 `IsEnabled`는 false — OverridableManager.cpp:26-33). 클래스 플래그가 아니라 객체 단위로 켜지고 Outer·archetype에서 상속된다(`InheritEnabledFrom`, .cpp:71-83 — `InitProperties`가 부른다, UObjectGlobals.cpp:4456-4459).
- 컨테이너: 배열은 `CPF_ExperimentalOverridableLogic`이 없으면 통째 Replace이고(OverriddenPropertySet.cpp:1172-1189), 있으면 instanced 원소만 Add(추가된 하위 객체 ID)·Remove(**원형 하위 객체 ID**)로 기록한다(:1235-1326). 맵은 key 기반 Add·Remove·Replace다(:1497-1569).
- 저장: 추적이 켜지면 op ≠ None인 속성만 쓴다(Class.cpp:2017). **값이 원형과 같아도 "일부러 넣은 값"이 남는다** — RCM의 명시 override 집합과 같은 목적이다.
- 전파: 이 객체들은 값 전파를 하지 않고 "propagation is done via reinstantiation"이다(ED/PropertyEditor/Private/PropertyHandleImpl.cpp:629-639).

### 2.8 원형 변경 전파

- `UObject::GetArchetypeInstances`(Obj.cpp:1079-1111)가 archetype의 인스턴스를 모은다. `PreEditChange`·`PostEditChangeChainProperty`는 알림만 전파한다(Obj.cpp:586-676).
- **"원형과 같으면 따라가고, 바꿨으면 유지"의 실제 위치**는 편집기 `FPropertyNode::PropagatePropertyChange`(ED/PropertyEditor/Private/PropertyNode.cpp:4188-4317)다. 인스턴스의 현재 값을 `ExportText(PPF_ForDiff)`로 만들어 **이전 원형 값 문자열과 같을 때만** 새 값을 넣는다(:4294-4303, 직접 확인). 컨테이너는 `Identical(PPF_DeepComparison)`로 판정한다(:3874-4043). 컴포넌트 템플릿용 `FComponentEditorUtils::PropagateDefaultValueChange`도 같은 규칙이다(ED/UnrealEd/Public/Kismet2/ComponentEditorUtils.h:146).
- BP 재컴파일은 옛 archetype 대비 차이만 기록해 새 archetype으로 만든 객체에 덮어쓴다(ENG/Private/UnrealEngine.cpp:18035-18090 `FCPFUOWriter`, ED/UnrealEd/Private/Kismet2/KismetReinstanceUtilities.cpp:3342-3383). 즉 UE의 전파는 **값 비교식 제자리 갱신(편집기)** 과 **차이 재적용식 재생성(재컴파일·override 추적)** 두 갈래다.

### 2.9 클러스터

`ULevel::CreateCluster`(ENG/Private/Level.cpp:1526-1561)는 cooked이고 액터 클러스터링이 켜졌을 때 `CanBeInCluster` 액터를 `ULevelActorContainer`로 묶는다(Level.cpp:1528-1531 주석 — Level 자신은 루트가 아니다). 호출은 로드 때 컴포넌트 증분 갱신을 마칠 때 한 번이다(Level.cpp:1930). 그래서 **실행 중 spawn한 Actor는 Level 클러스터에 들어가지 않는다.** 클러스터 생성 자체가 cooked 전용이다(CUO/Private/UObject/UObjectClusters.cpp:26-37·854-857). UE에 "prefab 단위 클러스터"는 없다.

### 2.10 Unity 비교(짧게)

Unity는 소스가 공개되지 않아 직렬화 YAML의 공개 필드 이름 기준으로만 적는다(파일:행 근거 없음).

- **PropertyModification**: `{target(원형 객체 fileID + 원형 에셋 guid), propertyPath(문자열, 배열은 `Array.data[i]`), value(문자열), objectReference}`. 인스턴스(`PrefabInstance`)의 `m_Modification`에 목록으로 둔다.
- **추가·삭제**: `m_RemovedComponents`·`m_RemovedGameObjects`(원형 객체 참조), `m_AddedComponents`·`m_AddedGameObjects`(붙일 원형 객체 + 추가 객체).
- **중첩·variant**: 중첩 prefab은 원형 안의 `PrefabInstance`이고, variant는 루트가 다른 prefab의 `PrefabInstance`인 prefab이다. 인스턴스 안 객체의 fileID는 인스턴스 fileID와 원형 객체 fileID에서 결정적으로 만든다.
- **약점**: 배열 원소 override가 index 경로라 원형에 원소를 끼우면 다른 원소를 고친다(EIP 20.3절이 지적한 위험). 값이 문자열이라 타입 변경을 늦게 알아챈다.

## 3. Rocks 설계

### 3.1 원형 참조

**원형은 데이터다.** 원형은 Registry 객체가 아니라 노드 표와 노드별 Record로 된 불변 값 블록이다. 이유는 셋이다.

- Actor·Component·Level은 `ROCKS_CLASS(WorldOnly)`이고(ER 4.2·4.6절) 에셋 객체 Registry는 WorldOnly 타입 생성을 거부한다(AS 6.1절, OF 1.3절). UE처럼 원형 객체를 에셋 패키지에 살려 둘 수 없다.
- RCM은 살아 있는 CDO를 거부했다(가변 기준이 결정성을 깬다, WorldOnly 객체의 장부 밖 상주, `IsDefaultObject` 분기 — RCM 76행). 같은 이유가 원형 객체에도 그대로 적용된다.
- 원형을 GC가 보지 않으므로 원형 수와 무관하게 GC 비용이 없다(3.9절).

구성:

| 이름 | 무엇 | 수명 |
|---|---|---|
| `PrefabAsset` | 에셋 객체 Registry의 대표 에셋(WorldOnly 아님). 원형 본문·기준 prefab·revision을 리플렉션 필드로 담는다(3.6절) | 패키지(A1) |
| `PrefabNodeInfo` | 노드 하나의 부가 정보: NodeGuid, 노드 종류(객체·클래스 subobject·중첩 인스턴스), 클래스 subobject면 SubobjectGuid, 중첩이면 대상 prefab. 타입·Outer·이름은 graph v2 NodeTable이 정본이다(3.6절) | 값 |
| `PrefabArchetype` | **해석된 원형**: 기준 사슬과 중첩을 모두 펼친 부분 그래프 목록 + 노드 주소 색인 + 그래프 사이 참조 표 + 미리 해석한 override 경로. 불변, 공유 | 캐시(3.9절) |
| `PrefabContentRevision`·`PrefabResolvedRevision` | 자기 내용 지문과 해석 지문(3.6절) | 값 |

- 원형 참조는 `PrefabAsset`의 AssetId다. World 객체는 에셋을 `ObjectRef`로 가리킬 수 없으므로(AS 6.3절) 영속 참조는 `SoftObjectRef<PrefabAsset>`, 런타임 보유는 `AssetLease`다. lease는 인스턴스 장부가 보유한다(3.9절 — 원형 캐시는 lease를 쥐지 않는다).
- **클래스 원형**(선언형 default subobject, 3.2절)은 아래 층이다. prefab 원형은 그 위에 얹힌다. 적용 순서는 EIP 5.3절 그대로다: native 생성자 → Sparks 필드 초기값(= 클래스 레코드) → subobject 기본값 레코드 → prefab·variant → instance override → spawn 인자.

### 3.2 클래스 원형: 선언형 subobject

**문제.** UE는 생성자 안의 `CreateDefaultSubobject`로 하위 객체를 만든다(2.1절). Rocks 생성자는 Registry·World·다른 객체를 건드리지 못하고 C++ 레코드의 객체 참조는 구조적으로 null이다(RCM 59·60행). 생성자는 `Actor(Allocator&)` 하나뿐이다(`WD/Actor.h:60-61`). 지금은 component를 `OnAwake`에서 `AddComponent`로 만든다(`WD/Actor.h:26-31`). graph v2에는 "이미 만들어진 객체를 노드로 쓰는" 개념이 없다(OF 5.1절).

**설계: subobject를 선언으로 옮긴다**(UE SCS가 선언 트리인 것과 같은 꼴 — 2.4절, 4절 D13).

- **선언**: C++는 소유 필드 지정자로 선언한다 — `ROCKS_PROPERTY(Subobject, Parent = "root") ObjectRef<StaticMeshComponent> mesh;`(지정자 이름은 PF1에서 확정). Sparks는 `let` component 필드가 같은 선언으로 컴파일된다(SL 4.5절).
- **subobject 표**: MetaCompiler가 클래스마다 생성한다. 항목은 `{SubobjectGuid, 타입(TypeId), 이름, 부착 부모(SubobjectGuid 또는 소유 Actor의 root), 소유 필드(FieldId)}`이고 상속 클래스의 표는 base 표 + 자기 항목이다. SubobjectGuid는 `.rocksids.json`에 발급한다(TypeId·FieldId와 같다 — SL 12.2절). 이름은 표 안에서 유일하다(MetaCompiler 오류).
- **생성**: 생성자가 아니라 World instancing이 만든다. `ConstructionContext`에서 소유 객체를 만든 직후 표 순서대로 subobject를 staged로 만들고(Outer = 소유 객체, 이름 = 표 이름), 소유 필드에 staged 쓰기로 넣고, 부착 부모를 정한다. `SpawnActor`·`AddComponent`·그래프 복원·prefab spawn이 모두 이 한 경로를 쓴다.
- **subobject 기본값 레코드**: (소유 클래스 TypeId, SubobjectGuid)마다 하나다. 내용 = subobject 타입의 클래스 레코드 + 소유 클래스가 그 subobject에 준 기본값 덮기. C++는 소유 클래스의 정적 함수가 Registry 밖 임시 subobject 값에 쓰는 방식으로 덮기를 준다(RCM 58·59행의 레코드 생성과 같은 결정성 계약 — 두 번 실행해 인코딩 비교). Sparks는 `let` 초기값의 필드 지정이 덮기다.
- **subobject 지역 번호 참조**: 클래스 레코드·subobject 기본값 레코드 안에서 "이 소유 객체의 k번째 subobject"를 가리키는 참조 wire를 둔다(예: `Actor.rootComponent` 기본값 = subobject 1, 부착 부모 = subobject 2). 값은 소유 객체 기준 지역 번호이고 instancing이 실제 handle로 바꾼다. 이 참조만 레코드의 non-null 객체 참조로 허용한다 — **RCM 59·60·68행 개정이 필요하다**(7절, D1 (a)의 선행 조건).
- **파생 클래스의 덮기**: 파생 클래스는 상속 subobject의 기본값을 SubobjectGuid 키로 덮는다(UE ICH가 `AssociatedGuid`로 대응하는 것과 같다 — 2.4절). 타입 교체(UE `SetDefaultSubobjectClass`)는 같은 SubobjectGuid에 base 타입의 파생만 허용하고, 제거(UE `DoNotCreateDefaultSubobject`)는 1차에 두지 않는다(비활성화는 `enabled` 덮기).
- **graph v2 노드 종류 "기존 default subobject"**: NodeTable 항목이 새 객체를 만들지 않고 "노드 k(소유 객체)의 SubobjectGuid g" 를 가리킨다. 복원 2a는 소유 노드를 만들 때 생긴 subobject를 그 노드 번호에 묶고, 2b는 그 위에 Record를 적용한다. 레벨 저장·prefab 본문·복제가 모두 이 종류로 subobject를 저장한다(**OF 5.1절 개정 필요** — 7절).
- **실행 중 추가 component**: `OnAwake`·게임 코드가 `AddComponent`로 만든 component는 subobject가 아니다. 생성 출처가 Runtime으로 표시되고 원형·레벨 저장에 들어가지 않는다(3.3절 10항).

### 3.3 인스턴스 생성

공통 instancing 순서(EIP 5.3절: AllocateGraph → ApplyDefaults → Deserialize/Remap → Validate → pre-commit Initialize → Commit → Register → BeginPlay)를 prefab에 이렇게 대응한다.

1. **원형 확보**: `PrefabArchetype`을 캐시에서 얻는다(없으면 3.9절의 해석). 이 단계는 Registry를 건드리지 않는다.
2. **인스턴스 계획**: 원형 노드 − 삭제 노드 + 추가 노드로 노드 집합을 정하고 override를 노드 주소별로 묶는다. 한도(3.8절)를 여기서 검사한다.
3. **AllocateGraph**: World의 `ConstructionContext` 하나에서 부분 그래프마다 graph v2 단계형 복원(OF 5.4절)으로 객체를 staged로 만든다. 클래스 subobject는 3.2절 경로로 소유 객체와 함께 생기고 노드는 "기존 default subobject" 종류로 묶인다.
4. **Outer·이름**(4절 D14):
   - Component의 Outer는 소유 Actor, 이름은 노드 이름(subobject는 표 이름)이다. 한 Actor 안의 이름 유일성은 prefab 저장과 override 추가 때 검사하므로 spawn에서 충돌하지 않는다. 인스턴스가 여러 개여도 Outer(Actor)가 다르므로 충돌하지 않는다.
   - Actor는 지금처럼 Outer·이름 없이 만든다(`World.cpp:425`, ER 4.2절). 그래서 같은 원형을 두 번 spawn해도 이름 충돌이 없다. 레벨 패키지 단계가 Actor의 Outer를 Level로 정하면 spawn은 노드 이름에서 빈 이름을 결정적으로 찾는다(가장 작은 빈 번호 접미 — UE `FindFirstFreeName`과 같은 목적, 2.3절). 이름은 정체성이 아니므로 재생성 전파(3.7절)는 새 이름을 받아도 된다. 파괴 요청된 객체가 이름을 계속 차지하는 규칙(OF 1.1절)은 그대로이며, 재생성은 옛 이름 해제를 기다리지 않는다.
5. **값 적용**: 노드마다 원형 Record를 staged 객체에 적용한 뒤(두 단계 decode), override 값을 적용하고(3.5절 — 통째 단위는 부분 Record 디코드), 마지막으로 spawn 인자를 적용한다.
6. **내부 참조 재연결**:
   - 같은 부분 그래프 안: graph v2 노드 번호라서 복원이 새 handle로 바꾼다(OF 5.1절 — UE `SourceToDestinationMap` 역할).
   - 다른 부분 그래프의 노드(중첩 원형 사이, cooked 분할 그래프 사이 — 3.6절): 강한 참조는 graph v2 외부 참조로 쓰고 2b의 `imports`에 **같은 트랜잭션 객체**를 넘긴다(OF 5.4절이 허용한다). weak 참조는 graph v2에 weak import가 없으므로(RX 5.1절) Record에는 null로 쓰고 원형의 **그래프 사이 참조 표** `{부분 그래프, 노드, 필드 경로, 대상 노드 주소}`에 둔다. 모든 부분 그래프의 2b가 끝난 뒤 이 표를 staged 경로 쓰기로 적용한다(4절 D17).
   - override 값 안의 노드 참조: 노드 주소(3.5절)이며 인스턴스 대응표 `PrefabInstanceMap`(노드 주소 → handle, spawn 동안만 존재 — 3.9절)으로 바꾼다. 삭제된 노드를 가리키는 참조는 null이 되고 진단을 낸다.
   - 원형 밖 World 객체 참조는 둘 수 없다(3.5절, 4절 D12).
7. **제외 플래그**: 원형 본문은 편집 World 객체의 저장 가능한 값을 **모두** 보존한다(DuplicateTransient·NonTryoutDuplicateTransient 포함 — 다시 편집할 때 값이 사라지지 않게. UE 템플릿과 같다, 2.3절). spawn 복원은 decode 정책 `excludedFlags = DuplicateTransient | NonTryoutDuplicateTransient`로 그 필드를 건너뛰어 생성자 값으로 둔다(에셋 복제 정책과 같다 — RX 9.1절, 4절 D20). 지금 decode 정책이 Record에 있는 제외 필드를 건너뛰는지 거부하는지는 PF2에서 확인하고, 거부라면 "건너뛰기" 갈래를 더한다(5.1절). Transient 필드는 원래 저장되지 않는다. 클래스가 Transient·Deprecated인 객체(저장 불가 객체 — RX 9.2절)는 원형 노드가 될 수 없다(prefab 저장이 거부·진단). UE의 "CDO·archetype은 Transient 예외"(RX 694행)는 원형이 객체가 아닌 Rocks에서 생기지 않는다.
8. **Validate**: 실효 값 Required(OF 4절), 부착 계층 순환, Transform 유효성(유한·단위 quaternion — ER 4.6절 레벨 편입 5항), 소유 컨테이너 일관성.
9. **소유 목록**(4절 D15): prefab에서 펼친 Actor는 Level의 영속 목록 `actors`가 아니라 Transient 소유 목록 `spawnedActors`(`ROCKS_PROPERTY(Transient) ObjectRefArray<Actor>`)에 넣는다. `actors`는 Required 영속 필드라(ER 4.6절) 펼친 Actor가 들어 있으면 레벨 저장에서 그 Actor를 빼는 순간 집합 밖 강한 참조가 되어 graph v2 Reject로 실패한다(OF 5.3절). Transient 목록은 저장되지 않고 GC 소유 간선 역할만 한다(생성 Trace가 Transient 참조 필드를 방문해야 한다 — 5.1절에서 확인). 레벨에 직접 배치한 Actor만 `actors`에 남는다.
10. **생성 출처 표시**: 객체마다 NATIVE 생성 출처를 둔다 — `ClassSubobject`·`PrefabNode`·`InstanceAdded`(인스턴스 override로 추가한 노드)·`Runtime`(hook·게임 코드의 `SpawnActor`·`AddComponent`). UE `CreationMethod`와 같은 목적이다(2.1절). 원형 본문과 레벨 저장은 Runtime 출처를 넣지 않는다. 편집 World에서는 게임 hook을 실행하지 않으므로(3.13절, 4절 D18) Runtime 출처가 생기지 않는 것이 정상이고, 이 표시는 그 계약의 방어선이다.
11. **pre-commit Initialize → Commit**: 최상위 Actor들을 root로 다중 root Commit 한 번(OF 1.6절). Commit 전 실패는 staged 그래프 전체를 rollback한다.
12. **Register → hook**: World가 Actor마다 `ActorRecord`를 만들고 클러스터에 가입시킨다(3.9절). hook은 spawn 묶음 단위다 — 묶음의 모든 Actor·Component `OnAwake`가 성공하면 노드 순서로 `OnEnable`, `OnStart`는 기존 규칙(ER 7.2절)을 따른다(SL 5.1절). Commit 뒤 `OnAwake` 실패는 묶음 전체를 RequestDestroy 경로로 정리한다(EIP 5.3절 — 공개된 객체를 rollback 경로로 지우지 않는다).

API(이름은 PF3에서 확정 — EIP 20.3절의 `InstantiatePrefab`·`PrefabInstanceDesc`와 맞출 점은 7절):

```cpp
struct SpawnPrefabParams {
    ObjectHandle level;                 // null이면 영구 Level(SpawnParams와 같다)
    Transform transform;                // 인스턴스 원점 Transform(3.10절 — 부착 부모가 있으면 그 기준)
    ObjectHandle attachParent;          // 선택. 최상위 root를 붙일 다른 Actor의 SceneComponent
    Guid instanceGuid;                  // 빈 값이면 새로 발급(3.4절)
    bool tracked = false;               // 인스턴스 장부·노드 대응표·앵커를 둔다(편집기·레벨 배치는 늘 true)
    const PrefabOverrideSet* overrides = nullptr;  // 레벨 배치 인스턴스 로드·편집기 생성용
};
// World API다(World registry의 WorldOnly 생성 키를 가진 경로 — ER 4.6절 정책 자리).
Result<PrefabSpawnResult> World::SpawnPrefab(const AssetLease& prefab, const SpawnPrefabParams&) noexcept;
```

`PrefabSpawnResult`는 인스턴스 Guid와 최상위 Actor handle 목록을 담는 **복사 가능한 값**이다. lease를 쥐지 않고 handle은 대상 파괴 뒤 stale이 된다. 추적 인스턴스(`tracked`)는 `PrefabInstanceId`(World 인스턴스 장부의 slot + generation)를 함께 돌려주며, `World::FindPrefabNode(PrefabInstanceId, PrefabNodeAddress)`로 노드 객체를 찾는다. 추적하지 않는 인스턴스는 노드 대응표를 남기지 않으므로 노드 조회가 `Unsupported`다(3.9절).

### 3.4 하위 객체 안정 ID와 이름

| ID | 발급 | 쓰는 곳 |
|---|---|---|
| `SubobjectGuid` | MetaCompiler가 subobject 선언마다 `.rocksids.json`에 발급 | 클래스 subobject의 정체성, 파생 클래스 덮기 키(UE ICH `AssociatedGuid` 대응) |
| `NodeGuid` | prefab 편집기가 노드를 만들 때 무작위 발급, 원형 수명 동안 불변(이름 변경·이동과 무관) | 원형 노드의 정체성, override 대상 |
| `PrefabInstanceGuid` | 인스턴스 생성 때 발급, 저장 시 보존, 복제(편집기 복사·Tryout이 아닌 복제) 때 재발급 | 인스턴스 정체성 |
| `PrefabNodeAddress` | `{중첩 인스턴스 경로: NodeGuid 목록, 노드: NodeGuid}` | override 대상, 바인딩(EIP 2111행) |
| 파생 Entity ID | `DeriveGuid(PrefabInstanceGuid, 주소)` — 결정적 | 세이브게임·외부 참조·네트워크 |

- **이름은 정체성이 아니다.** UE는 원형과 인스턴스를 같은 FName으로 대응하지만(2.1절) Rocks의 Outer 이름은 생성 뒤 불변이고(OF 1.1절) 편집 중 이름 변경을 허용해야 하므로 GUID로 대응한다. 노드 이름은 표시와 객체 경로용이다(이름 규칙은 3.3절 4항).
- 클래스 subobject 노드의 NodeGuid는 `DeriveGuid(소유 노드 NodeGuid, SubobjectGuid)`로 정한다. 그래서 클래스에 subobject가 추가돼도 원형 노드 표를 고치지 않고 주소가 안정하다.
- 중첩: 원형 B를 품은 원형 A에서, B 안 노드의 A 기준 주소는 `{[B 인스턴스 노드의 NodeGuid], B 안 NodeGuid}`다. 같은 원형을 두 번 중첩해도 경로가 달라 충돌하지 않는다(EIP 20.5절, UE `FLevelInstanceID`가 조상 GUID를 결합하는 것과 같은 목적 — 2.5절).
- **파생 Entity ID는 저장하지 않는다.** UE `FActorInstanceGuid`가 컨테이너 ID와 ActorGuid를 결합하듯(2.5절) 인스턴스 Guid와 주소에서 매번 같은 값을 만든다. 인스턴스 Guid가 보존되면 모든 파생 ID가 보존되고, 복제로 재발급되면 함께 바뀐다(EIP 20.5절의 "저장 시 보존, 새 복제 시 재발급"을 노드 단위로 만족). 인스턴스 안에서 추가한 노드는 그 인스턴스가 발급한 NodeGuid를 쓰므로 같은 식이 그대로 적용된다.
- **`DeriveGuid` 형식**: Core 공용 SHA-256 위에 둔 결합 함수이며 기능 모듈에 따로 만들지 않는다. 입력은 도메인 구분 문자열(`"Rocks.Prefab.NodeId.v1"`, `"Rocks.Prefab.SubobjectNode.v1"`처럼 용도마다 다르다)과 각 입력의 길이 접두(u32) + byte를 이어 붙인 것이다. 주소는 경로 원소 수 + 각 NodeGuid 16 byte로 쓴다. 출력은 앞 16 byte다. 도메인과 길이 접두가 있어 서로 다른 입력 조합이 같은 byte열을 만들 수 없다.
- 배열 원소에는 안정 ID를 두지 않는다(4절 D4). 원소 단위 override는 key 컨테이너(`OrderedMap`·`OrderedSet`)의 key가 안정 ID 역할을 한다(RX 1.5·7절).

### 3.5 override 기록

`PrefabOverrideSet`은 인스턴스(또는 variant)가 원형과 다른 점의 목록이다.

| 항목 | 내용 | UE·Unity 대응 |
|---|---|---|
| 값 override | `{PrefabNodeAddress, 소유형 PropertyPath(필드 ID Guid 단계 + PathKey), 단위 값 wire}` | `FOverriddenPropertySet` Modified·Replace, Unity PropertyModification |
| key 추가·제거 | Map·Set의 `{주소, 필드 경로, key, 값}` 추가·변경과 `{주소, 필드 경로, key}` 제거 | TMap key 단위 차이(2.2절), OS 맵 Add·Remove(2.7절) |
| 노드 추가 | `{부모 주소, 새 NodeGuid, 타입, 이름, 전체 Record}` — 추가한 Component·Actor·중첩 인스턴스 | OS ArrayAdd, Unity AddedComponents·AddedGameObjects |
| 노드 삭제 | `{주소}` — 부분 트리째 | OS ArrayRemove(원형 ID), Unity RemovedComponents |

- **단위**는 RX 10.2절 `OverridePaths`의 정규화를 따른다: Atomic struct는 struct 경로, 비Atomic struct는 멤버 끝 경로(`Transform`은 멤버 단위 — 이동만 덮고 회전·크기는 원형을 따른다, RX 301행), 단일 값은 끝 경로, Array·StaticArray·Optional·InstancedStruct는 필드 통째. **Map·Set만 다르다**: prefab override는 key 단위다(4절 D5 — UE 표준 TMap 차이도 key 단위다, 2.2절). 같은 필드에 통째 override와 key override가 함께 있으면 통째가 이긴다(저장이 key 항목을 지운다).
- **Map·Set key 단위 추출**(4절 D16): RX 10.2절 `Publish`의 override 경로는 Map·Set을 필드 통째 경로로 정규화하므로(RX 812-814행) 그대로 쓰면 key 단위가 사라진다. prefab 기록기는 `Publish`가 돌려주는 옛 값과 게시 뒤 값을 key로 비교해 추가·변경·제거 key를 직접 뽑는다. RX 10.2절은 바꾸지 않는다(다른 소비자 — A5 패키지 차이 — 는 통째가 맞다). 편집기의 경로 쓰기(대입 묶음 밖)도 같은 옛 값/새 값 비교를 쓴다.
- **통째 단위 값의 적용**: 지금 경로 쓰기는 struct·배열을 통째로 쓰면 `Unsupported(AggregateValue)`다(`OR/PropertyPath.h:362-363`). 그래서 Atomic struct·Array·StaticArray·Optional·InstancedStruct 단위 override를 적용할 수단이 없다. **"경로 위치에 그 단위의 부분 Record(wire)를 staged 디코드"하는 API**를 PF4 선행으로 정의한다: `ApplyPathWire(ConstructionContext&, handle, PropertyPath unit, Span<const uint8> wire)` — 그 위치의 필드·멤버 codec으로 두 단계 decode(검증 → 할당 외 실패 없는 적용)를 하고, 참조 원소는 staged 쓰기 규칙(삽입 장벽·대상 검사)을 지난다. 단일 값 단위도 같은 API로 적용해 경로 하나로 통일한다.
- **무엇을 기록하나**: RCM 62행 그대로 **명시 override 집합 ∪ 원형과 인코딩이 다른 값**이다. 편집기와 경로 쓰기가 집합에 기록하고, 저장 때 모든 노드를 원형 Record와 비교해 다른 값을 더한다. 원형과 같은 값을 일부러 넣은 경우도 집합에 남아 원형이 바뀐 뒤 유지된다(2.7절). "원형으로 되돌리기"는 원형 값을 쓰고(기록하지 않는 쓰기) 집합에서 지운다.
- **같음**은 RCM 63행 정의(wire byte, non-null 참조는 대상 정체성)다. 노드 참조의 정체성은 노드 주소이고, 죽은 weak handle은 null로 정규화한 뒤 비교한다(RX 5.1절). byte 비교가 의미를 갖도록 원형 값을 변환해 쓰는 경로(예: 최상위 root의 월드 Transform 구움)를 추적 인스턴스에 두지 않는다(3.10절).
- **소유 컨테이너는 override 대상이 아니다.** `Actor.components`·`Level.actors`·`Level.spawnedActors`처럼 소유 관계를 나타내는 필드는 노드 구조(추가·삭제)에서 다시 만든다. `Actor.rootComponent`처럼 노드를 가리키는 참조 필드는 일반 값 override다.
- **참조 값 표기**: override 값 안의 강한·weak 참조는 노드 주소 표의 번호로 쓴다(graph v2 노드 번호와 같은 고정 폭 U32 — 0 = null). 노드 주소 표는 override 집합 머리에 둔다. 에셋 참조(Soft·AssetId)는 값 그대로다. **원형 밖 World 객체를 가리키는 참조는 1차에 저장할 수 없다**(4절 D12). EIP 20.3절(1771행)은 이를 `SoftEntityId`로 유지하라고 하므로, World 단계의 영속 Entity 참조가 생기면 그 값으로 저장한다(7절).
- **노드 추가·삭제 규칙**:
  - 삭제는 원형 노드만 대상이다(추가한 노드는 그냥 목록에서 뺀다 — UE ArrayRemove가 앞의 Add를 지우면 no-op인 것과 같다, 2.7절). 삭제한 노드의 하위 노드도 삭제된다. 하위 노드를 대상으로 한 override는 고아가 된다(3.7절).
  - 클래스 subobject 노드는 삭제할 수 없다(클래스 선언이 만든다). 비활성화는 `enabled` 값 override로 한다.
  - 루트가 하나뿐인 원형의 루트는 삭제할 수 없다.
  - 추가 노드의 부모는 원형 노드나 다른 추가 노드다. 추가 노드의 Record는 기준이 클래스 레코드인 전부 저장 형식(RCM 66행 누락 = 기준)이다. 추가 노드의 이름은 부모 Actor 안에서 유일해야 한다(추가 때 검사).
- **reparent**: 부착 계층이 리플렉션 필드(WeakObjectRef 부모 — ER 4.6절, RF 결정 21)로 영속된 뒤에는 reparent가 부모 필드의 값 override다. Outer(소유 Actor)를 바꾸는 이동은 없다 — Outer는 불변이다(OF 1.1절).
- **타입 버전 기록**: override 집합은 대상 노드 타입마다 저장 당시 스키마 버전을 기록한다(마이그레이션 판정용 — 3.7절).

### 3.6 저장 형식

**prefab 패키지.** A1 패키지(AS 5절) 하나에 대표 에셋 `PrefabAsset` 하나다. 원형 객체들은 패키지 export가 아니라 `PrefabAsset`의 필드 값이다(3.1절 — WorldOnly 객체는 에셋 Registry에 둘 수 없다).

| `PrefabAsset` 필드 | 내용 | 정본 |
|---|---|---|
| `base` | `SoftObjectRef<PrefabAsset>` — variant면 기준 prefab, 아니면 null | — |
| `body` | 원형 본문: graph v2 바이트(NodeTable 있음, `BaseOuter` — OF 5.1절). 노드 Record는 **클래스 레코드 대비 차이**(subobject는 subobject 기본값 레코드 대비 — A5 차이 쓰기). variant는 비어 있다 | 노드의 타입·Outer·이름 |
| `nodeInfo` | `Array<PrefabNodeInfo>` — `body` NodeTable과 같은 순서·같은 길이의 부가 정보(NodeGuid·노드 종류·SubobjectGuid·중첩 대상) | NodeGuid·노드 종류 |
| `crossReferences` | 그래프 사이 weak 참조 표(3.3절 6항) — 편집기 본문에서는 중첩 노드 안을 가리키는 참조만 생긴다 | — |
| `overrides` | `PrefabOverrideSet` — variant의 기준 대비 차이(**variant의 추가 노드는 여기에만 있다**), 중첩 인스턴스 노드에 둔 override | variant 추가 노드 |
| `contentRevision` | 자기 내용 지문 | — |

- **정본은 하나씩이다**: 노드 타입·Outer·이름은 graph v2 NodeTable, NodeGuid와 노드 종류는 `nodeInfo`, variant 추가 노드는 `overrides`의 노드 추가 항목이다. 둘이 어긋나면(길이·순서) `CorruptPackage`다.
- `body`의 노드 수는 graph v2 `maxObjects`(4096 — OF 5.6절)로 묶이며 이 값을 `MaxPrefabNodes`로 이름 붙여 쓴다. `body`는 64 MiB(`maxValueBytes`) 이하다. 큰 본문을 Bulk entry로 옮길지는 PF2에서 크기를 재고 정한다.
- **두 가지 revision**(교차검증 I8):
  - `contentRevision` = SHA-256(이 패키지의 `base`·`body`·`nodeInfo`·`crossReferences`·`overrides`의 인코딩). 저장 때 계산한다. 편집기 dirty 판정과 쿡 입력 지문에 쓴다.
  - `resolvedRevision` = SHA-256(도메인 문자열, 자기 `contentRevision`, 기준의 `resolvedRevision`, 중첩 노드마다 대상의 `resolvedRevision`(노드 순서), 해석 결과가 쓰는 타입들의 (TypeId, 스키마 버전, 클래스 레코드·subobject 기본값 레코드 지문) TypeId 정렬 목록). 저장하지 않고 해석 때 계산한다(cooked는 쿠커가 계산해 저장한다).
  - 쓰임: 원형 캐시 키 = (AssetId, `resolvedRevision`). 레벨 배치 기록의 `baseRevision` = 저장 당시 `resolvedRevision`이라서 기준 사슬·중첩·코드 기본값이 바뀌어도 전파가 일어난다(3.7절). cooked 검증 = cooked `PrefabAsset`에 저장한 `resolvedRevision`과 cooked 레벨 배치 기록의 `baseRevision` 대조(다르면 `UnsupportedVersion` — 다시 쿠킹). 쿠커 재계산 = prefab의 cookKey 입력에 기준·중첩 prefab의 cookKey와 타입 지문 목록을 넣어 기준이 바뀌면 그것을 쓰는 prefab과 배치 레벨이 다시 쿠킹된다.
- **의존**: 원형 본문의 에셋 참조(World 객체의 Soft 참조)는 이 패키지의 Dependencies(Hard)로 기록한다 — "하드 의미는 그 World 데이터를 담는 레벨·prefab 패키지의 Dependencies(Hard)로 표현한다"(AS 6.3절). 기준 prefab과 중첩 prefab도 Hard다. override하지 않은 값의 클래스 레코드 참조도 포함한다(RCM 68행). prefab별 하드 의존 크기 예산은 쿡이 검사한다(SL 7.2절). Hard 의존 덕분에 prefab A가 상주하는 동안 그 기준·중첩 prefab도 상주한다.
- **레벨 배치 인스턴스.** 레벨에 놓인 인스턴스는 펼친 객체가 아니라 **배치 기록** `PrefabPlacement{instanceGuid, prefab(SoftObjectRef), baseRevision, transform, overrides}`로 저장한다(UE Level Instance가 World 에셋 + 배치 Actor인 구조 — 2.5절, 4절 D3). 배치 기록은 Level의 영속 struct 배열 필드다. 펼친 Actor·Component는 Transient 소유 목록에 있으므로(3.3절 9항) 레벨 저장에 들어가지 않는다. `baseRevision`이 다르면 로드 때 전파(3.7절)를 거친다.
- **실행 중 spawn한 인스턴스**는 저장하지 않는다. 세이브게임은 원형 ID·인스턴스 Guid·spawn/despawn 기록과 SaveGame 필드를 저장한다(EIP 951행 — 세이브게임 계층).
- **쿠킹**(4절 D8): 쿠커는 variant 사슬과 중첩을 펼친 **평탄화 원형**을 cooked `PrefabAsset`에 저장한다. 펼친 노드가 `MaxPrefabNodes`(graph v2 `maxObjects`)를 넘을 수 있으므로 평탄화 본문은 **부분 그래프 여러 개**(각각 4096 이하 — 원래의 원형 경계를 따라 나누고, 한 원형이 4096을 넘을 수는 없다) + 노드 주소 표 + 그래프 사이 참조 표다. 그래프 사이 참조는 3.3절 6항 규칙(강한 = 같은 트랜잭션 import, weak = 참조 표)을 그대로 쓴다. `base`·`overrides`는 비운다(UE cooked 빠른 경로가 차이 블록을 미리 만드는 것과 같은 목적 — 2.4절). 편집기 해석 결과와 cooked 평탄화 결과는 같은 입력에서 같은 byte여야 한다(PF8 시험). EditorOnly 필드·노드는 뺀다. 레벨 배치 인스턴스의 cooked 형태는 4절 D9.
- **A1과의 관계**: prefab은 새 섹션을 만들지 않는다. 일반 에셋 패키지이고, 원형 본문은 대표 에셋의 값이다. 패키지 Summary의 타입 표에는 `PrefabAsset`과 함께 **원형 본문이 쓰는 World 타입들**의 (TypeId, 스키마 버전, 클래스 레코드 지문)을 넣는다 — 본문 Record가 그 타입들의 레코드 대비 차이이기 때문이다(RCM 69행 지문 규칙을 본문 타입까지 넓힌다 — 7절). 지문이 다르면 편집기는 진단 뒤 열고 cooked는 `UnsupportedVersion`이다.
- 원점 규약 버전 칸은 두지 않는다(하위호환 없음 — 규약이 바뀌면 원형을 다시 만든다).

### 3.7 원형 변경 전파와 충돌 처리

**원칙**: 인스턴스는 차이만 가지므로 **새 원형 + 같은 override = 전파 결과**다(UE override 추적의 "재생성으로 전파" — 2.7절). 이것이 EIP 20.3절의 3-way(old base / new base / local override)를 그대로 구현한다: override가 없는 필드는 new base 값, 있는 필드는 local 값이다.

**언제**:

- 로드: 배치 기록의 `baseRevision` ≠ 현재 `resolvedRevision`이면 전파 후 spawn하고, 편집기는 레벨을 dirty로 표시한다.
- 편집기에서 원형 저장: 열린 World의 그 원형을 쓰는 추적 인스턴스(중첩·variant 포함 — 인스턴스 장부의 원형별 목록, 3.9절)를 모두 갱신한다.
- `RebasePrefabInstance(PrefabInstanceId, resolvedRevision)`(EIP 20.3절)로 명시 호출.
- 실행 중(Tryout·게임)에는 원형이 바뀌지 않는다. Tryout 중 원본 수정은 명시 live patch 범위에서만이다(EIP 20.3절).

**어떻게**(4절 D7):

- **제자리 갱신**: 노드 집합이 같으면(추가·삭제 노드 없음, 노드 타입 같음) 노드마다 override하지 않았고 현재 값이 **옛 원형 값과 인코딩이 같은** 단위에 새 원형 값을 쓴다(UE `PropagatePropertyChange`의 "이전 값과 같을 때만" — 2.8절. override 집합이 있으므로 비교는 확인용이다). 쓰기는 World API·setter hook 경로를 지난다(CU5). 객체 정체성·handle·hook 상태가 유지된다.
- **재생성**: 노드가 추가·삭제되었거나 노드 타입이 바뀌었으면 인스턴스를 같은 인스턴스 Guid로 다시 만든다 — 옛 객체 RequestDestroy(EndPlay 계열 hook) → 새 spawn. Actor는 Outer·이름이 없고(3.3절 4항) Component는 새 Actor 아래라서 옛 객체가 이름을 차지하고 있어도 충돌하지 않는다. 파생 ID가 같으므로 외부 바인딩·세이브 참조는 유지된다. BeginPlay 중복 방지는 EIP 1738행의 world session event 기록을 쓴다.

**override 마이그레이션**(4절 D19): 노드 타입의 스키마 버전이 override 집합에 기록된 버전과 다르면, 그 노드의 값 override 항목을 **부분 Record**로 묶는다(누락 = 기준이 형식 규칙이므로 일부 필드만 담은 Record가 유효하다 — RCM 66행). 그 Record에 타입 migrate(Record 단위, 값의 존재 여부를 받는다 — RF 2.2절, RCM 67행)를 적용한 뒤 결과 Record에 있는 단위 경로를 다시 뽑아 새 항목으로 바꾼다. Map·Set key 항목은 부분 Record로 표현할 수 없으므로, 그 필드를 migrate가 바꾸면(전후 wire가 다르면) key 항목을 고아로 보존하고 진단한다. FieldId는 이름 변경에도 유지되므로 이름만 바꾼 필드는 마이그레이션 없이 그대로 맞는다.

**충돌 분류**(전파는 충돌이 있어도 멈추지 않는다 — 충돌 항목만 보존하고 진단한다):

| 충돌 | 처리 | 진단 |
|---|---|---|
| override 대상 노드가 새 원형에 없다 | override 항목을 **고아로 보존**(적용하지 않음), 편집기에 표시, 사용자가 지우거나 다른 노드로 옮긴다 | `PrefabOverrideOrphaned` |
| override 경로의 필드가 마이그레이션 뒤에도 없다 | 고아 | `PrefabOverrideOrphaned` |
| override 값의 wire가 필드 종류와 맞지 않는다 | 고아 | `PrefabOverrideTypeMismatch` |
| migrate가 key 단위 override가 있는 Map·Set 필드를 바꿨다 | key 항목 고아 | `PrefabOverrideNeedsReview` |
| 삭제 항목의 노드가 이미 원형에서 없어졌다 | 항목을 지운다(목적 달성) | 없음(정보) |
| 추가 노드의 부모가 원형에서 없어졌다 | 최상위 Actor면 인스턴스 루트로, Component면 고아로 보존 | `PrefabAddedNodeParentMissing` |
| 추가 노드 이름이 새 원형 노드 이름과 겹친다 | 추가 노드 이름에 결정적 번호 접미를 붙이고 진단(정체성은 NodeGuid라 영향 없음) | `PrefabNodeNameConflict` |
| Required 필드가 전파 결과 null | spawn 실패(편집기는 진단과 함께 인스턴스를 비활성 표시) | `RequiredMissing`(OF 4절) |
| 새 원형이 순환·깊이 한도를 만든다 | 원형 저장 자체를 거부 | `PrefabCycle`·`PrefabDepthExceeded` |

- cooked 빌드에는 충돌이 없어야 한다 — 쿡은 고아 override가 남은 레벨·prefab을 오류로 거부한다.
- **Apply to source**(인스턴스 override를 원형에 올리기): 원형 편집 transaction으로 처리하고 영향 인스턴스 목록을 만든다(EIP 20.3절). 올린 항목은 인스턴스 집합에서 지운다. `EditScope = "Instance"` 필드의 override는 올리지 않고 인스턴스 집합에 남긴다(UE `SkipInstanceOnlyProperties` — [UI 툴킷](UiToolkit.ko.md) 7.3절 (a)). 같은 인스턴스를 연쇄로 다시 적용하지 않는다.
- **클래스 기본값 변경**(코드 수정·Sparks reload): 원형 본문이 클래스 레코드 대비 차이이므로 원형이 override하지 않은 값은 새 클래스 기본값을 따른다. 타입 지문이 `resolvedRevision`에 들어 있으므로 편집기 배치 인스턴스는 다음 로드 때 전파를 거치고, 살아 있는 인스턴스는 RCM 71행 reload 규칙을 노드마다 적용하되 "기준"을 해석된 원형 값으로 본다.

### 3.8 중첩과 variant

- **variant**: `base`가 다른 prefab인 prefab이다. 원형 = 기준의 해석된 원형 + 이 prefab의 `overrides`(추가 노드 포함). Unity variant·UE BP 상속(ICH)과 같은 축이다.
- **중첩**: 노드 종류가 "중첩 인스턴스"인 노드는 `{prefab, transform, overrides}`를 갖는다. 해석은 그 prefab의 해석된 원형을 이 노드 아래에 펼치고 주소에 이 노드의 NodeGuid를 앞에 붙인다. override 노드 추가 항목으로 중첩 인스턴스를 더할 수도 있다.
- **우선순위**(바깥이 이긴다): 클래스 레코드 → subobject 기본값 레코드 → 가장 안쪽 원형 본문 → 그 원형의 variant 사슬(기준부터) → 바깥 원형이 그 중첩 노드에 둔 override → … → 레벨 배치 override → spawn 인자.
- **순환 금지**: 해석은 방문 중인 AssetId 집합을 들고 깊이 우선으로 내려가며 다시 만나면 `PrefabCycle`로 실패한다. 기준 사슬, 본문의 중첩 노드, **override가 추가한 중첩 인스턴스 노드**(variant `overrides`와 중첩 노드의 override 안)를 모두 같은 집합으로 본다(A가 B를 품고 B가 A의 variant인 경우도 순환이다). 편집기 저장·로드·쿡이 모두 검사한다(UE는 편집기 로드의 `CheckForLoop`과 쿡 검증 `ValidateCircularReference`로 나눠 검사한다 — 2.5절. EIP 20.3절의 "cooker가 거부"보다 이르게 막는다).
- **한도는 해석 도중 점진적으로 검사한다**: 깊이는 내려갈 때마다, 누적 노드 수·override 수는 노드를 펼칠 때마다 비교해 넘는 순간 멈춘다(큰 입력을 다 펼친 뒤 거부하지 않는다 — 작업량도 한도 안).
- **한도**(이름 붙은 상수 — `Prefab/PrefabLimits.h`, 값은 PF0 확정 때 다시 본다):

| 상수 | 제안 값 | 근거 |
|---|---|---|
| `MaxPrefabBaseDepth` | 16 | variant 사슬 길이. EIP 20.3절 "초기 중첩 depth 상한 16" |
| `MaxPrefabNestingDepth` | 16 | 중첩 깊이 = 주소 경로 길이 상한 |
| `MaxPrefabNodes` | 4096 | 원형 하나의 `body` 노드 수 = graph v2 `maxObjects`(OF 5.6절) |
| `MaxPrefabInstanceNodes` | 65536 | 펼친 인스턴스 하나의 전체 노드 수(중첩 포함). spawn 한 번의 staged 객체 상한 |
| `MaxPrefabOverrides` | 65536 | override 집합 하나의 항목 수 |

  넘으면 `CapacityExceeded`다. `MaxPrefabInstanceNodes`가 graph v2 단일 그래프 한도보다 크므로 spawn은 부분 그래프마다 graph v2 복원을 따로 하고 한 ConstructionContext에 모은다(3.3절 3항).

### 3.9 실행 중 생성 비용·인스턴스 장부·GC

**spawn 경로에서 하지 않는 일**: 원형 사슬 해석, 원형과의 비교, 문자열 경로 해석, 원형 객체 복제. 모두 해석된 원형을 만들 때 한 번 한다.

- **해석된 원형 캐시**(교차검증 I7): 키는 (AssetId, `resolvedRevision`)이고 **lease를 쥐지 않는다.** lease를 쥐면 캐시가 자기 에셋을 영원히 붙잡는 순환이 된다. 캐시 항목은 본문 타입의 TypeLease만 쥔다(타입 등록이 원형보다 먼저 사라지지 않게 — RCM 55행 레코드와 같은 규칙). 항목은 AssetManager의 패키지 Discard 통지(그 AssetId의 패키지가 상주에서 빠질 때)로 버린다. 상주는 인스턴스 장부의 lease와 Hard 의존이 정한다. cooked는 쿠커가 이미 평탄화했으므로(3.6절) 로드가 곧 해석이다.
- **인스턴스 장부**(World 쪽, 4절 D21):

| 장부 | 언제 | 내용 | 1M 규모 비용 |
|---|---|---|---|
| 원형별 항목 `PrefabUsage` | 모든 spawn | `{AssetLease, 살아 있는 Actor 수, 추적 인스턴스 목록 머리}` — 원형 하나에 하나 | 원형 수에 비례(인스턴스 수와 무관) |
| Actor별 칸 | 모든 spawn | `ActorRecord`에 u32 `PrefabUsage` 번호(+ 추적이면 인스턴스 번호 u32) | Actor당 4–8 B |
| 추적 인스턴스 항목 `PrefabInstanceRecord` | `tracked`(편집기·레벨 배치·요청 시) | `{인스턴스 Guid, resolvedRevision, 앵커 행렬(3.10절), override 집합 사본, 노드 대응표(지연 생성)}` | 추적 인스턴스 수에 비례 |

  - lease 반납: `PrefabUsage`의 살아 있는 Actor 수가 0이 되면(마지막 Actor의 레코드 제거 — ER 7.2절) lease를 반납하고 항목을 지운다. Component는 소유 Actor와 함께 죽으므로 따로 세지 않는다.
  - 노드 대응표(`PrefabInstanceMap`)는 spawn 동안 임시로 만들고 끝나면 버린다. 추적 인스턴스는 `FindPrefabNode`를 처음 부를 때 다시 만든다(지연 생성 — 최상위 Actor부터 노드 순서로 소유 목록을 따라가며 맞춘다). 추적하지 않는 실행 중 spawn은 노드 대응표·인스턴스 항목을 전혀 남기지 않는다.
- **spawn 비용**: O(노드 수 + 실효 Record 크기 + 인스턴스 override 수). 실행 중 spawn은 보통 인스턴스 override가 없으므로 노드 수와 Record 크기에 비례한다. 할당은 staged 객체와 그 값뿐이다(장부는 `PrefabUsage` 계수 증가와 Actor 칸 하나).
- **대량 spawn**: `World::SpawnPrefabBatch(prefab, Span<const SpawnPrefabParams>)`로 여러 인스턴스를 한 ConstructionContext·한 Commit으로 만든다. Commit·클러스터 가입·관찰자 보고가 묶음마다 한 번이다. 묶음 크기는 `MaxPrefabInstanceNodes`로 나눈다.
- **GC**:
  - 원형은 Registry 객체가 아니므로 GC 표식·sweep 비용이 0이다. 원형 수가 많아도 GC와 무관하다.
  - 펼친 객체는 일반 World 객체다. Rocks World 클러스터는 **Level 하나**이고 World API 생성의 Commit에서 가입한다(GCS 13.3절, 개정 2). prefab spawn도 같은 경로로 대상 Level 클러스터에 가입한다. **UE와 다르다**: UE Level 클러스터는 로드 때 한 번 만들어지고 실행 중 spawn한 Actor는 들어가지 않는다(2.9절). Rocks는 간선 쓰기마다 장부를 고치므로 spawn한 객체도 가입한다. prefab 단위 클러스터는 두지 않는다(UE에도 없다).
  - 클러스터 소속 조건은 `completeFieldLayout` 타입이다(GCS 13.3절). native 파생 Actor·Component는 원형 본문에 저장할 수 없으므로(ER 4.6절 "native 파생이 든 그래프는 저장할 수 없다") prefab 노드는 모두 리플렉션 타입이고 클러스터 조건을 만족한다.
  - spawn은 열린 ConstructionContext 동안 GC를 막는다(OF 6절). 큰 묶음은 `MaxPrefabInstanceNodes` 단위로 나눠 GC 정지 구간을 묶는다.
- **비용 목표**(PF3 벤치에서 확정): 노드 16개 원형 1만 회 spawn, 노드 4096개 원형 1회 spawn, 1M 객체 누적 spawn 후 증분 GC 한 cycle의 표식 시간이 같은 수의 직접 `SpawnActor`·`AddComponent`와 같은 차수일 것. 추적하지 않는 spawn의 장부 비용은 Actor당 고정 byte(위 표)로 측정한다.

### 3.10 Transform 규약

좌표·단위·행렬은 UE 5.8과 같다: 왼손 +X 전방·+Y 오른쪽·+Z 위, 위치 cm, 편집기 회전 입력은 도 단위 Rotator(`ToQuaternion`으로 변환), `Transform`은 double 회전(quaternion)·이동·scale(R·T·S), 합성은 `Transform::TryMultiply(child, parent)` = UE `Child * Parent`(Core/Math/Transform.h 12-14행), SceneComponent 월드 행렬 = 상대 TRS 행렬 × 부모 월드 행렬(행 벡터 — ER 7.3절).

- **원형 원점**: 원형은 자기 원점(prefab 공간)을 갖는다. 최상위 Actor의 root component `relativeTransform`은 prefab 공간 기준이다. Actor에 붙은 하위 SceneComponent는 지금처럼 부모 기준이다.
- **추적 인스턴스 — 앵커**(4절 D10): 최상위 root의 `relativeTransform`에 월드 값을 구워 넣지 않는다. 구우면 byte 비교 override 판정(3.5절)이 늘 "다름"이 되고, 편집 뒤 역변환으로 되돌려도 비트가 달라 가짜 override가 생기며 제자리 전파(3.7절)도 깨진다. 대신 인스턴스 장부의 **앵커 행렬**(`Mat4d` — 인스턴스 Transform의 TRS 행렬, 부착 부모가 있으면 × 부모 월드 행렬)을 부착 부모 없는 최상위 root의 "부모 행렬"로 쓴다. 최상위 root의 월드 행렬 = 상대 TRS 행렬 × 앵커 행렬이다. root의 `relativeTransform`은 prefab 공간 값 그대로이므로 원형과 byte로 같고, 사용자가 그것을 바꾸면 정확히 그만큼 override가 된다. 인스턴스를 옮기면 앵커 행렬을 바꾸고 최상위 root 이하를 dirty로 표시한다.
  - 앵커는 행렬 합성이라 비균일 scale 인스턴스 아래 회전한 최상위 root도 shear 그대로 정확하다 — 추적 인스턴스에는 shear 제약이 없다.
  - 중첩: 중첩 인스턴스 노드의 `transform`은 바깥 prefab 공간 기준이다. 안쪽 최상위 root의 부모 행렬 = 중첩 노드 TRS 행렬 × 바깥 앵커 행렬이다(중첩 앵커도 행렬이다).
  - 앵커는 NATIVE 상태다(저장은 배치 기록 `transform`). SceneComponent의 부모 행렬 출처가 "부모 SceneComponent 또는 앵커"로 늘어나는 것은 World 단계 변경이다(7절).
- **추적하지 않는 실행 중 spawn — 구움**: 게임 코드는 부착 부모 없는 Actor의 상대 Transform을 월드 Transform으로 다룬다(ER 7.3절). 그래서 실행 중 spawn은 최상위 root `relativeTransform`에 `TryMultiply(원형 상대 Transform, 인스턴스 Transform)`을 써 넣는다. 저장하지 않는 인스턴스라 override 판정 문제가 없다. 합성이 shear로 실패하면(Transform.h 47-49행) spawn은 `Unsupported`·`PrefabTransformShear`로 실패하고 아무것도 남기지 않는다(EIP 147행 CF04 "불허 경로는 변경 없는 실패"). 비용: 원형 안에 회전된 최상위 root가 있으면 그 prefab을 비균일 scale로 실행 중 spawn할 수 없다. 이런 사용이 필요하면 `tracked = true`로 앵커를 쓴다.
- **부착 부모가 있는 spawn**(`attachParent`): 최상위 root를 그 SceneComponent에 붙인다. 추적이면 앵커 행렬 = 인스턴스 Transform TRS 행렬 × 부모 월드 행렬이고 부모가 움직이면 앵커를 다시 계산한다(부모의 dirty 전파가 앵커를 거친다). 추적하지 않으면 root `relativeTransform` = `TryMultiply(원형 상대, 인스턴스 Transform)`이 부모 기준 상대 값이 되며 shear 규칙은 같다. 다른 Actor의 Component를 부모로 저장하는 일(배치 기록의 부착)은 원형 밖 World 참조라 1차에 저장하지 않는다(4절 D12).
- **override**: `Transform`은 비Atomic이라 멤버 단위 override다(RCM 64행, RX 3.1절). 인스턴스에서 이동만 바꾸면 회전·scale은 원형 변경을 따른다(RX 301행이 말한 UE 동작).
- **저장**: 배치 기록의 `transform`은 인스턴스 원점 Transform(부착 부모 없으면 월드)이다. 최상위 root의 상대 Transform 편집은 prefab 공간 값의 override로 그대로 저장한다(역변환 없음).
- **큰 좌표**: 인스턴스 Transform과 앵커 행렬은 double이다. 렌더용 float 좁히기(Transform3f)는 렌더 계약을 따른다.

### 3.11 오류·진단

`ErrorCode`는 기존 것을 쓰고 원인은 진단 코드로 구분한다(AS 4.6절 진단 형식, OF 진단과 같은 꼴).

| 진단 | ErrorCode | 때 |
|---|---|---|
| `PrefabCycle` | InvalidArgument(편집)·CorruptPackage(로드) | 기준·중첩·추가 중첩 순환 |
| `PrefabDepthExceeded`·`PrefabNodeLimit`·`PrefabOverrideLimit` | CapacityExceeded | 3.8절 한도 |
| `PrefabMissingBase`·`PrefabMissingNested` | MissingDependency | 기준·중첩 prefab 로드 실패 |
| `PrefabDuplicateNodeGuid` | CorruptPackage | 노드 정보·추가 노드 GUID 중복 |
| `PrefabNodeTableMismatch` | CorruptPackage | `nodeInfo`와 NodeTable의 길이·순서 불일치 |
| `PrefabNodeNameConflict` | InvalidArgument(추가)·진단(전파) | 같은 Actor 안 노드 이름 중복 |
| `PrefabUnsaveableNode` | Unsupported | Transient·Deprecated 클래스, native 파생, Runtime 출처 노드 |
| `PrefabExternalReference` | InvalidArgument | 원형 밖 World 객체 참조 저장(3.5절) |
| `PrefabOverrideOrphaned`·`PrefabOverrideTypeMismatch`·`PrefabOverrideNeedsReview`·`PrefabAddedNodeParentMissing` | 편집기: 진단만, cooked: InvalidArgument | 3.7절 충돌 |
| `PrefabOverridePathInvalid` | InvalidArgument | 경로 해석 실패, ReadOnly 위반, 소유 컨테이너 대상, 편집 위치 위반(편집기 쓰기 경로 — [UI 툴킷](UiToolkit.ko.md) 7.3절 (a)) |
| `PrefabEditScopeViolation` | 편집기: 진단만(값은 적용), cooked: InvalidArgument | 저장물의 편집 위치 위반: 원형 저장물(`PrefabAsset`의 본문·variant `overrides`·중첩 노드 override)에 `EditScope = "Instance"` 필드가 클래스 레코드와 다른 값, 배치 저장물(`PrefabPlacement.overrides`·레벨 직접 배치 Record)에 `"Archetype"` 필드가 원형과 다른 값(UI 툴킷 7.3절 (a)) |

| `PrefabRevisionMismatch` | 편집기: 진단 후 전파, cooked: UnsupportedVersion | 배치 기록의 `baseRevision` 불일치 |
| `PrefabNodeLookupUntracked` | Unsupported | 추적하지 않는 인스턴스의 노드 조회 |

- 진단은 노드 주소·필드 경로를 함께 담는다(경로 표기는 RX 1.6절). 로그 문구는 영어다.
- 실패 원자성: 원형 해석 실패는 캐시를 만들지 않는다(할당 실패가 아닌 실패는 (AssetId, resolvedRevision)별로 기억한다 — RCM 56행과 같은 방식). spawn 실패는 3.3절 11·12항.

| prefab 패키지 로드 | A1 로더(IO·압축 해제 worker, 객체 생성 Game) | AS 11.2절 |
| 해석 입력 모으기: 대상·기준·중첩 `PrefabAsset`의 필드 byte 복사, 본문 타입 TypeLease 획득 | Game(`AssetManager::With` — 에셋 객체는 소유 스레드에서만 읽는다, AS 6.1절) | 교차검증 I12 |
| 원형 해석(사슬·중첩 펼침, override 경로 해석, `resolvedRevision` 계산) | 어느 스레드나 — **입력은 Game에서 복사한 불변 byte와 TypeLease뿐**이고 Registry를 건드리지 않는다(TypeRegistry 조회는 잠금) | OF 6절 `ObjectGraphStage::Validate`와 같은 조건 |
| graph v2 1단계(파싱·검증) | 어느 스레드나 | OF 6절 |

| 전파(편집기) | Game, 편집 transaction 안 | 3.7절 |

- **수명**: `PrefabArchetype`은 불변 공유 값이고 TypeLease만 쥔다(3.9절). 에셋 lease는 `PrefabUsage`가 쥐고 원형의 마지막 Actor가 사라질 때 반납한다. `PrefabSpawnResult`는 lease를 쥐지 않는 값이다.
- **World 종료·Tryout**: World 종료 시 `PrefabUsage`의 lease를 모두 반납한다. Tryout 시작은 편집 World를 복제하며 인스턴스 Guid·배치 기록·추적 인스턴스 장부를 유지한다(Tryout 복제 — DuplicateTransient만 제외, RX 9.1절). 늦게 끝난 비동기 로드는 종료된 World에 spawn하지 않는다(RCM 45행).
- **모듈 reload**: 본문 타입의 revision이 바뀌면 `resolvedRevision`이 바뀌므로 옛 캐시 항목은 더 쓰이지 않고 Discard 통지나 다음 정리에서 버린다.

### 3.13 편집기·네트워크와의 접점(자리)

- **편집 World**(4절 D18): prefab 편집은 원형을 **편집 전용 World**에 spawn해서 World API로 고치고 저장 때 다시 원형 본문으로 인코딩한다(UE Level Instance 편집 모드·Unity prefab mode와 같은 흐름). 편집 World와 레벨 편집 World는 게임 hook(`OnAwake`·`OnEnable`·`OnStart`·`OnTick`)을 실행하지 않는다. 등록(`OnRegister` — 표시·backend 등록)과 편집기 재구성 hook(`Validate` — EIP 5.3절·1740행)만 실행한다. 그래서 hook이 만드는 Runtime 출처 component가 원형에 섞이지 않는다(3.3절 10항). 지금 `FinishSpawning`은 등록과 `OnAwake`를 함께 하므로(ER 7.3절) 편집 World 모드가 World 단계 변경으로 필요하다(7절).
- **편집기 명령**(EIP 20.3절)은 이 문서의 API로 구현한다.
  - Revert = override 집합에서 지우고 원형 값 쓰기.
  - Unpack = 펼친 객체를 레벨에 직접 배치한 객체로 바꾸고 배치 기록을 지운다. 파생 ID를 그 시점 값으로 굳혀 각 Actor에 저장해야 하므로 **Actor의 영속 Entity Guid 필드가 선행 조건**이다(지금 ER 4.6절 Actor 필드에 없다 — 7절).
  - Make variant = 인스턴스의 override 집합으로 새 prefab의 `overrides`를 만들고 인스턴스는 새 variant를 가리킨다. `EditScope = "Instance"` 필드의 override는 옮기지 않고 인스턴스 집합에 남긴다(UI 툴킷 7.3절 (a)). 인스턴스가 추가했던 노드는 **NodeGuid를 그대로 새 variant로 옮긴다**(Apply와 같은 이동 의미 — 인스턴스 쪽 항목은 지워져 같은 NodeGuid가 두 곳에 남지 않는다). 그래서 파생 ID가 바뀌지 않는다.
  - Apply to source는 3.7절.
- 네트워크 spawn: 원형 AssetId·`resolvedRevision`·인스턴스 Guid·spawn 인자·권한 override를 보내고 받는 쪽이 같은 revision을 검증한 뒤 spawn한다(EIP 20.3절). 파생 ID가 결정적이므로 하위 객체 ID를 따로 보내지 않는다.
