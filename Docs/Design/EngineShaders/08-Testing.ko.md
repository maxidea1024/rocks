# 엔진 셰이더 — 8. 시험 방침

## 8. 시험 방침

### 8.1 시험 종류

6장 단계표의 기호를 쓴다.

| 기호 | 시험 | 방법 | 판정 |
|---|---|---|---|
| (C) | 컴파일 행렬 | 영역마다 "전체 include" 시험 엔트리 하나와 모든 엔진 엔트리를 엔진 컴파일 프로필의 모든 형식(`D3D12_SM6`·`D3D11_SM5`·`VULKAN_SM5`·`METAL_SM5`·`GLES31_*`)으로 컴파일(SS `shader-compile`). 퍼뮤테이션은 거르기를 통과한 전부(SS 12.2절 열거) | 컴파일·워커 규칙(SS 7.2절) 통과, 경고 0(SS 결정 7). 형식이 없어서 못 도는 호스트(예: Windows의 metallib 도구 없음)는 SKIP과 사유 |
| (N) | CPU 기준 구현 대조 | 같은 입력을 GPU probe와 CPU 기준 구현에 넣고 비교(8.2·8.3절) | 함수별 허용 오차 |
| (G) | golden 출력 | 정수·비트 함수와 결정적 패턴(해시·패킹·Morton·저불일치 정수부·정렬 결과)을 저장된 기대값과 bit 비교. 기대값은 CPU 기준 구현이 만들고 저장소에 둔다 | bit 일치 |
| (S) | 통계 시험 | 난수·표본 변환: χ² 균일성, pdf 대비 히스토그램, 평균·분산 | 고정 seed·고정 유의 수준. 실패 확률이 있는 판정은 seed를 고정해 결정적으로 만든다(시간·경쟁에 기대지 않는다) |
| (I) | 기준 영상 | RN·RB의 기준 영상 시험을 그대로 쓴다(채널 ±8·2%로 시작, RB 8절) | 그 문서의 기준 |
| (P) | 물리 성질 | BRDF 정규화·상반성·에너지 보존(백색 노), 위상 함수 정규화, 필터 커널 합 1, 색 행렬 왕복 | 수치 적분 허용 오차 |

### 8.2 CPU 기준 구현(결정 SLD10)

- **독립 구현.** CPU 기준 구현은 시험 코드 쪽 C++로 **따로** 쓴다. `Shared/*.h`의 상수·구조체 배치는 공유하지만 함수 본문은 셰이더 원문을 C++로 컴파일해 재사용하지 않는다. 같은 원문을 양쪽에 쓰면 원문의 오류가 양쪽에 같이 들어가 대조가 아무것도 잡지 못하기 때문이다.
- **정밀도.** 기준은 `double`로 계산하고 마지막에 float로 반올림한다. 셰이더 결과와의 차이는 그 float 값 기준으로 잰다.
- **출처.** 기준 구현은 공개 문헌의 식을 그대로 옮긴 "느리고 명확한" 버전이다(근사·최적화 없음). 근사 함수(`Fast*`·해석 근사)는 정확한 함수와 비교해 오차 상한을 잰다.
- **위치.** 시험 runner(EngineTests)의 엔진 셰이더 시험군에 둔다. 표(예: BRDF LUT·에너지 표)의 CPU 생성기가 엔진 쪽에 이미 있으면(RB 11.1절 기본 BRDF LUT) 그것과 따로 하나 더 만들지 않고, 그 생성기를 기준 구현의 일부로 쓴다(공용 유틸리티 중복 금지).
- **수치 적분.** BRDF·위상 함수·대기 적분의 기준은 CPU 적응 구적법 또는 고정 seed Monte Carlo(표본 수와 오차 추정을 함께 기록)다.

### 8.3 허용 오차

허용 오차는 함수마다, 그 함수가 쓰는 연산의 **사양 정밀도**에서 유도한다. 기준은 대상 형식 가운데 가장 느슨한 사양이다: Vulkan 명세 "Precision and Operation of SPIR-V Instructions" 표(SPIR-V·Metal 변환 경로)와 GLSL ES 3.20 명세 4.7.1절(highp — GLES 형식은 모든 실수가 highp, SS 7.2절 5항), D3D11 기능 명세의 부동소수점 규칙(DXBC·DXIL). 아래는 판정에 쓰는 사양 상한이다(highp·float32).

| 연산 | 사양 상한(가장 느슨한 형식 기준) | 출처 |
|---|---|---|
| `+`·`-`·`*`, 비교, 정수→실수 변환 | 올바른 반올림(0 ulp — 단, FMA 축약 허용) | GLSL ES 3.20 4.7.1, Vulkan 정밀도 표 |
| `a / b` | 2.5 ulp(‖b‖ ∈ [2⁻¹²⁶, 2¹²⁶]) | 같음 |
| `rsqrt`(inversesqrt) | 2 ulp | 같음 |
| `sqrt` | `1/inversesqrt`에서 유도 | 같음 |
| `exp`·`exp2` | (3 + 2·‖x‖) ulp | 같음 |
| `log`·`log2` | [0.5, 2] 밖 3 ulp, 안 절대 2⁻²¹ | 같음 |
| `pow(x, y)` | `exp2(y·log2 x)`에서 유도 | 같음 |
| `sin`·`cos` | [−π, π]에서 절대 2⁻¹¹ | GLSL ES 3.20 4.7.1(Vulkan 표도 같다) |
| `tan` | `sin/cos`에서 유도 | 같음 |
| `atan` | 4096 ulp | 같음 |
| `asin`·`acos` | `atan2(x, sqrt(1−x²))`에서 유도 | 같음 |
| `f32tof16`·`f16tof32`, `asuint`·비트 연산, 정수 산술 | 정확(bit 일치) | HLSL·SPIR-V 정의 |

Metal은 기본 컴파일이 fast-math라 정밀도가 위 표보다 느슨할 수 있다. `METAL_SM5` 형식 정의의 컴파일 옵션(fast-math 끔 여부)을 SH5 착수 때 확인하고 다르면 Metal 행을 따로 둔다(9.1절 미확인).

이 상한으로 함수 부류의 판정을 정한다. 판정값은 이름 있는 상수로 시험 코드 한 곳에 둔다.

| 함수 부류(예) | 쓰는 연산 | 판정 |
|---|---|---|
| 정수·비트(해시·패킹 부호화·Morton·정렬·morph 정수 누적) | 정수·비트 | bit 일치 |
| 산술만(행렬·색 행렬·unorm 복호화·팔면체 복호화) | `+ − × ÷` | 연산 수 n에 대해 상대 ≤ (n·0.5 + 2.5)·2⁻²³ 를 함수별로 계산해 적는다(대략 4–16 ulp) |
| `pow`가 들어간 전달 함수(sRGB·감마·PQ) | `exp2`·`log2` | 상대 ≤ (3 + 2·‖y·log2 x‖)·2⁻²³ + log2 절대 오차 전파 — 함수별로 계산한 값. 8 bit sRGB 왕복은 부호 일치로도 판정 |
| 삼각 함수가 들어간 것(구면 좌표·표본 변환·SH 기저) | `sin`·`cos`·`atan` | 절대 2⁻¹¹ 전파값(방향 벡터 성분 절대 ≤ 1e-3 수준). 각도 판정은 각 오차로 |
| 근사 함수(`Fast*`·해석 근사) | — | 주석에 적은 근사 오차 상한 + 위 사양 오차 |
| 수치 적분 대조(BRDF·대기·사전 필터) | — | 상대 ≤ 1%(기준 쪽 표본 수·오차 추정과 함께 기록) |
| 영상 | — | RN·RB 기준 |

- 함수별로 더 좁게 잡을 수는 있다(측정값이 사양보다 훨씬 좋을 때). 사양보다 넓힐 때는 사유를 적는다.
- 다른 정밀도(half)가 들어오면(결정 SLD4 후속) mediump 표(GLSL ES 3.20 4.7.1)를 따로 둔다.

### 8.4 입력 고르기

- 규칙마다 양성·음성: 정의역 안 대표값, 경계값(0·1·정확히 임계각·NoV=0), 정의역 밖 입력에 대한 문서화된 동작(예: `SafeNormalize`의 0 벡터).
- 무작위 입력은 고정 seed의 CPU 난수로 만들고 seed·개수를 시험 이름에 남긴다.
- 전수 가능하면 전수(8·10·16 bit 패킹, sRGB 8 bit, 작은 Morton).
- 각 단계(SL0–SL10)의 시험은 그 단계 파일의 공개 함수를 모두 덮는다. 덮지 않은 함수는 coverage 사유 목록에 남긴다(7.7절 5항).
- **비결정적 순서의 결과.** GPU 메시지·print·append 버퍼처럼 원자 증가로 순서가 정해지는 결과는 순서를 비교하지 않는다. 정렬한 다중집합(같은 값의 개수 포함)으로 golden과 비교한다.
- **시간 의존 시험.** 노출 적응·시간 누적(TAA·GTAO)처럼 프레임 시간에 기대는 시험은 고정 dt와 고정 프레임 수로 돌린다(벽시계 시간을 쓰지 않는다).
- **큰 표본의 배치.** 표본이 많은 시험(2²⁰ 등)은 W×H 2D 배치로 한 번에 돈다(폭 ≤ 16,384, 장치 한도가 작으면 나눈다 — 7.6절). 1D 텍스처·버퍼 한도에 기대지 않는다.

### 8.5 형식 사이 대조

- 같은 probe를 D3D12 하드웨어·WARP·Vulkan·GLES 미리보기에서 돌려 서로 대조한다(CPU 기준과 별도로). backend 사이 차이가 CPU 기준과의 차이보다 크면 원문의 형식 의존(정밀도·미정의 동작)을 의심하고 원인을 기록한다.
- D3D11·Metal은 SS SH5, Android 실기기는 SH6 단계에서 같은 시험을 더한다.
- 웨이브 경로가 있는 함수(CS 전용, SL1부터)는 웨이브 경로가 있는 형식(지금 `D3D12_SM6`뿐)에서 웨이브 경로·대체 경로를 모두 돌려 대조한다: 정수 연산은 bit 일치, float 합은 허용 오차 안(결정 SLD5).

### 8.6 회귀

- 셰이더 원문이 바뀌면 SS 키(include 폐포 SHA-256)가 바뀌므로 영향받는 시험만 다시 돈다(반복 중에는 바뀐 시험만, 전체는 끝에 한 번 — 검증 단계 규칙).
- golden 기대값 갱신은 CPU 기준 구현을 고친 커밋에서만 한다. 셰이더 원문 커밋이 golden을 바꾸면 시험 실패로 본다.
