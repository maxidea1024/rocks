# 엔진 셰이더 — 4.10 그림자(A10)

[4장 목차](README.ko.md)

### 4.10 그림자(A10)

**역할.** 그림자 depth 그리기(CSM 단·spot·point 6면, shadow atlas 하나), 조명 함수 안 직접 표본(비교 샘플러 PCF·필터 커널·bias), CSM 단 고르기와 단 사이 섞기, 화면 공간 contact shadow.

**UE 파일(17).** `ShadowDepthVertexShader.usf`, `ShadowDepthPixelShader.usf`, `ShadowDepthCommon.ush`, `ShadowProjectionVertexShader.usf`, `ShadowProjectionPixelShader.usf`, `ShadowProjectionCommon.ush`, `ShadowFilteringCommon.ush`, `ShadowPercentageCloserFiltering.ush`, `ShadowFactorsUpsampleCommon.ush`, `ForwardShadowingCommon.ush`, `CopyShadowMaps.usf`, `ScreenSpaceShadows.usf`, `ScreenSpaceShadowRayCast.ush`, `bend_sss_gpu.ush`(+`.tps` 2), `LateZDummyPS.usf`.

**UE 구조 메모.** UE Deferred는 그림자 투영 pass(`ShadowProjection*`)가 screen shadow mask를 만들고, Forward는 `ForwardShadowingCommon.ush`로 CSM을 직접 표본한다. 화면 공간 그림자는 자체 ray cast(`ScreenSpaceShadowRayCast.ush`)와 Bend Studio 방식(`bend_sss_gpu.ush`) 두 가지다.

**Rocks 차이(RN 9.2절).** screen shadow mask가 없다. 두 경로가 조명 함수 안에서 atlas·CSM을 직접 표본한다. 그래서 `ShadowProjection*`의 전체 화면 투영 pass는 대응이 없고, 그 안의 필터 함수만 `ShadowFiltering.rsh`로 가져온다. 그림자 depth는 보통 Z(가까움 0, `LessEqual`, clear 1)·`D16Unorm`이다(화면 깊이와 반대 — RN 9.2절).

**의존.** A05·A07 `MeshPassCommon`(`ShadowDepth` pass), A02(표본 패턴·회전 잡음), A06(깊이·HZB 추적), A08(광원 기록의 그림자 index). 쓰는 곳: A09·A15. 렌더러: RN 9절, 6.2절 F7, RS3·RS10. 내장 자원: 빈 그림자 depth(RB 11.1절), 비교 샘플러(SX13).

**Rocks 파일.**

| 파일 | 내용 | 단계 |
|---|---|---|
| `Shadow/ShadowDepthPass.rsf` | `ShadowDepth` 메시 pass(VS + masked·PDO면 PS): 직교(CSM)·원근(spot·point 면) 투영, slope-scaled bias는 래스터 상태, 직교 깊이 clamp 미지원 backend의 셰이더 clamp 대체(RN RS3 (d)), point 6면 한 번 그리기용 viewport index 출력 변형(`vertexViewportLayerOutput`) | SL5 |
| `Shadow/ShadowAtlas.rsh` | atlas 타일 좌표(광원·단 → 타일 사각형), point 면 고르기(주축), 타일 경계 clamp | SL5 |
| `Shadow/CascadeSelection.rsh` | view Z → CSM 단, 단 사이 섞기 구간, 단별 bias 보정 | SL5 |
| `Shadow/ShadowFiltering.rsh` | 비교 샘플러 PCF(3×3·5×5 가중 커널, Castaño 최적화 커널), 회전 Poisson 디스크, 수신 깊이 [0,1] clamp(빈 그림자 depth 규칙, RB 11.1절), 법선 offset bias | SL5 |
| `Shadow/ShadowSampling.rsh` | 조명 함수가 부르는 진입점: 광원 하나의 그림자 인자(directional·spot·point·rect) | SL5 |
| `Shadow/ContactShadows.rsh` | 조명 함수 안 화면 공간 광선(깊이 버퍼, 짧은 거리, 두께 가정, 잡음 jitter) | SL10(RN RS10) |

**들이지 않는 것.** screen shadow mask 투영·업샘플(`ShadowProjection*`, `ShadowFactorsUpsampleCommon.ush`), 그림자 맵 복사(`CopyShadowMaps.usf` — 정적·동적 그림자 맵 캐시 결합, Mixed 정적 그림자 처리는 bake 스펙(EIP 14.10절)이 정할 때), Bend 방식 화면 공간 그림자(`bend_sss_gpu.ush`) — contact shadow 1차는 조명 함수 안 짧은 광선 하나로 하고, 광원당 전체 화면 pass 방식은 측정 뒤 후속. `LateZDummyPS.usf` — 모바일 파일이 아니라 directional 그림자 stencil pass에서 NVIDIA 드라이버 문제를 피하려고 묶는 빈 PS다(`SRC/Runtime/Renderer/Private/ShadowRendering.cpp:1048–1056, 1221–1224`). Rocks는 screen shadow mask·stencil 투영이 없으므로 필요 없다.

**단계.** SL5(RN RS3), SL10(contact shadow, RN RS10).

**근거 문헌.** Williams, *Casting Curved Shadows on Curved Surfaces*, SIGGRAPH 1978; Reeves, Salesin, Cook, *Rendering Antialiased Shadows with Depth Maps*, SIGGRAPH 1987(PCF); Engel, *Cascaded Shadow Maps*, ShaderX5 2006; Zhang, Sun, Xu, Lun, *Parallel-Split Shadow Maps for Large-scale Virtual Environments*, VRCIA 2006; Dimitrov, *Cascaded Shadow Maps*, NVIDIA 2007; Castaño, *Shadow Mapping Summary*, 2013(The Witness 최적 PCF 커널); Holbert, *Normal Offset Shadows*, GDC 2011; Microsoft, *Common Techniques to Improve Shadow Depth Maps*; Aldridge(Bend Studio), *Screen Space Shadows* 공개 자료 2023(참고만).
