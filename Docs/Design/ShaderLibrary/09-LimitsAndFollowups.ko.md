## 9. 한계·후속·다른 문서 요구

### 9.1 한계

- **UE와 bit 동일이 아니다.** 같은 알고리즘·같은 파라미터 의미를 목표로 하지만 원문을 옮기지 않으므로 세부 근사·상수·연산 순서가 다르다. 기준 영상 허용 오차(RN·RB)로 판정한다. UE와 나란히 놓고 비교하는 시험은 이 문서 범위 밖이다(Unreal 교환 문서가 장면 대조를 정할 때 다룬다).
- **UE 5.8 근거의 전환기.** 고전 shading model 함수가 5.7부터 deprecated이므로 BRDF·셰이딩 모델의 UE 근거는 Substrate 단일 slab 평가의 역할로 잡았다(결정 SLD3). Substrate 원문 구조는 다중 closure 전제라 단일 slab 부분만 떼어 보는 데 해석이 들어간다. 구현 때 의도와 다른 점을 발견하면 4.4절을 고친다.
- **파일 목록은 초안이다.** 4장의 Rocks 파일 나눔은 역할 기준 초안이고, 구현하면서 합치거나 나눌 수 있다. 바꿀 때는 이 문서(4·11장)를 먼저 고친다(스펙 먼저 규칙).
- **미확인.** (1) cube 면 방향을 UE capture와 같게 둔다는 규약(3.4절)의 정확한 축 배치는 SL9 기준 영상으로 확인한다. (2) UE forward 경로에서 하늘을 무엇이 그리는지(RN 10.2절 미확인)는 Rocks 설계에 영향이 없다(두 경로 모두 전체 화면 pass — RN 결정 RN8). (3) UI 블렌드 색 공간(감마 공간인지 선형인지, HDR 출력 때 규칙)은 UT2 착수 때 UE 5.8 UI 렌더러에서 확인한다(4.19절). (4) 4장 근거 문헌 가운데 발표 자료(SIGGRAPH Advances·GDC)는 판·쪽을 적지 않았다. 구현 착수 때 각 파일 머리 주석에 정확한 판을 적는다.
- **GLES 품질 등급.** 모바일 GGX half 근사(UE `MobileGGX`)·저품질 AO 같은 GLES 전용 품질 등급은 정하지 않았다. GLES도 같은 원문·float로 시작하고, 성능 측정(RN 16절) 뒤 품질 등급(MS MSR9 기능 등급)과 함께 정한다.
- **퍼뮤테이션 수.** 영역별 셰이더 타입·퍼뮤테이션 수를 아직 세지 않았다. SS 12.2절 수 보고 함수가 생기면 단계마다 기록한다.
- **성능.** 이 문서는 기능 대응이다. pass별 GPU 시간 예산은 RN 16절이 정한다.

### 9.2 후속

| 항목 | 내용 | 시점 |
|---|---|---|
| half 정밀도 | `FP16Math`·lane·dual pixel 벡터화 대응, GLES mediump. 측정(형식별 속도·정밀도 손실) 뒤 결정 | 기본 영역 완료 뒤 측정 |
| HDR 출력 | ACES 2.0 출력 변환, PQ·scRGB 출력, paper white·UI 휘도, HDR UI 합성 | EIP 26.4절 M5/M6 |
| 후속 영역 A24–A35 | 4.24절 | 각 기능 스펙 |
| 각 영역 "들이지 않는 것(지금)" | 하드웨어 가림 질의, 셀 기반 GPU 장면 컬링, 넓은 필터 resolve, Bend 방식 화면 공간 그림자, ambient cubemap, 애니메이션 bank, 런타임 블록 압축, GPU 해시 표, 편집기 색 도구·메시 칠하기, GPU crash breadcrumb | 해당 기능이 필요해질 때 |
| 벤더 확장 | AMD·Intel·NVIDIA 확장 — 표준 SM 6.x로 안 되는 기능이 생기면 | 필요할 때(결정 SLD13) |
| 플러그인 셰이더 | Niagara·Water·PCG·TextureGraph 등 | CC 9절·기능 문서 |

### 9.3 다른 문서에 대한 요구

이 문서는 다른 문서를 고치지 않는다(사용자 지시 — ShaderSystem은 링크만). 아래는 그 문서를 맡은 세션이 해당 기한까지 반영할 요구다.

| ID | 문서 | 요구 | 기한 |
|---|---|---|---|
| SLR1 | SS 11.1절 SC10 | 정의 조립에 형식 정의 `features`의 기능 정의 `ROCKS_FEATURE_<이름>` = 1을 더한다(웨이브 연산·typed UAV load 등). 그 전에는 `ShaderFeatures.rsh`가 형식 id 표로 판정한다(3.2절) | SL0 착수 전(없으면 임시 표로 진행) |
| SLR2 | SS 11.1절 SC2·12.3절 | 시험 runner의 셰이더 폴더를 시험 전용 플러그인 루트(`/Plugin/ShaderLibraryTests`)로 mount하는 것을 허용하고, 엔진 내장 라이브러리 쿠킹에서 제외한다(7.6절) | SL0 |
| SLR3 | SS 16절 SH2 | SH2 완료 기준에 "SL0 공통 라이브러리 컴파일 행렬·CPU 대조"를 선택 항목으로 더한다(6장 SL0) | SH2 착수 전(선택) |
| SLR4 | RN 17.2절 | 각 RS 단계 완료 기준에 대응 SL 단계의 셰이더 라이브러리 시험(6장 표 마지막 열)을 더하고, RS 행에 SL 단계를 적는다 | RN 다음 개정 |
| SLR5 | RB 11.1절 | 내장 자원 팩에 LTC 표(RS9), GGX 에너지 보존 표(RS1), 파란 잡음 텍스처(RS7 AO·SSR)를 더한다. 생성 방식은 BRDF LUT와 같은 CPU 생성을 권장 | 해당 RS 착수 전 |
| SLR6 | MS 7.2·5.7절 | 노드 보조 함수 파일 `Material/MaterialNodeLibrary.rsh`와 텍스처 표본 보조 `Material/MaterialTextureSampling.rsh`를 7.2절 파일 구조에 적는다. 노드 묶음 1차 범위의 HLSL 함수가 이 파일에 있다 | MS2 착수 전 |
| SLR7 | CC 3·5·8절 | 5.2절 "기본 영역에 없는 것"의 컴포넌트 묶음 선행에 셰이더 영역을 적는다: CM10 → A33, CM11 → A25·A22 후속 부분, CM15 → A24(DOF), CM17 `MediaComponent` → A35, CM18 → A34, CM21 → Niagara 플러그인 셰이더 | CC 다음 개정 |
| SLR8 | EIP 26.1절 | "출력·색 관리" 행의 ACES 계열을 ACES 2.0으로 적는다(UE 5.8 기본, 1.3은 들이지 않음) | EIP 다음 개정 |
| SLR9 | bake 스펙(EIP 14.10절, 문서 없음) | 라이트맵·볼륨 라이트맵 데이터 형식이 정해지면 A14 함수 서명을 그에 맞춘다 | bake 스펙 작성 때 |
| SLR10 | UI 툴킷 UT2(EIP 21.4절) | UI 셰이더 파일(`Ui/*`, A19)과 UI 블렌드 색 공간 규칙(UE 5.8 UI와 같게)을 UT2 범위에 적는다 | UT2 착수 전 |
