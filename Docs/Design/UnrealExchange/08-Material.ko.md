## 8. 머티리얼

### 8.1 그래프 추출

`UMaterial::GetExpressions()`(EP/Materials/Material.h:1478-1480)와 `GetEditorComments()`의 노드마다 아래를 쓴다. 쿠킹된 에셋에는 그래프가 없으므로(`UMaterialEditorOnlyData`는 `UCLASS(Optional)` — Material.h:324-325) 미쿠킹 프로젝트에서만 추출할 수 있다. `UMaterialEditorOnlyData`와 expression의 Outer는 그 머티리얼이다(E/Private/Materials/MaterialInterface.cpp:182-185, 1073). 그래서 덤프 범위는 "Outer가 그 머티리얼인 객체"로 정한다.

```json
{ "guid": "…", "class": "MaterialExpressionTextureSampleParameter2D",
  "position": [x, y],
  "inputs":  [ { "name": "Coordinates", "from": { "node": "<guid>", "output": 0 }, "mask": [r, g, b, a] | null } ],
  "outputs": [ { "name": "RGB", "mask": [1, 1, 1, 0] } ],
  "properties": { … 노드 고유 UPROPERTY 덤프(11.5절) … } }
```

- 입력 열거는 `CountInputs()`·`GetInput(i)`·`GetInputName(i)`(MaterialExpression.h:328-345)다. 5.5에서 deprecated된 `GetInputsView`는 쓰지 않는다. 연결은 대상 노드 GUID(`MaterialExpressionGuid`, :177)와 출력 번호다. reroute는 따라가지 않고 노드 그대로 쓴다(Rocks 쪽 번역이 접는다).
- Custom 노드는 `Code`·`OutputType`·`Inputs`·`AdditionalOutputs`·`AdditionalDefines`·`IncludeFilePaths`를 그대로 쓴다(MaterialExpressionCustom.h:79-101). include 파일 내용은 추출하지 않는다(`CustomIncludeSkipped` 진단).
- 머티리얼 출력: `bUseMaterialAttributes`(Material.h:1066)에 따라 개별 출력 핀(BaseColor·Metallic·…·`FrontMaterial`) 또는 `MaterialAttributes` 핀(UX5a부터 그 뒤에 `FrontMaterial` — 8.6절 3번). 핀마다 연결 또는 미연결 상수(`FMaterialInput<T>`의 `UseConstant`·`Constant` — EP/MaterialExpressionIO.h:158-171)를 쓴다.
- 기본 속성: `MaterialDomain`, `BlendMode`, `ShadingModel`, `OpacityMaskClipValue`, `TwoSided`, `bTangentSpaceNormal`, usage 플래그(`bUsedWith*`), 그 밖의 표면 설정 UPROPERTY.

### 8.2 인스턴스·함수·컬렉션

- 인스턴스: `Parent`, 종류별 override 배열 9종(Scalar·Vector·DoubleVector·Texture·TextureCollection·ParameterCollection·RuntimeVirtualTexture·SparseVolumeTexture·Font — MaterialInstance.h:773-805)의 `ParameterInfo{Name, Association, Index}`·값, static 파라미터(`GetStaticParameters()` — switch·component mask·레이어, MaterialInstance.h:654-663), `BasePropertyOverrides`(MaterialInstanceBasePropertyOverrides.h:12-138). 해석된 최종 값(`GetAllParametersOfType`, MaterialInterface.h:950)도 `resolved`로 함께 쓴다(파라미터 키 순 정렬). Rocks 번역이 부모 사슬을 다시 풀지 않고 결과를 대조할 수 있게 하기 위해서다.
- 함수: 그래프(8.1절과 같은 형식), 입출력 노드, 용도(`Default`·`MaterialLayer`·`MaterialLayerBlend`), `bExposeToLibrary`. 함수 인스턴스: 부모와 override.
- 파라미터 컬렉션: scalar·vector 파라미터 이름·GUID·기본값.

### 8.3 Substrate

UE 5.8은 엔진 기본이 Substrate 꺼짐이지만(`r.Substrate` 기본 0 — RT/RenderCore/Private/RenderUtils.cpp:2068-2072), 5.7 이후 새로 만든 프로젝트에는 켜진 설정이 들어간다(Engine/Source/Editor/GameProjectGeneration/Private/GameProjectUtils.cpp:199-212). 그래프 자동 변환(`ConvertMaterialToSubstrateMaterial` — 옛 핀용 `ShadingModels` 노드, `ConvertMaterialAttributes` 노드, 도메인별 변환 노드를 만든다, E/Private/Materials/Material.cpp:3522-3829, 3905-4128)은 5.8에서 **사용자가 요청할 때만** 돈다(옛 slab 칸·glint의 로드 변환은 따로 돈다 — 8.8절 4번). `IsHiddenMaterialAssetConversionEnabled`가 상수 true이고(RenderUtils.cpp:2564-2570) 그러면 `PostLoad`의 변환 호출이 그래프를 건드리지 않고 돌아오기 때문이다(Material.cpp:3560-3564, 호출 :4643). FrontMaterial이 연결되지 않은 머티리얼은 Substrate 프로젝트에서도 옛 핀 그래프 그대로이고, 컴파일 때 숨은 변환을 거친다(E/Private/Materials/SubstrateTranslatorCommon.cpp:1579-1593 — Blendable이면 고전 셰이더 그대로). (개정 26에서 고쳤다 — 전에는 "PostLoad가 바꾼다"였다.)

- 플러그인은 에디터 메모리의 그래프를 그대로 추출하고, `bundle.json`의 `projectSettings.substrate`와 머티리얼별 변환 버전(`SubstrateConversionVersion`, Material.h:424)을 기록한다.
- Rocks 번역의 1차 범위(UX4)는 옛 출력 핀 그래프다(Substrate 프로젝트의 FrontMaterial 없는 머티리얼 포함 — 위 숨은 변환이 8.7절 6번 `SurfaceFromShadingModel`과 같다). FrontMaterial에 이어진 Substrate 그래프(`SlabBSDF`, 연산자 노드 — MaterialExpressionSubstrate.h)는 UX5다(8.8절). UX5 전에 Substrate 그래프를 만나면 8.5절 결과 결정을 따른다.

### 8.4 굽기 대체(선택)

추출 옵션 `-BakeMaterials`를 주면 플러그인이 머티리얼마다 `IMaterialBakingModule::BakeMaterials`(Dev/MaterialBaking/Public/IMaterialBakingModule.h:28-37)로 BaseColor·Normal·Metallic·Roughness·Specular·Emissive·Opacity·OpacityMask·AmbientOcclusion을 텍스처로 굽는다. 크기는 호출자가 `PropertySizes`로 주며(MaterialBakingStructures.h:24, 49) 플러그인 기본값은 `-BakeSize`의 기본 `RocksDefaultBakeSize`(= 1024)다. emissive는 `SetEmissiveHDR(true)`(IMaterialBakingModule.h:43)로 HDR(RGBA16F)로 굽고, 나머지는 8비트(BGRA8 — 8.9절 1번)다. 메시 데이터 없이 정사각 quad 기준으로 굽는다(MaterialBakingStructures.h:120-121). 결과는 그 머티리얼 JSON의 `baked` 아래에 텍스처 원본 형식으로 넣는다. commandlet에서 굽기를 하려면 `-AllowCommandletRendering`이 필요하다(RT/Core/Public/Misc/App.h:400-406).

- Epic GLTFExporter가 같은 선례다. 속성마다 상수·단순 텍스처 샘플이면 직접 쓰고, 아니면 MaterialBaking으로 굽는다(Engine/Plugins/Enterprise/GLTFExporter/Source/GLTFExporter/Private/Tasks/GLTFDelayedMaterialTasks.cpp:1264-1513, 1636-1799).
- 구운 결과는 UV 공간 결과라 월드 위치·카메라·시간에 의존하는 그래프는 맞지 않는다. 대체 수단이며 번역의 목표 품질이 아니다.
- GPU 렌더 결과라 같은 UE 상태라도 GPU·드라이버에 따라 bytes가 다를 수 있다. 결정성 보장에서 제외하고 `environment`에 기록한다(3.2절).

### 8.5 Rocks 쪽 번역

- **번역 표**: UE 노드 클래스 → Rocks 노드. 정본은 머티리얼 쪽 노드 카탈로그(MaterialSystem 19장)이고 교환 쪽은 카탈로그 규칙으로 풀리지 않는 핀 별칭·속성 예외만 둔다(8.7절 1·3·4번 — 개정 25에서 고침).
- **같은 이름 파라미터 병합**: UE는 한 머티리얼 안에서 이름이 같은 파라미터 노드 여러 개를 파라미터 하나로 다룬다. 함수 안 파라미터도 global association이면 이름으로 합친다. Rocks는 같은 scope의 같은 이름을 검증 오류(MaterialSystem 5.4절 V8)로 보고 함수 호출 위치마다 독립 파라미터로 만든다. 번역은 같은 이름·같은 종류의 파라미터를 Rocks 파라미터 노드 하나로 합치고 나머지 사용처를 그 노드에 잇는다. 기본값이 다르면 UE 순회에서 처음 만나는 노드의 값을 쓰고 `ParameterDefaultConflict` 경고를 낸다(8.7절 8번 — UE는 처음 만난 값을 고정한다, 개정 30에서 원본으로 확인했다). 함수 안 global association 파라미터는 "공유" 표시를 붙인 전역 scope 파라미터로 옮긴다. 결과 그래프에는 같은 scope의 같은 이름이 남지 않아 V8을 통과한다(MaterialSystem 9.2절 "외부 그래프 번역", UXR4 반영).
- **결과 결정**:
  1. 출력에 닿는 모든 노드가 번역되면 `Material` 그래프로 저장한다.
  2. 번역 못 한 노드가 출력에 닿고 `baked`가 있으면, 임포터가 만든 "구운 표면" 그래프(구운 텍스처 파라미터 → 표면)의 `Material`로 저장한다(8.9절 3번). 구운 텍스처는 같은 임포트의 다중 출력 에셋으로 만든다(ImportRecord `outputs`·`ownerAssetId` — AssetSystem 6.2절 ImportOwner). 원래 그래프는 따로 저장하지 않는다. 원본(묶음 JSON)이 ImportRecord의 원본으로 남는다. `MaterialBakedFallback` 경고.
  3. `baked`도 없으면 엔진 기본 머티리얼을 `MaterialSample`로 받는 그래프의 `Material`로 저장하고(8.9절 4번) `UntranslatedMaterialNode` 경고(노드 클래스 목록)를 낸다. 자리 노드가 든 그래프로 저장하지 않는 이유: 출력에 닿은 자리 노드는 쿠킹 오류이고(MaterialSystem 5.4절 V12), 쿠킹은 하나라도 실패하면 게시하지 않으므로(AssetSystem 10절) 머티리얼 하나가 프로젝트 쿠킹 전체를 막는다.
  - 2·3번도 `Material`인 이유(개정 26에서 고쳤다 — 전에는 내장 부모의 `MaterialInstance`였다): A2f 임포터의 주 출력 타입은 고정이고(AssetSystem 7.1절 A2f `Output` — 빈 key는 `outputType`), 결과는 재임포트마다 바뀔 수 있다(머티리얼 쪽 노드가 늘면 3 → 1). 타입이 고정이어야 참조자의 `ObjectRef<MaterialBase>`가 결과와 상관없이 이어진다.
- 인스턴스는 부모가 1번으로 번역되었으면 override를 Rocks 파라미터 키로 옮긴다. 부모가 2번이면 부모의 구운 텍스처 파라미터를 인스턴스의 구운 텍스처로 override하고(플러그인이 인스턴스도 굽는다 — 8.9절 5번), 3번이면 override 없이 부모를 따른다.
- 번역 결과 확인: `resolved` 파라미터 값과 Rocks 인스턴스 해석 결과를 대조한다(다르면 `ParameterResolveMismatch` 경고).

### 8.6 구현에서 정한 점(UX4a)

UX4a(UE 쪽 머티리얼 계열 추출, `FRocksMaterialExtractor`) 중 8.1·8.2절이 정하지 않았거나 다르게 정한 점이다. 모두 권장안으로 확정했다. 번역(8.5절)·Substrate 번역(8.3절)·굽기(8.4절)는 하지 않는다.

1. **노드 식별자는 객체 이름이다(8.1절을 고침).** 8.1절은 연결을 대상 노드 GUID(`MaterialExpressionGuid`)로 정했지만 엔진 콘텐츠에서도 GUID가 겹치는 노드가 흔하다(내보낸 엔진 그래프 29개 중 11개, `M_Grid`는 노드 91개 중 13개가 다른 노드와 GUID가 같다 — 같은 클래스 노드끼리 겹치므로 복사한 노드가 GUID를 물려받은 것으로 보인다). UObject 이름은 같은 Outer(그 머티리얼·함수) 안에서 UE가 유일하게 보장하므로 노드마다 `name`(예: `MaterialExpressionAdd_3`)을 쓰고 연결 `from.node`는 그 이름이다. `guid`는 노드 속성으로 남긴다. (8.5절 병합의 "첫 노드"는 GUID 순이 아니라 UE 순회 순서다 — 8.7절 8번, 개정 30에서 고쳤다.)
2. **`data` 스키마.** Material은 `{ "nodes", "outputs" }`, MaterialFunction은 `{ "nodes" }`, MaterialInstanceConstant는 `{ "resolved" }`, MaterialFunctionInstance·MaterialParameterCollection은 `{}`다(settings 덤프가 전부다 — 함수 인스턴스의 부모·override, 컬렉션의 scalar·vector 파라미터 이름·`Id`·기본값). 노드는 `{ "guid", "name", "class", "position": [x, y], "inputs", "outputs", "properties" }`이고 expression 다음 comment 순(각자 UE 배열 순서)이다. 입력은 `CountInputs`·`GetInput`·`GetInputName` 순서의 `{ "name", "from": { "node", "output" } | null, "mask": [r, g, b, a] | null }`(mask는 연결이 있고 `Mask`가 켜졌을 때만), 출력은 `GetOutputs()`의 `{ "name"(None이면 ""), "mask" }`다. `properties`는 노드 UPROPERTY 덤프에서 소유 역참조(`Material`·`Function`), 위치·GUID·`Outputs`(노드 키로 따로 쓴다), 입력 구조체(`FExpressionInput` 계열 — 덤퍼 공통 규칙, 11.7절)를 뺀 것이다. 함수 호출의 `MaterialFunction`, 텍스처·컬렉션 참조는 `{ "objectPath" }`라 의존에 합쳐지고, 노드끼리 참조(이름 있는 reroute의 `Declaration` 등)는 `{ "subobject": 노드 이름 }`이다. Custom 노드의 include 파일은 info `CustomIncludeSkipped`(파일 수)다.
3. **출력 핀.** `UMaterialEditorOnlyData`의 핀 프로퍼티를 선언 순으로 쓴다. 핀 구조체는 `FMaterialInput` 계열이고 `MaterialAttributes`만 `FExpressionInput` 계열이다(EP/Materials/Material.h:157-265, 333-413). `bUseMaterialAttributes`면 `MaterialAttributes` 하나(UX5a부터 그 뒤에 `FrontMaterial` — 8.8절 2번), 아니면 나머지 전부다(29개 — 고정 배열 `CustomizedUVs[8]`은 칸마다 `CustomizedUVs[0]`…`[7]`). 핀은 `{ "name", "from", "mask", "constant" }`이고 `constant`는 `UseConstant`가 켜졌을 때 핀 구조체가 직접 선언한 상수 칸(`Constant` 하나면 그 값, `FVector2MaterialInput`은 `[ConstantX, ConstantY]`), 아니면 `null`이다.
4. **`settings`.** 객체 UPROPERTY 덤프에서 그래프 묶음(`FMaterialExpressionCollection` — 노드·comment 배열)과 핀(`FMaterialInput` 계열)을 뺀다. 노드는 settings 덤프 전에 "펼친 객체"로 표시해서 settings에서 노드를 만나도 `{ "subobject" }`만 쓴다(노드 본문은 `data.nodes`에만 있다). `UMaterialEditorOnlyData` 하위 객체(파라미터 그룹, `SubstrateConversionVersion` 등)는 settings에 남는다. 인스턴스 settings에는 `Parent`, override 배열 9종, `StaticParametersRuntime`, `BasePropertyOverrides`, 에디터 데이터의 static 파라미터가 들어간다.
5. **`resolved`.** `GetAllParametersOfType`을 `EMaterialParameterType` 전 종류(Scalar·Vector·DoubleVector·Texture·TextureCollection·Font·RuntimeVirtualTexture·SparseVolumeTexture·StaticSwitch·ParameterCollection·StaticComponentMask — EP/Materials/MaterialParameters.h:187-205)로 부른 결과다. 항목은 `{ "parameter": FMaterialParameterInfo 덤프(Name·Association·Index), "type": 종류 이름, "value" }`이고 값은 scalar 수, vector·double vector 4개, switch bool, component mask bool 4개, 텍스처 계열·컬렉션 `{ "objectPath" }` 또는 `null`, font `{ "font", "page" }`다. 종류 이름은 플러그인 표로 쓴다(`StaticComponentMask`가 `NumRuntime`과 같은 값이라 UEnum 값 조회는 `NumRuntime`을 낸다). 순서는 `parameter`의 compact JSON bytes 순, 같으면 종류 번호 순이다(8.2절 "파라미터 키 순"의 결정적 형태).
6. **Substrate.** 그래프는 에디터 메모리 그대로 쓴다. Substrate 노드도 다른 노드와 같은 형식으로 덤프하고 플러그인은 따로 진단하지 않는다(8.3절 — 판정은 Rocks 번역). 판단 근거인 `projectSettings.substrate`(bundle.json)와 `SubstrateConversionVersion`(settings의 에디터 데이터)이 묶음에 있다.
7. **자기 시험.** `RocksExport.MaterialExtraction`(commandlet `-SelfTest`에도 포함)이 엔진 `M_Grid`(함수 호출·이름 있는 reroute·파라미터, GUID 겹침 포함), 인스턴스 사슬 `Widget3DPassThrough_Translucent_OneSided`, 컬렉션 참조 머티리얼 `M_RenderNormalizedDepth_01`을 내보내 노드 수·순서·이름·클래스, 모든 입력 연결(대상 이름·출력 번호)을 UE 그래프와, `BaseColor` 핀 연결을 UE 핀과 대조하고, 출력 핀이 개별 핀인지, settings에 노드·핀이 펼쳐지지 않았는지, 함수·컬렉션·부모 참조가 dependencies에 있는지, `resolved` 수가 `GetAllParametersOfType` 전 종류의 합이고 scalar 값이 `GetScalarParameterValue`와 같은지, 추출 전후 덤프가 같은지 본다.
8. **Rocks 쪽 확인.** 받는 MaterialSystem 클래스가 아직 없으므로 선택 시험 `UnrealExchange_ExternalBundle`은 머티리얼 계열 Ready 기록의 구조 불변식만 본다: 노드 모양, 노드 이름 유일, 모든 연결(노드 입력·머티리얼 출력 핀)의 대상 노드가 있고 출력 번호가 그 노드 `outputs` 범위 안, mask가 `null` 또는 0·1 넷, 출력 핀 이름 유일, 함수 호출의 함수와 인스턴스 부모가 dependencies에 있음, settings·data의 모든 `{ "objectPath" }`가 dependencies에 있음, `resolved` 항목 모양. 노드 이름이나 출력 번호를 바꾼 묶음 사본은 이 검사에서 실패한다.
9. **함수 인스턴스 시험 콘텐츠 없음.** 엔진 콘텐츠에 MaterialFunctionInstance가 없고, Python에서는 만들 수 없다(`MaterialFunctionInstanceFactory`의 `InitialParent`가 스크립트에 노출되지 않고 `UMaterialFunctionInstance::SetParent`는 C++ 전용이다). 함수 인스턴스는 settings 덤프만 쓰는 경로라 추출 코드는 MPC와 같다. 실제 콘텐츠로 확인하는 일은 UX4b(번역)에서 시험 콘텐츠를 C++로 만들 때 한다.
10. **수동 검증(2026-11-22).** 엔진 머티리얼 5개 선택(`M_Grid`, `M_RenderNormalizedDepth_01`·`M_RenderMotionVectors` — MPC `MPC_R2T` 참조, `Widget3DPassThrough_Translucent_OneSided`·`TranslucentLaserPointerMaterialInst` — 인스턴스 사슬 2단)을 닫힘과 함께 내보낸 묶음(에셋 46개 — Material 5·MaterialFunction 24·MaterialInstanceConstant 4·MPC 1·텍스처 12)을 두 번 내보내 `createdUtc` 말고 bytes가 같고, 리더가 머티리얼 계열 34개 모두 위 8번을 통과했다(노드 1,046개 연결 전부 해석). 정적 메시·스킨 메시 묶음을 다시 내보내 그 안의 엔진 머티리얼(`WorldGridMaterial`, Interchange 기본 머티리얼·함수, 튜토리얼 캐릭터 머티리얼)도 통과했다. 교환 범위 밖 의존(`TextureRenderTarget2D` 등)은 기존대로 의존에만 남는다.

11. **`resolved` 참조는 Soft(개정 15).** `resolved`의 텍스처·컬렉션·font 참조는 부모 사슬을 풀어 계산한 값이라 덤프 참조와 달리 의존을 새로 만들지 않아야 한다(부모·override가 이미 Hard로 담는다). 그래서 의존에 Soft로 합친다(같은 대상이 Hard로도 있으면 Hard 하나).

### 8.7 Rocks 임포트 설계(UX4b — 명세만)

설계일 2026-11-27(사용자 결정: 선행 MaterialSystem MS3·MS6 전이라 명세만 먼저). 기준은 머티리얼 세션의 최신 설계(`feature/material` — MaterialSystem 04·05·09·11·19장, `MaterialSchema` 노드 정의·`MaterialNodeCatalog.json`, NodeGraph `GraphDocument`)다. 교차 검증(리뷰어 1명 — 14건 반영) 뒤 확정했다. 구현은 MS3(Material 필드·쿠킹)·MS6(함수·인스턴스·컬렉션) 뒤 UX4b1b·UX4b2로 한다(7번 설정은 MS3b 뒤 UX4b1a — 개정 32). 8.5절 결과 결정 1–3번과 파라미터 병합은 아래로 구체화한다. 모두 권장안이다.

1. **노드 찾기와 번역 가능 판정(8.5절 "번역 표는 UnrealExchange 데이터"를 고침).** 정본은 머티리얼 쪽 노드 카탈로그다(MaterialSystem 19장 — 교환 쪽에 같은 표를 두면 어긋난다). 카탈로그 키는 `UMaterialExpression<X>`(옛 클래스는 `UDEPRECATED_…`)이고 내보낸 `class`는 `MaterialExpression<X>`라 앞에 `U`를 붙여 찾는다. Rocks 노드 타입 이름은 카탈로그의 값을 그대로 쓴다(이름 규칙을 추측하지 않는다 — `CollectionParameter` → `ParameterCollectionValue`, `Custom` → `CustomHlsl` 등). 번역 가능 = 그 노드 타입이 임포트 때 스키마에 **등록**되어 있다(플러그인 노드는 플러그인이 등록했으면 가능) 또는 공용 그래프 노드(`CommonGraph` — `Reroute`·`Composite`·`PinBase`·`Comment`, 5번). 그 밖(카탈로그에 없음·등록 안 됨·`PrerequisiteMissing`·추상·제외)은 "번역 못 한 노드"다. 등록된 정의가 UE 클래스를 갖지 않으므로 요구 UXR12다.
2. **노드 식별자.** `GraphNode.id`(Guid)는 결정적으로 만든다: UE 노드는 SHA-256(그래프 소유 objectPath, `"node:"`, UE 노드 이름) 앞 128비트(UE GUID는 겹친다 — 8.6절 1번), 임포터가 만드는 노드는 같은 해시에 역할 문자열(`"output"`, `"surface"`, `"domain"`, `"mask:<노드>:<입력>"`, `"const:<핀>"`)이다. `GraphEdge.order`는 대상 입력 순서다. 파라미터 노드의 `parameterId`는 UE `ExpressionGUID`다(인스턴스 override가 이 id로 이어진다 — 8.6절 1번 `guid`(MaterialExpressionGuid)와 다르다). 병합(8번) 뒤에도 서로 다른 파라미터가 같은 `ExpressionGUID`면 둘째부터 위 해시(`"param:<이름>"`)로 바꾸고 warning `ParameterIdCollision`(새 코드)이다. 병합(8번)이 남기는 노드는 UE 순회에서 처음 만나는 노드다(개정 30에서 고쳤다 — 전에는 `ExpressionGUID` 순).
3. **핀 대응.** 노드 속성(4번)으로 그 노드의 실제 핀 목록(정적 핀 + 속성이 정하는 동적 핀 — `MaterialDynamicPins`)을 먼저 만들고, 내보낸 입력 `name`(UE `GetInputName` 표시 이름)을 그 목록의 UE 표시 이름에 맞춘다. 맞지 않는 입력은 남은(아직 짝 없는) 핀과 번호 순으로 맞춘다. UE와 Rocks의 표시 이름이 다른 알려진 경우(빈 이름 Custom·Switch 입력 — Rocks `Input<n>`, 속성마다 바뀌는 대표 이름 — Substrate 계열, 27번째 이후 연산자 입력)는 교환 쪽 별칭 표(`ExchangeMaterialPinAliases`)에 둔다. 출력은 내보낸 번호를 실제 출력 목록 순서에 맞춘다. 표시 이름의 빈틈을 머티리얼 쪽이 메우는 것이 요구 UXR13이다. 8.1절 예의 입력 이름 `UVs`는 실제로 `Coordinates`다(UE `MaterialExpressions.cpp` — 예만 고친다).
4. **연결·상수·속성.**
   - 연결은 `GraphEdge{fromNode, fromPin, toNode, toPin, order}`다. UE `ConnectExpression`은 출력 mask를 입력 mask로 복사하므로 대부분의 R·G·B·A 연결에 mask가 있다. **입력 mask가 원본 출력의 mask와 다를 때만** 사이에 `Material.ComponentMask`(2번의 `mask:` id)를 끼운다.
   - 미연결 입력의 UE 상수(`OverridingInputProperty` 계열 `ConstA` 등)는 그 노드의 `GraphNode.inputDefaults`(`PinValueEntry{pin, value}` — 타입 공용 `MaterialPinDefault`가 아니다)다. 동적 핀의 상수는 노드 속성으로 남는다(카탈로그 규칙).
   - `properties`(UE 덤프)는 10.6절 8번 설정 번역의 공통 규칙으로 번역해 노드 정의의 속성 struct에 값 대상 `ImportJson`한다(5.5절 4번과 같은 방식). 이름·모양이 다른 속성만 노드 타입별 교환 쪽 표(`ExchangeMaterialNodeRules`)에 둔다(예: `Constant3Vector.Constant` → `constant`, `TextureSample.ConstCoordinate` → `constCoordinate`, 파라미터 공통 `ParameterName`·`ExpressionGUID`·`Group`·`SortPriority`). UE 기반 클래스 `UMaterialExpression`의 칸(`Desc`·`bRealtimePreview`·`bCollapsed`·`SubgraphExpression`·편집기 위치·`bShowOutputNameOnPin` 등)은 공용 무시 표로 버리고, `Desc`는 layout 설명 풍선으로 옮긴다. 그 밖에 표에 없는 키는 노드마다 `UnsupportedSetting`(detail = 노드 번호)이다.
   - 속성 값이 머티리얼 쪽에서 아직 TODO인 칸(`subsurfaceProfile` 등 — 값이 있으면 `PrerequisiteMissing`)은 값을 버리고 `UnsupportedSetting`이다(노드는 번역한다).
   - 텍스처·함수·컬렉션 참조는 옵션 `references`로 연다(없으면 텍스처 null — 엔진 기본 텍스처, 함수·컬렉션이 없으면 그 노드는 번역 못 한 노드).
5. **공용 그래프 노드·layout.** UE `Reroute` → `Graph.Reroute`, `Composite`·`PinBase` → `Graph.CollapsedGraph`(하위 그래프), 이름 있는 reroute → `Material.NamedRerouteDeclaration`·`Usage`(`declaration`은 선언 노드의 2번 id). comment와 노드 `position`은 `GraphDocumentLayout`(EditorOnly, semantic hash 밖)이다.
6. **머티리얼 출력(MaterialSystem 19.8절).** `Material.Output` 하나(2번 `output` id)다.
   - 옛 표면 핀은 `Material.SurfaceFromShadingModel`(2번 `surface` id — UE Substrate 변환 `ShadingModels` 노드와 같은 모양)의 입력이고 그 `Result`가 `Output.Surface`다. 키는 명시 표로 옮긴다(표시 이름 규칙을 쓰지 않는다): `BaseColor`·`Metallic`·`Specular`·`Roughness`·`Anisotropy`·`EmissiveColor`·`Normal`·`Tangent`·`SubsurfaceColor` → `SubSurfaceColor`·`ClearCoat`·`ClearCoatRoughness`, `ShadingModelFromMaterialExpression` → `ShadingModel`.
   - `Opacity`는 UE처럼 `Output.Opacity`와 `SurfaceFromShadingModel.Opacity` 둘 다에 잇는다(UE `Material.cpp` — Subsurface·Foliage·ThinTranslucent가 표면 쪽 Opacity를 쓴다).
   - `OpacityMask`·`AmbientOcclusion`·`WorldPositionOffset`·`PixelDepthOffset`·`Refraction`·`Displacement`·`SurfaceThickness`·`CustomizedUVs[i]`(→ `CustomizedUv<i>`)·`MaterialAttributes`(→ `Attributes`)는 `Material.Output`의 같은 핀이다. `FrontMaterial`은 Substrate 그래프라 UX5다(8.8절).
   - UE 설정 `ShadingModel`은 `shadingModelOverride`(UE `MSM_*` → `ShadingModelPreset` 이름), `MSM_FromMaterialExpression`이면 위 `ShadingModel` 핀이다. `SubsurfaceProfile`은 머티리얼 쪽 TODO라 4번 규칙(값을 버리고 경고)이다.
   - 미연결 핀의 `constant`(8.6절 3번)는 상수 노드(`Material.Constant`·`Constant2`·`Constant3`·`Constant4` — 2번 `const:` id)를 만들어 잇는다(`SurfaceFromShadingModel` 핀은 값 칸이 없다 — UE도 상수 노드를 만든다).
   - domain이 Surface가 아니면 UE처럼 domain 변환 노드를 거친다(`Material.SurfaceToDecal`·`SurfaceLightFunction`·`SurfacePostProcess`·`SurfaceUserInterface` — 2번 `domain` id, UE `Material.cpp` domain 변환과 같은 연결).
   - 블렌드 모드가 받지 않는 핀은 스키마 V5가 경고와 함께 버린다(교환은 그대로 옮긴다).
7. **머티리얼 설정(`settings`).** 번역 표 `ExchangeMaterialSettingRows`로 `Material.traits`(`MaterialTraitsDesc`)에 `ImportJson`한다(MaterialSystem 19.9절: `MaterialDomain`(`MD_`)·`BlendMode`(`BLEND_`)·`TwoSided`·`OpacityMaskClipValue`·`bTangentSpaceNormal`·`bUseMaterialAttributes`·`NumCustomizedUVs` 등). `bUsedWith*`는 `usage` 정점 입력 집합(19.10절 — 구현된 것만, 나머지 `UnsupportedSetting`). 19.9절 "다른 곳" 키(`ShadingModel`·`SubsurfaceProfile`)는 6번, 대응 없는 키는 Unsupported 행이다. 레이어 그래프(`MaterialAttributeLayers` 기본 레이어)는 MS7 전이라 번역 못 한 노드다.
   - **구현에서 정함(UX4b1a — 개정 32).** 설정 번역은 그래프와 무관해 UXR12–UXR16·MS6 전에 먼저 한다(사용자 지시 2026-11-28 "순서대로" — MS3b 필드가 생겨 가능해졌다).
     - **표.** `ExchangeMaterialSettingRows`는 UMaterial 덤프 최상위 키마다 행 하나이고 MaterialSystem 19.9–19.11절 대응을 그대로 따른다. "필드"·"필드(효과는 Renderer)"는 옮긴다. "필드 + TODO"는 `Unsupported`다(4번 노드 속성과 같은 규칙 — 값을 넣으면 쿠킹 `PrerequisiteMissing`으로 머티리얼 전체가 쿠킹되지 않는다). "다른 곳"·"에디터 데이터"·"제외"는 `Ignore`다(단 `AssetUserData`는 `Unsupported` — 빈 배열이 기본값). 19.11절에서 "필드"인 `TextureStreamingDataVersion`·`TextureStreamingData`(→ `textureSamplingScales`)는 `Ignore`다 — 쿠킹이 계산해 채우는 값이다(MaterialSystem 12.5절, `MaterialBase.h`). `Unsupported` 기본값 텍스트는 UE 5.8 새 머티리얼의 값(golden `M_Golden` 덤프와 같다)이다. UObject 공통 키(`AssetImportData`·`ThumbnailInfo`·`LightingGuid`·`bIncludedInBaseGame`·`EditorOnlyData` 등)도 `Ignore` 행으로 둬서 엔진 머티리얼 덤프에 모르는 키 경고가 나지 않는다.
     - **대상.** 표의 출력은 `Material.traits`(`MaterialTraitsDesc`)에 값 대상 `ImportJson`한다. 하위 struct 칸은 행 묶음(10.6절 8번)으로 그 키의 하위 객체에 쓴다: `translucency`(`Translucen*`·`TranslucencyPass`·`TranslucencyLightingMode`·`bEnableMobileSeparateTranslucency`·`bAllowTranslucentLocalLightShadow`), `forward`(`bForwardRenderUsePreintegratedGFForSimpleIBL`·`bUseHQForwardReflections`·`bForwardBlendsSkyLightCubemaps`·`bUsePlanarForwardReflections`), `postProcess`(`Blendable*`·`bIsBlendable`·`UserSceneTexture`·`UserTextureDivisor`·`ResolutionRelativeToInput`·`bDisablePreExposureScale`·`bEnableStencilTest`·`StencilCompare`·`StencilRefValue`). `displacement`는 칸이 모두 TODO라 쓰지 않는다. `UserTextureDivisor`(FIntPoint `{X, Y}`)는 `Flatten`으로 `userTextureDivisorX`·`userTextureDivisorY`다.
     - **enum.** 접두만 다른 것은 `Enum`이다(`MDR_`·`TLM_`·`RCM_`·`MSC_`). 이름이 다른 것은 `EnumMap`이다(UE 이름은 5.8 `EngineTypes.h`·`Material.h`·`MaterialDomain.h`·`BlendableInterface.h`에서 확인했다).
       - MaterialDomain: `MD_UI` → `UserInterface`, `MD_RuntimeVirtualTexture`는 Rocks에 없는 값이다. 나머지는 접두를 뗀 이름이다.
       - BlendMode: `BLEND_AlphaHoldout`은 Rocks 값이 TODO(`MPQ-AlphaHoldout`)라 Rocks에 없는 값으로 다룬다(위 TODO 규칙). `BLEND_TranslucentColoredTransmittance`는 `Translucent`다(8.8절 3번 — `projectSettings.substrate` 참이면 변환이 `UnsupportedSetting`(detail = BlendMode 행)을 더한다). UE 별칭 값 이름 `BLEND_TranslucentGreyTransmittance` → `Translucent`, `BLEND_ColoredTransmittanceOnly` → `Modulate`(EngineTypes.h 별칭 정의)다.
       - TranslucencyPass: `MTP_BeforeDOF`·`MTP_AfterDOF`·`MTP_AfterMotionBlur` → `BeforeDepthOfField`·`AfterDepthOfField`·`AfterMotionBlur`.
       - RefractionMethod: `RM_2DOffset` → `Offset2D`, 나머지는 접두를 뗀 이름이다.
       - PixelDepthOffsetMode: `PDOM_Legacy` → `ViewDepth`, `PDOM_AlongCameraVector` → `AlongCameraVector`.
       - ShadingRate: `MSR_<a>x<b>` → `Rate<a>x<b>`.
       - BlendableLocation: `BL_SceneColorBeforeDOF` → `SceneColorBeforeDepthOfField`, `BL_SceneColorAfterDOF` → `SceneColorAfterDepthOfField`, `BL_TranslucencyAfterDOF` → `TranslucencyAfterDepthOfField`, `BL_SSRInput` → `ScreenSpaceReflectionInput`, 나머지는 접두를 뗀 이름이다.
       - "Rocks에 없는 값"은 `UnsupportedSetting`(detail = 행 번호)이고 키를 버려 Rocks 기본값이 남는다(10.6절 8번 `EnumMap`). 표에 없는 값은 지금처럼 `CorruptData`다.
     - **사용 대상(19.10절).** 표에서는 `Ignore`이고 변환이 덤프를 읽어 `Material.usage`를 정한다: `bUsedWithStaticMesh` 참 → `StaticMesh`(`StaticMeshVertexInputName`), 거짓이면 넣지 않는다(키가 없으면 UE 기본값 true — UMaterial 생성자). `bUsedWithSkeletalMesh`·`bUsedWithMorphTargets`는 옮기지 않는다 — skinned 정점 입력 이름을 RenderBase RB5가 아직 정하지 않았고, 쿠킹 유도(MaterialSystem 8.4절)가 그 머티리얼을 쓰는 스킨 메시에서 모으므로 선언이 없어도 쿠킹된다(이름이 생기면 옮긴다). `bUsedWithEditorCompositing`은 `Ignore`(다른 곳), 나머지 TODO 플래그는 `Unsupported`(기본 false)다.
     - **미리보기.** `EditorPitch`·`EditorYaw`는 표에서 `Ignore`이고 변환이 `Material.preview.cameraPitch`·`cameraYaw`(EditorOnly)에 옮긴다. `PreviewMesh`는 그때까지 `Unsupported`(기본 null — 값이 있으면 경고)다(미리보기 메시 참조는 UX4b1b의 참조 연결과 함께 옮긴다).
     - **그래프 쪽 키.** `ShadingModel`·`ShadingModels`는 `Ignore`다(6번 그래프 번역이 `ShadingModel`을 읽는다).
     - **API.** `ExchangeMaterialSettings.h`(표·묶음 이름·행 번호 enum), 변환 `ExchangeMaterialSettingsInput{asset, substrate, registry, access}` → `TranslateExchangeMaterialSettings(input, traits, usage, preview, warnings, failure)`. 오류 규칙은 정적 메시와 같다(10.6절 8번 — 번역 `CorruptData`는 `InvalidSource`, `ImportJson` 진단 거부는 `InvalidSource` / `CorruptData`, 행 표 결함·writer·할당 오류는 코드 없이 그 오류).
     - **시험.** golden `M_Golden`(경고 없음, 결과 traits가 기본 `MaterialTraitsDesc`와 같음, usage = `StaticMesh`), 엔진 머티리얼 `DefaultLightFunctionMaterial`(GoldenBaked — 모르는 키 경고 없음, LightFunction·ViewDepth), 경로 편집 사본(enum 대응 전부, 묶음 하위 칸, `Flatten`, TODO 칸 경고, Rocks에 없는 값, ColoredTransmittance 두 프로젝트 설정, 사용 플래그, 미리보기, 모르는 키).
8. **파라미터 병합(8.5절 — MaterialSystem 9.2절 UXR4).** 그래프 하나 안에서 파라미터 노드를 (종류, 이름 — 대소문자 무시, UE FName 비교)로 묶어 **UE 순회에서 처음 만나는 노드**를 남기고 나머지 노드의 출력 간선을 그 노드로 옮긴 뒤 지운다(기본값이 다르면 `ParameterDefaultConflict`). UE는 같은 이름 파라미터의 값을 처음 만난 노드에서 고정한다(`TryAddParameter`가 이미 있으면 값을 넣지 않는다 — E/Private/Materials/MaterialCachedData.cpp:173-218, 주석 "parameter values are latched the first time" :436-437). 순회는 그래프의 `GetExpressions()` 배열 순서(= 덤프 `data.nodes`의 expression 순서 — 8.6절 2번)이고, 함수 호출 노드를 만나면 그 함수가 의존하는 함수들을 먼저, 다음 그 함수 자신의 노드를 돈다(:430-458, 726-730). 함수 안 global 파라미터 노드는 다른 그래프(함수 에셋)의 키라 이 병합에서 지우지 않지만, UE에서는 같은 이름·종류면 한 파라미터라 **값**은 함수 쪽 노드를 포함한 전체 순회의 첫 값이다 — 남긴 노드의 기본값을 그 값으로 두고, 함수 쪽 기본값과 다르면 `ParameterDefaultConflict`(detail에 함수 objectPath)다. 설명·그룹은 UE처럼 첫 노드의 값이 비었을 때만 뒤 노드에서 채운다(:203-215). 함수 그래프에서 UE association이 global인 파라미터는 `shared` 참(Global scope)이다. 같은 이름·다른 종류는 V8 오류라 결과 결정 3번이고 경고는 `ParameterKindConflict`(새 코드)다 — 8.5절 병합은 같은 종류만 합치므로 모순이 없다. 그래프 사이(머티리얼의 `Tint`와 함수의 global `Tint`)는 Rocks에서 키가 둘이므로 합치지 않고 인스턴스 override를 둘 다에 쓴다(11번). V8 문구(05장 "다른 종류" / 09장 "같은 이름")의 정리는 요구 UXR16이다.
9. **함수·컬렉션.**
   - MaterialFunction: 같은 그래프 번역, 입출력 노드 `Material.FunctionInput`·`FunctionOutput`(UE `Id` GUID → `id`), `usage`(UE `Default`·`MaterialLayer`·`MaterialLayerBlend` → `General`·`Layer`·`LayerBlend`), `exposeToLibrary`·`libraryCategories`·`description`.
   - 함수 호출 `Material.FunctionCall`의 `inputs`·`outputs`는 **그 호출 노드의 덤프**(`FunctionInputs`·`FunctionOutputs`의 `ExpressionInputId`·`InputName` 등)로 만든다(함수 에셋에서 다시 만들면 낡은 호출 노드가 내보낸 입력 번호와 어긋난다 — 임포트 순서 요구도 없다, 참조는 Hard 의존 그대로).
   - MaterialFunctionInstance: 부모와 override(11번 키 — owner는 함수).
   - MaterialParameterCollection → `ParameterCollection`(`scalars`·`vectors` — UE `Id`·이름·기본값, `Base`와 base override → `base`·`scalarBaseOverrides`·`vectorBaseOverrides`), 컬렉션 노드 → `Material.ParameterCollectionValue{collection, parameterName, parameterId}`(9.7절 상한 2개 위반은 오류 → 결과 결정 3번).
10. **결과 결정의 판정.** "번역 못 한 노드가 결과에 닿는가"는 렌더 경로·capability 분기에 따라 (형식, pass) 조합마다 다르다. 판정은 엔진 컴파일 프로필의 **모든 조합 중 하나라도** 닿으면 닿음이다(그 조합의 쿠킹이 실패하므로). 도달을 가르는 static 파라미터(StaticSwitch·StaticBoolParameter 계열)는 인스턴스가 값을 바꿔 다른 static 변형을 쿠킹하므로 **모든 값의 분기가 닿는 것**으로 본다(기본값으로만 보면 인스턴스 변형이 저장 그래프에서 빠진 노드에 닿는다 — 개정 26). 대가: 쓰지 않는 분기에 번역 못 한 노드 하나만 있어도 머티리얼 전체가 결과 2·3번이 된다. 인스턴스 static 변형이 정확하게 쿠킹되는 쪽을 골랐다. 카탈로그에 없는 클래스는 노드 정의가 없어 간선 끝이 될 수 없으므로, 저장 전 판정용 그래프에서는 내보낸 입출력 수만큼 핀을 가진 자리 노드로 둔다(NodeGraph 자리 노드 GD14 — 자리 노드를 핀과 함께 만드는 API와 판정 API가 요구 UXR14). 닿는 노드 클래스 목록이 `UntranslatedMaterialNode` 경고 detail이다. 닿지 않는 번역 못 한 노드는 저장 그래프에서 빼고 info다.
11. **인스턴스(MaterialInstanceConstant → `MaterialInstance`).**
    - `parent`(옵션 `references`), override 배열 → Rocks `ParameterKey{ownerAssetId, parameterId, scope}`. `ownerAssetId`는 그 파라미터 노드를 가진 에셋이다(머티리얼이면 그 머티리얼, 함수 안 global 파라미터면 그 함수 에셋 — `shared`라 scope Global — MaterialSystem 9장).
    - UE `ParameterInfo{Name, Association, Index}`의 이름 → `parameterId`는 **부모 사슬의 번역된 에셋을 읽어** 찾는다(따로 표를 두면 낡는다). 같은 이름이 여러 키(8번 그래프 사이)면 모두에 쓴다.
    - 레이어 association(`LayerParameter`·`BlendParameter`)과 `layerStack`·`overridesLayerStack`은 MS7 전이라 `UnsupportedSetting`이다.
    - static switch·component mask → `staticSwitchOverrides`·`staticComponentMaskOverrides`, `BasePropertyOverrides` → `traitOverrides`(19.11절 — `bOverride_X`가 켜진 것만 `Optional` 값).
    - 부모가 2·3번 결과면 인스턴스도 같은 결과를 따른다(8.5절).
12. **확인.** `resolved`와 Rocks 인스턴스 해석 결과의 대조(`ParameterResolveMismatch` — 8.5절)는 해석 API가 MaterialRuntime(MS4)이라 MS4 뒤다. UX4b2는 override 키·값이 옮겨졌는지만 본다.
13. **내장 머티리얼(8.5절 3번).** 결과 3번 그래프의 `MaterialSample`이 가리키는 엔진 기본 머티리얼(domain별 — MaterialSystem 11.3절)은 이름이 아니라 고정 AssetId로 건다. 그 고정 id 목록과, `/Engine` 마운트 전 내장 머티리얼을 `MaterialSample`의 참조(Hard `ObjectRef` — Build 의존)로 가리키는 방법이 요구 UXR15다. "구운 표면"은 내장 부모가 아니라 임포터가 만드는 그래프다(8.9절 3번 — 개정 26에서 고쳤다).
14. **단계.** UX4b1a(7번 설정 — MS3b, 개정 32), UX4b1b(1–6·8–10번 — MS3·MS6, UXR12–UXR16 — 결과 3번의 기본 머티리얼 참조가 UXR15), UX4b2(11·12번 — MS6, 대조는 MS4). 시험: golden `M_Golden`·`MI_Golden`, 외부 묶음 엔진 머티리얼(M_Grid — 함수 호출·이름 있는 reroute·GUID 겹침), 경로 편집으로 병합·종류 충돌·id 충돌·번역 못 한 노드(닿음·안 닿음)·mask가 다른 간선·옛 출력 핀·Opacity 두 곳·domain 변환·ShadingModel·인스턴스 override(그래프 사이 같은 이름 포함)·레이어 경고.

### 8.8 Substrate 번역 설계(UX5 — 명세만)

설계일 2026-11-27(사용자 결정: 선행 UX4b1·MaterialSystem MS3·MS6 전이라 명세만 먼저). 교차 검증(리뷰어 1명 — 8.8·8.9절 합쳐 14건 반영) 뒤 확정했다. Rocks 그래프 모델이 이미 Substrate형이고(MaterialSystem 10.3절 결정 MD1) Substrate 노드 25개가 카탈로그에 있으므로(19.6.22절 — Toon만 TODO) 노드 번역은 8.7절 1–5번 그대로다. UX5가 따로 정하는 것은 모드 판정·출력 핀·설정이다. 모두 권장안이다.

1. **모드 판정.** **Substrate 모드** = `projectSettings.substrate` 참이고 머티리얼 출력 핀 `FrontMaterial`이 reroute(이름 없는 `Reroute`·이름 있는 reroute 사용)를 따라간 최종 출발 노드를 가짐이다(UE `GetTracedInput()` — 앞이 끊긴 reroute에만 이어진 핀은 연결 없음이다). `bUseMaterialAttributes`와 상관없이 이 조건이다(UE 번역기가 `EditorOnlyData->FrontMaterial`로 갈래를 정한다 — SubstrateTranslatorCommon.cpp:1574-1579, `RebuildShadingModelField`도 같다 — Material.cpp:5605-5615). 그 밖은 **옛 핀 모드**(8.7절 6번)다.
   - Substrate 프로젝트에서 FrontMaterial이 비면 옛 핀 모드다(UE 숨은 변환 — 8.3절. 속성 집합이면 `ConvertMaterialAttributes` 숨은 변환 — SubstrateTranslatorCommon.cpp:1710-1716, Rocks는 `SurfaceFromAttributes`).
   - Substrate가 꺼진 프로젝트에서 FrontMaterial이 연결돼 있으면 UE는 그 핀을 읽지 않으므로 옛 핀 모드이고 info `InactiveMaterialPin`(새 코드 — detail은 핀 이름 목록)이다. FrontMaterial 쪽 노드는 출력에 닿지 않는 노드로 다룬다(8.7절 10번 — 번역된 노드는 남고 번역 못 한 노드는 빠진다).
   - 머티리얼 함수에는 출력 핀이 없으므로 모드가 없다. Substrate 노드와 Substrate 타입 입출력(`FunctionInput_Substrate` → 표면 값 타입, `ExchangeMaterialNodeRules`)은 어느 프로젝트에서나 번역한다. 그 함수를 부르는 머티리얼의 모드가 쓰임을 정한다.
2. **Substrate 모드 출력.** `SurfaceFromShadingModel`·domain 변환 노드를 만들지 않는다(Substrate 그래프는 domain 표면 노드 `SubstrateConvertToDecal`·`SubstrateUI` 등을 사용자가 직접 둔다).
   - 개별 핀이면 `FrontMaterial` → `Material.Output.Surface`다. 속성 집합이면 `MaterialAttributes` → `Output.Attributes`이고, 사이에 속성 설정 노드(`Material.SetMaterialAttributes`, 8.7절 2번 역할 id `"attrs:front"`)를 끼워 그 FrontMaterial 칸에 `FrontMaterial` 핀 출발을 넣는다(UE는 속성 집합 머티리얼에서도 FrontMaterial 핀을 표면으로 쓴다 — 1번. Rocks 출력 노드는 속성 집합 모드에서 개별 핀을 읽지 않는다 — MaterialSystem 06-IR FunctionsAttributes "출력 노드 `useMaterialAttributes`"). 그래서 UX5a는 `bUseMaterialAttributes`일 때도 `FrontMaterial` 핀을 덤프한다(6번 — 8.6절 3번을 고친다).
   - 나머지 핀: domain이 Substrate 모드에서 **어떤 블렌드·shading 조건에서도 읽지 않는 핀**만 잇지 않고 info `InactiveMaterialPin`이다. 블렌드·shading·thin 같은 조건이 붙은 핀은 모두 잇는다. 조건은 인스턴스의 `traitOverrides`로 바뀌므로(UE도 파생 인스턴스 기준으로 판정한다 — `IsPropertyActiveInDerived`, Material.cpp:8083-8110) 판정은 Rocks 컴파일(traits 기준, 스키마 V5)이 한다. 표는 UE `IsPropertyActive_Internal`의 Substrate 분기(Material.cpp:7785-7965)에서 조건을 뗀 것이다.

   | domain | 잇는 핀(조건과 상관없이) |
   |---|---|
   | Surface·RuntimeVirtualTexture(Surface 분기 — :7898 이하) | Refraction, Opacity, OpacityMask, AmbientOcclusion, WorldPositionOffset, Displacement, PixelDepthOffset, SurfaceThickness, CustomizedUVs, MaterialAttributes |
   | DeferredDecal | WorldPositionOffset, AmbientOcclusion, Opacity |
   | PostProcess | Opacity |
   | UserInterface | WorldPositionOffset, OpacityMask, Opacity, CustomizedUVs |
   | LightFunction·Volume | 없음 |

   - 읽지 않는 핀은 옛 표면 핀(BaseColor·Metallic·Specular·Roughness·Anisotropy·EmissiveColor·Normal·Tangent·SubsurfaceColor·ClearCoat·ClearCoatRoughness·ShadingModelFromMaterialExpression 등)과 위 표에 없는 핀이다. 그 핀 쪽 노드는 1번과 같이 닿지 않는 노드다.
   - Opacity 핀은 UE Substrate 분기에서 AlphaComposite일 때만 읽고, 그 밖의 반투명 opacity는 표면 트리의 coverage다(:7801-7803, :7926-7929). 머티리얼 쪽 규칙은 "Opacity 출력 핀이 쓰이지 않으면 표면 opacity"(MaterialSystem 06-IR Surface "opacity")라, 핀이 이어진 Translucent 머티리얼에서 UE와 다르다. 표면 트리가 고전 preset이 아닐 때 Opacity 핀을 AlphaComposite에서만 읽는 규칙이 요구 UXR17이다.
3. **설정(8.7절 7번에 더함).**
   - Substrate 모드에서 `ShadingModel`·`ShadingModels`는 UE가 그래프에서 다시 계산한 값이라(Material.cpp:5605-5680 — 편집할 수 없다) 옮기지 않는다(무시 행 — Rocks도 트리에서 shading model을 정한다, MaterialSystem 10.3절 접기 표). `MaterialDomain`은 저장된 사용자 값이다(`RebuildShadingModelField`는 FromExpression·순환일 때만 Surface로 바꾼다 — :5625, :5796). 그대로 옮긴다.
   - `bIsThinSurface` → `traits.thinSurface`, `bSubstrateRoughnessTracking` → `traits.roughnessTracking`(두 모드 모두 — MaterialSystem 19.9절 표). 에디터 데이터의 `SubstrateConversionVersion`·`SubstrateVersion`은 무시 행이다(판정 근거로만 쓴다).
   - 블렌드 모드 `BLEND_TranslucentColoredTransmittance`는 모드와 상관없이 Rocks 값이 TODO(`MPQ-ColoredTransmittance`)인 동안 `Translucent`다. UE도 dual-source blending이 없는 플랫폼에서 회색 투과(일반 알파 블렌드)로 물러난다(HLSLMaterialTranslator.cpp:15003-15004, 모바일 예외 — MaterialShared.cpp:2041). `projectSettings.substrate` 참이면 `UnsupportedSetting`이다. 거짓이면 경고 없이 옮긴다: UE는 편집 때 값을 `Translucent`로 바꾸고(Material.cpp:5393-5397 — `PostEditChangeProperty` 안), 로드한 값이 그대로 남아도 Substrate가 꺼진 셰이더 환경이 이 값을 `MATERIALBLENDING_TRANSLUCENT`로 컴파일하므로(MaterialShared.cpp:2727-2763 — `Translucent`와 같은 갈래) 그려지는 결과가 `Translucent`다(개정 29에서 원본으로 확인했다). 머티리얼 쪽이 그 값을 구현하면 Substrate 프로젝트 행을 Same으로 바꾼다.
4. **Substrate 노드 속성·핀.** 노드 속성은 8.7절 4번 공통 규칙이다. 머티리얼 쪽 TODO 속성(`SpecularProfile`·`SubsurfaceProfile` — `MPQ-SpecularProfile`·`MPQ-SubsurfaceProfile`)은 값을 버리고 `UnsupportedSetting`이다.
   - **UE 로드 변환.** Substrate가 켜진 프로젝트에서만 `PostLoad`가 옛 slab을 고친다(Material.cpp:4628-4640): `bUseSSSDiffusion` → `SubSurfaceType`(`ConvertSlabExpressionMaterialSubSurfaceType` — 호출한 머티리얼의 블렌드로 판정하고 **함수 소유 slab도** 고친다, :4259-4263), glint 밀도 변환(칸이 아니라 그래프 변환 — `SMF_GlintConversion` 함수 호출 노드와 `/Engine` 의존을 끼운다, :4269-4290). 교환은 덤프된 그래프를 그대로 번역한다(끼워진 함수 호출도 보통 함수 호출이다). deprecated `bUseSSSDiffusion`은 여전히 `UPROPERTY()`라 늘 덤프되므로(MaterialExpressionSubstrate.h:396-398) 무시 행이다. 다만 `projectSettings.substrate` 거짓이고 값이 참이면(변환되지 않은 옛 값) `UnsupportedSetting`이다.
   - **결정성 위험(개정 29에서 원본으로 확인).** 이 변환은 `AddMaterialSubstrateSubsurfaceType` 버전 전에 저장된 머티리얼에서만 돈다(Material.cpp:4631 — 이 버전을 보는 곳은 이 하나다). 그런 머티리얼을 로드할 때마다 그 머티리얼의 블렌드·thin 설정으로 호출하는 함수의 slab을 메모리에서 다시 쓰므로(:4259-4263 — 함수 쪽 PostLoad에는 변환이 없다) 함수 덤프의 `SubSurfaceType`은 **그 함수를 부르는 옛 버전 머티리얼 가운데 마지막에 로드된 것**의 판정이다. 플러그인은 내보내기 대상을 objectPath 순으로 정렬해(RocksExportClosure.cpp:489) 그 순서로 로드하므로(RocksExporter.cpp:125) 같은 선택·같은 UE 상태면 같은 결과이고, 선택이 다르면(다른 옛 머티리얼이 마지막이 되면) 함수 덤프가 다를 수 있다. 5.8에서 저장한 에셋은 이 변환을 거치지 않아 영향이 없고, 옛 에셋은 UE 5.8로 다시 저장하면 사라진다. 5.8 에디터로는 옛 버전 에셋을 만들 수 없어 실행으로는 재현하지 않았다.
   - **핀 별칭**(`ExchangeMaterialPinAliases` — 8.7절 3번): Slab 입력 16·17번은 플랫폼 glint 지원에 따라 이름 끝에 ` (Disabled)`가 붙으므로(MaterialExpressionSubstrate.cpp:1166-1170) 그 접미를 떼고 맞춘다. `SubstrateShadingModels` 입력 8–10·17·18번은 속성 shading model마다 이름이 바뀌므로(8: `Subsurface Color`·`Fuzz Color`, 9: `Custom0`·`Clear Coat`·`Iris Mask`·`Backlit`·`Fuzz Amount`·`Unused`, 10: `Custom1`·`Clear Coat Roughness`·`Iris Distance`·`Unused`, 17: `Clear Coat Bottom Normal`·`Iris Normal`·`Unused`, 18: `Iris Tangent`·`Custom Tangent` — :442-527) 번호로 맞춘다.

### 8.9 굽기 대체 설계(UX6 — 명세만)

설계일 2026-11-27(UX5와 같은 사용자 결정, 같은 교차 검증). 8.4절 굽기의 UE 쪽 기록 형식과 8.5절 결과 2번의 Rocks 쪽 산출물을 정한다. 결과 2·3번 저장 타입은 이 설계에서 고쳤다(8.5절). 모두 권장안이다.

1. **UE 쪽 굽기(UX6a — `FRocksMaterialBaker`).**
   - 명령 `-BakeMaterials`(`-BakeSize=<n>`, 기본 `RocksDefaultBakeSize` = 1024, 1–8192). 렌더링이 필요하므로 `-AllowCommandletRendering`이 없거나 `-nullrhi`이면 내보내기 전에 오류로 끝낸다(App.h:400-406). 지금 commandlet의 "UX6 전에는 쓸 수 없다" 거부를 바꾼다.
   - 대상은 범위 안 Material·MaterialInstanceConstant 가운데 domain Surface인 것이다(UV 공간 굽기라 Decal·LightFunction·PostProcess·UI·Volume은 뜻이 없다 — info `BakeSkipped`, detail domain). 함수·컬렉션은 굽지 않는다. 번역 가능 여부는 UE 쪽에서 알 수 없으므로 대상 전부를 굽는다.
   - 에셋마다 `BakeMaterials(FMaterialDataEx, FMeshData)` 한 번(IMaterialBakingModule.h:28-37): 속성 9개(아래 순서)에 `PropertySizes` = (n, n), `bTangentSpaceNormal` 참(GLTFExporter와 같다 — GLTFMaterialUtilities.cpp:142-160), 메시는 기본 quad(`MeshDescription` null — MaterialBakingStructures.h:118-121), 나머지(`bPerformBorderSmear`·`bPerformShrinking`·`BackgroundColor`)는 UE 기본값이다. 굽기 전에 `SetLinearBake(true)`·`SetEmissiveHDR(true)`를 부르고, 굽기 뒤에는 linear 상태를 굽기 전 값으로 되돌리며(`IsLinearBake`로 읽어 둔다 — 모듈 시작 값은 true, MaterialBakingModule.cpp:287) EmissiveHDR는 기본값 false로 둔다(getter가 없다 — GLTF·FBX 내보내기도 HDR을 켜지 않는다). 모듈 전역 상태다.
   - 속성 순서와 이름(UE `MP_` 이름에서 접두를 뗀 것): `BaseColor`, `Normal`, `Metallic`, `Roughness`, `Specular`, `EmissiveColor`, `Opacity`, `OpacityMask`, `AmbientOcclusion`(8.4절 목록).
   - 결과(MaterialBakingModule.cpp:980-1012):
     - EmissiveColor는 `HDRPropertyData`(`FFloat16Color` → `RGBA16F`)의 정규화하지 않은 원값이다(RGB만 뜻이 있고 알파는 굽기 결과가 0이라 1.0으로 채운다). shrinking·border smear는 8비트 배열에만 걸리므로 크기는 언제나 요청 크기 (n, n)이다(`PropertySizes`의 EmissiveColor 크기는 8비트 배열 기준이라 쓰지 않는다). `EmissiveScale`은 8비트 배열용이라 쓰지 않는다.
     - 나머지는 `PropertyData`(`FColor` → `BGRA8`, 알파는 255로 채운다 — GLTFExporter `bFillAlpha`와 같다, 굽기 결과 알파는 0이다)와 `PropertySizes`의 그 속성 크기(상수면 1×1까지 줄어든다)다. 색 공간은 `PropertyIsLinearColor`다(MaterialBakingStructures.h:158-192 — `SetLinearBake(true)`에서 BaseColor만 sRGB, MaterialBakingModule.cpp:1136-1146).
     - 실패 판정: 크기의 한 변이 0이거나 배열 길이가 가로 × 세로와 다르면 **warning** `BakeFailed`이고 그 에셋의 `baked`는 `null`이다(`PrepareBakeOutput`이 요청 속성 키는 늘 만든다 — :548-560). error가 아닌 이유: 플러그인 error 진단은 Rocks 리더가 에셋 전체를 거부하므로(10.4절 20번 — `ExporterError`) 굽기 하나의 실패로 번역할 수 있는 머티리얼과 그 인스턴스까지 못 쓰게 된다. `baked` null은 결과 결정(8.5절)이 "구운 것 없음"으로 받는다(개정 28 리뷰에서 고쳤다).
   - 한 번이라도 실제로 구우면(`BakeMaterials`를 부른 에셋이 있으면 — `BakeSkipped`만이면 아니다) `bundle.json`의 `environment`에 `{ "rhi": GDynamicRHI->GetName(), "gpu": GRHIAdapterName, "driver": GRHIAdapterUserDriverVersion }`(RHIGlobals.h:819-821)를 쓴다(3.4절).
   - `BakeSkipped`(info)·`BakeFailed`(warning)는 플러그인 진단 코드다(11장 9번에 적는다).
   - 공개 API `FRocksExporter::Export`도 `BakeSize`(0 또는 1–8192)와 렌더링 가능 여부를 내보내기 전에 검사한다(commandlet만 검사하면 에디터 메뉴·다른 호출자가 nullrhi에서 굽기를 부른다).
2. **`baked` 기록.** Material·MaterialInstanceConstant의 `data`에 `baked`를 더한다(굽지 않았으면 키가 없다, 실패면 `null`). `{ "bakeSize": n, "properties": [ 위 순서의 속성마다 { "property", "linear": bool, "source": 4.5절 1번 텍스처 원본 } ] }`이다. `source`는 `format` `BGRA8`·`RGBA16F`, `compression` `None`, `lossyOrigin` null, `longLat` 거짓, 층·블록·mip 각 1개, 층 `gammaSpace`는 `linear`면 `Linear` 아니면 `sRGB`, blob은 4.5절 2번 배치다. 굽기 blob은 결정성 대상이 아니다(3.2절). Rocks 리더의 구조 검사(8.6절 8번)는 `baked`의 모양·blob 참조·속성 순서, 원본마다 `compression` None·층·블록·mip 각 1개·층 `gammaSpace`와 `linear`의 일치·mip 크기 = 블록 크기·blob texel 수 = 가로 × 세로, EmissiveColor 크기 = (bakeSize, bakeSize), 8비트 속성 크기 1–bakeSize를 본다.
3. **결과 2번 그래프(UX6b — UE Material).** 주 출력은 `Material`이고(8.5절), 그래프는 임포터가 만든다(노드 id는 8.7절 2번 해시에 역할 `"baked:<속성>"`).
   - 구운 속성마다 텍스처 파라미터 노드 `Baked<속성>`(parameterId도 같은 해시) — 기본값은 그 속성의 보조 출력 텍스처다. 샘플 종류는 BaseColor 색, Normal 노멀, 나머지 선형이다. 좌표는 UV0이다(quad로 구웠다).
   - `SurfaceFromShadingModel`에 BaseColor(RGB)·Metallic·Roughness·Specular(R)·EmissiveColor(RGB — HDR 원값이라 배율이 없다)·Normal을 잇는다. shading model은 UE 설정이 `MSM_Unlit`이면 `Unlit`, 그 밖은 `DefaultLit`이다(구운 9속성으로는 다른 모델의 칸을 채울 수 없다 — 바뀌면 경고 detail에 원래 모델을 적는다).
   - `Material.Output`: Opacity(R — Output과 preset 둘 다, 8.7절 6번), OpacityMask(R), AmbientOcclusion(R). 블렌드 모드가 읽지 않는 핀은 스키마 V5가 다룬다(인스턴스가 블렌드를 바꿀 수 있으므로 늘 잇는다 — 8.8절 2번과 같은 이유). WPO·PDO·Displacement·Refraction·CustomizedUVs는 굽지 않으므로 잇지 않는다(원래 그래프가 이었으면 경고 detail에 적는다).
   - `traits`는 8.7절 7번 설정 번역 그대로이되 `tangentSpaceNormal` 참(굽기가 tangent 공간 노멀이다), `useMaterialAttributes` 거짓, `numCustomizedUVs` 0이다.
   - 보조 출력: 속성마다 `Output("Baked_<속성>", Texture2D)`(경로 `<머티리얼 경로>_Baked_<속성>` — AssetSystem 7.1절 12)을 4.6절 2번 원본 변환과 텍스처 임포트로 채운다. 텍스처 설정은 `SRGB` = 비선형, 압축은 Normal → 노멀 맵, EmissiveColor → HDR, 단일 채널 속성 → 회색조, BaseColor → 기본이다(4.6절 3번 설정 표의 Rocks 대응값).
   - **경로 충돌.** 보조 출력 경로가 묶음의 다른 에셋 대상 경로나 기존 에셋과 겹치면 AssetSystem이 임포트를 거부하므로, 임포트 계획(10.5절)이 `baked`가 있는 머티리얼 계열 에셋의 보조 출력 경로 9개를 대상 경로 집합에 넣어 미리 검사한다. 겹치면 다른 경로 충돌과 같은 `UnrealPathCollision`(오류, 계획 실패)이다.
   - 경고는 `MaterialBakedFallback`(detail = 닿은 번역 못 한 노드 클래스 목록, 바뀐 shading model, 버린 핀)이다.
4. **결과 3번 그래프.** 주 출력 `Material`, 그래프는 `Material.MaterialSample`(그 domain의 엔진 기본 머티리얼 — 고정 AssetId, UXR15) → `Material.Output.Surface` 하나다(역할 id `"default"`). `traits`는 설정 번역 그대로다. 눈에 띄는 격자 표면이 나오므로 실패가 보인다(MaterialSystem 11.3절 "검은 표면 금지").
5. **결과 표지.** 주 출력 Material에 교환 태그 `UnrealExchange.MaterialResult` = `Translated`·`Baked`·`Default`(결과 1·2·3번)를 더한다(10.6절 7번 태그 — 다른 교환 태그와 같은 접두). 인스턴스는 그래프 모양이 아니라 이 태그로 부모의 결과를 안다(사용자 파라미터 이름 `Baked…`와 겹쳐도 틀리지 않는다).
6. **인스턴스(MaterialInstanceConstant).** 주 출력은 언제나 `MaterialInstance`다.
   - 부모(사슬의 맨 위 Material — 인스턴스 부모가 인스턴스면 따라 올라간다)가 결과 1번: 8.7절 11번.
   - 결과 2번: `parent`는 원래 부모, override는 `Baked<속성>` 텍스처 파라미터(인스턴스 자기 `baked`의 보조 출력 `Baked_<속성>` — 경로 충돌 검사는 3번과 같다)다. 원래 override(굽기에 이미 들었다)는 옮기지 않고 info다. `BasePropertyOverrides`는 8.7절 11번 그대로 `traitOverrides`다. 인스턴스에 `baked`가 없으면 부모 쪽 구운 표면을 그대로 쓰고 `MaterialBakedFallback`(detail "instance not baked")이다.
   - 결과 3번: `parent`만 두고 override는 info로 버린다.
7. **재임포트.** 결과가 바뀌면(1 ↔ 2 ↔ 3) 주 출력은 같은 Material로 덮어쓰고 태그를 고친다. 더는 만들지 않는 `Baked_*` 보조 출력은 AssetSystem의 `OrphanedOutput`이다(7.1절 8 — 에셋은 남고 `asset-orphans-*`로 정리한다). 결과가 바뀌면 경고 `MaterialResultChanged`(새 코드 — detail 옛·새 결과)를 낸다. 그 Material을 부모로 쓰는 인스턴스는 override 키가 맞지 않게 되므로 다시 임포트해야 한다. 같은 묶음 임포트에서는 계획의 위상 순서가 인스턴스를 부모 뒤에 두므로 함께 맞춰진다. 부모만 임포트하면(`--only`) 경고 detail에 그 묶음 안의 자식 인스턴스 objectPath를 적는다.
8. **시험.** UE: 자기 시험 `RocksExport.MaterialBaking`(commandlet `-SelfTest`에도 포함 — 렌더링이 안 되면 "not run")은 렌더링이 되는 실행(`-AllowCommandletRendering`, `-nullrhi` 없음)에서만 돈다. 그 밖에서는 "not run: rendering unavailable"로 보고한다. `M_Golden`(상수 BaseColor·Roughness 파라미터)을 구워 BaseColor·Roughness가 1×1로 줄고 값이 기대 8비트 값과 ±1 안인지(BaseColor는 sRGB 부호화 값, Roughness는 선형 값), `MI_Golden`의 Roughness override가 반영되는지, 색 공간 표시, EmissiveColor `RGBA16F`·요청 크기, `environment`, 굽기 뒤 모듈 상태 복원을 본다. Rocks: GPU마다 bytes가 다르므로 `-BakeSize=16`으로 한 번 내보낸 `GoldenBaked.rxbundle`(`M_Golden`·`MI_Golden` 굽기 포함 — HDR emissive는 줄지 않으므로 크기를 작게 한다)을 고정 fixture로 두고, 경로 편집으로 번역 못 한 노드를 넣어 결과 2번(그래프 모양·보조 출력 9개·텍스처 설정·태그·인스턴스 override), `baked` 제거로 결과 3번, 인스턴스 `baked` 제거, Unlit shading model, 굽기 실패 `null`, 보조 출력 경로 충돌, 재임포트 결과 전환과 `OrphanedOutput`·`MaterialResultChanged`를 본다.
9. **구현(UX6a, 2026-11-27).** `FRocksMaterialBaker`(Public/RocksMaterialBaker.h — `CanBake`·`WriteBaked`·`WriteEnvironment`), 머티리얼 추출기가 `BakeSize` > 0이면 data 끝에 `baked`를 더하고(`FRocksExportOptions::BakeSize`, 0 = 굽지 않음), exporter가 `bundle.json` `environment`를 쓴다. 상수 `DefaultBakeSize` 1024·`MinBakeSize` 1·`MaxBakeSize` 8192(RocksExportCommon.h). commandlet은 `-BakeMaterials`(값 없는 switch)와 `-BakeSize=<정수>`를 받고, 범위 밖·소수·`-BakeMaterials` 없는 `-BakeSize`와 렌더링 불가(`FApp::CanEverRender` 거짓)를 내보내기 전에 거부한다. 결과는 모두 확인한 뒤에 쓴다(실패면 `baked` null 하나와 warning). `-BakeSize`는 int64로 읽어 범위를 본다(UE `Atoi`는 플랫폼에 따라 넘침을 자른다). 리뷰 반영(개정 28): `BakeFailed` warning, linear 상태 복원, `Export`의 인자 검사, 실제로 구웠을 때만 `environment`, HDR 알파 1.0, `CheckBaked` 보강, 굽지 않은 묶음에 `environment`가 없음을 단언. 플러그인 의존에 `MaterialBaking`·`RHI`를 더했다. Rocks 쪽은 외부 묶음 판정(8.6절 8번)에 `baked` 구조 검사(`CheckBaked` — 없음·null·bakeSize 범위·속성 9개 순서·형식·층·블록·mip·EmissiveColor 크기)를 더했고, 렌더링 실행으로 내보낸 `GoldenBaked.rxbundle`(`M_Golden`·`MI_Golden`·LightFunction 엔진 머티리얼, `-BakeSize=16`)을 시험 `UnrealExchange_GoldenBakedBundle`이 읽는다(12.3절).
