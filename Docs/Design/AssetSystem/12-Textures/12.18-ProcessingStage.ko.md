#### 12.18.2 결정

- **TP-D1 `bUseNewMipFilter`를 구현으로 바꾼다.** 지금은 기록만 하고 늘 새 경로다(12.5절 끝). UE에서 이 값이 결과를 가르는 곳은 다음이 전부다(빌드 경로 전수 — 키 직렬화 TDD 263–394와 ISPC ASTC 법선 정규화 TextureFormatIntelISPCTexComp.cpp 954는 해당 없음: Rocks ASTC는 astcenc 경로다).
  - 주소 방식: 새 경로만 Cube를 Clamp로, 텍스처 Address를 반영한다(TCM 1180–1243).
  - 최대 크기 축소: 새 경로이고 Volume·alpha coverage·PreserveBorder가 모두 아닐 때만 한 번 재표본한다. 그 밖은 mip 단계 축소다(TCM 4359–4426, TP1).
  - Sharpen·Blur 커널 mip: 새 경로는 분리 커널(색 이동 보정 없음), 옛 경로는 2D 커널(색 이동 보정 조건부)이다(TCM 994–1028).
  - 색 보정: `AdjustColorsNew`·`AdjustColorsOld`(TCM 2672·2826).
  - 알파 판정: 보정을 반영할 때 New·Old를 고른다(TCM 3054–3064, TP2).
  - Downscale: 크기 계산(TCM 1427–1475)과 필터(TCM 1504 —), LOD 그룹 Default 옵션의 해석(TextureLODSettings.cpp 454–465).
  - 합성 법선 사슬과 `GenerateTopMip`: 본 텍스처 값을 물려받는다(TCM 1277·3962).
  - 기본값: Rocks 리플렉션 기본값은 UE 멤버 기본값대로 false이고(Texture.h 62), 임포터만 true로 둔다(TextureImporter.cpp 180 — UE `SetModernSettingsForNewOrChangedTexture`). 임포트하지 않고 만든 텍스처(`asset-new`, 조합 Cube·Array, 시험 고정값)는 TP1 뒤 옛 경로로 간다. UE도 같다 — modern 설정은 새 임포트와 ImageUtils 생성에서만 쓰고(TP1 착수 세부), NewObject·배열·Cube 배열·Volume factory(Texture2DArrayFactory.cpp 38–72, TextureCubeArrayFactory.cpp 37–60, VolumeTextureFactory.cpp 30–58)와 재임포트는 false다. 그래서 생성 경로 기본값은 바꾸지 않는다. TP1은 기존 시험·TestContent 가운데 false이면서 최대 크기 축소가 걸리는 것을 찾아 기대값을 고친다(2×2 SimpleAverage는 주소 방식이 바뀌어도 같은 결과라 영향은 최대 크기 경로뿐이다).
  - 각 단계는 자기 기능의 두 경로를 함께 구현한다. 기존 기능(주소 방식·최대 크기)의 옛 경로는 TP1이 맡는다.
- **TP-D2 처리 순서는 UE `BuildTextureMips`·`BuildTexture`와 같다.** 12.5절의 순서를 다음처럼 고친다(번호는 12.5절).
  - 3번 PowerOfTwoMode → 4번 최대 크기 → (TP5) 원본 mip 복사 → (TP3) Downscale → (TP2) 색 보정 → (TP2) Bokeh 알파 → 4a번 `bFlipGreenChannel` → 5번 mip 생성(TP1 필터·alpha coverage, TP6 Angular) → 6번 NormalizeNormals → 채널 복제 → (TP7) YCoCg 블록 스케일 → (TP4) 합성(완성된 사슬 — TCM 3984) → 형식 선택·쿠킹 편향·출력.
  - 원본 mip 복사부터 FlipGreen까지는 복사한 원본 mip마다 같은 순서다(TCM 4504–4607 — LeaveExistingMips면 여러 장).
  - **알파 판정은 처리 뒤 그림을 다시 보지 않는다.** UE와 지금 Rocks 모두 원본 mip 0의 채널 min·max로 판정한다(TCM 3016–3086, TextureBuild.cpp 1427–1432). 보정은 그 두 색에 적용해 반영한다(TP2). 그래서 합성이 알파를 바꾸거나(`NormalRoughnessToAlpha`) mip이 알파를 바꿔도 판정은 그대로다.
  - 지금 4a번(FlipGreen)은 최대 크기 바로 뒤다. 사이 단계(Downscale·보정·Bokeh·원본 mip)가 지금은 모두 없으므로 순서 변경은 기존 출력 byte를 바꾸지 않는다. Bokeh 그룹 텍스처의 출력은 TP2에서 그 자체로 바뀐다(버전 올림).
- **TP-D3 식과 연산 순서를 UE와 같게 한다.** 결정성은 지금 빌드와 같은 규칙이다(`DeterministicMath`만, batch마다 결정적 FP — 12.17.9).
  - 화소 연산은 UE처럼 float다. 합산 순서는 UE 루프 순서 그대로다(예: 2D 커널은 KernelY 바깥·KernelX 안쪽, 2×2는 ((A + B) + C) + D, 3성분 내적은 (R·w0 + G·w1) + B·w2 — UnrealMathSSE.h 1493).
  - 초월 함수(exp·sqrt·pow·log2·sin·cos·atan2)는 float 인자를 double로 넓혀 `DeterministicMath`(오차 2 ulp 이하 double)로 계산하고 float로 반올림한다. 결과는 float 정확 반올림과 같다(같지 않은 경우는 double 오차가 float 반올림 경계를 넘는 극히 드문 경우뿐이고, 시험이 잡는다). UE는 호스트 libm의 float 함수라 1 ulp 차이가 날 수 있다. 그 범위는 probe의 두 판 차이(TP-D4)로 재서 대조표에 적는다.
  - UE가 double로 계산하는 곳은 double이다: Angular의 방향·면 변환·정규화·내적·원뿔 교차(FVector — TCM 2194–2253·2335–2350), NormalizeNormals(이미 double — 12.5절).
- **TP-D4 기준값은 UE 원본 probe가 만든다(개정 2).** `Tools/TextureProcessingProbe/`가 TC1의 NvttGolden처럼 UE 클론의 TCM 함수(커널·mip 생성·alpha coverage·색 보정·Downscale·Angular·Toksvig)를 직접 컴파일한다. UE 코드는 저장소에 복사하지 않는다 — `make_golden.py`가 고정 commit의 TCM에서 함수 구간(첫 줄 내용으로 확인)을 잘라 작업 디렉터리에 묶고, `ProbeShim.h`가 FImage·FLinearColor·VectorRegister(SSE와 같은 원소별 float 연산과 내적 순서)·ParallelFor(직렬)·FMath·check·로그를 대신한다.
  - 판 둘: **기준 판**은 shim의 FMath 초월 함수를 float 인자 → Rocks `DeterministicMath`(probe가 `DeterministicMath.cpp`를 같이 컴파일한다) → float 반올림으로 둔다. 정의상 Rocks 계산(TP-D3)과 같은 값이고 생성 호스트와 무관하다. 이 판의 출력이 시험 golden이고 Rocks는 byte 단위로 같아야 한다. **UE 판**은 호스트 float libm(UE와 같은 호출)이다. 두 판의 차이가 UE와 Rocks의 차이이고, 대조표에 적는다.
  - 입력 그림은 시험과 probe가 같이 쓰는 생성기 헤더(`Tests/ProcessingGoldenImages.h` — BlockGoldenImages.h와 같은 방식)가 만든다. golden은 `Tests/Fixtures/TextureProcessingGolden/`의 이진 파일이다.
  - 개정 1의 Python 참조(numpy float32 이식)는 뺀다. 같은 오독을 걸러내는 데는 원본 컴파일이 더 확실하고, 참조를 둘 두면 맞춰야 할 기준이 셋이 된다.
  - probe로 묶지 못하는 함수가 생기면 그 이유와 대체 근거(예: 작은 손 계산 표)를 그 단계 대조표에 적는다.
- **TP-D5 설정마다 계약을 푼다.** 단계가 끝나면 그 설정을 12.4절 표에서 구현으로 옮기고 12.8절 계약 판정에서 뺀다. 출력이 바뀌는 단계마다 `TextureBuildVersion`을 올린다(너겟 키). 너겟 키 사본은 lodGroup을 고정하므로(TextureCook.cpp 188–190), 해석된 그룹 값이 결과를 바꾸면(Downscale·DownscaleOptions·mip 필터) 키에 그 값을 명시한다. TestContent에 그 설정을 쓰는 텍스처가 있으면 재쿠킹한다.
- **TP-D6 TextureBuild.cpp를 기능별 파일로 나눈다.** 지금 1661줄이고 이 단계에서 크게 는다. TP0에서 이동 커밋으로 나눈다(내용 변경 없음): 선형화·재표본·패딩(`TextureBuildResize.cpp`), mip 생성(`TextureBuildMips.cpp`), 출력(`TextureBuildEncode.cpp`), 크기 계획·쿠킹 편향·설정 해석·본문(`TextureBuild.cpp`). 새 단계는 `TextureBuildKernel.cpp`(TP1)·`TextureBuildAdjust.cpp`(TP2·TP3)·`TextureBuildComposite.cpp`(TP4)·`TextureBuildAngular.cpp`(TP6)를 더한다.
- **TP-D7 병렬은 행 단위다.** 화소마다 독립인 처리(커널 mip·색 보정·Downscale 재표본)는 TC5a의 `TextureBuildExecution` scheduler로 행을 나눠 돌린다. 결과는 분할과 무관하다. alpha coverage 개수 합은 정수라 분할과 무관하다. Bokeh 평균은 UE `ComputeImageLinearAverage` 순서(행마다 순서대로 더한 행 합을 다시 순서대로 더하고 마지막에 1/화소 수를 곱함 — ImageParallelFor.cpp 82–117)라 행 단위 병렬도 결정적이다. Angular의 적분 순서는 사분 재귀(TP6)라 대상 texel 단위로만 나눈다.

**TP1 mip 필터**
1. 커널 표 `FImageKernel2D`(TCM 174–389): 2탭은 평균(0.5·0.25 — sharpen 무시), sharpen < 0이면 Gauss(크기 n, 분산 = −sharpen, 합 1로 정규화 — exp·sqrt), 4·6탭은 기본 lobe(가운데 두 칸 0.5·합) 양수 1 + s·음수 −s, 음수 lobe를 상자 흐림 1회(4)·2회(6), 8탭은 s × 2 뒤 양수 lobe 흐림 1회·음수 lobe 흐림 3회, 두 lobe를 더하고 2D는 바깥곱이다. 상자 흐림은 이웃 셋 합 / 3(끝은 둘)이다. Sharpen 8탭 표는 초월 함수가 없다. 홀수 Gauss(`GenerateTopMip`이 `| 1`로 만드는 7)도 이 표가 만든다(TP4가 쓴다).
2. `GetMipGenSettings` 대응(TextureLODSettings.cpp 395–448): Sharpen n은 sharpen 0.2n·크기 8, Blur n은 sharpen −2n·크기 2 + 2n·평균 사슬 없음·색 이동 보정 없음·BorderBlack. 색 이동 보정은 `!Normalmap && Compression != Masks`일 때만이다(403). 그 밖(SimpleAverage·NoMipmaps·LeaveExisting 등)은 sharpen 0·크기 2.
3. 평균 사슬(`bDownsampleWithAverage`, 크기 2면 끔 — TCM 1831–1838): 출력 mip k + 1은 평균 사슬 mip k에서 커널로, 평균 사슬 mip k + 1은 같은 평균 사슬 mip k에서 2×2로 만든다. 두 생성 모두 필터 → alpha scale → 테두리 다시 쓰기 순서이고, alpha scale은 각 생성의 원본(평균 사슬 mip)에서 따로 구한다(1971–2012).
4. 커널 mip 생성: 새 경로는 분리(세로 먼저 행 버퍼, 다음 가로 — TCM 855–935), 옛 경로는 2D(TCM 763–852)이고 색 이동 보정이면 2×2 평균 색에 새 휘도 / 옛 휘도를 곱한다(휘도 0.3·0.59·0.11, 옛 휘도 > 0.001일 때만, 알파는 커널 값). 2×2 커널은 색 이동 보정을 무시한다(TCM 973). 원본 위치는 대상 × 2 + 탭 − (크기 − 1) / 2다.
5. 주소 방식(TCM 1180–1243): PreserveBorder면 BorderBlack(Blur) 또는 Clamp, 새 경로 Cube면 Clamp, 2의 거듭제곱이 아니면 Clamp, 새 경로면 두 축이 모두 Wrap이 아닐 때 Clamp이고 한 축만 Wrap이면 Wrap, 옛 경로는 Wrap이다. BorderBlack의 원본 밖은 (0, 0, 0, 0)이다(TCM 124–131). 세 방식의 원본 밖 처리(`LookupSourceMip` 104–171)를 그대로 옮긴다.
6. alpha coverage(TCM 391–605·1898–1907): 텍스처의 두 칸이 모두 켜져야 하고 임계값이 (0,0,0,0)이 아니어야 한다(TDD 1159–1170). 목표 coverage는 base mip의 slice 0에서 한 번 구해 모든 slice·면에 쓴다. 각 생성의 scale은 8단계 이분 탐색([0, 4], 시작 1, 채널 임계값 0은 건너뜀, `KINDA_SMALL_NUMBER` 비교), 비교 임계값은 `DetermineScaledThreshold`(nextafter로 x·scale ≥ t와 같게 맞춤)다. 테두리 다시 쓰기는 scale 뒤에 덮으므로 테두리 texel에는 scale이 없다(1104–1107).
7. Volume: 커널 결과를 두 번째 slice(2z + 1, 끝이면 마지막)에서도 만들어 (a + b) × 0.5다(Unfiltered 제외 — TCM 1092–1108).
8. 최대 크기 축소: 새 경로 재표본 조건은 `useNewMipFilter && !volume && !alphaCoverage && !preserveBorder`다(TCM 4359–4360). 그 밖은 `GenerateMipChain(…, 1)`을 한 단계씩 부르는 mip 단계 축소이고, 단계마다 텍스처의 mip 필터·주소 방식·alpha coverage(목표는 그 단계 입력에서 다시 구함)·테두리 다시 쓰기를 모두 쓴다(4404–4426). 지금 Rocks의 단계 경로(`volume || preserveBorder`, 2×2만 — TextureBuild.cpp 1038·1475–1487)를 이 조건으로 바꾼다.
9. 시험 크기: Sharpen 8탭은 축 ≥ 16, 평균 사슬은 3단계 이상, 2의 거듭제곱인데 Address Clamp, X Wrap·Y Clamp 혼합(→ Wrap), Blur + PreserveBorder(BorderBlack), 2의 거듭제곱 Cube의 두 경로(Wrap 대 Clamp), alpha coverage 다층 slice(slice 0 목표).

4. 새 경로 필터(ImageCore.cpp 2063–2082): Default CubicMitchell, Unfiltered 점 표본, SimpleAverage 삼각, Sharpen0 CubicGaussian(B-spline), Sharpen1·2 Mitchell, 3·4 B = ¼, 5·6 B = ⅙, 7·8 Catmull-Rom, 9 B = −⅙, 10 B = −⅓. cubic 계열은 같은 길이 축에서도 무연산이 아니다(1925–1953 — 12.5절 크기 조정 필터의 point 표본 규칙과 다르다).
5. 옛 경로 필터(TCM 1573–1722): 몫이 2보다 큰 동안 2×2를 Clamp로 반복하고, 마지막 단계는 Unfiltered 반올림 점 표본, SimpleAverage 픽셀 중심 보정 없는 bilinear, Sharpen n은 `FImageKernel2D(8, 0.2n)` × bilinear 탭이다. 비율은 X 비율 하나를 Y에도 쓴다. TP1 커널 표에 의존한다.
6. 크기 계획: Downscale 크기를 크기 계획(형식 선택의 4 배수 판정, 계획 검사 — TextureBuild.cpp 1497)에 넣는다(UE `GetOutputMipInfo` TCM 3735–3748).
7. TargetProfile LOD 그룹에 `downscale`·`downscaleOptions` 칸을 더하고(10.2절), 해석된 값을 너겟 키에 명시한다(TP-D5).
8. 시험: 블록 정렬·비정렬·GCD·8 초과.

**TP4 합성**
1. 입력(TDD 1330–1340, TextureDerivedDataTask.cpp 245·1374–1378): 쿠킹 처리기가 참조 텍스처의 원본을 읽는다. 참조 원본이 없으면 Disabled, Availability가 CPU면 합성을 끈다. 참조 빌드는 기본 설정이라 참조 텍스처의 FlipGreen·NormalizeNormals·MaxTextureSize·Address 등은 쓰지 않는다. 너겟 키에는 참조 원본(SHA-256)과 원본 감마(sRGB·LegacyGamma)만 넣는다.
2. 법선 사슬(TCM 3940–3962): top mip은 `GenerateTopMip`(ScaleFactor 1, 홀수 `6 | 1` = 7탭 Gauss −3.5, top mip 재정규화를 먼저 — TCM 1245–1303), 나머지 mip은 짝수 6탭 Gauss −3.5를 평균 사슬 없이 매 mip에 쓴다. NormalizeNormals는 끈다. 주소 방식은 기본 Address(Wrap)라 2의 거듭제곱이면 Wrap, 아니면 Clamp다. `bUseNewMipFilter`는 본 텍스처 값이다.
3. 적용(TCM 4725–4787·3298–3400): `DestLODBias`는 쓰지 않는다. 대상 mip이 법선 mip 0보다 두 축 모두 크면 건너뛴다(roughness 그대로). 같은 크기의 법선 mip이 없으면 법선 길이를 UV 중심 bilinear로 늘리는데, 이때 slice 수가 1이 아니면 실패하고 빌드 전체가 실패한다(3356–3363·3991–3996). Toksvig(`CompositeNormalLengthToRoughness` — pow 0.25 포함)로 대상 채널(R·G·B·A)을 바꾼다.
4. 참조 순환·자기 참조의 진단은 착수 때 정한다.
5. 시험: 건너뜀·늘림·slice 실패·CPU 비활성, 합성 → A가 알파 판정에 영향이 없음(TP-D2).

**TP5 원본 mip**
1. 원본 mip 저장: TextureSource 형식에 mip 수와 mip별 픽셀을 둔다(원본 bulk 판 올림 — 하위 호환 없이 재저장). DDS 임포터가 mip 사슬을 보존한다(12.10절 76). UE 교환 `NumMips`.
2. 빌드 규칙: PowerOfTwoMode가 크기를 실제로 바꿀 때만 실패다(TCM 4181–4194 — 원본이 이미 2의 거듭제곱이면 성공). 최대 크기는 원본 mip을 따라 내려가고, 맞는 원본 mip이 없으면 마지막 원본 mip에서 줄인다(4330–4355). 원본 mip이 1장이면 출력 1장이다(4476). 모자란 mip은 생성한다(2×2, alpha coverage면 함께). 원본 mip마다 TP-D2의 보정 순서를 적용한다.
3. 불완전 사슬 규칙과 기존 에디터 패키지 재저장 절차는 착수 때 정한다.

**TP6 Angular**
1. 조건: Cube만(CubeArray 포함 그 밖은 SimpleAverage — TextureLODSettings.cpp 417).
2. `GenerateAngularFilteredMips`(TCM 2572–2654): mip 0까지 모든 mip을 다시 만든다. 평균 mip 가속 사슬, `DiffuseConvolveMipLevel` = 4(RenderCore `GDiffuseConvolveMipLevel`). 원뿔 적분은 `TCubemapSideRasterizer`의 사분 재귀·가지치기 순서로 더한다(2391–2405). 가중치는 커널 가중치뿐이다(`AreaCompensation`은 계산하지만 쓰지 않음 — 2355–2359). 출력 알파는 늘 0이다(2439). 방향·면 변환·정규화·내적·원뿔 교차는 double이다(TP-D3).
3. 출력 크기는 `1 << (NumMips − 1)`로 2의 거듭제곱 아래로 내린다(2621). UE `GetOutputMipInfo`는 이를 반영하지 않는다(3688–3786 — 2의 거듭제곱이 아닌 면에서 오류 로그). Rocks는 크기 계획에 이 내림을 넣는다(형식 선택이 맞는 크기를 보게 — UE와 다른 점으로 적는다).
4. NumMips ≤ 4(면 ≤ 8)이면 `i / (NumMips − 4)`가 0 나눗셈이 되어 원뿔 각이 π/2로 clamp된다. UE와 같은 결과를 내되 NaN·Inf를 거치지 않는 식으로 같은 값을 만든다(결정성).
5. 시험: 면 8·16·≥ 128, 2의 거듭제곱이 아닌 면.

**TP7 압축 보조**
1. `CompressionYCoCg`: UE에서 편집할 수 없는 UPROPERTY이고(Texture.h 1622–1624) RVT만 켠다(RuntimeVirtualTextureComponent.cpp 484). 형식 선택에는 분기가 없고, 효과는 `bApplyYCoCgBlockScale` 하나다(TDD 874). 블록 스케일은 완전한 4×4 블록에만 적용하고(남는 행·열과 4보다 작은 mip은 그대로) B를 덮어쓴다(TCM 3181–3236). 구현은 블록 스케일과 저장·교환이다(RVT는 범위 밖).
2. `LossyCompressionAmount`·`bOodlePreserveExtremes`: Developer 아래에서 TextureFormatOodle.cpp만 소비한다(전달 코드 제외). UE 기본 텍스처 인코더는 Oodle이지만(BaseEngine.ini 3727–3728) Rocks는 12.17절대로 비 Oodle 인코더(NVTT·ISPC·astcenc 대응)를 기준으로 삼는다. 그래서 두 칸을 기록(저장·교환만)으로 바꾼다.

#### 12.18.4 시험(완료 조건)

- 기준값 표: 단계마다 probe 기준 판 golden과 byte 단위로 같다. 그림은 홀수·1 길이 축·2의 거듭제곱 아님·Volume·Cube·2DArray와 단계별 크기 조건(TP1 9·TP3 8·TP6 5)을 포함한다. 두 경로(TP-D1)를 모두 본다.
- UE 판 대조: 단계마다 기준 판과 UE 판의 차이를 대조표에 적는다(TP-D4).
- 조건 표: 각 설정이 효과를 갖는 조건에서 켜짐·꺼짐 결과(alpha coverage 두 칸, Downscale 조건, Angular Cube만, 합성 Disabled·CPU, chroma key·Bokeh 알파 판정).
- 결정성: 같은 입력은 두 번 빌드해도 같은 byte이고, scheduler 참여자 수(1·2·여러)와 무관하다.
- 계약 판정: 구현으로 옮긴 설정은 더 이상 `UnsupportedSetting`이 아니고 남은 계약 설정은 그대로다.
- 너겟 키: `TextureBuildVersion`이 오르고, 설정 값과 해석된 그룹 값이 키에 들어간다(TP4는 참조 원본·감마도).
- 할당 실패 주입: 새 작업 버퍼의 모든 할당 지점.
- 쿠킹 시나리오: TestContent에 단계별 대표 텍스처를 더해(Sharpen5 + alpha coverage, 색 보정, Downscale, 합성, Angular Cube) 쿠킹 → 로드 데이터를 대조한다.
