### 12.5 빌드 처리와 mip 규칙

적용 순서(한 텍스처의 각 slice·면에 같은 순서 — 2026-11-24 A5i 교차 검증으로 UE 5.8 TextureCompressorModule.cpp·TextureBuildUtilities.cpp·TextureLODSettings.cpp·ImageCore.cpp에 맞춰 개정. 처음 판은 홀수 크기 3탭 평균·가장 가까운 2의 거듭제곱 Stretch·Lanczos3·d = max(편향, 상한)이었다):

1. 원본 → 선형 float 디코딩(12.2절 1번). 알파는 그대로.
2. (자리 비움 — `bFlipGreenChannel`은 UE처럼 4번 뒤에 한다, 4a번.)
3. `PowerOfTwoMode`(UE `GetPowerOfTwoTargetTextureSize`):
   - Pad·Stretch는 각 축을 n 이상인 가장 작은 2의 거듭제곱으로 올린다(`RoundUpToPowerOfTwo`). Square 변형은 세 축(Volume이 아니면 X·Y) 최대값이다. ResizeToSpecificResolution은 `ResizeDuringBuildX`·`ResizeDuringBuildY`(0이면 원래 길이)다.
   - Volume의 Pad는 Z도 늘린다(새 slice도 채운다). Volume의 Stretch·Resize는 X·Y만 바꾼다(UE는 Stretch 대상 Z를 올리지만 `ResizeImage`가 slice 수가 다르다고 거부해 Z가 채워지지 않는다 — Rocks는 Z를 그대로 둔다, UE와 다름).
   - Pad: 늘어난 영역은 `bPadWithBorderColor`면 그 행의 마지막 texel(아래 행은 위 행, 새 slice는 앞 slice), 아니면 `PaddingColor`다. `PaddingColor`는 원본 형식과 무관하게 8비트 sRGB로 디코딩한다(UE `FLinearColor(FColor)` — 알파는 a / 255).
   - Stretch·Resize: UE `ResizeImage` 기본 필터 AdaptiveSharp다. 축마다 확대면 Catmull-Rom(Mitchell–Netravali B = 0, C = ½), 축소면 Mitchell(B = C = ⅓), 같은 길이 축은 point 표본(복사 — UE `MapFilterToStb`의 `FilterIsNopWhenSameSize`)이다. 가장자리는 clamp, 알파 가중 없음(아래 "크기 조정 필터").
   - 차원 규칙: Cube·CubeArray 면은 정사각형이어야 하고(원본이 아니면 `InvalidSource`) Resize가 정사각형을 깨면 `InvalidSetting`이다. 2DArray·CubeArray·Volume의 slice는 모두 같은 크기·형식이어야 한다(파일 구성이면 `InvalidSource`, 에셋 원본 묶음이면 `InvalidSetting`).
4. 최대 크기(UE `MaxTextureResolution`): 상한 = min(`MaxTextureSize`(0이면 없음), 16384)이다. X 또는 Y가 상한보다 크면 두 축을 함께 max(1, n >> 1)로 반씩 줄여 상한 이하가 되는 크기를 정한다(Volume은 X·Y만 보고 Z도 함께 줄어든다).
   - Volume이 아니고 `bPreserveBorder`가 꺼져 있으면 그 크기로 한 번에 재표본한다(3번 필터). 그 밖에는 아래 mip 규칙으로 한 단계씩 줄인다.
4a. `bFlipGreenChannel`(UE `FlipGreenChannel` — Pad·Stretch·최대 크기를 거친 mip 0에서 g → 1 − Clamp(g, 0, 1), TextureCompressorModule.cpp 3176·4603).
5. mip 생성(선형 float, 아래 규칙): 4번 결과에서 1×1(×1)까지 만든다(Volume은 Z 포함 사슬). mip k + 1은 mip k에서 만들고, `bPreserveBorder`는 만든 직후 그 mip에 적용되어 다음 mip의 입력이 된다(mip 0에는 적용하지 않는다).
6. `bNormalizeNormals`(Normalmap만 — UE `NormalizeMip`): 사슬을 다 만든 뒤 mip 0을 포함한 모든 mip에 적용하는 후처리다(다음 mip의 입력이 되지 않는다).
7. 쿠킹 편향(쿠킹 때, UE `CalculateLODBias` — 그룹 = 프로파일 LOD 그룹, `FromTextureGroup`·`Default`도 그룹 값으로 바뀐다). W·H = 5번 사슬 mip 0의 X·Y, N = 사슬 길이다.
   - `NoMipmaps`면 버리지 않는다(그룹 MaxLODSize도 적용되지 않는다 — UE 헤더 "no effect for textures with no mip chain". 크기는 4번 `MaxTextureSize`만 줄인다).
   - TextureMaxLOD = floor(log2(max(W, H)))(Volume도 X·Y만), 편향 b = 텍스처 LODBias + 그룹 LODBias(음수 허용)다.
   - WantedMaxLOD = Clamp(TextureMaxLOD − b, CeilLog2(그룹 MinLODSize), CeilLog2(그룹 MaxLODSize))를 다시 [0, TextureMaxLOD]로 자른다. Clamp는 UE `FMath::Clamp`(x < 최소면 최소, 아니면 min(x, 최대) — 최소 > 최대면 x < 최소일 때 최소가 이긴다)이고 CeilLog2(0) = 0이다.
   - d = min(TextureMaxLOD − WantedMaxLOD, N − 1)개의 상위 mip을 버린다.
   - 편향에는 `NumCinematicMipLevels`를 넣지 않는다(UE와 같다, 12.5.1절 4번). 이 절의 LODBias는 쿠킹 편향이며 런타임 bias·표본 mip bias와 다른 양이다(12.5.1절 5번).
   - UE의 그룹 `MaxLODMipCount`는 설정 칸이 아니라 CeilLog2(MaxLODSize)로 계산하는 스트리밍 값이라 쿠킹 편향에 쓰지 않는다.
8. 출력 부호화·양자화(12.2절 3·5번), swizzle 기록(12.4.3절).

크기 조정 필터(AdaptiveSharp — UE ImageCore가 쓰는 stb_image_resize2의 Catmull-Rom·Mitchell과 같은 식, 결정적 계산):
- 커널 k(x)(Mitchell–Netravali, |x| < 1: ((12 − 9B − 6C)|x|³ + (−18 + 12B + 6C)|x|² + (6 − 2B)) / 6, 1 ≤ |x| < 2: ((−B − 6C)|x|³ + (6B + 30C)|x|² + (−12B − 48C)|x| + (8B + 24C)) / 6, 그 밖 0).
- 표본 중심: 대상 i의 원본 좌표 = (i + 0.5) × (원본 길이 / 대상 길이) − 0.5. 축소(비율 s = 대상 / 원본 < 1)면 커널을 1/s배 넓힌다(k(x·s), 반경 2/s). 가중치는 탭 합으로 정규화한다. 축별 분리(X → Y).
- 가장자리는 clamp(끝 texel 반복 — 텍스처 Address와 무관, UE와 같다).
- 결과를 자르지 않는다(UE는 RGBA32F로 재표본하고 stb_image_resize2는 float 출력을 자르지 않는다). 음수 lobe의 넘침도 그대로 다음 단계(mip 평균)로 가고, 자르기는 출력 양자화(12.2절 5번) 한 번뿐이다.
- stb_image_resize2와 byte까지 같은지는 빌드 때 UE 결과와 대조한다(14.1.99절 — 다르면 허용 오차를 적는다).

mip 규칙(UE `GenerateMip2x2`·`GenerateMipUnfiltered`·`GenerateMipBorder`):

- 크기: 각 축 길이 n의 다음 mip 길이는 m = max(1, n >> 1)이며 1×1(×1)까지 만든다. 홀수 길이의 마지막 행·열·slice는 다음 mip에 들어가지 않는다(UE와 같다).
- SimpleAverage: 대상 (i, j)는 원본 (2i, 2j)·(2i + 1, 2j)·(2i, 2j + 1)·(2i + 1, 2j + 1)을 float로 ((A + B) + C) + D) × 0.25다. 원본 밖 위치(길이 1인 축)는 주소 방식으로 읽는다 — 길이 1이면 Wrap·Clamp 모두 같은 texel이다. Volume은 slice 2z·2z + 1의 2D 결과를 (a + b) × 0.5로 평균한다(깊이 1이면 2D 결과만).
- Unfiltered: 원본 (2i, 2j)(Volume은 slice 2z) 표본이다.
- 색은 선형 float에서 평균하고 알파 가중하지 않는다(UE SimpleAverage).
- mip 생성의 주소 방식(UE `ComputeAddressMode`): PreserveBorder면 Clamp, Cube·CubeArray면 Clamp, 원본 크기가 2의 거듭제곱이 아니면 Clamp, 두 축 Address가 모두 Wrap이 아니면 Clamp, 그 밖 Wrap이다. 2×2 상자에서는 길이 1인 축에서만 원본 밖을 읽는다.
- PreserveBorder(mip k ≥ 1, 각 slice·면 — Volume은 slice 2z): 대상 테두리 texel마다, mip k − 1에서 그 2×2 발자국 안에 있는 원본 테두리 texel만 float로 더해 개수로 나눈다(원본이 2의 거듭제곱이면 Wrap 조회, 아니면 Clamp). UE는 PreserveBorder일 때 mip 주소를 Clamp로 바꾼다 — Rocks는 Address가 Wrap이면 `PreserveBorderWithWrap` 경고를 더한다(Rocks 추가).
- NormalizeNormals(UE `NormalizeMip`): v = (r, g, b) × 2 − 1(float)을 double 벡터로, 제곱합이 정확히 1이면 그대로, 1e−8 미만이면 (0, 0, 1), 아니면 1 / sqrt(제곱합)을 곱한 뒤 float(v × 0.5 + 0.5)로 되돌린다. 알파는 그대로다.
- Cube: 면별 독립 mip(면 경계 연속성은 Angular와 함께 후속).
- 정수 반올림은 출력 양자화에서만 한다(12.2절 5번).
- `bUseNewMipFilter`: Rocks는 늘 UE의 새 필터 경로(위 규칙)다. 교환으로 들어온 false 텍스처는 UE 옛 경로(주소 방식·최대 크기 축소가 다르다)와 결과가 다를 수 있다(차이로 적는다 — 12.4.1절 기록 칸).
- 시험: 4×4·5×3·1×7·3×1·Volume 4×4×4·3×3×3 원본의 mip 픽셀 표, PowerOfTwoMode 6종·필터 기준값 표, 최대 크기·쿠킹 편향(LODBias·MaxTextureSize·그룹 MaxLODSize·MinLODSize·NoMipmaps) 표.

#### 12.5.1 스트리밍 메타와 상주 꼬리(텍스처 스트리밍 T1·T5·T8)

2026-11-20 렌더 세션 요구([텍스처 스트리밍](../../TextureStreaming.ko.md) 4.3·4.4·11절, [렌더 기반](../../RenderBase.ko.md) 6.5절)를 쿠킹 규칙으로 정한다. 렌더는 상주 mip 수를 다시 계산하지 않고 아래 메타를 쓴다. N = 쿠킹 뒤 mip 수(12.5절 7번에서 d개를 버린 뒤), X·Y = 쿠킹 뒤 상위 mip의 크기다.

1. **덩어리와 hash.**
   - 스트리밍 mip은 mip 하나가 bulk 덩어리 하나다(그 mip의 모든 slice·면·깊이).
   - 상주 꼬리 mip은 모두 덩어리 하나에 큰 mip부터 이어 둔다. 메타의 mip 항목은 그 덩어리 안 오프셋과 바이트 크기를 가진다.
   - 덩어리 hash는 그 덩어리 `BulkDataRef`의 raw SHA-256이다(5절 Bulk 섹션 다이제스트). hash 칸을 따로 두지 않는다. 스트리밍 전송은 읽고 푼 뒤 대조하고, 다르면 손상 오류를 낸다(TextureStreaming 5.1절). 상주 꼬리 덩어리는 패키지 로드의 bulk 검증을 따른다.
   - UE 대응: mip마다 bulk 하나(`FTexture2DMipMap`, TextureResource.h 45–57), inline mip은 에셋과 함께 상주.
2. **상주 꼬리 mip 수 R**(T8, 쿠킹 때 계산해 메타에 쓴다).
   - 비스트리밍(3번)이거나 N ≤ 1이면 R = N.
   - 그 밖에는 R = min(N, max(1, 형식 mip tail 수, `TextureMinResidentMipCount` = 7)). 형식 mip tail 수는 플랫폼이 작은 mip을 한 할당에 묶는 수다(타일링 플랫폼이 없어 지금은 0).
   - 블록 압축 형식(블록 4×4)은 R = max(R, N − floor(log2(X / 4)), N − floor(log2(Y / 4)))다. 스트리밍 mip은 각 축이 블록의 배수가 되고, 상주 꼬리의 가장 큰 mip은 각 축이 4 이상이 된다. 스트리밍 텍스처는 2의 거듭제곱이므로(3번) 식이 정확하다. X 또는 Y가 4보다 작으면 N ≤ 2라 첫 규칙에서 이미 R = N이다.
   - UE 5.8 `GetNumNonStreamingMipsDirect`(Developer/TextureFormat/Public/Interfaces/ITextureFormat.h 157–195, `NUM_INLINE_DERIVED_MIPS` = 7)와 같다. UE는 LOD 편향으로 자르기 전의 크기로 계산한 뒤 남은 mip 수로 자르는데, N − floor(log2(X / 4))는 자르기 전후가 같으므로 결과가 같다.
   - 7은 이름 있는 상수다. 바꾸면 쿠킹 결과가 바뀌므로 쿠커 버전을 올린다.
3. **비스트리밍**(T5). 다음이면 쿠킹이 R = N으로 써서 모든 mip을 상주 꼬리 덩어리 하나에 둔다. 스트리밍 덩어리를 만들지 않고 별도 표시 칸도 두지 않는다 — R = N이 곧 비스트리밍이다(UE와 같다: 비스트리밍이면 모든 mip을 inline으로 쓴다, TextureDerivedData.cpp 3001–3004).
   - `NeverStream`, UI 그룹, N = 1, `NoMipmaps`.
   - Cube·CubeArray(UE `GetStreamingDisabledForNonVirtualTextureProperties`, ITextureFormat.h 49–64). Volume·2DArray는 스트리밍한다(UE 기본값과 같다).
   - X 또는 Y — Volume은 Z도 — 가 2의 거듭제곱이 아닌 크기(UE Texture.cpp 1873–1877, 2026-11-24 A5j 교차 검증).
   - `MipLoadOptions` = `OnlyFirstMip`(12.4.1절과 같다).
   - `Availability` = CPU(GPU에는 placeholder만 있다).
   - TextureStreaming 4.3절의 "전체 상주 전용" 표시는 셰이더 사용에서 정하는 런타임 판정이라 쿠킹 대상이 아니다.
4. **시네마틱 mip.** 쿠킹 편향 d(12.5절 7번)에는 `NumCinematicMipLevels`를 넣지 않고, 시네마틱용으로 버릴 mip을 따로 남기지도 않는다. 시네마틱 mip은 쿠킹 결과의 상위 mip이다. 런타임은 시네마틱 pin이 아닐 때 `NumCinematicMipLevels`만큼 bias를 더해(상주 꼬리 아래로는 줄이지 않는다) 그 mip을 쓰지 않고, 시네마틱 pin일 때는 그 bias를 뺀다. `NumCinematicMipLevels`는 `StreamableRenderAsset`의 저장 설정 그대로 메타가 된다(12.1절).
   - UE 5.8 확인: 쿠킹은 `CalculateLODBias`를 `NumCinematicMipLevels` = 0으로 부른다(TextureDerivedData.cpp 2969). 쿠킹된 플랫폼에서 런타임 `CalculateLODBias`는 텍스처·그룹 LODBias를 다시 더하지 않고 `NumCinematicMipLevels`만 더한다(TextureLODSettings.cpp 262–275). 스트리밍은 강제 상주 + 시네마틱 mip 사용일 때 그만큼 뺀다(StreamingTexture.cpp 187–193, Texture.cpp 2112 주석 "ResourceLODBias almost always == NumCinematicMipLevels").
   - 예: 원본 1024, LODBias 2, `NumCinematicMipLevels` 1이면 쿠킹 상위 256, 평소 128, 시네마틱 256이다. 렌더 세션 요구안("min(NumCinematicMipLevels, 쿠킹 LOD bias)개를 남긴다")이면 쿠킹 상위 512, 평소 256, 시네마틱 512가 되어 UE와 다르다. 그래서 UE 방식으로 정했고, TextureStreaming 4.3절 문구 개정을 렌더 세션에 요청했다.
5. **bias 용어**(T1). 서로 더하지 않는 세 양이다.
   - 쿠킹 편향: 텍스처·그룹 `LODBias`와 크기 상한으로 버리는 상위 mip 수(12.5절 7번). 쿠킹 결과에 이미 반영되어 런타임이 다시 더하지 않는다.
   - 런타임 bias: 전역 bias + 예산 bias + 비시네마틱 감산(4번). TextureStreaming 4.3절 `maxMips`가 쓴다.
   - 표본 mip bias: view의 텍스처 mip bias(temporal upscaler의 음수 bias 등). 상주 계획의 표본 해상도 = 렌더 폭 × 2^(−표본 mip bias)다(TextureStreaming 4.1절). 에셋 데이터와 무관하며 쿠킹에 들어가지 않는다.
6. **시험(A5).**
   - R 표: 비압축·블록 압축 형식 × 1×1·4×4·8×8·256×256·2048×2048·2048×64.
   - 비스트리밍 조건마다 R = N이고 스트리밍 덩어리가 없음.
   - 쿠킹 편향과 `NumCinematicMipLevels` 조합의 쿠킹 상위 mip 표(4번 예 포함).
   - 덩어리 SHA-256이 쿠킹 데이터 바이트와 같음, 메타 오프셋·바이트 크기 합이 꼬리 덩어리 크기와 같음.

### 12.6 GPU 압축 조사

BC·ASTC·ETC 인코더 없음, 렌더러는 비압축만. 쿠킹은 비압축으로 완성하고 프로파일의 압축 지원은 "없음". 압축 인코더는 텍스처 파이프라인 후속 단계(사용자 결정 순서).
