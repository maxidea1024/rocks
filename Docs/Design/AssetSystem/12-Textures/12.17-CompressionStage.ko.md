### 12.17 텍스처 압축 단계 구현 세부(TC — 2026-11-26 착수 때 정함, 교차 검증 반영 개정 1)

12.16절 형식 표를 구현하는 단계다. 착수는 사용자 결정(2026-11-26 — 화면 마일스톤 SM7·SM8에서 쿠킹 비압축 텍스처가 화면에 나온 뒤, 렌더 SM9와 병행)이다. 기준은 UE 5.8 Oodle 없는 경로다: BC1–5 `TextureFormatDXT`(NVTT 2.0.8 — Quality_Production), BC6H·BC7 `TextureFormatIntelISPCTexComp`(ISPC Texture Compressor), ASTC `TextureFormatASTC`(ARM astc-encoder). 형식 선택은 `GetDefaultTextureFormatName`(Texture.cpp 4201–4489), 채널 복제는 TextureDerivedData.cpp 876–883, 알파 판정은 TextureCompressorModule.cpp 2998–3080·TextureCompressorModule.h 388–400, 압축 입력 변환은 TextureFormatDXT.cpp 506이다.

개정 1(2026-11-26, 교차 검증 필수 15·권장 8 반영): 압축 입력을 형식 선택 뒤 RGBA8로 고정(F1), 가장자리 채움을 NVTT 주기 반복으로(F2), BC3 색의 알파 가중치(F3), BC4·BC5·BC3 알파를 NVTT `compressDXT5A`로(F4), cluster fit 선택을 닫힌식 대리 오차로(F5), 끝점 순서·같은 끝점 규칙(F6), 기준 디코더(F7), 품질 기준을 NVTT 원본 golden으로(F8 — UE 클론의 NVTT 2.0.8 원본, MIT), 결정성 규칙(F9), Android 4의 배수(F10)·Normalmap 대체(F11)·Displacementmap SRGB(F12)를 UE대로 12.16절 정정, 너겟 키에 형식·인코더 버전(F13), 단계 사이 동작(F14), 샘플링 검증 전제(F15 — 렌더 요청).

#### 12.17.1 결정

- **TD1 BC1–BC5는 자체 구현 — NVTT 2.0.8 Production 경로를 옮긴다**(사용자 승인 2026-11-26: 자체 구현. 교차 검증 F8·F9: UE 클론 `Engine/Source/ThirdParty/nvTextureTools/nvTextureTools-2.0.8/src`에 원본이 있다 — MIT). 알고리즘·순서를 NVTT 스칼라(비 AVX2) 경로와 같게 옮기고, 같은 원본을 시험 probe로 빌드해 golden을 만든다(TD9). 외부 라이브러리로 링크하지 않는 이유: NVTT 2는 nvcore·nvimage·nvmath 전체를 끌고 오며 필요한 것은 블록 압축 경로 몇 파일이다. UE도 호스트(AVX2·비 AVX2 DLL)에 따라 byte가 달라 UE 자체가 byte 동일을 보장하지 않는다(squish/weightedclusterfit.cpp 137) — Rocks는 스칼라 경로 하나로 고정한다.
- **TD2 인코더 알고리즘**(NVTT CompressDXT.cpp·QuickCompressDXT.cpp·squish 대응):
  - BC1 색: 중복 색을 가중치로 묶은 집합(squish `ColourSet` minimal set — CompressDXT.cpp 224, colourset.cpp 35–)으로 시작한다. 단색 블록(알파 무시 — ColorBlock.cpp 114–128)은 최적 단색 표(SingleColorLookup — `PrepareOptTable`의 오차식 그대로)다. 그 밖은 `WeightedClusterFit`이다: 주축은 공분산의 power iteration(시작 벡터 = 노름이 가장 큰 행, 정규화는 절댓값 최대로 — NVTT maths.cpp 64–77·123의 max 나눗셈은 0·음수가 될 수 있어 abs-max로 바꾼다, Rocks 차이), 투영값 안정 정렬(동률은 texel 순서). 4색 순서 분할(n개 집합이면 C(n+3, 3) — n = 16이면 969)·3색(C(n+2, 2) — 153)마다 닫힌식 대리 오차(양자화 격자 k/31·k/63, 이상적인 1/3 보간 — weightedclusterfit.cpp 784–840)로 고른다. 실제 오차(TD7 기준 디코더의 정수 제곱합)는 마지막 후보 비교(3색 대 4색)에만 쓴다. 정련은 NVTT처럼 하지 않는다. 3색 모드는 index 3(투명 검정)을 쓰지 않는다(UE `bSupportDXT1a = false`, TextureFormatDXT.cpp 155). 채널 가중치 1:1:1(231).
  - BC3: 색은 4색 모드만이고 texel 가중치는 (a + 1)/256이다(squish `kWeightColourByAlpha` — CompressDXT.cpp 353, colourset.cpp 63·96). 단색 색 블록도 단색 표를 쓴다(347–350). 알파는 아래 DXT5A다.
  - BC4·BC5(채널마다)·BC3 알파: NVTT `QuickCompress::compressDXT5A`(CompressDXT.cpp 343·421·458, QuickCompressDXT.cpp 537–578) — 8값 모드만, min·max를 범위/34만큼 안으로 당긴 뒤 최소제곱 반복 최대 8회. 6값 모드는 쓰지 않는다(UE와 같다). BC5는 R·G를 따로 한다.
  - **끝점 순서(F6)**: 4색·8값은 e0 > e1(uint16 / uint8)로 쓴다. 양자화 뒤 끝점이 같으면 index를 모두 0으로 쓴다(squish colourblock.cpp 116–130). 3색은 e0 ≤ e1로 쓰고 index 0·1을 맞바꾼다.
- **TD3 압축 입력(F1)**: 형식 선택(12.17.2)을 12.13절 출력 단계(8번) 앞에 둔다. 고른 형식이 BC1–BC5·BC7이면 출력 단계는 원본 정밀도와 무관하게 RGBA8을 만든다(sRGB 텍스처는 색을 sRGB 부호화, 알파는 선형 — UE `CopyTo(BGRA8, GetDestGammaSpace())`, TextureFormatDXT.cpp 506). BC6H 입력은 RGBA16F다. 오차는 그 부호화 공간에서 잰다(UE와 같다). BC4 입력은 복제 뒤 R(TD6), BC5는 R·G다.
- **TD4 블록 가장자리(F2)**: 블록보다 작은 mip(하위 mip — 상위 mip은 TD8 규칙상 4의 배수)은 NVTT `ColorBlock` 주기 반복으로 채운다: 폭(높이) 1은 0,0,0,0, 2는 0,1,0,1, 3은 0,1,2,0(nvimage/ColorBlock.cpp 58–82 remainder 표). 채움 texel도 맞춤 가중치에 들어간다(NVTT와 같다). 블록 수는 ceil(w/4) × ceil(h/4)이다.
- **TD5 알파 판정**(UE `DetermineAlphaChannelTransparency` cpp 2998–3080, `GetTextureExpectsAlphaInPixelFormat` h 388–400): ForceNoAlpha면 불투명, 아니고 ForceAlpha면 투명, 아니면 원본 mip 0(모든 블록·slice)의 선형 최소 알파 ≤ 254.5/255면 투명(8비트 A ≠ 255와 같다). 원본에 알파 채널이 없으면 불투명이다. ReplicateRed 설정은 빨강 최솟값을 본다. UE는 ChromaKey·Bokeh LOD 그룹을 투명으로 강제하고 AdjustMin/MaxAlpha 등 보정을 판정 전에 적용한다 — 보정·ChromaKey는 Rocks에 아직 없으므로(12.4.1 계약) 그 단계를 구현할 때 이 판정에 넣는다. Bokeh 그룹은 TD8 비압축 조건이라 형식에 영향이 없다.
- **TD6 채널 복제 UE 대응 확정**(12.4.3 표 개정 — 그 표는 UE 5.6 공개 문서만으로 정했다): Grayscale·Alpha는 ReplicateRed(RGBA = R), Displacementmap·DistanceFieldFont는 ReplicateAlpha(RGBA = A — TextureCompressorModule.cpp 3151–3164)다. 지금 Displacementmap·DistanceFieldFont의 "빨강"은 UE와 다르다 — TC2에서 알파로 바꾼다. 원본에 알파가 없으면 결과는 1이다(UE 그대로 — UE에 경고가 없으므로 Rocks도 경고하지 않는다, R3).
- **TD7 기준 디코더(F7)**: 오차·시험·golden은 이 디코더로 잰다. BC1·BC3 색: 565 확장 `(q << 3) | (q >> 2)`(6비트는 `(q << 2) | (q >> 4)`), 4색 보간 (2a + b + 1)/3·(a + 2b + 1)/3, 3색 중간 (a + b + 1)/2(정수, D3D 참조 디코더와 같은 반올림 — TC1 설계 때 D3D 명세 문구로 확인해 적는다). BC4·BC3 알파: 8값 (k·a + (7 − k)·b + 3)/7 정수식(같은 확인). 동률은 |e0 − e1|이 작은 쪽, 그다음 탐색 순서가 앞선 쪽이다.
- **TD8 비압축 대체·마무리(F10·F11·F12·R2)**: UE `GetDefaultTextureFormatName` 순서를 그대로 쓴다(12.17.2). 4의 배수 규칙(상위 mip 한 변이 4 미만이거나 4의 배수 아님 → 비압축)은 Android(ASTC 재대응 전)에도 적용한다(Texture.cpp 4253–4263, AndroidTargetPlatformControls.cpp 509 — 12.16.2 "정렬" 문단을 정정한다). Normalmap 대체는 UE대로 `BGRA8Unorm`이다(4396–4434 — XGXR8은 DXT5n일 때만, 12.16.1 정정). SRGB를 막는 설정은 Alpha·Normalmap·Masks·HDR류뿐이고(772–777) G8 + SRGB → `BGRA8UnormSrgb`는 Displacementmap·DistanceFieldFont에도 적용한다(4444–4446 — 12.4.3·12.13 `TextureCompressionIgnoresSrgb`·12.16.1을 같이 맞춘다). G16 원본 + SRGB는 선형 `R16Unorm` 그대로다(TextureFormatUncompressed.cpp 230–232). 32F → 16F 대체(4450–4475)는 샘플링 검증 앞이다. 4채널 8비트 비압축 출력은 `BGRA8Unorm`(sRGB면 `BGRA8UnormSrgb`)이고 byte 순서는 B, G, R, A다.
- **TD9 결정성과 품질 기준(F8·F9)**:
  - 결정성: 블록 인코딩은 블록 하나의 순수 함수다. 블록 안 부동소수점은 12.13절 계산 정밀도 규칙(FMA 금지·연산 순서 고정·fast-math 금지)을 따르고, 정렬은 안정 정렬이다. 블록 범위 병렬은 제자리에 쓰므로 스레드 수와 무관하다. 이후 SIMD 최적화는 byte가 같아야 하고, 아니면 인코더 버전(TD10)을 올린다.
  - 품질: UE 클론의 NVTT 2.0.8 원본(스칼라 경로)을 저장소 밖 probe로 한 번 빌드해 시험 그림 셋(그라디언트·노이즈·사진 조각·알파 경계·노멀 — 생성기, mip 크기 1–9 포함)의 압축 byte와 PSNR을 golden으로 기록한다. 판정은 byte 동일을 목표로 하고, byte가 다른 블록 비율과 PSNR(≥ NVTT − 0.01 dB)을 시험이 단언한다(다르면 원인을 찾아 기록 — float 순서 등). 단색 블록은 단색 표와 같은 끝점이다. golden 생성 도구와 절차는 저장소에 둔다(Tools — probe 원본은 UE 클론 경로를 인자로 받는다, NVTT 원본을 저장소에 복사하지 않는다).
- **TD10 너겟 키·버전(F13)**: 고른 PixelFormat, 인코더 id(`RocksBc` 등)와 형식별 인코더 버전(UE `GetEncoderName`·`GetVersion` 대응)을 너겟 키에 넣는다. 형식은 프로필(backend 검증·32F 필터·압축 볼륨 지원·TC4 형식 계열)에 따라 달라지므로 12.14절 "프로필은 키에 넣지 않고 대상 형식은 빌드 버전으로 대신"을 이 둘로 바꾼다. TC2에서 출력 byte가 바뀌므로 `TextureBuildVersion`도 한 번 올린다. 이후 인코더만 바뀌면 그 형식 버전만 올린다.
- **TD11 단계 사이 동작(F14)**: TC2 뒤 TC3 전에는 BC7 설정이 `BGRA8Unorm(Srgb)` 대체 + 경고 `EncoderUnavailable`(detail = 원래 형식), HDR_Compressed는 12.16.1 대체 `RGBA16Float`(경고 같음)다. TC4 전 Android 프로필은 12.16.2 재대응 없이 TD8 비압축이다(BC를 Android에 내지 않는다 — 형식 계열 칸이 없으면 비압축). 12.4.3 끝의 "프로파일이 압축을 요구하면 UnsupportedSetting"은 TC2에서 지운다(압축을 하므로).
- **TD12 모든 backend 샘플링 검증(F15·R5)**: 고른 형식(대체 포함)은 프로필 `graphicsBackends`마다 샘플링 보장이어야 하고, 못 하면 다음 대체로, 마지막 대체는 backend별 보장 비압축(`RGBA8Unorm` 계열)이다. 경고 `PlatformFormatFallback`(detail = 원래 형식, 진단 related에 backend·텍스처 id). 판정 표는 쿠커가 쓸 수 있는 공개 표여야 하는데 지금 backend 대응표는 backend 모듈 Private이고 Metal 표는 SH5 전까지 없으며 Vulkan BC는 선택 기능(textureCompressionBC)이다. TC2 착수 전에 렌더 세션(rocks-20)에 GraphicsTypes 공개 "쿠킹 보장 샘플링" 표와 Vulkan·Metal 가정을 요청한다. 표가 오기 전까지 TC2는 검증을 끈 채(경고 없이) 12.16.1 표만 쓴다 — 렌더가 명확한 진단으로 실패한다(12.16.2와 같은 원칙).
- **TD13 외부 인코더(TC3·TC4 — 착수 때 세부, R8)**: BC6H·BC7은 ISPC Texture Compressor(MIT) 원본을 ThirdParty로 들여와 빌드한다(커널 컴파일용 ISPC 컴파일러는 LLVM처럼 `out/toolchains`에 받는 도구다 — 미리 만든 ispc_texcomp 라이브러리는 쓰지 않는다). ASTC는 ARM astc-encoder(Apache-2.0 — C++ 예외를 쓰지 않는 빌드 설정 확인). 품질 설정은 UE 그 모듈의 기본(ISPC BC7 프로필·astcenc preset ↔ CompressionQuality)을 따른다.

#### 12.17.2 형식 선택(TC2 — UE `GetDefaultTextureFormatName` 순서의 코드화)

입력: 유효 CompressionSettings·SRGB(TD8로 막힌 설정은 끔)·ForceAlpha·ForceNoAlpha·CompressionNone·LOD 그룹·차원, TD5 알파, 원본 형식(회색·16비트·float), 상위 mip 크기, 프로필(backend 목록·norm16·32F 필터·압축 볼륨·형식 계열). 순서:
1. 계약 밖 설정(LQ 등)은 지금처럼 `InvalidSetting`(12.8절).
2. 비압축 강제(CompressionNone, LOD 그룹 ColorLookupTable·Bokeh·IESLightProfile, 압축 볼륨 미지원 대상의 Volume)면 비압축 형식.
3. 12.16.1 표의 형식(AutoDXT = TD5 알파로 BC1·BC3, sRGB 짝 BC1·BC3·BC7).
4. BC이고 상위 mip 한 변이 4 미만이거나 4의 배수가 아니면 비압축(TD8 — 모든 플랫폼).
5. UE 마무리: G8 + SRGB → `BGRA8UnormSrgb`, 32F → 16F(필터·플랫폼).
6. TD11 단계 사이 대체(인코더 없음).
7. 형식 계열 ASTC(TC4)면 12.16.2 재대응.
8. TD12 샘플링 검증(표가 있을 때).

swizzle 칸(TexturePlatformData)은 12.16.4 (가)대로 sampler type 계약 데이터이고, UE처럼 형식이 아니라 CompressionSettings로 정한다(MaterialExpressionUtils.cpp 32–48 — R1): Grayscale·Alpha·DistanceFieldFont `rrrr`, Displacementmap `r001`, Normalmap `rg01`(BC5·대체 BGRA8 모두 — 셰이더가 Z 복원), 그 밖 항등. 12.13절이 회색 sRGB를 데이터에 복제한 뒤 항등으로 두는 지금 동작은 TC2에서 이 규칙으로 바꾼다(12.16.4 (가) — 데이터는 BGRA8 그대로, swizzle 칸만).

#### 12.17.3 단계

| 단계 | 내용 | 모듈 |
|---|---|---|
| TC1 | BC1·BC3·BC4·BC5 블록 인코더(TD1–TD4·TD7·TD9) — 공개 API(형식·채널 선택·slice·행 pitch·출력 크기 함수·allocator), NVTT golden 도구와 시험 그림 셋, 시험(golden byte·PSNR·단색·끝점 규칙·가장자리 1–9·결정성·할당 실패) | TextureTools(공개 헤더 `TextureBlockEncode.h`)·Tools |
| TC2 | 형식 선택(12.17.2)·채널 복제(TD6)·알파 판정(TD5)·비압축 대체·BGRA8(TD8)·단계 사이 대체(TD11)·쿠킹 연결(TexturePlatformData 형식·mip byte·swizzle)·너겟 키(TD10)·`TextureBuildVersion`, 12.4.3·12.13·12.16 문서 정정, TestContent 재쿠킹·렌더 알림(업로드 pitch 확인), 시험(설정 15종 × 알파 × sRGB × 원본 종류 표, 대체 조건마다, 경고) | TextureTools·Texture·TargetProfiles |

| TC4 | ASTC: astc-encoder 반입, Android 형식 계열 칸·재대응(12.16.2), 시험 | ThirdParty·TextureTools·TargetProfiles |

각 단계는 구현 전에 남은 세부(공개 API 이름·진단 코드·시험 목록)를 이 절에 더하고, 단계마다 리뷰어 하나가 교차 검증한다.
