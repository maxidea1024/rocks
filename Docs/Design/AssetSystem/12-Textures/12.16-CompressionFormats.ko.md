### 12.16 블록 압축 형식 표(개정 3 — 2026-11-26, 12.17 교차 검증의 UE 정정: Normalmap 대체·회색 sRGB·Android 4의 배수)

텍스처 압축 단계(12.6절 후속)에 앞서 쿠킹이 고르는 출력 형식을 렌더 세션(rocks-6b)과 맞춘 표다. 형식 이름과 번호는 [PixelFormat](../../PixelFormat/05-FormatList.ko.md) 5절을 따른다. 기준은 UE 5.8이다: 기본 선택은 `GetDefaultTextureFormatName`(Runtime/Engine/Private/Texture.cpp 4201–4489), Android 재대응은 `FAndroid_*TargetPlatformControls::GetTextureFormats`(AndroidTargetPlatformControls.cpp 487–670), ASTC 블록 크기는 `GetQualityFormat`(TextureFormatASTC.cpp 271–345)이다. 렌더 회신(2026-11-25)의 근거는 backend 형식 대응(D3D12·D3D11PixelFormats.cpp, VulkanFormats.cpp, GlesFormats.cpp)과 DeviceCaps다. 인코더 선택·구현 단계는 [12.17절](12.17-CompressionStage.ko.md)이다.

현재 상태(2026-11-26, 렌더 rocks-20 문의): 압축 단계 전인 지금 빌드 출력은 12.4.3절 표를 따른다 — 4채널 8비트는 `RGBA8Unorm`·`RGBA8UnormSrgb`(항등 swizzle)이고 회색 sRGB도 `RGBA8UnormSrgb`다. 이 표(회색 sRGB·비압축 대체의 `BGRA8Unorm(Srgb)` — UE와 같음)가 목표이며 코드는 압축 단계 구현 때 이 표로 맞춘다(렌더는 둘 다 받는다).

개정 1 → 2(렌더 회신): 회색 sRGB는 `BGRA8UnormSrgb`(R8 sRGB는 DXGI에 없다), 모든 backend 샘플링 검증 규칙, BC6H는 Ufloat만(음수는 0), D3D11 프로필의 항등 swizzle 요구, Android는 ASTC 하나(ETC2는 후속 Multi), ASTC HDR 기본 꺼짐, Android 볼륨은 비압축, ASTC 정렬, Mac은 BC 표.

#### 12.16.1 데스크톱(BC — Windows·Mac) — CompressionSettings별 기본 형식

| CompressionSettings | 알파 없음 / 있음 | 비고(UE) |
|---|---|---|
| Default·Masks | `BC1Unorm` / `BC3Unorm`(AutoDXT) | CompressionNoAlpha면 늘 BC1, CompressionForceAlpha면 늘 BC3. 알파 판정은 원본 알파 채널의 실제 값(UE DetectAlpha) |
| Normalmap | `BC5Unorm` | RG를 그대로 쓰고 Z는 셰이더가 RG에서 복원한다. UE의 DXT5n(`Compat.UseDXT5NormalMaps` — BC3 + R→A swizzle)은 두지 않는다 |
| Grayscale·Displacementmap | `R8Unorm`(원본 G16이면 `R16Unorm`) — 비압축 | 8비트 원본 + sRGB면 `BGRA8UnormSrgb`(UE GrayscaleSRGB 꺼짐과 같다 — DXGI에 R8 sRGB가 없고 Vulkan·GLES는 선택 기능, Texture.cpp 4444–4446). G16 원본 + sRGB는 선형 `R16Unorm` 그대로다(TextureFormatUncompressed.cpp 230–232 — 12.17 TD8) |
| Alpha | `BC4Unorm` | |
| DistanceFieldFont | `R8Unorm` — 비압축 | sRGB면 `BGRA8UnormSrgb`(Grayscale과 같다 — UE가 SRGB를 막는 설정은 Alpha·Normalmap·Masks·HDR류뿐이다, Texture.cpp 772–777) |
| HDR | `RGBA16Float` — 비압축 | |
| HDR_F32 | `RGBA32Float` — 비압축 | 필터가 Point가 아니고 플랫폼이 32F 필터링을 못 하면 `RGBA16Float` |
| HDR_Compressed | `BC6HUfloat` | Ufloat만 둔다(PixelFormat에 Sfloat 없음 — UE PF_BC6H UF16). 음수 입력은 0으로 자른다(UE와 같다). 압축을 못 하면 `RGBA16Float` |
| BC7 | `BC7Unorm` | |
| HalfFloat | `R16Float` — 비압축 | |
| SingleFloat | `R32Float` — 비압축 | HDR_F32와 같은 32F 대체 |
| VectorDisplacementmap | `BGRA8Unorm` — 비압축 | |
| LQ | — | Rocks는 받지 않는다(12.8절 InvalidSetting 그대로 — UE는 BC1·BC3 또는 R5G6B5·A1RGB555) |
| EditorIcon·EncodedReflectionCapture | 비압축 `BGRA8Unorm`(HDR 원본이면 `RGBA16Float`) | |

공통 규칙:
- 비압축으로 바꾸는 조건(UE와 같음): 쿠킹 뒤 상위 mip 한 변이 4 미만이거나 4의 배수가 아님(BC — D3D 요구), CompressionNone, LOD 그룹 ColorLookupTable·Bokeh·IESLightProfile, 압축 볼륨을 지원하지 않는 대상의 VolumeTexture. 바꾼 형식은 HDR_Compressed·HDR 원본이면 `RGBA16Float`, 회색 원본 + Grayscale·Displacementmap이면 `R8Unorm`·`R16Unorm`(8비트 + sRGB면 `BGRA8UnormSrgb`), 그 밖(Normalmap 포함 — UE는 `BGRA8Unorm`이고 XGXR8은 DXT5n일 때만, Texture.cpp 4396–4434)은 `BGRA8Unorm`이다(개정 3 — 12.17 교차 검증 F11: 전에는 Normalmap을 비압축 RG로 적어 UE와 달랐다).
- sRGB 짝: BC1·BC2·BC3·BC7은 `…UnormSrgb` 짝을 쓴다(srgb 켠 텍스처). BC4·BC5·BC6H는 sRGB가 없다(UE도 같다 — 그 설정들은 srgb를 끈다).
- **모든 backend 샘플링 검증(렌더 요구)**: 고른 형식(재대응 뒤 결과 포함)은 프로필 `graphicsBackends`의 모든 backend가 샘플링할 수 있어야 한다. 못 하면 비압축 대체로 떨어뜨리고 경고 진단을 남긴다(텍스처 id·고른 형식·backend). 판정은 PixelFormat 7절 FormatCaps와 8절 backend 대응으로 한다. 정적 표가 모자라면 렌더 쪽이 backend별 "보장 샘플링" 표를 GraphicsTypes에 공개한다(구현 때 요청).
- **swizzle(렌더 요구)**: view swizzle은 D3D12·Vulkan·GLES에만 있고 D3D11에는 없다(DeviceCaps.textureViewSwizzle — 항등이 아니면 Unsupported). D3D11이 든 프로필(Windows)의 형식은 항등 swizzle이어야 한다 — 12.16.4 열린 항목(지금의 단일 채널 출력 swizzle).
- Mac 프로필은 이 BC 표를 그대로 쓴다(Metal은 Apple silicon·Intel 모두 BC 지원). iOS(ASTC)는 Metal 단계 때 정한다.
- Availability CPU(자리표시) 텍스처는 UE `BC1Unorm` — Rocks는 Availability를 기록만 하므로(12.4.1절) 해당 없음.

#### 12.16.2 Android — ASTC

Android 프로필은 ASTC 하나로 쿠킹한다(UE5 기본 Android_ASTC와 같다 — 지금 backend는 GLES31_ANDROID 하나이고 ES 3.1 이상 기기는 ASTC LDR이 사실상 모두 있다). 렌더는 ASTC LDR이 없는 기기에서 시작할 때 명확한 진단으로 실패한다.

- 재대응(UE `FAndroid_ASTCTargetPlatformControls`): AutoDXT → ASTC 자동(알파에 따라 RGB·RGBA), BC1 → ASTC RGB, BC3 → ASTC RGBA, BC7 → ASTC RGBA HQ, BC5 → ASTC 노멀(RG), BC4 → ASTC 한 채널.
- 블록 크기는 CompressionQuality로 정한다(UE ETextureCompressionQuality): Medium `ASTC8x8`, High `ASTC6x6`(기본), Highest `ASTC4x4`. 노멀은 늘 `ASTC6x6`이다. ASTC 노멀의 채널 배치(rrrg 등)는 TexturePlatformData swizzle로 X→R, Y→G가 되게 기록한다 — GLES·Vulkan은 view swizzle로 적용하므로 셰이더는 늘 `.rg`를 읽는다.
- ASTC HDR은 기본 꺼짐이다(GLES `KHR_texture_compression_astc_hdr`·Vulkan 선택 기능 — UE bSupportsASTCHDR 꺼짐과 같다). HDR_Compressed는 `RGBA16Float`로 대체한다. 켜는 것은 나중에 프로필 칸으로 둔다.
- VolumeTexture는 비압축(`RGBA8Unorm`·`RGBA16Float`)이다. GLES 3.x는 ETC2·EAC를 TEXTURE_3D에 쓸 수 없고(2D·2D_ARRAY만) ASTC 3D는 sliced_3d나 hdr 확장이 있어야 한다. GLES backend도 3D에는 비압축 색 형식만 공개한다(GlesFormats.cpp 335). UE의 "볼륨은 ETC2" 대체와 다르다.
- 정렬: 4의 배수 규칙(상위 mip 한 변이 4 미만이거나 4의 배수 아님 → 비압축)은 Android에도 적용한다 — UE는 그 검사를 플랫폼과 무관하게 `GetDefaultTextureFormatName`에서 하고 Android는 그 뒤 ASTC로 재대응한다(Texture.cpp 4253–4263, AndroidTargetPlatformControls.cpp 509·542–). 개정 3 정정: 전에는 "ASTC에는 적용하지 않는다 — UE 4260 주석"이라 적었으나 그 주석은 쓰이지 않는 BlockSize 인자의 설명이었다(12.17 교차 검증 F10). 업로드는 ceil(블록 수) pitch로 계산한다(렌더). streaming bulk 정렬 max(프로필, 4096)는 그대로다.
- **후속(Multi)**: ETC2 재대응(UE `FAndroid_ETC2TargetPlatformControls` ETCRemap — BC1 → `ETC2RGB8Unorm`, BC3 → `ETC2RGBA8Unorm`, BC5 → `EACRG11Unorm`, BC4 → `EACR11Unorm`, BC7 → ETC2 RGBA, BC6H → `RGBA16Float`)는 지금 쿠킹하지 않는다. ASTC + ETC2를 한 쿠킹에 두는 Multi를 할 때 쓴다. ETC2 sRGB 짝(`ETC2RGB8UnormSrgb`·`ETC2RGBA8UnormSrgb`)은 GLES core·Vulkan 대응이 있다.

#### 12.16.3 형식 선택의 위치

데스크톱 기본 표(12.16.1)는 코드다(UE 함수 대응). 플랫폼 재대응(12.16.2)은 TargetProfile 칸이다(UE TargetPlatform 코드 대신 데이터). 모든 backend 샘플링 검증은 재대응 결과에도 적용한다.

#### 12.16.4 아직 열린 것

- **단일 채널 출력의 swizzle과 D3D11 — (가)로 확정(2026-11-25 렌더 세션)**: 쿠킹은 그대로 두고 셰이더가 sampler type에 따라 복제한다. 단일 채널 swizzle과 노멀 채널 배치는 모든 backend에서 view swizzle로 적용하지 않는다(backend마다 결과가 갈리거나 이중 적용되지 않게 — UE MaterialTexture.ush의 SAMPLERTYPE별 복제, GLES·Vulkan LA 노멀 셰이더 define과 같다). TexturePlatformData swizzle은 "sampler type 계약" 데이터이고 렌더러는 view swizzle을 항등으로 둔다. ASTC 노멀도 셰이더 쪽이다(UE LA_NORMALMAPS) — 쿠킹은 swizzle 칸에 채널 배치만 정확히 기록한다. 같이 고친 것: UE 5.8 계약에 맞춰 Grayscale·Alpha·DistanceFieldFont를 `.rrrr`로(12.4.3절 — 전에는 rrr1·r001), Displacementmap은 Color sampler라 r001 그대로. 렌더 쪽(RenderBase·머티리얼 문서, 텍스처 inspector 셰이더)은 SM7에서 이 규칙으로 고친다.
- 인코더: BC1–5는 자체 구현이 가능한 크기지만 BC6H·BC7·ASTC는 외부 라이브러리가 필요하다(UE는 Oodle Texture·ISPC Texture Compressor·ARM astc-encoder). Oodle은 쓸 수 없으므로 후보는 ISPC Texture Compressor(BC6H·BC7)와 ARM astc-encoder(ASTC)다 — 선택은 별도 절.
- 압축 출력의 결정성(같은 입력 → 같은 byte, 플랫폼·스레드 수 무관 — 쿠킹 결정성)과 그 검증. 렌더는 쿠킹 byte를 그대로 올리므로 따로 요구가 없다.
