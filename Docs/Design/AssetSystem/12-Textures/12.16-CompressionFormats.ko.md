### 12.16 블록 압축 형식 표(초안 — 2026-11-25, 렌더 세션 합의 전)

텍스처 압축 단계(12.6절 후속)에 앞서 쿠킹이 고르는 출력 형식을 렌더 세션(rocks-6b)과 맞추려는 초안이다. 형식 이름과 번호는 [PixelFormat](../../PixelFormat/05-FormatList.ko.md) 5절을 따른다. 기준은 UE 5.8이다: 기본 선택은 `GetDefaultTextureFormatName`(Runtime/Engine/Private/Texture.cpp 4201–4489), Android 재대응은 `FAndroid_*TargetPlatformControls::GetTextureFormats`(AndroidTargetPlatformControls.cpp 487–670), ASTC 블록 크기는 `GetQualityFormat`(TextureFormatASTC.cpp 271–345)이다. 렌더 세션은 플랫폼·backend별 지원(블록 크기, sRGB 짝, ASTC HDR, BC6H 부호)을 붙여 회신하기로 했다. 합의가 끝나면 이 절을 확정하고 인코더 선택·구현 단계를 따로 적는다.

#### 12.16.1 데스크톱(BC) — CompressionSettings별 기본 형식

| CompressionSettings | 알파 없음 / 있음 | 비고(UE) |
|---|---|---|
| Default·Masks | `BC1Unorm` / `BC3Unorm`(AutoDXT) | CompressionNoAlpha면 늘 BC1, CompressionForceAlpha면 늘 BC3. 알파 판정은 원본 알파 채널의 실제 값(UE DetectAlpha) |
| Normalmap | `BC5Unorm` | UE는 `Compat.UseDXT5NormalMaps` 설정이면 DXT5n(BC3 + R→A swizzle). Rocks는 BC5만 둔다(제안) |
| Grayscale·Displacementmap | `R8Unorm`(원본 G16이면 `R16Unorm`) — 비압축 | sRGB면 UE는 `BGRA8`로 바꾼다(GrayscaleSRGB가 모든 대상에서 꺼져 있음). Rocks는 `R8UnormSrgb`가 있으므로 그것을 제안(렌더 지원 확인) |
| Alpha | `BC4Unorm` | |
| DistanceFieldFont | `R8Unorm` — 비압축 | |
| HDR | `RGBA16Float` — 비압축 | |
| HDR_F32 | `RGBA32Float` — 비압축 | 필터가 Point가 아니고 플랫폼이 32F 필터링을 못 하면 `RGBA16Float` |
| HDR_Compressed | `BC6HUfloat` | 압축을 못 하면 `RGBA16Float` |
| BC7 | `BC7Unorm` | |
| HalfFloat | `R16Float` — 비압축 | |
| SingleFloat | `R32Float` — 비압축 | HDR_F32와 같은 32F 대체 |
| VectorDisplacementmap | `BGRA8Unorm` — 비압축 | |
| LQ | `BC1Unorm` / `BC3Unorm` | LQ 형식을 지원하는 플랫폼은 R5G6B5·A1RGB555(UE). Rocks는 받지 않는다 — 12.8절 InvalidSetting 그대로 |
| EditorIcon·EncodedReflectionCapture | 비압축 `BGRA8Unorm`(HDR 원본이면 `RGBA16Float`) | |

공통 규칙(UE와 같음):
- 압축 형식을 골랐어도 다음이면 비압축으로 바꾼다: 쿠킹 뒤 상위 mip 한 변이 4 미만이거나 4의 배수가 아님, CompressionNone, LOD 그룹 ColorLookupTable·Bokeh·IESLightProfile, 압축 볼륨을 지원하지 않는 대상의 VolumeTexture. 바꾼 형식은 Normalmap이면 BC5 대신 비압축 RG, HDR_Compressed·HDR 원본이면 `RGBA16Float`, 회색 원본 + Grayscale·Displacementmap이면 `R8Unorm`·`R16Unorm`, 그 밖은 `BGRA8Unorm`이다.
- sRGB 짝: BC1·BC2·BC3·BC7은 `…UnormSrgb` 짝을 쓴다(srgb 켠 텍스처). BC4·BC5·BC6H는 sRGB가 없다(UE도 같다 — 그 설정들은 srgb를 끈다).
- Availability CPU(자리표시) 텍스처는 `BC1Unorm`(UE NameDXT1) — Rocks는 Availability를 기록만 하므로(12.4.1절) 해당 없음.

#### 12.16.2 Android — ASTC·ETC2 재대응

- ASTC 대상(UE `FAndroid_ASTCTargetPlatformControls`): 데스크톱 이름을 ASTC 이름으로 바꾼다 — AutoDXT → ASTC 자동(알파에 따라 RGB·RGBA), BC1 → ASTC RGB, BC3 → ASTC RGBA, BC7 → ASTC RGBA HQ, BC5 → ASTC 노멀(RG 또는 LA), BC6H → ASTC HDR(대상이 ASTC HDR을 지원할 때, 아니면 대체 형식), BC4 → ASTC 한 채널. VolumeTexture는 ASTC 대신 ETC2(UE — 일부 기기의 ASTC 볼륨 결함).
- ASTC 블록 크기는 CompressionQuality로 정한다(UE ETextureCompressionQuality): Medium `ASTC8x8`, High `ASTC6x6`(기본), Highest `ASTC4x4`. 노멀은 늘 `ASTC6x6`(+ RG swizzle). HDR도 같은 단계(`ASTC8x8Hdr`·`ASTC6x6Hdr`·`ASTC4x4Hdr`).
- ETC2 대상(UE `FAndroid_ETC2TargetPlatformControls` ETCRemap): BC1 → `ETC2RGB8Unorm`, BC3 → `ETC2RGBA8Unorm`, AutoDXT → 알파에 따라 둘 중 하나, BC5 → `EACRG11Unorm`, BC4 → `EACR11Unorm`. BC6H·BC7은 대체(BC7 → ETC2 RGBA, BC6H → `RGBA16Float`).
- 렌더 세션에 물을 것: Android 프로필이 ASTC 하나인지 ASTC + ETC2 둘(UE Multi — 한 쿠킹에 두 형식)인지, ASTC HDR 지원 범위, ETC2 sRGB 짝 사용, ASTC 정렬(블록 배수가 아니어도 되므로 4의 배수 규칙을 ASTC에는 적용하지 않음 — UE 4260 주석).

#### 12.16.3 아직 열린 것

- 형식 선택을 TargetProfile 칸으로 둘지(플랫폼별 재대응 표 — UE TargetPlatform 코드 대신 데이터) 코드 표로 둘지. 제안: 데스크톱 기본 표는 코드(UE와 같은 함수), 플랫폼 재대응은 프로필 칸.
- 인코더: BC1–5는 자체 구현이 가능한 크기지만 BC6H·BC7·ASTC·ETC2는 외부 라이브러리가 필요하다(UE는 Oodle Texture·ISPC Texture Compressor·ARM astc-encoder·etc2comp). Oodle은 쓸 수 없으므로 후보는 ISPC Texture Compressor(BC6H·BC7·ETC1), ARM astc-encoder(ASTC), etc2comp 또는 ETCPACK(ETC2)이다 — 선택은 합의 뒤 별도 절.
- 압축 출력의 결정성(같은 입력 → 같은 byte, 플랫폼·스레드 수 무관 — 쿠킹 결정성)과 그 검증.
