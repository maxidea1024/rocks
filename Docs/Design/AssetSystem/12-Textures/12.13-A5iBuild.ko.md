### 12.13 A5i 구현 명세 — 텍스처 빌드(2026-11-24 — 교차 검증 1차 반영)

이 절은 12.5절 빌드 규칙을 TextureTools 함수로 구현하는 방법을 정한다(12.7절 A5i).
- 규칙 자체(적용 순서·재표본 필터·최대 크기·mip·쿠킹 편향)는 12.5절, 색 해석·출력 부호화·양자화는 12.2절 1–5번, 출력 형식·swizzle은 12.4.3절이다.
- 교차 검증에서 12.5절 처음 판의 다섯 곳이 UE 5.8과 결과가 달랐다(홀수 크기 평균·Stretch 반올림·Volume Z·MaxTextureSize와 편향의 합성·재표본 필터). 그래서 12.5절을 UE에 맞춰 개정했고 이 절은 개정판을 구현한다.
- 이 절은 코드로 옮길 때 남는 선택(입력·출력 구조, 계산 정밀도, 채널 배치, 진단, 시험)을 정한다.
- 빌드는 순수 함수다. 패키지·Registry·프로파일을 모른다. 쿠킹(A5j)이 텍스처 객체와 프로파일 LOD 그룹에서 입력을 만들고 결과를 `TexturePlatformData`로 옮긴다.

**API**(TextureTools `TextureTools/TextureBuild.h`):
- `TextureLodGroupValues`: 빌드가 쓰는 LOD 그룹 값이다(12.4.5절 구현 행의 부분집합).
  - 기본값은 UE `FTextureLODGroup` 멤버 기본값이다(TextureLODSettings.h): `minLodSize` 1, `maxLodSize` 4096, `lodBias` 0, `mipGenSettings` SimpleAverage.
  - 프로파일 표·필터·aniso·로드 옵션은 A5j가 더한다(샘플러는 빌드 결과가 아니다).
- `TextureBuildSettings`: 유효 설정이다(텍스처 값 + 그룹 값을 합친 결과 — 아래 해석 규칙).
- `ResolveTextureBuildSettings(texture, dimension, group, out, result) → Result<void>`: 텍스처 객체 값에서 유효 설정을 만든다.
  - texture는 dimension의 클래스여야 한다(호출자 계약 — 클래스별 주소 필드를 읽는다).
  - 계약 설정 판정(`CheckTextureSettings`)은 Registry가 필요하므로 호출자(A5j)가 먼저 한다. 이 함수는 그룹 값의 계약 판정만 한다(그룹 `mipGenSettings`가 SimpleAverage·NoMipmaps·Unfiltered 밖이면 `UnsupportedSetting`).
- `BuildTexture(allocator, settings, sourcePixels, out) → Result<void>`: 원본 정규 픽셀(TextureSource bulk raw byte)을 쿠킹 mip으로 만든다. 쿠킹 편향(12.5절 7번)으로 버릴 상위 mip은 결과에 넣지 않는다.
- `TextureBuildResult`:
  - `pixelFormat`(GraphicsTypes `PixelFormat`), `srgb`(sRGB 형식인지), `swizzle[4]`(R·G·B·A — `TextureSwizzle`).
  - `mips`: 상위 mip부터. mip마다 `sizeX`·`sizeY`·`sizeZ`(Volume 깊이, 그 밖 1)와 byte(slice·면을 차례로 이은 형식 texel — 행 사이 패딩 없음, 위에서 아래).
  - `numSlices`(Volume 1, 그 밖 원본 slice 수).
  - `warnings`(`SrgbIgnored`·`PreserveBorderWithWrap` — 각 한 번), `failure`(code·error·detail).
- `TextureCompressionIgnoresSrgb(compression)`: SRGB를 막는 종류인지다(UE `bPreventSRGB` — Normalmap·Masks·Alpha·HDR·HDR_Compressed·HalfFloat·SingleFloat·HDR_F32, 2026-11-27 TC2에서 UE 목록으로 고침 — 전에는 Displacementmap·VectorDisplacementmap·DistanceFieldFont도 넣었다).
- 새 진단 `SrgbIgnored`·`PreserveBorderWithWrap`(경고 — 4.6절 이름 그대로 `AssetDiagnosticCode`에 더한다).

**유효 설정 해석**(`ResolveTextureBuildSettings`):
- 원본: format Invalid·크기 0이면 `InvalidSource`다. slice 수 규칙은 Texture2D 1, TextureCube 6, TextureCubeArray 6의 배수(≥ 6), 2DArray·Volume 1 이상이고, 어기면 `InvalidSource`(detail = slice 수)다.
- `mipGenSettings` FromTextureGroup은 그룹 값이 된다(UE TextureLODSettings.cpp 408–413). 결과는 SimpleAverage·NoMipmaps·Unfiltered 셋 중 하나다.
- `availability` CPU인 Texture2D는 NoMipmaps다(UE `GetTextureBuildSettings`의 CPU 접근 블록).
- `lodBias`는 텍스처 값 + 그룹 값이다. `maxTextureSize`는 텍스처 값 그대로다.
- 주소: Texture2D는 addressX·Y, 2DArray는 X·Y·Z, Volume은 addressMode(세 축), Cube·CubeArray는 Clamp다(12.4.2절). 주소는 mip 생성의 주소 방식(12.5절)과 PreserveBorder 경고만 바꾼다 — 재표본은 늘 clamp다.
- `normalizeNormals`는 `compressionSettings`가 Normalmap일 때만 켠다(UE `bNormalizeNormals && IsNormalMap()`).
- `powerOfTwoMode` ResizeToSpecificResolution은 Texture2D만 받는다. 그 밖 클래스는 `InvalidSetting`이다. 정규화(12.12절)가 저장 값을 None으로 바꾸므로 교환으로 들어온 값만 걸린다.
- 숨김 CompressionSettings(LQ·EncodedReflectionCapture)는 `InvalidSetting`이다.

**계산 정밀도**(결정성 — 같은 입력이면 모든 호스트에서 같은 byte, 그리고 UE와 같은 연산 순서):
- 작업 픽셀은 float32 RGBA다. 회색 원본(G8·GA8·G16·GA16)은 r = g = b, R16F·R32F는 (v, 0, 0, 1)(UE `CopyImage` — 2026-11-25 A5j2b에서 고쳤다, 12.14절), 알파가 없으면 1이다.
- mip 평균·PreserveBorder는 UE와 같은 float 식이다(2×2 상자 ((A + B) + C) + D) × 0.25, Volume (a + b) × 0.5, 테두리 합 / 개수).
- 재표본 필터는 double로 누적하고 결과를 float로 반올림해 저장한다. 가중치는 double 커널 값을 모두 구한 뒤 그 합으로 나눈다(순서 고정). 법선 재정규화는 UE처럼 double이다(`sqrt`는 IEEE 정확 반올림).
- 곱셈과 덧셈은 별도 문장으로 써서 FMA로 합쳐지지 않게 한다. 부동소수 제어 상태(FTZ·DAZ)에 기대지 않는다 — subnormal도 IEEE 그대로 다룬다.
- 초월 함수는 DeterministicMath만 쓴다: `SrgbByteToLinear`·`SrgbToLinear`·`Gamma22ToLinear`·`LinearToSrgbByte`. CRT `pow`·`sin`은 쓰지 않는다.
- 16F 변환은 Core `Float16`(round-to-nearest-even — 12.2절 5번)이다. 시험이 하드웨어 경로(F16C)와 소프트웨어 경로가 같은 byte인지 subnormal·NaN 입력으로 본다.
- texel마다 독립이다(병렬화해도 같은 결과 — 지금은 단일 스레드).

**단계별 규칙**(12.5절 1–8번 순서):
1. 선형화(12.2절 1번):
   - `encodingOverride` Linear는 모든 정수 원본을 선형으로, sRGB는 모든 정수 원본을 sRGB 구간 함수로 읽는다.
   - None이면 8비트 원본(G8·GA8·RGBA8)은 `srgb` on일 때 `useLegacyGamma ? Gamma22ToLinear : SrgbByteToLinear`, off일 때 v / 255다. 16비트 원본은 v / 65535(SRGB와 무관)다.
   - float 원본은 그대로다(override도 적용하지 않는다). 알파는 언제나 선형(v / 최대)이다.
2. (12.5절 개정 — flipGreen은 4a번으로 옮겼다.)
3. `powerOfTwoMode`: 12.5절 3번. 재표본은 AdaptiveSharp(12.5절 "크기 조정 필터" — 같은 길이 축은 복사, 결과를 자르지 않는다).
4. 최대 크기: 12.5절 4번. 2×2 단계 경로도 `mipGenSettings`(Unfiltered)를 따른다(UE GenerateMipChain).
4a. `flipGreenChannel`: 12.5절 4a번(g → 1 − Clamp(g, 0, 1)).
5·6. mip 사슬·PreserveBorder·NormalizeNormals: 12.5절 5·6번과 mip 규칙. PreserveBorder가 켜져 있고 쓰는 축 주소 중 하나가 Wrap이면 `PreserveBorderWithWrap` 경고(한 번)다.
7. 쿠킹 편향: 12.5절 7번. 버린 mip은 만들되 결과에 넣지 않는다.
8. 출력(2026-11-27 TC2 개정 — 12.17.5절 2·3번이 정본): NormalizeNormals 뒤 채널 복제(Grayscale·Alpha는 RGBA = R, Displacementmap·DistanceFieldFont는 RGBA = A — 모든 mip), AutoDXT면 사슬 mip 0의 알파 판정(최소 알파 ≤ 254.5/255), 형식 선택(`SelectTextureFormat` — 쿠킹 상위 mip 크기는 `TextureBuildTopMipSize`), 출력 부호화다. 비압축은 형식의 byte 배치(BGRA8은 B, G, R, A)이고, BC는 RGBA8을 만들어 `EncodeTextureBlocks`로 압축한다. 전 판의 RG8·RG16·RGBA16Unorm 출력과 R8·RG8의 sRGB 확장은 없어졌다(UE에 없는 출력).
   - 양자화는 12.2절 5번이다.

**규모**: 작업 픽셀은 texel당 16 B다. 작업 단계 하나(PowerOfTwo 뒤 크기 × slice)가 `TextureBuildMaxWorkingBytes`(4 GiB — 16384² RGBA32F)를 넘으면 할당 전에 `InvalidSource` + CapacityExceeded다. Pad 대상 크기로 먼저 판정한다(예: 16385 → 32768² = 16 GiB는 거부). 곱셈은 넘침 검사한다.

**진단**(`failure` — 반환 오류와 같은 error):
- `InvalidSource`: 원본 없음(format Invalid·크기 0), 픽셀 byte 수가 sizeX × sizeY × slices × texel과 다름(detail = byte 수), slice 수 규칙, Cube 면 비정사각, 작업 byte 상한(CapacityExceeded).
- `InvalidSetting`: Resize가 Cube 정사각을 깸, 비 2D Resize, 숨김 CompressionSettings.
- `UnsupportedSetting`: 그룹 mipGen이 계약 값.
- `None` + OutOfMemory: 할당 실패.

**UE와 다른 곳**(12.5절에 적은 것 — 빌드 때 UE 결과와 대조):
- Volume Stretch의 Z(UE는 Z를 올리고 채우지 못한다 — Rocks는 Z 그대로).
- `bUseNewMipFilter` false 텍스처(Rocks는 늘 새 경로).
- 재표본 byte 일치는 stb_image_resize2와의 대조로 확인한다(14.1.99절). stbir는 가중치 합이 1에서 `stbir__small_float` 이상 벗어날 때만 다시 나누고(stb_image_resize2.h 3564–3572), float로 계산하며, 두 축 중 먼저 할 축을 비용으로 고른다 — Rocks는 double 누적·늘 정규화·X 먼저라 마지막 bit가 다를 수 있다.
- PreserveBorder + Wrap 경고(Rocks 추가).
- `Availability` CPU: UE는 GPU 쪽에 placeholder mip 하나를 두고 원본을 CPU 사본으로 둔다(TextureCompressorModule.cpp 3675–3685). 빌드는 NoMipmaps mip 0을 내고, placeholder·CPU 사본 배치는 쿠킹(A5j)이 정한다.
- 16384를 넘는 Resize·Stretch + LODBias: UE는 플랫폼 상한으로 줄인 MaxTextureResolution을 `<< LODBias`로 되올린다(TextureDerivedData.cpp 838–851). Rocks는 16384로 줄인 뒤 편향을 그대로 적용한다(드문 경우 — 차이로 둔다).
- 8비트 선형 디코딩(v / 255)과 알파는 double 나눗셈 뒤 float다. UE `ReinterpretAsLinear`의 float 식과 마지막 bit가 다를 수 있다(대조 대상).

**버린 대안**:
- 12.5절 처음 판의 규칙 유지(홀수 3탭 평균·Lanczos3·d = max): 흔한 입력에서 UE와 픽셀·크기가 달라진다. 사용자 방침(UE 텍스처 동등성)에 맞추어 UE로 바꿨다.
- stb_image_resize2를 ThirdParty로 들여와 그대로 쓰기: SIMD 경로가 호스트마다 다른 byte를 낼 수 있어 결정성을 보장하기 어렵다. 같은 식을 결정적으로 구현하고 UE 결과와 대조한다.
- 작업 픽셀을 원본 채널 수대로 두기: 단계마다 채널 분기가 늘어난다. RGBA float 하나로 두고 출력에서 고른다.

**시험(A5i)**:
- mip 픽셀 표: 4×4·5×3·1×7·3×1(2×2 상자 — 홀수 끝 버림, 길이 1 축)·Volume 2×2×2·3×3×3(slice 평균)·2DArray, Unfiltered.
- PowerOfTwoMode: Pad(색 sRGB 디코딩·테두리·Volume Z·Square 세 축), Stretch(올림 — 3 → 4, 5 → 8), Square, Resize 0 축.
- 재표본 기준값 표: Catmull-Rom 확대·Mitchell 축소·같은 길이 축의 Mitchell, 정수 출력 자르기, float 출력 음수 유지.
- 최대 크기: 4096 → MaxTextureSize 1024 재표본 한 번, PreserveBorder·Volume은 2×2 단계.
- 쿠킹 편향 표: LODBias 합·음수, MaxTextureSize + LODBias(4096·1024·1 → 512), 그룹 MaxLODSize·MinLODSize(2의 거듭제곱 아님 — CeilLog2, Min > Max), NoMipmaps(그룹 MaxLODSize 무시), Volume(X·Y만).
- 선형화: override 셋 × SRGB × legacy gamma × 원본 정밀도, 알파 선형, flipGreen.
- 출력: CompressionSettings 15종 × 원본 G8·GA8·RGBA8·G16·RGBA16·R16F·RGBA32F의 형식·swizzle·채널 값, G16·RGBA16 × SRGB on(16비트 출력·경고 없음), sRGB 출력(RGBA8·R8·RG8 확장), SrgbIgnored, HDR_Compressed 알파 1, 양자화 경계(0.5/255·NaN·Inf·65504 넘음).
- PreserveBorder(테두리 평균·Wrap 경고)·NormalizeNormals(mip 0 포함 후처리, 길이 0, 제곱합 1).
- 해석: FromTextureGroup, LODBias 합, Availability CPU → NoMipmaps, NormalizeNormals는 Normalmap만, 클래스별 주소.
- 진단: 원본 없음·byte 수·slice 수·Cube 비정사각·Resize 정사각 깸·비 2D Resize·숨김 CompressionSettings·그룹 계약 mipGen·작업 byte 상한, 할당 실패 전수.
- 결정성: 같은 입력 두 번 같은 byte, Float16 하드웨어·소프트웨어 경로 같음.
- 빌드 때: UE 결과 대조 픽스처(재표본·mip·편향).
