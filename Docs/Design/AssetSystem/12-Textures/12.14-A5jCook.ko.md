### 12.14 A5j 구현 명세 — 텍스처 쿠킹(2026-11-24, 착수 전)

이 절은 12.7절 A5j(TargetProfile 텍스처 칸·텍스처 쿠킹 처리기·`TexturePlatformData`·에셋 원본 묶음)의 구현 방법을 정한다.
- 처리기 틀은 10.2절 결정 6이다(`CookProcessor` — 대표 에셋 타입의 가장 가까운 등록 처리기).
- 너겟 키 구성은 9절 텍스처 표, Record 규칙은 9.1절이다.
- 빌드는 A5i(12.13절), 스트리밍 메타는 12.5.1절, LOD 그룹은 12.4.5절이다.
- 둘로 나눈다. **A5j1**은 프로파일 텍스처 칸, 처리기, 플랫폼 데이터, 너겟, 호스트 연결이다. **A5j2**는 에셋 원본 묶음(`SourceTextures`·`Source2DTexture` — Build 의존)이다.

#### A5j1

**TargetProfile 텍스처 칸**(AssetCooker `CookConfig.h` — A4f에서 TargetProfiles 모듈로 옮겨질 때 같이 옮긴다):
- `textureLodGroups`(`OrderedMap<TextureGroup, TextureLodGroup>`): UE `FTextureLODGroup`(12.4.5절 구현 행). struct `TextureLodGroup`의 칸과 기본값은 UE 멤버 기본값(TextureLODSettings.h)이다.
  - `minLodSize` 1, `maxLodSize` 4096, `lodBias` 0, `mipGenSettings` SimpleAverage, `maxAniso` 0(전역 값), `highPriorityLoad` false, `mipLoadOptions` AllMips, `cookPlatformTilingDisabled` false.
  - `minMagFilter`(enum `TextureLodMinMagFilter` Point·Linear·Aniso — 기본 Aniso)·`mipFilter`(enum `TextureLodMipFilter` Point·Linear — 기본 Point). UE는 FName 문자열이다. Rocks는 같은 세 값의 enum으로 둔다.
  - 표에 없는 그룹은 기본값 struct다(UE도 정의하지 않은 그룹은 멤버 기본값이다).
  - 샘플러 필터는 두 값의 조합이다(12.4.5절 표: point → Point, linear·point → Bilinear, linear·linear → Trilinear, aniso·point → AnisotropicPoint, aniso·linear → AnisotropicLinear). 처음 판의 "Filter만 적기"는 받지 않는다. UE 설정도 MinMagFilter·MipFilter로 적고, 한 값을 두 곳에 적지 않게 한다.
- `textureNorm16Supported`(bool, 기본 true): 대상이 R16·RG16·RGBA16 Unorm 텍스처를 표본할 수 있는지다.
  - false면 그 출력을 같은 채널 수의 16F로 바꾼다. A5i 빌드 설정에 `norm16Supported`를 더해 출력 종류를 정할 때 바꾼다. 값은 선형 그대로이고 정밀도는 약 11비트다.
  - 엔진 Android는 false다. OpenGL ES 3.2 core에 norm16이 없고(EXT_texture_norm16), Vulkan에서도 R16_UNORM 표본은 필수 형식이 아니다. Windows·Mac은 true다.
- 프로파일 JSON 병합: `ReadTargetProfile`의 import를 `mapMerge = MergeByKey`로 한다. 프로젝트 파일은 그룹 하나의 칸 하나만 덮을 수 있다(struct 값 멤버 병합 — TextJson.h).
  - 한계: 옵션이 import 전체에 걸린다. A4f의 `shaderFormats`(Replace 의미)는 필드 지정자가 필요하다. 10.3절 1항이 그때 정한다.
- 검증: 그룹의 `minLodSize` > `maxLodSize`는 `InvalidSetting`(12.4.5절 결정 — UE는 Clamp 순서로 Min이 이기지만 설정 실수로 본다), 음수 크기 `InvalidSetting`.
- 엔진 파일(`Engine/Config/TargetProfiles/Windows.json`·`Android.json`)은 UE 5.8 `BaseDeviceProfiles.ini` `[GlobalDefaults DeviceProfile]`의 TextureLODGroups 27행과 같은 값을 적는다(Windows·Android 둘 다 이것을 물려받는다).
  - 예: World·NormalMap·Character 계열은 MaxLODSize 16384·aniso·point. Effects는 linear. UI는 NoMipmaps. Bokeh는 MaxLODSize 256·linear·linear. Pixels2D는 point. 8BitData·16BitData는 point·NoMipmaps(크기 생략 — 기본값).

**처리기 `TextureCookProcessor`**(TextureTools — `TypeIdOf<Texture>()`에 등록, Texture 파생 다섯 클래스에 쓰인다):
1. **정체성**: 처리기 Guid·버전 Guid(빌드 규칙·출력 배치가 바뀌면 버전 Guid를 바꾼다).
2. **설정 판정**: `CheckTextureSettings`(12.8절 — 계약 `UnsupportedSetting`·숨김 `InvalidSetting`)가 이슈를 내면 첫 이슈의 코드로 실패한다(detail = 이슈 수 — 경로는 보고서 후속).
3. **유효 설정**:
   - 그룹 = `profile.textureLodGroups[texture.lodGroup]`(없으면 기본값)이다.
   - `ResolveTextureBuildSettings(texture, 차원, 그룹 값)`(A5i)에 `norm16Supported = profile.textureNorm16Supported`를 더한다.
   - 차원은 객체 타입이다: Texture2D·TextureCube·Texture2DArray·TextureCubeArray·VolumeTexture.
4. **원본 byte**: `context.bulkSource->ReadBulk(texture.source.bulk)`이다(파일 bulk 저장소가 CRC·해제·SHA-256을 확인한다). 원본이 비면 `InvalidSource`다(A5j2의 묶음 원본은 그 단계가 채운다).
5. **너겟 키**(bucket `texture`, 9절 표):
   - `WriteNuggetKeyHeader` 뒤 차례로 쓴다:
     - TypeId.
     - 원본 정체성: bulk SHA-256·rawBytes·형식·크기·slice·mip·layer 수.
     - 유효 빌드 설정 `TextureBuildSettings`의 모든 칸(명시적 기록 함수 `WriteTextureBuildKey`).
     - 압축 기록 칸(`compressionNoAlpha`·`compressionForceAlpha`·`compressionNone`·`compressionCacheId` — 결과를 바꾸지 않지만 9절 표대로 넣는다).
     - 그룹 행 전부.
     - 샘플러 입력: `filter`·주소·`borderColor`.
     - 스트리밍 입력: `neverStream`·`mipLoadOptions`·`availability`·`lodGroup`.
     - 프로파일 id·`textureNorm16Supported`·상주 꼬리 상수 `TextureMinResidentMipCount`.
   - 텍스처 객체를 `WriteReflected`로 통째로 쓰지 않는다. `compositeTexture`(ObjectRef)는 키에 쓸 수 없다(Unsupported). 대신 9.1절 결정 2의 의무대로 **칸마다 바꾸면 키가 바뀌는 변이 시험**을 둔다(`TextureBuildSettings`·그룹 struct는 칸 수를 static_assert로 묶어, 칸을 더하면 기록 함수와 시험을 고치게 한다).
   - Build 의존이 없으므로 SCC는 구성원 하나다(`NuggetSccKey` — Record는 SCC key, 9.1절 결정 3). A5j2의 묶음 원본은 외부 의존 튜플로 들어간다.
6. **너겟 값**: ValueId = mip 번호(상위부터 0, 쿠킹 편향 뒤 남은 mip)다.
   - meta(결정적, 64 KiB 이하)는 머리 { 형식 버전 1, PixelFormat 번호, srgb, swizzle 넷, numSlices, mip 수, mip마다 sizeX·sizeY·sizeZ·byte 수 }다.
   - 적중이면 meta와 값으로 결과를 다시 만든다. meta가 해석되지 않거나 값 수·크기가 맞지 않으면 미적중으로 다룬다(9.1절 — 틀린 적중 0건).
   - `verifyNuggets`면 적중이어도 빌드해 byte를 대조하고, 다르면 `NuggetMismatch`다(10.2절 결정 12).
   - 미적중이면 빌드하고 Put한다(Put 실패는 쿠킹 실패가 아니다 — `required`면 오류).
7. **`TexturePlatformData`**(12.1·12.5.1절):
   - `dimension`, `pixelFormat`(PixelFormat 번호 — 12.8절 저장 계약), `srgb`, `swizzle*`를 채운다.
   - `sizeX`·`sizeY`·`sizeZ`(쿠킹 상위 mip — Volume 깊이, 그 밖 1), `numMips`(N), `numSlices`(Volume 1, 그 밖 slice 수)를 채운다.
   - `mips[i]`: 크기, `byteSize`. 스트리밍 mip은 `bulk`(mip 하나가 bulk 하나)를 쓰고, 상주 꼬리 mip은 `tailOffset`(꼬리 덩어리 안 오프셋)을 쓴다.
   - `tailBulk`(상주 꼬리 mip을 큰 mip부터 이은 bulk 하나), `residentTailMips`(R)를 채운다.
   - R은 12.5.1절 2번이다. 비압축이라 블록 규칙이 없고 형식 mip tail 수는 0이다. 상수 `TextureMinResidentMipCount` = 7은 TextureTools 공개 상수다.
   - 비스트리밍(R = N)은 12.5.1절 3번 조건이다: `neverStream`, UI 그룹, N = 1, NoMipmaps(유효 설정), Cube·CubeArray, X 또는 Y가 2의 거듭제곱이 아님, `mipLoadOptions` OnlyFirstMip(계약이라 2번에서 이미 거부), `availability` CPU.
   - `availability` CPU: UE는 GPU 쪽 placeholder mip 하나와 CPU 사본을 둔다(12.13절). A5j1은 mip 0을 상주 꼬리에 두고 비스트리밍으로 쓴다. placeholder 배치는 렌더러 CPU 텍스처 지원(화면 마일스톤 뒤)과 함께 정한다(계약 — 렌더 세션 알림에 적는다).
8. **샘플러 `TextureSamplerSettings`**:
   - `filter`는 텍스처 `filter`다. Default면 그룹 MinMagFilter·MipFilter 조합이고, Nearest → Point, Bilinear → Bilinear, Trilinear → Trilinear다.
   - `maxAniso`는 그룹 값이다.
   - 주소: Texture2D addressX·Y(W Clamp), 2DArray X·Y·Z, Volume addressMode 세 축, Cube·CubeArray Clamp 셋이다.
   - `borderColor`: Texture2D·2DArray·Volume의 값, Cube 계열 TransparentBlack이다.
9. **쿠킹 패키지**:
   - 처리기는 쿠킹 Registry에 연 에디터 객체의 `platformData`를 채운다. 이 객체는 저장하지 않는다 — 쿠킹 실행이 닫는다.
   - 새 bulk(mip·꼬리)는 `MemoryBulkSource`에 둔다.
   - `WritePackage(kind Cooked, …, bulkSource = 그 MemoryBulkSource)`다. 쿠킹 그래프의 BulkDataRef는 EditorOnly 원본이 빠지므로 새 bulk뿐이다. 다른 bulk ref가 남으면 writer가 NotFound로 실패한다 — 처리기 결함이다.
   - bulk codec·정렬은 프로파일 값(기본 처리기와 같다)이다.
10. **경고**: 빌드 경고(`SrgbIgnored`·`PreserveBorderWithWrap`)를 `CookContext`의 새 칸 `warnings`(`Array<CookDiagnostic>*`, null이면 버린다)에 둔다.
    - 쿠킹 실행은 이것을 실행 진단에 `warning = true`로 옮긴다.
    - `CookRunResult::HasErrors`는 경고가 아닌 진단만 센다(지금은 "실행 진단은 모두 오류"). 보고서·명령 출력은 경고 줄로 낸다.

**호스트 연결**(A5h의 임포터·hook과 같은 방식):
- `commandlet_host::AssetCommandContext`에 `AssetCookProcessorSetup cookProcessors{registerProcessors(state, CookProcessorTable&)}`를 더한다.
- `asset-cook` 명령은 표를 만든 뒤 이것을 부른다.
- 제품 호스트(Commandlet)는 TextureTools `RegisterTextureCookProcessors(state = TextureCookProcessor*)`를 건다.
- TextureTools는 AssetCooker·AssetNugget에 의존하고, AssetCooker는 Texture 모듈(LOD 그룹 enum)에 의존한다.

**버린 대안**:
- 텍스처 객체 통째 `WriteReflected`: ObjectRef(compositeTexture)가 키에 쓸 수 없는 종류라 실패한다. 명시 기록 + 변이 시험 + 칸 수 static_assert로 R-0을 지킨다.
- 그룹 표를 배열로 두기: 배열은 통째 교체라 프로젝트가 그룹 하나를 바꾸려면 27행을 모두 다시 적어야 한다.
- 16비트 Unorm을 Android에서 거부: 16비트 원본 텍스처 쿠킹이 Android에서 실패한다. 16F 대체는 정밀도만 낮다.
- 쿠킹 패키지를 처리기가 새 그래프로 만들기: 기본 처리기와 같은 writer 경로(EditorOnly 제외)를 쓰는 편이 패키지 규칙을 한 곳에 둔다.

**시험(A5j1)**:
- 프로파일: 텍스처 칸 기본값, MergeByKey(그룹 하나의 칸 하나만 덮음·새 그룹 넣기), 검증(Min > Max·음수), 엔진 Windows·Android 파일의 27행과 Android norm16 false, 출력 설정 SHA-256이 텍스처 칸을 포함함.
- 처리기:
  - 차원 다섯의 쿠킹 패키지(EditorOnly 원본 없음·platformData 칸·bulk 수와 SHA-256이 mip byte와 같음).
  - R 표(12.5.1절 6번 — 1×1·4×4·8×8·256×256·2048×2048·2048×64), 비스트리밍 조건마다 R = N·스트리밍 bulk 없음.
  - 샘플러 표, norm16 대체(Android), 계약 설정·그룹 계약 mipGen 실패, 빈 원본 `InvalidSource`.
- 너겟:
  - 미적중 → Put → 같은 키 적중(빌드 호출 없음·같은 byte), meta 손상·값 수 불일치는 미적중.
  - verify 일치·불일치(`NuggetMismatch`), 변이 시험(유효 설정·그룹·샘플러·스트리밍·프로파일 칸마다 키가 바뀜, 경로·이름은 바뀌지 않음).
- 경고: 쿠킹 진단 경고(`SrgbIgnored`)는 publish를 막지 않고 보고서에 나온다.
- 명령: `asset-cook --profile=Windows`의 텍스처 쿠킹(제품 호스트 연결), 할당 실패.

#### A5j2

**에셋 원본 묶음**(12.3절 — `asset-new Texture2DArray … SourceTextures=…` 등):
- Texture2DArray·TextureCubeArray의 `sourceTextures`(Texture2D·TextureCube 목록)와 VolumeTexture의 `source2DTexture`·`source2DTileSizeX/Y`가 원본을 정한다.
- UE는 편집 때 묶음을 자기 `Source`로 복사한다(`UpdateSourceFromSourceTextures`). Rocks도 UE처럼 **편집 때 복사**한다.
  - 설정 정규화 hook(12.12절)이 아니라 서비스 단계다. 대입이 `sourceTextures`·`source2DTexture`를 바꾸면 서비스가 참조 에셋을 열어 원본을 이어 붙인 `TextureSource`를 만든다.
  - 그래서 쿠킹은 자기 원본만 읽는다. 쿠킹 처리기에는 묶음 경로가 없고, 묶음 원본의 변경은 재복사 명령(`asset-reimport`의 묶음 버전 — 세부는 A5j2 명세)으로 반영한다.
- A5j2 착수 때 세부를 이 절에 적는다: 서비스 API, 원본 규칙(같은 크기·형식·차원 — 12.3절), 진단, UE `UpdateSourceFromSourceTextures`·`UpdateSourceFromSourceTexture` 대조, Build 의존 필요 여부.
  - Build 의존 판정: 편집 때 복사하면 쿠킹 입력에 다른 에셋이 없으므로 Build 의존이 필요 없다. 12.7절의 "Build 의존" 문구는 이 결정으로 바꾼다.
