#### 14.1.111 요구 대조표(A4f3 — 비에셋 산출물 단계)

명세는 [10.3절 2·3·5·6·9항](../../10-Cooker/10.3-ShaderLibrary.ko.md)과 [10.3.1절 A4f3](../../10-Cooker/10.3.1-A4fDetails.ko.md)이다.

구현:
- AssetCooker 새 헤더 `CookArtifacts.h`:
  - 요청·출력·sink·단계: `CookArtifactRequest`·`CookArtifactOutput`·`CookArtifactSink`(NewStagingPath·Produce·Reuse·Report·ReportStat)·`CookArtifactStage`.
  - 표: `CookArtifactStageTable`(종류별 칸·사용 중 계수 Busy)·`CookArtifactStageUse`, 프로세스 표 `CookArtifactStages()`.
  - 실패 원인: `CookArtifactCall`·`CookArtifactCallName`·`CookArtifactFailure`.
- `CookProject`:
  - `CookPackages` 뒤·`Finish` 전에 `RunArtifactStages`를 돈다.
  - 셰이더 없는 프로필은 단계를 부르지 않는다. 단계가 없으면 code None·`UnsupportedCapability`다.
  - 재사용 후보는 `PlanCookReuse`와 같은 머리 조건 + 게시 파일 대조다.
  - sink `ArtifactStageSink`가 계약을 확인한다.
  - 요청·결과 칸: `CookProjectRequest::stages`, `CookProjectResult::artifacts`·`stats`·`stageFailure`.
  - 보고서 `artifacts`·`stageStats`(새 struct `CookReportArtifact`·`CookReportStat`, 안정 id 추가).
- `CookPublisher`:
  - `Begin`이 `Shaders/`도 만든다.
  - `PutArtifact`: 직접 해시 → 내용 주소 이름 → no-replace 이동 → 대조, `CorruptEntry`·교체.
  - `ReuseArtifact`·`ArtifactFileMatches`·`Artifacts()`.
  - 패키지 `Put`과 공용 `PlaceStaged`.
  - `Finish`: 이번 artifact를 정렬해 넣고 병합한다. 전체 쿠킹은 `Shaders/`를 정리한다.
- CookSettings `cookDevelopmentShaders`(안정 id 추가).
- `asset-cook`이 `CookArtifactStages()`를 넘기고, 단계 실패 줄에 정체성·호출·형식을 적는다.
- 시험 장면 `ProjectScene`을 `CookProjectTestSupport.h`로 옮겼다(CookProjectTests·CookArtifactTests가 함께 쓴다).

| 요구 | 항목 | 시험 |
|---|---|---|
| 단계 표 | 등록·찾기(종류 0·2는 null), 같은 종류 AlreadyExists, 다른 객체 해제 NotFound, 사용 중 해제·등록 Busy(구간 뒤 다시 됨), 모르는 종류 등록 InvalidArgument·해제 NotFound, 프로세스 표 하나·왕복, 호출 이름 | `CookArtifact_StageTable` |
| 게시 | 형식 둘 × 이름 둘 게시, 매니페스트 크기·SHA = 게시 파일(쿠커 계산), `FindArtifact`·`CheckCookedArtifactFile`, 정렬, 보고서 `kind`·`reused`·`stageStats` | `CookArtifact_PublishesAndReuses` |
| 재사용 | 두 번째 쿠킹 후보 넷 모두 Reuse·새 byte 0·보고서 reused true, 게시 파일 손상 → 후보 셋 → 다시 만든 같은 이름이 `CorruptEntry`(asset null) 뒤 교체 | `CookArtifact_PublishesAndReuses` |
| 정리 | 전체 쿠킹이 옛 파일·떠도는 파일 삭제, 부분 쿠킹은 옛 파일 유지(매니페스트는 새 항목) | `CookArtifact_PublishesAndReuses`·`CookArtifact_PartialAndVerify` |
| 후보 조건 | verify 쿠킹·프로파일 출력 설정 다름은 후보 없음 | `CookArtifact_PartialAndVerify` |
| 오류·능력 | job 오류 → 게시 안 함(진단), 단계 미등록 → code None·`UnsupportedCapability`·게시 안 함·보고서, 셰이더 없는 프로필은 등록되어 있어도 단계 안 부름, 에셋 오류(사라진 파일)가 있어도 단계가 돎 | `CookArtifact_ErrorsAndCapability` |
| 계약 위반 | 이름·형식 문법·프로필에 없는 형식·sink가 주지 않은 경로·같은 경로 두 번·같은 키 두 번·0 byte·후보 밖 Reuse → InvalidArgument로 멈춤, `stageFailure` 호출·정체성·형식, 게시 안 함 | `CookArtifact_ContractViolations` |
| 설정·사용 중 | `cookDevelopmentShaders`가 요청으로 닿음(cookKey가 바뀌어 다시 만듦), Run 중 해제·등록 Busy, 끝나면 사용 중 아님 | `CookArtifact_SettingsAndBusy` |
| 설정 SHA | `cookDevelopmentShaders` true가 CookSettings SHA-256을 바꿈 | `CookConfig_Hashes` |
| 할당 | 첫 쿠킹·재사용 쿠킹의 모든 지점 OutOfMemory, 표 사용 중 아님 | `CookArtifact_AllocationFailures` |
| 명령 | 가짜 단계로 게시(`--json`의 ShaderLibrary·형식, `Shaders/`), 미등록 `UnsupportedCapability: <루트>: error`, 계약 위반 실패 줄 `stage <Guid> Produce(<형식>)`, 기존 명령 시험은 RAII 등록으로 그대로 | `AssetCookCommand_ArtifactStage`·`AssetCookCommand_*` |

engineOnly 요청(`Engine`만)은 A4f4 `asset-cook --engine`과 함께 시험한다(지금 `CookProject`는 늘 거짓으로 넘긴다).
