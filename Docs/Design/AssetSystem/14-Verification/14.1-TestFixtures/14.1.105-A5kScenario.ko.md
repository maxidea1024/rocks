#### 14.1.105 요구 대조표(A5k — 텍스처 시나리오)

명세는 [12.15절](../../12-Textures/12.15-A5kScenario.ko.md)이다. 새 제품 코드는 없다(문서 판정과 시험만).

시험은 TextureTools `Tests/TextureScenarioTests.cpp`의 `TextureScenario_ImportEditCookLoad`다.

| 요구 | 항목 |
|---|---|
| 시나리오 1 | PNG 임포트 → 닫고 다시 열어 같은 AssetId·원본 형식·크기·SRGB·원본 byte = PNG 픽셀 |
| 묶음(A5j2a) | `asset-new Texture2DArray sourceTextures=…` → 쿠킹 형식 RGBA8 sRGB·slice 2·mip 1(처음 만들기 NoMipmaps)·R 1, 쿠킹 객체에 묶음 칸 없음 |
| 설정 편집 | `asset-set compressionSettings=Masks lodBias=1` → 쿠킹 RGBA8Unorm·sRGB off(정규화)·mip 4·상위 8×8·R 4 |
| 시나리오 2 | Wall 원본 PNG를 지운 뒤 쿠킹 성공 |
| 시나리오 10 | mip 0 = 원본 2×2 상자 평균(UE 식, 8비트 선형 디코딩 식은 빌드 때 대조 — 1 차이 허용) |
| 시나리오 11 | 쿠킹 객체의 EditorOnly 원본 없음 |
| 시나리오 13 | 다시 쿠킹 → cooked 0·reused 3·같은 매니페스트 byte |
| PostLoad 판정 | 텍스처는 클래스 PostLoad를 쓰지 않음(문서 — 시험 없음) |

빌드 때 더할 것(화면 마일스톤 뒤 — 미빌드): 시험 실행, 8비트 선형 디코딩 식을 확정해 1 차이 허용을 없앰, 런타임 AssetManager 경로(로더 Pump·PostLoad handler 없음)로 같은 쿠킹 결과 로드.
