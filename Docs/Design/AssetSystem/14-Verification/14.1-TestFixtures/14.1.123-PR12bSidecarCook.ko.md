#### 14.1.123 요구 대조표(PR12b — sidecar 쿠킹·게시·검증 명령)

명세는 [20.5절](../../20-StreamingBulk.ko.md)이고, 런타임 범위 읽기 손잡이(PR12c)는 뒤 단계다.

구현:
- `CookChainedBulkSource::Add(bytes, PackageBulkPlacement)`·`Placement`(새 bulk는 그 배치, 그 밖은 next).
- `CookContext::sidecar`: 기본 `WriteCookedPackage`가 writer에 넘기고, null이면 배치만 Package로 바꾸는 어댑터로 감싼다(서버 프로필 자리).
- 실행기: sidecar 메모리 sink, 로더 대조 항목·`CookedPackage::sidecar`·`sidecarSha256`.
- 게시기: sidecar를 먼저 `Packages/<a>/<A>-<h>.rbsc`에 둔다(`PutFile` — 패키지와 같은 staging·no-replace·대조). 항목·병합·재사용이 sidecar 칸을 옮긴다. 재사용 판정은 sidecar 파일을 대조하고, 전체 쿠킹 정리는 참조 sidecar를 남긴다.
- AssetRuntime `VerifySidecarFile`, `asset-load-cooked --verify-sidecars`(대상 선택, 검증만이면 타입 모듈을 등록하지 않는다).

| 요구 | 항목 | 시험 |
|---|---|---|
| 쿠킹 bulk 원본 배치 | 새 bulk Package·Sidecar, next 배치, next 없음 Package | `CookRun_ChainedBulkPlacement` |
| 실행기 sidecar | Hero sidecar byte·SHA·bulkRawBytes 0, Sidecar 섹션 = 출력, VerifySidecarFile 통과, bulk 없는 대상은 sidecar 없음, 두 번 같은 byte, 출력 null이면 패키지 안 | `CookRun_SidecarPlacement` |
| 실행기 할당 실패 | sidecar 처리기로 모든 지점 OutOfMemory, 다 지나면 같은 패키지·sidecar | `CookRun_AllocationFailures` |
| 게시 | 놓임·항목 칸·새로 쓴 byte, 같은 내용 안 씀, 손상 교체, 패키지 단계 실패 시 매니페스트 불변, sidecar 쓰기 실패 시 패키지 없음·임시 파일 없음, 부분 쿠킹 보존, 재사용 항목의 칸, 전체 쿠킹이 옛 sidecar만 지움 | `CookPublish_Sidecar` |
| 재사용 판정 | 그대로 재사용·sidecar 지움·바뀜 다시 쿠킹·sidecar 없는 항목 | `CookPublish_PlanReuseSidecar`, `CookPublish_PlanReuse`(할당 실패에 sidecar 대조 포함) |
| 게시 할당 실패 | sidecar 있는 Put·병합·재사용·정리(낡은 `.rbsc` 지움)의 모든 지점 | `CookPublish_AllocationFailures` |
| 파일 검증 | 조각 크기 여섯, 크기·머리 detail 0, 블록 1·마지막 블록 번호, 전체 SHA만 다름, IO 오류, 빈 scratch·sidecar 없는 패키지 | `AssetSidecar_VerifyFile` |
| 검증 명령 | 대상 없이 verified 1, 대상과 함께(로드 줄 뒤), 손상 CorruptPackage·없음 MissingFile `(sidecar)`, 두 번·대상 없음 사용법 | `AssetLoadCookedCommand_VerifySidecars` |
