#### 14.1.107 요구 대조표(A4f1 — TargetProfiles 모듈·셰이더 칸·Map 병합 플래그)

명세는 [10.3절 1항](../../10-Cooker.ko.md)과 10.3.1절 A4f1이다.

구현:
- Core 리플렉션 `FieldFlags::TextMapMergeByKey`(256): TypeSchema.h, ObjectRuntime `KnownFieldFlags`, MetaCompiler(지정자·비트·RMC2202·descriptor), ReflectionText `TextJsonImport.cpp`(옵션 MergeByKey 또는 플래그).
- 새 모듈 `Engine/Source/Developer/TargetProfiles`:
  - 타입: `TargetProfile`(+ `graphicsBackends`·`shaderFormats` — `ShaderFormatList`로 감쌈, `textureLodGroups`에 플래그)·`TextureLodGroup`·enum 셋.
  - 함수: `ReadTargetProfile`·`ReadHostTargetProfile`·`ApplyConfigJsonFile`·`IsKnownGraphicsBackend`·`IsValidShaderFormatId`·`FindTextureLodGroup`.
  - 실패 진단: `TargetProfileFailure`·`TargetProfileField`·`TargetProfileFile`.
  - 안정 id: AssetCooker에서 같은 Guid로 옮김, `graphicsBackend`는 retired.
- AssetCooker:
  - `ReadTargetProfile`은 변환 wrapper다(`ToCookConfigField`·`ToCookConfigFile`, 새 칸 `GraphicsBackends`·`ShaderFormats`).
  - CookSettings는 공개 도우미로 읽는다.
  - 의존: Texture를 TargetProfiles로 바꿈.
- 명령 문구, AssetRuntime 상수 `CookedManifestMaxBackends`·`CookedManifestMaxFormatsPerBackend`, 엔진 파일 Windows·Android 셰이더 칸·새 Mac.json.

| 요구 | 항목 | 시험 |
|---|---|---|
| 플래그 수용·거부 | Map 필드 descriptor flags·비트 256·생성 헤더 컴파일, Map 아닌 필드 RMC2202 | `Meta.TextMapMergeByKeyReachesMapFields`·`Meta.TextMapMergeByKeyNeedsMap` |
| 플래그 의미 | 플래그 Map 키별 병합(있던 항목 멤버 병합 — 안쪽 플래그 없는 Map은 통째 교체, 새 항목, 없는 키 유지), 플래그 없는 Map 통째 교체, 옵션 MergeByKey는 모두 키별 | `TextJson_FieldMapMergeByKey` |
| 알 수 없는 플래그 | 다음 비트(512) 등록 거부 | `TypeFlags_*`(TypeFlagTests) |
| Replace·병합 | 프로젝트가 형식 Map을 한 backend만 적으면 Map 통째 교체 → 빠진 backend 거부, 함께 덮으면 받음, LOD 그룹 키별 병합, 프로젝트 층 없는 문맥 | `TargetProfile_ShaderFieldsReplaceAndLodMerge` |
| 구조 검증 | 어휘 밖·중복·상한 8(index 8)·형식 목록 없음·빔·목록에 없는 키(index = Map 순서)·형식 id 문법·전역 중복·backend 안 중복·형식 수 17·셰이더 없는데 Map 있음, 받는 경계(빈 프로파일·셰이더 없는 프로파일·어휘 다섯), 어휘·문법 함수 | `TargetProfile_ShaderChecks` |
| JSON 층 도우미 | 없는 파일·크기 상한(File)·문법(Json·위치)·대입 진단(Text)·성공 | `TargetProfile_ConfigJsonLayer` |
| 호스트 프로파일 | 빈 재정의 = HostPlatformName(), 재정의 이름, 엔진 파일 없는 플랫폼 InvalidSetting | `TargetProfile_HostProfile` |
| 엔진 파일 | Windows·Android·Mac backend·형식·LOD 그룹 27행·norm16 | `TargetProfile_EngineFiles`·`CookConfig_TextureProfile`·`CookConfig_ProfileMerge` |
| AssetCooker | SHA-256이 셰이더 칸 변화로 바뀜(backend·형식), 변환 wrapper(기존 거부 표 그대로), 할당 실패 전수의 새 칸 | `CookConfig_Hashes`·`CookConfig_ProfileRejects`·`CookConfig_AllocationFailures` |

시험 지원 예외: TargetProfiles 시험은 AssetDatabase 시험 헤더 `MemoryFileSystem.h`(header only — Core만 쓴다)를 쓴다(FoundationTests `TestGroupModules["TargetProfiles"] = ["AssetDatabase"]`). 제품 코드와 링크는 AssetCooker·에셋 DB 없이 단독이다. 메모리 파일 시스템을 공용 시험 지원(TestSupport)으로 옮기면 이 예외를 지운다(후속).

리뷰(2026-11-25): 승인. 권장 셋 반영 — descriptor 읽기의 Map 전용 검사(`ModuleMeta` 손상 사례 `mapMergeScalar`), 셰이더 판정 순서·index 뜻(10.3.1절 3번 앞), 시험 지원 예외 기록.

빌드 때 더할 것(화면 마일스톤 뒤 — 미빌드): 시험 실행(C# MetaTests 포함), 대응 표 전부를 도는 `ToCookConfigField` 시험, 다른 모듈이 import하는 descriptor 왕복의 플래그 보존.
