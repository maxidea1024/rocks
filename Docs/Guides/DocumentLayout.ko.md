# 문서 배치 규칙

기준일: 2026-11-23(사용자 결정). `Docs/` 아래 설계·구현·안내 문서의 파일 크기와 나누는 방식을 정한다.

## 1. 크기 기준

- 파일 하나는 500줄을 넘지 않는다.
- 500줄을 넘는 문서는 폴더로 바꾸고 장(최상위 `##` 절)마다 파일 하나로 나눈다.
- 장 하나가 500줄을 넘으면 그 장을 다시 폴더로 바꾸고 절마다 파일로 나눈다.
- 기록 문서(`Docs/Reviews`·`Docs/Releases`)와 측정 결과 표(`Docs/Benchmarks`)는 대상이 아니다.

## 2. 폴더 구성

```text
Docs/Design/AudioSystem/
  README.ko.md             표지: 제목·기준일·현재 개정·요약, 약어, 장 목차(링크), 개정 기록
  01-Scope.ko.md           "## 1. …" 장
  03-Mixer/                500줄을 넘는 장
    README.ko.md           장 머리말과 절 목차
    03.15-ReverbZone.ko.md "### 3.15 …" 절
  img/                     그림(문서 하나만 쓰면 그 폴더 안에)
```

- 파일 이름은 장 번호 두 자리, `-`, 영어 주제(PascalCase), `.ko.md` 순서다. 절 파일은 `03.15-` 처럼 절 번호를 쓴다.
- 장·절 번호는 나누기 전과 같게 둔다. 파일 안 제목도 `## 3. …` 그대로다. 그래서 기존 "3.15절" 인용은 계속 맞는다.
- 개정 기록이 길면 `README.ko.md` 대신 `Revisions.ko.md`로 뺀다.

## 3. 참조

- 문서 사이 링크는 장 파일을 직접 가리킨다. 예: `[오디오](../AudioSystem/03-Mixer.ko.md) 3.15절`. 문서 전체를 가리킬 때는 폴더의 `README.ko.md`다.
- 코드 주석·빌드 스크립트·정책 파일은 폴더 경로와 절 번호를 쓴다. 예: `Docs/Design/AudioSystem 3.15절`. 이렇게 하면 장을 다시 나눠도 주석을 고치지 않는다.
- 문서 약어(EIP·AU 등)는 바꾸지 않는다.

## 4. 옮기는 절차

- 기존 문서는 그 문서를 맡은 세션이 다음에 그 문서를 고칠 때 나눈다. 다른 세션의 문서를 일괄로 옮기지 않는다(동시 작업과 충돌하므로).
- 나누기는 내용 변경 없는 이동 커밋 하나로 한다. 내용 수정과 섞지 않는다.
- 같은 커밋에서 저장소 전체의 옛 경로를 새 경로로 고친다(`git grep "<이름>.ko.md"`). 과거 기록(`Docs/Reviews`·`Docs/Releases`)의 옛 경로는 고치지 않는다.
- 확인: 옛 경로 `git grep` 결과 0건(기록 문서 제외), 새 링크 대상 파일 존재, 각 파일 500줄 이하.
- 새 문서가 500줄을 넘을 것으로 보이면 처음부터 폴더로 만든다.
