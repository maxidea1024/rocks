Rocks Engine

Rocks가 다른 여섯 가지 이유

안정성·정확성을 먼저, 그다음 확장성과 성능. 이 순서를 한 번도 바꾸지 않았기에 위에 무엇을 쌓아도 바탕이 흔들리지 않는다.

엔진 구조

깨끗하게 나뉜 단방향 층 구조

아래 층은 위 층을 모른다. 엔진은 창과 그래픽을 직접 알지 않으므로, 같은 엔진이 게임으로도, 화면 없는 서버와 시험으로도 그대로 돈다.

콘텐츠 파이프라인

한 번 만든 결과는 다시 만들지 않는다

에디터 쪽 도구가 원본을 임포트·빌드하고, 대상 기기에 맞춰 쿠킹한 패키지만 게임이 읽는다. 텍스처 원본은 무손실 형식과 JPEG만 받고, 압축은 쿠킹 단계에서 기기별 형식으로 한다.

빌드 결과는 입력·설정·도구 판으로 만든 키로 에셋 너겟에 저장한다. 같은 키가 있으면 그대로 꺼내 쓰므로, 팀원과 기기가 빌드 비용을 나눠 진다.

게임플레이 언어

Sparks — 쓰기 쉽고 실수하기 어려운 언어

프로그래머가 아니어도 읽고 쓸 수 있는 단순한 정적 타입 언어. 파괴된 객체 참조는 null이 되고, 메모리·리소스 누수는 언어 구조상 생길 수 없다. 컴파일러부터 VM·도구·에디터 지원까지 모두 Rocks가 직접 만들었다.

Sparks 코드

게임을 멈추지 않고 코드를 바꾼다

class PlayerCharacter : Character {
    @edit var MoveSpeed: float = 600.0;        // 초당 600 cm
    let JumpAction = Action("Gameplay.Jump");  // 입력 액션, 컴파일 시 검증
    var CurrentTarget: Enemy?;                 // 대상이 파괴되면 null

    on JumpAction.Triggered() {
        AddImpulse(vec3(0.0, 0.0, 500.0));
    }

    on Tick() {
        if (let target = CurrentTarget) {
            LookAt(target.Location);
        }
    }
}
