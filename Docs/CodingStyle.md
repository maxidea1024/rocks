# Rocks 코드 스타일

**사람이 알아보기 좋은 코드 스타일 유지**를 필수 구현·리뷰 기준으로 적용한다.

## 서식과 가독성

- 들여쓰기는 스페이스 4칸이다. 실제 탭 문자는 사용하지 않는다.
- 함수·타입 정의와 의미가 다른 처리 단계 사이에는 적절한 빈 줄을 둔다.
- 이름만으로 역할과 단위가 드러나도록 작성한다. 긴 함수는 책임 경계에 따라 나눈다.
- 여러 처리 단계나 분기를 한 줄에 압축하지 않는다. 서식 검사를 통과하더라도 읽기 어려운 코드는 리뷰에서 수정한다.
- 줄 길이는 기본 100열이다. 자동 정렬 규칙은 저장소 루트의 `.clang-format`을 따른다.
- 파일은 UTF-8, LF, 마지막 개행을 사용한다. 에디터 설정은 `.editorconfig`를 따른다.

## 이름과 경계

공개 C++ API는 `rocks` 네임스페이스와 자체 이름을 사용한다. U/F/A 등 타입 분류용 접두사를 사용하지 않는다. C ABI·외부 언어 연결에는 충돌 방지를 위한 `rocks_` 접두사를 검토하며, 외부 공급자의 네이밍은 adapter 내부로 제한한다. 구체 API·수명·스레드 규약은 설계 문서를 따른다.

## 자동 검사와 사람의 검토

현재 설정 및 설계 문서의 C++ 예제는 **clang-format 21.1.6**으로 검증하였다. 버전을 고정하고 버전 변경은 독립 변경으로 검토한다.

실제 소스가 추가되면 C00에서 `clang-format --dry-run --Werror` 검사와 의도적으로 잘못된 서식 fixture를 로컬·CI에 연결한다. 현재 저장소에는 엔진 소스와 CI 구현이 없으므로 이 검사 체계가 이미 구현되었다고 간주하지 않는다.

포맷터는 책임 분리, 명명 품질, 수명과 동시성 규약의 이해 가능성을 판정하지 않는다. 이 항목들은 코드 리뷰와 하네스 검증을 함께 요구한다.
